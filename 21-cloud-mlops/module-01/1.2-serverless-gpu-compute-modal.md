# 1.2 Serverless GPU Compute Platforms: Scale-to-Zero and Cold Starts

## Phase A: Problem-First Breakdown

### 1. Real-World Pain Point (The Why)
You've decided to move away from expensive always-on IaaS and use a Serverless GPU platform like Modal, RunPod, or Together AI. You configure your LLM to scale to zero when unused. But now you face a new nightmare: The "Cold Start". When a user sends a request after an hour of inactivity, the platform has to provision a container, download a 16GB model file from cloud storage, load it into VRAM, and *then* run inference. The user waits 45 seconds for a response and closes the tab.

### 2. Plain English Metaphor (The What)
**The Cold Start:** You ordered a pizza (API request), but the chef was asleep (scaled to zero). The chef has to wake up (provision container), drive to the store to buy ingredients (download model weights), prep the ingredients (load to VRAM), and then cook.
**The Warm Pool / Baked-in Model:** The chef is asleep, but the ingredients are already prepped and sitting on the counter. Cooking takes much less time.

### 3. Complete Runnable Code
Here is how you deploy a Serverless Llama-3 API on Modal, utilizing Modal's Volume architecture to cache model weights so you don't download them on every cold start.

```python
# app.py (Run with: modal deploy app.py)
import modal
import os

# 1. Define the Container Environment
image = modal.Image.debian_slim().pip_install(
    "vllm==0.4.0", "huggingface_hub"
)

# 2. Define a persistent Volume to cache model weights
volume = modal.Volume.from_name("llama-weights-cache", create_if_missing=True)

app = modal.App("serverless-llama-api")

# 3. Download weights ONCE during image build, not during cold start
def download_model():
    from huggingface_hub import snapshot_download
    # Downloads to the volume path
    snapshot_download("meta-llama/Meta-Llama-3-8B-Instruct", local_dir="/data/model")

# 4. Define the Web Endpoint
@app.function(
    image=image.run_function(download_model, volumes={"/data": volume}),
    gpu="A10G",
    keep_warm=1, # Keep 1 container alive (no cold start for 1st concurrent request)
    container_idle_timeout=300 # Scale to zero after 5 mins of inactivity
)
@modal.web_endpoint(method="POST")
def generate_text(request: dict):
    from vllm import LLM, SamplingParams

    # Loads from the fast local volume, not the internet
    llm = LLM(model="/data/model")

    prompt = request.get("prompt", "Hello!")
    sampling_params = SamplingParams(temperature=0.7, max_tokens=100)

    outputs = llm.generate([prompt], sampling_params)
    return {"text": outputs[0].outputs[0].text}
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: Container & Volume Setup**
We define a Docker-like image using `modal.Image`. Crucially, we attach a `modal.Volume`. If we don't do this, the container will download the 15GB Llama-3 model from Hugging Face every single time it boots.

**Step 2: Pre-baking the Model**
We use `image.run_function(download_model...)`. This executes `download_model` *at build time*. The weights are saved to the `/data` volume. When the container boots during a cold start, the weights are already physically present on the disk attached to the GPU.

**Step 3: Keep-Warm & Timeouts**
We use `keep_warm=1` and `container_idle_timeout=300`. This means Modal will always keep at least 1 container running (costing you money 24/7 for 1 GPU, but ensuring instant responses). Additional concurrent traffic will trigger cold starts, but those containers will die 5 minutes after traffic stops.

### 5. ASCII Data Flow
```text
[User Request]
      |
      v
[Modal Load Balancer]
      |
      +-- Is there a warm container?
      |       |--> YES: Route immediately (Latency: 200ms)
      |       |--> NO (Scale from 0):
      |             1. Provision VM/Container (2-3s)
      |             2. Mount Volume with pre-downloaded weights (1s)
      |             3. Load weights into GPU VRAM (10s)
      |             4. Process Request
      v             Total Cold Start Latency: ~14 seconds
[Response]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `LLM(model="meta-llama/...")` directly in the endpoint without a Volume. This forces the container to download the model over the internet on every cold start, making cold starts take 2+ minutes.
**Pro Tip:** For production, always use a Volume or bake the weights directly into the container image. Combine this with `keep_warm=1` to guarantee a snappy experience for base load, relying on scale-to-zero only for burst traffic.

### Level 2: Real-World
**Challenge:** The current implementation instantiates the `LLM()` engine inside the `generate_text` function. This is terrible! It means every single HTTP request re-loads the model into VRAM. Refactor the code using Modal's Class-based syntax (`@modal.cls`) to load the model into VRAM *once* during container boot using an `__enter__` method.

<details>
<summary>Hint</summary>
Create a class, decorate it with `@app.cls()`. Move the `LLM` initialization to `@modal.enter()`. Decorate the inference method with `@modal.web_endpoint()`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
@app.cls(gpu="A10G", keep_warm=1)
class ServerlessLlama:
    @modal.enter()
    def load_model(self):
        # Runs ONCE when the container boots
        from vllm import LLM
        print("Loading weights into VRAM...")
        self.llm = LLM(model="/data/model")

    @modal.web_endpoint(method="POST")
    def generate_text(self, request: dict):
        # Runs on every HTTP request
        from vllm import SamplingParams
        prompt = request.get("prompt", "Hello!")
        sampling_params = SamplingParams(temperature=0.7, max_tokens=100)
        outputs = self.llm.generate([prompt], sampling_params)
        return {"text": outputs[0].outputs[0].text}
```

### Level 3: Boss Level
**Challenge:** You are deploying a multi-tenant LLM platform. You need a system that routes requests for "Llama" to a Modal endpoint, but routes requests for "Mistral" to a RunPod serverless endpoint. Write a FastAPI gateway (to run locally) that intercepts the user's request, checks the `model` parameter, and forwards the payload to the correct Serverless Provider's HTTP URL.

<details>
<summary>Hint</summary>
Use FastAPI and `httpx`. Create a route that takes a JSON body containing `model` and `prompt`. Use an `if/else` block to define the target URL based on the model name, forward the request using `httpx.post`, and return the response.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
# gateway.py
from fastapi import FastAPI, HTTPException
import httpx
from pydantic import BaseModel

app = FastAPI()

class InferenceRequest(BaseModel):
    model: str
    prompt: str

MODAL_LLAMA_URL = "https://your-workspace--serverless-llama-api.modal.run"
RUNPOD_MISTRAL_URL = "https://api.runpod.ai/v2/your-endpoint/runsync"

@app.post("/v1/completions")
async def route_inference(req: InferenceRequest):
    async with httpx.AsyncClient() as client:
        if "llama" in req.model.lower():
            # Route to Modal
            response = await client.post(
                MODAL_LLAMA_URL,
                json={"prompt": req.prompt},
                timeout=60.0
            )
            return response.json()

        elif "mistral" in req.model.lower():
            # Route to RunPod
            headers = {"Authorization": "Bearer YOUR_RUNPOD_KEY"}
            payload = {"input": {"prompt": req.prompt}}
            response = await client.post(
                RUNPOD_MISTRAL_URL,
                json=payload,
                headers=headers,
                timeout=60.0
            )
            return response.json()

        else:
            raise HTTPException(status_code=400, detail="Unsupported model")

# Run with: uvicorn gateway:app --reload
```

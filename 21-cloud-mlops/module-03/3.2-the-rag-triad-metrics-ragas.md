# 3.2 The RAG Triad Metrics: Context, Faithfulness, and Relevance (Ragas)

## Phase A: Problem-First Breakdown

### 1. Real-World Pain Point (The Why)
Your company built a Retrieval-Augmented Generation (RAG) system to answer questions based on internal HR documents. A user asks "What is the parental leave policy?" and the bot answers "We do not offer parental leave."
This is a catastrophic failure, but *where* did it fail?
- Did the vector database fail to find the HR document? (Retrieval failure)
- Did the LLM find the document, but ignore it and hallucinate? (Generation failure)
- Did the LLM answer a completely different question? (Relevance failure)
Writing custom LLM-as-a-judge prompts for all these nuanced failure modes is tedious and scientifically imprecise.

### 2. Plain English Metaphor (The What)
**Context Precision/Recall (Retrieval):** The librarian finding the right books. Did they find all the books you needed (Recall)? Did they avoid giving you junk books you didn't need (Precision)?
**Faithfulness (Hallucination):** The student writing an essay using *only* the books provided. If the student makes up a fact not found in the books, they fail Faithfulness.
**Answer Relevance (Usefulness):** The student answering the actual essay prompt. The essay might be factually true based on the books, but if it answers the wrong question, it fails Relevance.

### 3. Complete Runnable Code
Here is how you use the open-source `ragas` library to automatically calculate these Triad metrics without writing complex judge prompts yourself.

```python
import os
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import (
    context_precision,
    context_recall,
    faithfulness,
    answer_relevancy
)
from langchain_openai import ChatOpenAI, OpenAIEmbeddings

# 1. Define the RAG Trace Data
# To evaluate RAG, you MUST record what the retriever found AND what the LLM generated.
data_samples = {
    "question": ["What is the parental leave policy?"],
    "answer": ["Employees get 12 weeks of paid parental leave."],
    "contexts": [
        [
            "HR Policy v2: The company offers 12 weeks of fully paid parental leave for new parents.",
            "Lunch menu: Pizza on Fridays." # Note: We retrieved some junk context
        ]
    ],
    "ground_truth": ["12 weeks of paid leave."]
}

# 2. Convert to HuggingFace Dataset format (required by Ragas)
dataset = Dataset.from_dict(data_samples)

# 3. Configure the Judge LLM and Embeddings for Evaluation
# It is highly recommended to use strong models for evaluation
judge_llm = ChatOpenAI(model="gpt-4o")
judge_embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

if __name__ == "__main__":
    # Ensure OPENAI_API_KEY is set in environment
    print("Running Ragas Evaluation (This takes a few seconds...)")

    # 4. Run the Evaluation
    result = evaluate(
        dataset,
        metrics=[
            context_precision,
            context_recall,
            faithfulness,
            answer_relevancy
        ],
        llm=judge_llm,
        embeddings=judge_embeddings
    )

    # 5. Output the Automated Report
    print("\n--- RAG Triad Evaluation Report ---")
    df = result.to_pandas()
    for index, row in df.iterrows():
        print(f"Question: {row['question']}")
        print(f"Faithfulness (0-1): {row['faithfulness']:.2f} (Did it hallucinate?)")
        print(f"Answer Relevancy (0-1): {row['answer_relevancy']:.2f} (Did it answer the Q?)")
        print(f"Context Precision (0-1): {row['context_precision']:.2f} (Was retrieval clean?)")
        print(f"Context Recall (0-1): {row['context_recall']:.2f} (Did retrieval find everything?)")
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Four Pillars of RAG Data**
To use Ragas, you must track four strings for every test case: `question` (input), `answer` (what your RAG generated), `contexts` (what your vector DB retrieved), and `ground_truth` (what a human expert says the answer should be).

**Step 2: The Dataset Format**
Ragas utilizes HuggingFace `Dataset` objects because they handle batching and async processing efficiently, making it fast to evaluate thousands of rows.

**Step 3: Execution under the Hood**
When you call `evaluate()`, Ragas makes several concurrent calls to GPT-4o.
- To calculate *Faithfulness*, it asks GPT-4o to extract all claims from your `answer`, then checks if every single claim is supported by the `contexts`.
- To calculate *Answer Relevancy*, it uses the embeddings model to check the semantic distance between the `question` and the `answer`.

### 5. ASCII Data Flow
```text
[Dataset: Question, Contexts, Answer, Ground_Truth]
      |
      +-- 1. Faithfulness Check
      |      LLM Judge: "Is the Answer entirely supported by Contexts?" -> 1.0
      |
      +-- 2. Answer Relevancy Check
      |      LLM Judge: "Does the Answer directly address the Question?" -> 0.95
      |
      +-- 3. Context Recall Check
      |      LLM Judge: "Can the Ground_Truth be fully deduced from the Contexts?" -> 1.0
      |
      +-- 4. Context Precision Check
      |      LLM Judge: "Are the useful contexts ranked higher than the junk contexts?" -> 0.50
      v
[Final Evaluation DataFrame Output]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Obsessing over the final generated answer and ignoring the `contexts`. If your RAG is hallucinating correct answers without the context, it fails Faithfulness. It might be right today, but it will be confidently wrong tomorrow.
**Pro Tip:** If `context_recall` is low, your embeddings model or chunking strategy is bad (fix your Vector DB). If `faithfulness` is low, your generation prompt is bad (fix your LLM system prompt). Use these metrics to pinpoint exactly which part of the pipeline to fix.

import pandas as pd
import json
from datasets import Dataset

def load_csv_for_ragas(csv_path="production_logs.csv"):
    df = pd.read_csv(csv_path)

    ragas_dict = {
        "question": df["user_query"].tolist(),
        "answer": df["bot_reply"].tolist(),
        # Need to parse stringified JSON lists back into actual lists
        "contexts": [json.loads(doc) for doc in df["retrieved_docs"]],
        "ground_truth": df["human_label"].tolist()
    }

    return Dataset.from_dict(ragas_dict)

### Level 3: Boss Level
**Challenge:** You have built a CI/CD pipeline using Ragas. However, GPT-4o occasionally throws a `RateLimitError` or temporary network error during evaluation, causing your pipeline to randomly fail (flaky tests). Write a wrapper function around the `evaluate` call that implements an Exponential Backoff Retry mechanism using the `tenacity` library to make your pipeline bulletproof.

<details>
<summary>Hint</summary>
Install and import `tenacity`. Use the `@retry` decorator on a function that calls `evaluate`. Configure it to retry on any Exception, waiting 2 seconds, then 4, then 8, up to a max of 3 attempts.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type
from ragas import evaluate
import openai

# We specifically catch OpenAI API errors, but let data formatting errors crash normally
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=2, min=2, max=10),
    retry=retry_if_exception_type((openai.RateLimitError, openai.APIConnectionError))
)
def robust_evaluate(dataset, metrics, judge_llm, judge_embeddings):
    print("Attempting evaluation...")
    return evaluate(
        dataset,
        metrics=metrics,
        llm=judge_llm,
        embeddings=judge_embeddings
    )

# Usage in pipeline:
try:
    result = robust_evaluate(dataset, [faithfulness], judge_llm, judge_embeddings)
    print("Evaluation succeeded!")
except Exception as e:
    print(f"Evaluation completely failed after retries: {e}")
    exit(1)
```

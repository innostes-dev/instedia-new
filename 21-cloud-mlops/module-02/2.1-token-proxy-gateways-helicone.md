# 2.1 Token Proxy Gateways: Observability, Caching, and Caps

## Phase A: Problem-First Breakdown

### 1. Real-World Pain Point (The Why)
Your company builds an internal AI assistant using the OpenAI API. It gets popular. Suddenly, your monthly OpenAI bill spikes to $5,000. You log into the OpenAI dashboard to investigate, but all you see is a bar chart showing "Total Tokens Used."
- Which department is spending the most?
- Is one specific user looping an expensive script?
- Are users asking the exact same questions repeatedly, causing you to pay for identical completions?
You have zero visibility, zero caching, and zero control over per-user spending.

### 2. Plain English Metaphor (The What)
**Direct API Usage:** Giving every employee an unlimited company credit card with no receipts. You just get one massive bill at the end of the month.
**Proxy Gateway (Helicone/Portkey):** A strict finance department approval desk. Every employee must hand their request to the desk. The desk checks their budget, logs the request in a ledger, checks if the answer is already in the filing cabinet (cache), and *then* uses the company card to get the answer.

### 3. Complete Runnable Code
Here is how you integrate Helicone, a popular LLM Proxy Gateway, into a standard Python OpenAI call to instantly gain observability and caching.

```python
import os
from openai import OpenAI

# 1. Standard OpenAI initialization, but we point the Base URL to Helicone
# and pass the Helicone API key in the headers.
client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url="https://oai.hconeai.com/v1",
    default_headers={
        "Helicone-Auth": f"Bearer {os.environ.get('HELICONE_API_KEY')}",
        "Helicone-Cache-Enabled": "true",       # Enable Caching
        "Helicone-Property-Department": "HR",   # Custom Tagging
        "Helicone-User-Id": "user_12345"        # User Tracking
    }
)

def ask_assistant(prompt: str):
    print(f"Sending request for user_12345: '{prompt}'")

    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}]
    )

    return response.choices[0].message.content

if __name__ == "__main__":
    # Ensure keys are set: export OPENAI_API_KEY="..." export HELICONE_API_KEY="..."

    # Request 1: Hits OpenAI, costs money, takes ~1-2 seconds
    print("--- Request 1 ---")
    print(ask_assistant("What is the capital of France?"))

    # Request 2: Exactly the same prompt.
    # Helicone intercepts it, returns the cached answer instantly. Cost: $0.
    print("\n--- Request 2 (Should be cached) ---")
    print(ask_assistant("What is the capital of France?"))
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: Reroute the Traffic**
Instead of sending the request directly to `api.openai.com`, we change the `base_url` to `oai.hconeai.com`. The OpenAI Python SDK is completely unaware; it just formats the HTTP request and sends it to the proxy.

**Step 2: Add Proxy Authentication**
We must pass `Helicone-Auth` in the headers. This tells Helicone which account to log the metrics to. Helicone then unwraps the request, reads your actual `OPENAI_API_KEY`, and forwards it to OpenAI on your behalf.

**Step 3: Inject Meta-Data (The Magic)**
By adding headers like `Helicone-User-Id` and `Helicone-Property-Department`, we attach metadata to the request. When you log into the Helicone dashboard, you can now group costs by user or department, instantly solving the "who spent $5,000?" mystery.

### 5. ASCII Data Flow
```text
[User Application]
      | (1) POST /v1/chat/completions (Headers: User=123, Cache=True)
      v
===================================================================
| HELICONE PROXY                                                  |
| (2) Read Headers. Is User 123 over budget? No.                  |
| (3) Check Cache: Has anyone asked "Capital of France"?          |
|      -> YES: Return cached answer (Latency 50ms, Cost $0)       |
|      -> NO: Forward to OpenAI (Latency 1s, Cost $0.01)          |
| (4) Log tokens used, latency, and cost to User 123's ledger     |
===================================================================
      | (If Cache Miss)
      v
[OpenAI API]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Building your own caching layer using Redis and hashing the prompt string. This breaks easily (what if the temperature changes? what about semantic similarity?). It also doesn't provide cost dashboards.
**Pro Tip:** Use an off-the-shelf proxy like Helicone, Portkey, or LiteLLM. They handle edge cases (like streaming caches), provide beautiful UIs, and often include fallback routing (if OpenAI is down, route to Anthropic).

### Level 2: Real-World
**Challenge:** Hardcoding custom headers in the global client means *every* request gets the same User ID and Session ID. This doesn't work for a web server handling multiple users. Refactor the code to use the standard OpenAI client, but pass the Helicone headers dynamically *per-request* within a FastAPI route.

<details>
<summary>Hint</summary>
The `.create()` method for chat completions accepts an `extra_headers` parameter. Remove the headers from the global `OpenAI()` instantiation and move them there.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
from fastapi import FastAPI
from pydantic import BaseModel
from openai import OpenAI
import os

app = FastAPI()

# Global client, NO user-specific headers here
client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url="https://oai.hconeai.com/v1",
)

class ChatRequest(BaseModel):
    user_id: str
    prompt: str

@app.post("/chat")
async def chat(req: ChatRequest):
    # Pass headers per-request
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": req.prompt}],
        extra_headers={
            "Helicone-Auth": f"Bearer {os.environ.get('HELICONE_API_KEY')}",
            "Helicone-User-Id": req.user_id,
            "Helicone-Cache-Enabled": "true"
        }
    )
    return {"reply": response.choices[0].message.content}
```
</details>

### Level 3: Boss Level
**Challenge:** Implement a custom Rate Limiter middleware in Python. Before sending the request to the LLM Proxy, check a local dictionary to see if the user has exceeded 5 requests in the last minute. If so, return a 429 Too Many Requests error. (While Helicone has this built-in, building it locally teaches you how API Gateways work under the hood).

<details>
<summary>Hint</summary>
Create a dictionary `user_requests = {}` storing lists of timestamps. In the route, append `time.time()`, filter out timestamps older than 60 seconds, and check if the length is > 5.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
import time
from fastapi import FastAPI, HTTPException

app = FastAPI()
user_requests = {} # Store {user_id: [timestamp1, timestamp2, ...]}

def check_rate_limit(user_id: str):
    current_time = time.time()

    # Initialize if new user
    if user_id not in user_requests:
        user_requests[user_id] = []

    # Filter timestamps to only keep those within the last 60 seconds
    user_requests[user_id] = [ts for ts in user_requests[user_id] if current_time - ts < 60]

    # Check limit (5 requests per minute)
    if len(user_requests[user_id]) >= 5:
        raise HTTPException(status_code=429, detail="Rate limit exceeded. Try again later.")

    # Record this request
    user_requests[user_id].append(current_time)

@app.post("/chat")
async def chat(req: ChatRequest):
    # 1. Enforce local rate limit
    check_rate_limit(req.user_id)

    # 2. Proceed to LLM Proxy
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": req.prompt}],
        extra_headers={"Helicone-User-Id": req.user_id}
    )
    return {"reply": response.choices[0].message.content}
```
</details>

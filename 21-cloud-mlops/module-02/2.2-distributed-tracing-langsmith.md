# 2.2 Distributed Tracing: Spans, Latency, and LangSmith

## Phase A: Problem-First Breakdown

### 1. Real-World Pain Point (The Why)
You built an advanced RAG (Retrieval-Augmented Generation) application or a multi-agent system. A user asks a question, and it takes 15 seconds to reply. The user is frustrated. Where is the bottleneck?
- Did the vector database take 4 seconds to search?
- Did the web-search tool take 6 seconds?
- Did the LLM take 5 seconds to generate the answer?
Without tracing, your application is a black box. You only know the total time, making it impossible to optimize performance or debug hallucinations (e.g., seeing exactly *what* context the vector DB returned to the LLM).

### 2. Plain English Metaphor (The What)
**No Tracing:** Ordering a package and only knowing when you clicked "Buy" and when it arrived at your door 5 days later. If it's late, you have no idea who to blame.
**Distributed Tracing:** A detailed FedEx tracking number. You see exactly when it left the warehouse (Vector Search), when it arrived at the local facility (Tool Execution), and when it went out for delivery (LLM Generation). Every step is a "Span," and the whole journey is a "Trace."

### 3. Complete Runnable Code
Here is how you use LangSmith to trace a multi-step LangChain workflow. It automatically records the inputs, outputs, and latency of every tool, retrieval, and LLM call.

```python
import os
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# 1. Enable LangSmith Tracing via Environment Variables
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_ENDPOINT"] = "https://api.smith.langchain.com"
os.environ["LANGCHAIN_API_KEY"] = "ls_..." # Your LangSmith Key
os.environ["LANGCHAIN_PROJECT"] = "MLOps-Tracing-Demo"

# 2. Mock a Vector Store Retrieval (A "Span" in the trace)
def mock_retriever(query: str) -> str:
    import time
    time.sleep(1.5) # Simulate latency
    return "LangSmith is a platform for LLM observability and tracing."

# 3. Build the Chain
prompt = ChatPromptTemplate.from_template(
    "Answer the question based ONLY on the context: {context}\n\nQuestion: {question}"
)
llm = ChatOpenAI(model="gpt-4o-mini")
output_parser = StrOutputParser()

# The Chain: Retrieve -> Format Prompt -> LLM -> Parse Output
chain = (
    {"context": mock_retriever, "question": RunnablePassthrough()}
    | prompt
    | llm
    | output_parser
)

if __name__ == "__main__":
    # Ensure OPENAI_API_KEY and LANGCHAIN_API_KEY are set

    print("Executing chain... (Check LangSmith UI for the trace!)")

    # 4. Invoke the chain. This automatically generates a distributed trace.
    result = chain.invoke("What is LangSmith?")
    print(f"\nFinal Answer: {result}")
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: Environment Variables**
LangSmith (and most tracing tools like Arize Phoenix or DataDog) relies heavily on environment variables. By setting `LANGCHAIN_TRACING_V2="true"`, you activate a background thread that listens to LangChain events and batches them to the LangSmith API.

**Step 2: The Chain Execution**
When `chain.invoke()` runs, LangChain creates a "Root Run" (The Trace). It starts a timer.

**Step 3: Child Spans**
As the execution flows, it creates "Child Spans".
- Span 1: `mock_retriever` (Records input query, output context, and 1.5s latency).
- Span 2: `prompt` formatting (Records template filling, ~0.01s latency).
- Span 3: `llm` (Records the exact payload sent to OpenAI, token counts, and network latency).

**Step 4: The UI Visualization**
When you log into LangSmith, you see a waterfall diagram. If the whole process took 3 seconds, the UI clearly visually indicates that 1.5s (50%) of the time was spent in retrieval.

### 5. ASCII Data Flow
```text
Trace: "What is LangSmith?" [Total: 3.2s]
|
+-- Span 1: RunnableParallel <context, question> [1.5s]
|     |
|     +-- Span 1.1: mock_retriever [1.5s]
|           Input: "What is LangSmith?"
|           Output: "LangSmith is a platform..."
|
+-- Span 2: ChatPromptTemplate [0.01s]
|     Input: {context: "...", question: "..."}
|
+-- Span 3: ChatOpenAI (LLM Call) [1.6s]
|     Tokens: 45 prompt, 20 completion
|
+-- Span 4: StrOutputParser [0.01s]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `print()` statements to log inputs and outputs at every step of a complex agent. It clutters the console, gets lost in server logs, and provides zero visual latency tracking.
**Pro Tip:** Use the `@traceable` decorator in LangSmith (or OpenTelemetry standards) to instrument custom Python functions that are outside of the LangChain ecosystem. Tracing is about the *whole* system, not just the LLM.

## Phase B: Real-World Challenges

### Level 1: Warm-Up
**Challenge:** The `mock_retriever` in the example is a standard Python function, but because it's wrapped in a LangChain `Runnable`, it gets traced automatically. What if you have an external API call function that is *not* part of a LangChain chain, but you still want it to appear as a Span in your LangSmith trace?

<details>
<summary>Hint</summary>
LangSmith provides a Python decorator that you can wrap around any arbitrary Python function to force it to generate a trace/span.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
from langsmith import traceable

@traceable(name="External_Weather_API")
def fetch_weather(city: str):
    import time
    time.sleep(2) # Simulate API call
    return f"The weather in {city} is sunny."

# Calling this directly will now generate a trace in LangSmith!
fetch_weather("San Francisco")
```
</details>

### Level 2: Real-World
**Challenge:** You want to group traces together. For example, your application has a "Customer Support Bot" and an "Internal Research Bot." You want to tag traces so you can filter them in the UI. Modify the chain invocation to include a specific tag (e.g., "customer_support_v2").

<details>
<summary>Hint</summary>
The `.invoke()` method takes an optional `config` dictionary where you can pass metadata and tags.
</details>

<details>

```python
# Pass a config dictionary to invoke
result = chain.invoke(
    "What is LangSmith?",
    config={
        "tags": ["customer_support_v2", "production"],
        "metadata": {"user_tier": "premium"}
    }
)
```

### Level 3: Boss Level
**Challenge:** You are moving away from vendor lock-in (LangSmith) and want to implement an open-source standard: OpenTelemetry (OTel). Write a basic Python script using the `opentelemetry` SDK that manually creates a Tracer, starts a Span named "Vector_Search", simulates a 1-second delay, and adds a custom attribute `db.results_count = 5` to the span. (Note: You don't need to export it anywhere, just print to console).

<details>
<summary>Hint</summary>
You'll need `opentelemetry-api` and `opentelemetry-sdk`. Set up a `TracerProvider`, get a tracer, and use the `with tracer.start_as_current_span(...)` context manager.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import SimpleSpanProcessor, ConsoleSpanExporter
import time

# 1. Setup the Tracer Provider (The engine)
provider = TracerProvider()
# Export traces to the console for debugging
processor = SimpleSpanProcessor(ConsoleSpanExporter())
provider.add_span_processor(processor)
trace.set_tracer_provider(provider)

# 2. Get a Tracer instance
tracer = trace.get_tracer(__name__)

def perform_vector_search():
    # 3. Create a Span using a context manager
    with tracer.start_as_current_span("Vector_Search") as span:
        print("Searching database...")
        time.sleep(1) # Simulate work

        # 4. Add custom metadata to the span
        span.set_attribute("db.results_count", 5)
        span.set_attribute("db.collection", "knowledge_base")
        print("Search complete.")

perform_vector_search()
# Output will include standard OTel JSON representing the span, duration, and attributes!
```
</details>

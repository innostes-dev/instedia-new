# 4.3 Server-Sent Events Token Streaming

## Phase A: The Core Concept

### 🚨 Real-World Pain Point (The Why)
A user asks your AI Assistant: "Summarize our Q3 earnings report." The LLM takes 25 seconds to generate the 800-word response. If you use standard HTTP REST, the user stares at a blank screen and a spinning loader for 25 seconds. They assume the app is broken and refresh the page, duplicating the expensive API call.

### 💡 Plain English Metaphor (The What)
Standard REST API is like **buying a book**. You wait at the store while they print the entire 500-page book in the back room, bind it, and hand it to you all at once.
Server-Sent Events (SSE) token streaming is like having an author **dictate the book to you over the phone**. As soon as they think of the first word, they say it. You write it down immediately. The response feels instantaneous, even if it takes 25 seconds to finish the whole story.

### 💻 Complete Runnable Architecture/Code Example (Python/FastAPI Backend & React Frontend)

**Backend: Python (FastAPI & LangChain)**
```python
import os
import asyncio
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
from langchain.callbacks import AsyncIteratorCallbackHandler

app = FastAPI()

# Required: OPENAI_API_KEY
llm = ChatOpenAI(
    model="gpt-4",
    streaming=True, # Critical: Tell the model to stream
)

@app.post("/api/chat/stream")
async def chat_stream(request: Request):
    data = await request.json()
    user_query = data.get("query")

    # The CallbackHandler acts as a pipe. The LLM pours words in, and our generator yields them out.
    callback_handler = AsyncIteratorCallbackHandler()

    # We must attach the callback to the LLM for THIS specific request
    chat = ChatOpenAI(model="gpt-4", streaming=True, callbacks=[callback_handler])

    # Start the LLM generation in a background task so it doesn't block our streaming loop
    async def generate_response():
        try:
            await chat.agenerate([[HumanMessage(content=user_query)]])
        finally:
            # Signal that generation is done
            callback_handler.done.set()

    # Fire and forget the background task
    asyncio.create_task(generate_response())

    # This is the Generator function that yields SSE formatted text
    async def event_generator():
        # Read from the callback handler's queue as tokens arrive
        async for token in callback_handler.aiter():
            # SSE Format requires: "data: <content>\n\n"
            # We replace newlines in the token to prevent breaking the SSE protocol
            safe_token = token.replace("\n", "\\n")
            yield f"data: {safe_token}\n\n"

        # Send a final event to tell the frontend we are done
        yield "data: [DONE]\n\n"

    # Return a StreamingResponse with the correct MIME type
    return StreamingResponse(event_generator(), media_type="text/event-stream")

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

**Frontend: React (TypeScript)**
```tsx
import React, { useState } from 'react';
import ReactMarkdown from 'react-markdown';

export default function AIChat() {
  const [query, setQuery] = useState('');
  const [response, setResponse] = useState('');
  const [isStreaming, setIsStreaming] = useState(false);

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setResponse('');
    setIsStreaming(true);

    try {
      // 1. Fetch using standard POST, but we don't await the FULL JSON response.
      const res = await fetch('http://localhost:8000/api/chat/stream', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ query })
      });

      if (!res.body) throw new Error("ReadableStream not supported in this browser.");

      // 2. Get a reader to process the stream byte-by-byte
      const reader = res.body.getReader();
      const decoder = new TextDecoder('utf-8');

      while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        // 3. Decode the byte array into a string
        const chunk = decoder.decode(value, { stream: true });

        // SSE chunks look like: "data: hello\n\ndata:  world\n\n"
        // We split by \n\n to get individual events
        const events = chunk.split('\n\n');

        for (const event of events) {
          if (event.startsWith('data: ')) {
            const dataStr = event.slice(6); // Remove "data: " prefix

            if (dataStr === '[DONE]') {
              setIsStreaming(false);
              return;
            }

            // Un-escape newlines (we escaped them on the backend!)
            const token = dataStr.replace(/\\n/g, '\n');

            // 4. Append to React state (Triggers re-render with ReactMarkdown)
            setResponse(prev => prev + token);
          }
        }
      }
    } catch (error) {
      console.error("Stream failed", error);
      setIsStreaming(false);
    }
  };

  return (
    <div className="p-4 max-w-2xl mx-auto">
      <form onSubmit={handleSubmit} className="mb-4 flex gap-2">
        <input
          value={query}
          onChange={e => setQuery(e.target.value)}
          className="border p-2 flex-1"
          placeholder="Ask a question..."
        />
        <button type="submit" disabled={isStreaming} className="bg-blue-600 text-white p-2">
          {isStreaming ? 'Thinking...' : 'Send'}
        </button>
      </form>

      <div className="border p-4 bg-gray-50 min-h-[200px] prose prose-blue">
        {/* react-markdown beautifully renders bold, code blocks, and lists AS they stream in! */}
        <ReactMarkdown>{response}</ReactMarkdown>
      </div>
    </div>
  );
}
```

### 🪜 Progressive Step-by-Step Breakdown

#### Step 1: The Backend Generator
FastAPI's `StreamingResponse` expects a generator. We use LangChain's `AsyncIteratorCallbackHandler` to capture the LLM's output token by token. As the LLM yields a word (e.g., "The"), we immediately `yield` it out of our FastAPI route over the open TCP connection.

#### Step 2: The SSE Protocol formatting
If we just blast raw text over the pipe, the browser gets confused. We use the Server-Sent Events (SSE) standard format: `data: <content>\n\n`. We must be careful because if the LLM generates a newline character (`\n`), it will accidentally break the SSE format. We escape it as `\\n` on the server and un-escape it on the client.

#### Step 3: Frontend Byte Stream Parsing
On the frontend, we don't use `await res.json()`. That would wait for the connection to close. Instead, we grab `res.body.getReader()`. This gives us raw bytes as they arrive over the network. We decode them into strings, parse the `data: ` prefix, and append them to React state.

#### Step 4: Markdown Rendering
Because LLMs return markdown (e.g., `**Bold**` or \`\`\`code\`\`\`), we use `<ReactMarkdown>`. The beauty of this library is that it handles malformed/incomplete markdown gracefully. If the stream pauses at `**Bol`, it might look weird for a split second, but as soon as the `d**` arrives, it snaps into bold text instantly.

### 🔀 ASCII / Architecture Flow

```text
[ Client (React) ]                      [ Server (FastAPI) ]                       [ OpenAI API ]
        |                                         |                                       |
        |--- (POST /stream) --------------------->|                                       |
        |                                         |-- (POST /chat/completions) ---------->|
        |                                         |                                       |
        |<-- (HTTP 200 chunked headers) ----------|                                       |
        |                                         |<-- (Token: "The") --------------------|
        |<-- (SSE: "data: The\n\n") --------------|                                       |
  (UI: "The")                                     |                                       |
        |                                         |<-- (Token: " capital") ---------------|
        |<-- (SSE: "data:  capital\n\n") ---------|                                       |
  (UI: "The capital")                             |                                       |
```

### ⚠️ Noob Trap vs 👑 Pro Tip
* **Noob Trap**: Using WebSockets for simple LLM text generation. WebSockets are bi-directional and require complex state management, heartbeats, and room logic. Text generation is strictly uni-directional (Server -> Client). SSE is built specifically for this, runs over standard HTTP, and is much easier to scale.
* **Pro Tip**: Use Vercel's `ai` SDK (`@ai-sdk/react`). Writing the raw stream reader (`getReader()`, `TextDecoder`) is prone to bugs, especially when network packets split a token exactly in half! The `ai` SDK provides a simple `useChat()` hook that abstracts all the stream parsing, error handling, and message history state management for you.

### 🔴 Level 3: Boss Level
**Task:** Refactor the frontend React code to completely remove the manual `fetch` and `TextDecoder` logic, and replace it with the `@ai-sdk/react` library's `useChat` hook, ensuring it remains compatible with the FastAPI backend.
<details>
<summary>💡 Hint & Solution</summary>
The Vercel AI SDK expects a very specific format: plain text stream or its own data stream protocol.

**Solution Approach:**
1. `npm install @ai-sdk/react`
2. Frontend:
```tsx
import { useChat } from '@ai-sdk/react';

export default function Chat() {
  // useChat automatically handles the POST request, stream parsing, and state!
  const { messages, input, handleInputChange, handleSubmit, isLoading, stop } = useChat({
    api: 'http://localhost:8000/api/chat/stream' // Point to your backend
  });

  return (
    <form onSubmit={handleSubmit}>
      {messages.map(m => <div key={m.id}>{m.role}: {m.content}</div>)}
      <input value={input} onChange={handleInputChange} />
    </form>
  );
}
```
3. Backend (FastAPI): The `ai` SDK by default just expects raw tokens, not necessarily `data: ` prefixed SSE (unless you use the data protocol). You can simplify the backend generator to just `yield token` and return a standard `StreamingResponse` without the `text/event-stream` media type if using the simplest `useChat` configuration.
</details>

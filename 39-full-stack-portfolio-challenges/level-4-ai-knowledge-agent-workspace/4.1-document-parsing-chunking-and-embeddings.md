# 4.1 Document Parsing, Chunking, and Embeddings

## Phase A: The Core Concept

### 🚨 Real-World Pain Point (The Why)
You want an AI to answer questions based on a 500-page employee handbook PDF. You can't just pass the whole PDF to the LLM; it exceeds the context window (token limit) and costs $5 per query. If you just split the text randomly every 1,000 characters, a chunk might start with "However, this rule does not apply to..." leaving the AI completely context-blind about what "this rule" is.

### 💡 Plain English Metaphor (The What)
Document Parsing is like **turning a printed book into raw text**.
Chunking is like **cutting the book into index cards**. You don't cut in the middle of a sentence (Random split); you cut at the end of paragraphs or sections (Semantic split) so each card makes sense on its own.
Embeddings are like **assigning GPS coordinates** to each index card based on its meaning. Cards about "Vacation Days" get coordinates clustered in one area, while cards about "IT Security" get coordinates in another. When a user asks about "Time Off," you just look at the GPS coordinates near "Time Off" and pull those specific cards.

### 💻 Complete Runnable Architecture/Code Example (Python & LangChain/pgvector)

**Python (FastAPI, LangChain, OpenAI, PostgreSQL pgvector)**
```python
# pip install fastapi langchain-openai langchain-community psycopg2-binary pgvector pypdf tiktoken
import os
from fastapi import FastAPI, UploadFile, File
from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import PGVector
import tempfile

app = FastAPI()

# Required Environment Variables: OPENAI_API_KEY, DATABASE_URL
# Example DB URL: postgresql+psycopg2://user:pass@localhost:5432/mydb

embeddings_model = OpenAIEmbeddings(model="text-embedding-3-small")
CONNECTION_STRING = os.environ.get("DATABASE_URL")
COLLECTION_NAME = "enterprise_knowledge"

@app.post("/api/ingest")
async def ingest_document(file: UploadFile = File(...)):
    # 1. Parsing: Handle arbitrary file format chaos (PDF)
    # Save uploaded file to temporary disk space
    with tempfile.NamedTemporaryFile(delete=False, suffix=".pdf") as tmp:
        tmp.write(await file.read())
        tmp_path = tmp.name

    try:
        # Extract raw text from PDF
        loader = PyPDFLoader(tmp_path)
        raw_documents = loader.load()

        # 2. Semantic Chunking Boundaries
        # Recursive splitter tries to split by paragraphs (\n\n) first, then sentences (\n), then words.
        # This keeps semantic concepts together.
        text_splitter = RecursiveCharacterTextSplitter(
            chunk_size=1000, # Aim for ~1000 characters per chunk
            chunk_overlap=200, # 20% overlap ensures context isn't lost at the boundaries
            length_function=len
        )

        chunked_documents = text_splitter.split_documents(raw_documents)

        # 3. Generating Embeddings & Storing in Vector DB (pgvector)
        # This API call sends text to OpenAI, receives float arrays (e.g. [0.01, -0.05...]),
        # and saves them into the PostgreSQL pgvector extension table.
        PGVector.from_documents(
            embedding=embeddings_model,
            documents=chunked_documents,
            collection_name=COLLECTION_NAME,
            connection_string=CONNECTION_STRING
        )

        return {
            "status": "success",
            "message": f"Ingested {len(chunked_documents)} chunks from {file.filename}."
        }

    finally:
        # Cleanup temporary file
        os.unlink(tmp_path)
```

### 🪜 Progressive Step-by-Step Breakdown

#### Step 1: Parsing the File
Enterprise data comes in PDFs, DOCX, CSVs, and HTML. You must normalize this into raw strings. The `PyPDFLoader` handles the heavy lifting of extracting text from PDF binaries.

#### Step 2: Semantic Chunking (Recursive Splitter)
The `RecursiveCharacterTextSplitter` is the industry standard. It doesn't just slice a string at index 1000. It looks for the nearest natural break (like a double newline `\n\n`) *before* the 1000 limit.
The **Overlap (200 chars)** is critical. If Chunk 1 ends with "John went to the bank." and Chunk 2 starts with "He withdrew money.", the pronoun "He" loses context. Overlap ensures Chunk 2 actually starts with the last sentence of Chunk 1: "John went to the bank. He withdrew money."

#### Step 3: Embeddings and pgvector Storage
We convert the text into dense mathematical vectors (arrays of 1536 floating-point numbers for OpenAI). We use `PGVector` (which requires PostgreSQL with the `pgvector` extension enabled) to store both the original text and its vector. This allows the database to do nearest-neighbor math (Cosine Similarity) later.

### 🔀 ASCII / Architecture Flow

```text
[ HR_Handbook.pdf ]
        |
        v
[ PyPDFLoader ] ---> Raw String: "Welcome to Acme Corp... Vacation policy is..."
        |
        v
[ Recursive Text Splitter ]
        |---> Chunk 1: "Welcome to Acme Corp..."
        |---> Chunk 2: (overlap) "Vacation policy is..."
        v
[ OpenAI Embeddings API ]
        |---> Vector 1: [0.001, -0.042, 0.991, ...]
        |---> Vector 2: [0.124,  0.033, 0.000, ...]
        v
[ PostgreSQL (pgvector) ]
  Table: embeddings
  | id | text_chunk          | embedding (vector) | metadata          |
  |----|---------------------|--------------------|-------------------|
  | 1  | "Welcome..."        | [0.001...]         | {file: "HR.pdf"}  |
```

### ⚠️ Noob Trap vs 👑 Pro Tip
* **Noob Trap**: Using a massive `chunk_size` (e.g., 4000 tokens) because "the LLM can handle it." Large chunks dilute the vector embedding. A chunk about IT, HR, and Finance combined gets an "average" vector coordinate, making it impossible to find via search.
* **Pro Tip**: Inject **Metadata** into your chunks before embedding! Add `{"title": "HR Handbook", "chapter": "Vacation"}` to the document metadata. Later, when searching, you can do a fast SQL `WHERE metadata->>'chapter' = 'Vacation'` *before* doing the expensive vector math (this is called Pre-filtering).

**Task:** Implement a background worker for ingestion. Parsing a 100-page PDF and calling OpenAI 500 times takes 2 minutes. The HTTP request will time out. Refactor the architecture so the FastAPI route saves the file, returns a `jobId` immediately, and a Celery or Redis RQ worker does the chunking and embedding asynchronously.

Use `rq` (Redis Queue) in Python.

**Solution Approach:**
1. Setup Redis and RQ.
2. In FastAPI:
```python
from redis import Redis
from rq import Queue
q = Queue(connection=Redis())

@app.post("/api/ingest")
async def ingest(file: UploadFile, background_tasks: BackgroundTasks):
    filepath = save_to_disk(file)
    job = q.enqueue(process_document_worker, filepath)
    return {"job_id": job.id}
```
3. The `process_document_worker` function contains the LangChain loading, chunking, and embedding logic from Phase A.

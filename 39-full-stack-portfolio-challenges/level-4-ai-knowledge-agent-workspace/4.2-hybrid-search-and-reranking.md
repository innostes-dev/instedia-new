# 4.2 Hybrid Search and Reranking

## Phase A: The Core Concept

### 🚨 Real-World Pain Point (The Why)
A user searches an enterprise knowledge base for "TS-4992 Error Code".
If you use **Pure Vector (Semantic) Search**, the embedding model looks for the *meaning* of the phrase. It might return documents about "Server Failures" or "Error Handling," completely missing the exact document containing the literal string "TS-4992".
If you use **Pure Keyword (BM25) Search**, and a user searches "How do I ask for time off?", it fails because the document uses the words "Requesting PTO" instead of "time off".

### 💡 Plain English Metaphor (The What)
Hybrid Search is like having **Two Librarians**.
Librarian 1 (Keyword/BM25) has a photographic memory for exact words. They find every book containing "TS-4992".
Librarian 2 (Vector/Semantic) understands concepts. They know "time off" means "PTO".
You ask both librarians to bring you their top 10 books. You put them in a pile of 20 books.
Reranking is like asking a **Senior Master Librarian (Cross-Encoder)** to look at that pile of 20 books, read the actual question, and painstakingly sort them from most relevant (Rank 1) to least relevant (Rank 20) before handing the top 5 to you.

### 💻 Complete Runnable Architecture/Code Example (Python)

**Python (LangChain, pgvector, BM25, Cohere Rerank)**
```python
import os
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import PGVector
from langchain_community.retrievers import BM25Retriever
from langchain.retrievers import EnsembleRetriever
from langchain_cohere import CohereRerank
from langchain.retrievers.contextual_compression import ContextualCompressionRetriever
from langchain_core.documents import Document

# 1. Setup Keyword Search (BM25)
# In production, BM25 would be backed by Elasticsearch or Postgres Full Text Search.
# For demonstration, we use an in-memory BM25 over our documents.
def setup_hybrid_retriever(documents: list[Document], pg_connection_string: str):

    # Librarian 1: Keyword Search (BM25)
    keyword_retriever = BM25Retriever.from_documents(documents)
    keyword_retriever.k = 10 # Get top 10 matches

    # Librarian 2: Semantic/Vector Search (pgvector)
    embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
    vector_store = PGVector(
        connection_string=pg_connection_string,
        embedding_function=embeddings,
        collection_name="enterprise_knowledge"
    )
    vector_retriever = vector_store.as_retriever(search_kwargs={"k": 10})

    # 2. Combine them (Ensemble/Hybrid Search)
    # Weights: 50% keyword, 50% semantic
    hybrid_retriever = EnsembleRetriever(
        retrievers=[keyword_retriever, vector_retriever],
        weights=[0.5, 0.5]
    )

    # 3. Setup Reranking (The Senior Librarian)
    # We use Cohere's dedicated Rerank API (requires COHERE_API_KEY)
    compressor = CohereRerank(
        cohere_api_key=os.environ["COHERE_API_KEY"],
        top_n=5 # Final output will be the absolute best 5 documents
    )

    # Wrap the hybrid retriever with the reranker
    advanced_retriever = ContextualCompressionRetriever(
        base_compressor=compressor,
        base_retriever=hybrid_retriever
    )

    return advanced_retriever

# Usage
async def search_knowledge_base(query: str, retriever):
    # This single call executes Keyword + Vector, merges them, and Reranks them!
    final_docs = retriever.invoke(query)

    return [doc.page_content for doc in final_docs]
```

### 🪜 Progressive Step-by-Step Breakdown

#### Step 1: Keyword Retrieval (BM25)
BM25 (Best Matching 25) is the algorithm behind Elasticsearch. It looks for exact word matches but penalizes words that appear too often everywhere (like "the" or "and"). It is unbeatable for acronyms, IDs, and specific nouns.

#### Step 2: Semantic Retrieval (pgvector) & Ensembling
We perform the standard cosine similarity search in our Vector DB. The `EnsembleRetriever` runs both searches in parallel. If Keyword returns Docs [A, B, C] and Vector returns [C, D, E], the Ensemble merges them into a unique set [A, B, C, D, E] and calculates a combined score using a mathematical formula (Reciprocal Rank Fusion - RRF).

#### Step 3: Cross-Encoder Reranking
Standard embeddings (Bi-encoders) are fast but slightly dumb—they compress whole paragraphs into a single coordinate. A Reranker (Cross-encoder) is a heavier ML model. It takes the user's Query and Document A, feeds them *together* into a transformer, and outputs a highly accurate relevance score. We only run this on the Top 20 results because running it on a million documents would take hours.

### 🔀 ASCII / Architecture Flow

```text
User Query: "TS-4992 Error Fix"
       |
       |--------------------------------------|
       v                                      v
[ Keyword Search (BM25) ]           [ Vector Search (pgvector) ]
  (Finds exact "TS-4992")             (Finds "Error Fix" concepts)
       |                                      |
       |--- Top 10 Docs                       |--- Top 10 Docs
       v                                      v
    [ Ensemble Retriever (Reciprocal Rank Fusion) ]
       |
       | (Combined pool of ~20 unique documents)
       v
    [ Cohere Rerank API (Cross-Encoder) ]
       | (Scores Query against each Doc deeply)
       | (Discards the bottom 15)
       v
  [ Final Top 5 Highest Quality Docs ] ---> Sent to LLM for Answer Generation
```

### ⚠️ Noob Trap vs 👑 Pro Tip
* **Noob Trap**: Using purely in-memory `BM25Retriever` (like in the basic demo above) for a production app with 1,000,000 chunks. Your server will run out of RAM instantly.
* **Pro Tip**: Use a database that supports **Native Hybrid Search**. PostgreSQL can do this! You can use `pgvector` for the semantic search, and Postgres' built-in `tsvector` (Full Text Search) for the keyword search, merging them in a single SQL query using CTEs (Common Table Expressions) and RRF logic.

### 🔴 Level 3: Boss Level
**Task:** Write the Raw PostgreSQL SQL query that performs a true Native Hybrid Search without LangChain. It must execute a `ts_rank_cd` full-text search AND a pgvector `<=>` cosine distance search, then combine them using Reciprocal Rank Fusion (RRF) entirely within the database.
<details>
<summary>💡 Hint & Solution</summary>
You need Common Table Expressions (WITH clauses).

**Solution Approach (SQL):**
```sql
WITH semantic_search AS (
    SELECT id, text_chunk,
           RANK() OVER (ORDER BY embedding <=> '[0.1, ...]'::vector) AS rank
    FROM embeddings
    ORDER BY embedding <=> '[0.1, ...]'::vector
    LIMIT 20
),
keyword_search AS (
    SELECT id, text_chunk,
           RANK() OVER (ORDER BY ts_rank_cd(to_tsvector('english', text_chunk), plainto_tsquery('english', 'TS-4992')) DESC) AS rank
    FROM embeddings
    WHERE to_tsvector('english', text_chunk) @@ plainto_tsquery('english', 'TS-4992')
    LIMIT 20
)
-- Reciprocal Rank Fusion (RRF)
SELECT
    COALESCE(s.id, k.id) as id,
    COALESCE(s.text_chunk, k.text_chunk) as text_chunk,
    -- RRF formula: 1 / (60 + rank). The 60 is a smoothing constant.
    COALESCE(1.0 / (60 + s.rank), 0.0) + COALESCE(1.0 / (60 + k.rank), 0.0) AS rrf_score
FROM semantic_search s
FULL OUTER JOIN keyword_search k ON s.id = k.id
ORDER BY rrf_score DESC
LIMIT 5;
```
</details>

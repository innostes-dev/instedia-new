# 2.1 WebSocket Handshake and Room Architecture

## Phase A: The Core Concept

### 🚨 Real-World Pain Point (The Why)
Imagine a team using a Kanban board. To see updates from other team members, the frontend code executes `setInterval(() => fetch('/api/board'), 2000)`. With 50 users on the board, that's 25 requests per second just asking, "Any updates?" Most of the time, the answer is no. This HTTP polling exhausts server bandwidth, wastes mobile battery, and still feels laggy. Furthermore, without a "room" architecture, every update is broadcast to everyone on the server, rather than just the people looking at that specific board.

### 💡 Plain English Metaphor (The What)
HTTP Polling is like **calling your friend every 2 minutes** asking, "Are you ready to go?" It's annoying and inefficient. WebSockets are like **keeping the phone line open** and silent; the moment your friend is ready, they just say, "Let's go."
A Room Architecture is like having **different conference call numbers**. Instead of a company-wide PA system blasting every department's updates, you dial into the "Marketing Room" and only hear updates relevant to Marketing.

### 💻 Complete Runnable Architecture/Code Example (TypeScript & Python)

**TypeScript (Node.js & Socket.io)**
```typescript
import express from 'express';
import { createServer } from 'http';
import { Server, Socket } from 'socket.io';
import jwt from 'jsonwebtoken';

const app = express();
const httpServer = createServer(app);
const io = new Server(httpServer, {
  cors: { origin: '*' }
});

const JWT_SECRET = process.env.JWT_SECRET || 'secret';

// 1. Authentication Handshake Middleware
io.use((socket, next) => {
  const token = socket.handshake.auth.token;
  if (!token) return next(new Error('Authentication error'));

  try {
    const user = jwt.verify(token, JWT_SECRET);
    socket.data.user = user; // Attach user data to socket session
    next();
  } catch (err) {
    next(new Error('Authentication error'));
  }
});

// 2. Connection and Room Management
io.on('connection', (socket: Socket) => {
  console.log(`User ${socket.data.user.id} connected via WebSocket`);

  // Client requests to join a specific Kanban board (Room)
  socket.on('join_board', (boardId: string) => {
    // Security check: Verify user has permission to view this board in DB
    // if (!canAccess(socket.data.user.id, boardId)) return;

    socket.join(`board:${boardId}`);
    console.log(`User joined room board:${boardId}`);

    // Notify others in the room
    socket.to(`board:${boardId}`).emit('user_joined', { userId: socket.data.user.id });
  });

  // Client leaves a board
  socket.on('leave_board', (boardId: string) => {
    socket.leave(`board:${boardId}`);
  });

  // 3. Channel Multiplexing (Routing messages only to specific rooms)
  socket.on('card_moved', (payload: { boardId: string, cardId: string, newColumn: string }) => {
    // Broadcast to everyone in the room EXCEPT the sender
    socket.to(`board:${payload.boardId}`).emit('card_moved_update', payload);
  });

  socket.on('disconnect', () => {
    console.log(`User disconnected`);
  });
});

httpServer.listen(3000, () => console.log('WebSocket Server running on port 3000'));
```

**Python (FastAPI & WebSockets)**
```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect, Depends, HTTPException
from typing import Dict, Set
import jwt

app = FastAPI()
JWT_SECRET = "secret"

# Simple in-memory Room Manager
class ConnectionManager:
    def __init__(self):
        # board_id -> set of active websocket connections
        self.rooms: Dict[str, Set[WebSocket]] = {}

    async def connect(self, websocket: WebSocket, board_id: str):
        await websocket.accept()
        if board_id not in self.rooms:
            self.rooms[board_id] = set()
        self.rooms[board_id].add(websocket)

    def disconnect(self, websocket: WebSocket, board_id: str):
        if board_id in self.rooms:
            self.rooms[board_id].discard(websocket)
            if not self.rooms[board_id]:
                del self.rooms[board_id]

    async def broadcast_to_room(self, message: dict, board_id: str, exclude: WebSocket = None):
        if board_id in self.rooms:
            for connection in self.rooms[board_id]:
                if connection != exclude:
                    await connection.send_json(message)

manager = ConnectionManager()

# Authentication Dependency for WebSocket
async def get_ws_user(token: str):
    try:
        payload = jwt.decode(token, JWT_SECRET, algorithms=["HS256"])
        return payload
    except jwt.JWTError:
        raise HTTPException(status_code=403, detail="Invalid token")

@app.websocket("/ws/board/{board_id}")
async def websocket_endpoint(websocket: WebSocket, board_id: str, token: str):
    # 1. Authentication Handshake
    try:
        user = await get_ws_user(token)
    except HTTPException:
        await websocket.close(code=1008) # Policy Violation
        return

    # 2. Join Room
    await manager.connect(websocket, board_id)
    try:
        while True:
            # 3. Listen for messages and multiplex
            data = await websocket.receive_json()
            if data.get("event") == "card_moved":
                await manager.broadcast_to_room(
                    message={"event": "card_moved_update", "data": data["payload"]},
                    board_id=board_id,
                    exclude=websocket # Don't send back to sender
                )
    except WebSocketDisconnect:
        manager.disconnect(websocket, board_id)
```

### 🪜 Progressive Step-by-Step Breakdown

#### Step 1: Authentication Handshake
WebSockets don't follow traditional HTTP headers in the same way once connected. We must authenticate the user *during the initial handshake*. In Socket.io, this is done via middleware `io.use`. In FastAPI, we pass a token via query parameters or custom subprotocols and validate it before accepting the connection.

#### Step 2: Room Connection Management
Once authenticated, a user isn't just "connected to the server"; they declare intent to join a specific context (a `boardId`). The server groups these socket connections. Socket.io handles this natively with `socket.join()`. In raw WebSockets (Python example), we must manually maintain a dictionary mapping room IDs to sets of active connections.

#### Step 3: Channel Multiplexing (Targeted Broadcasting)
When a user moves a card, they send the event to the server. The server uses `socket.to(room).emit()` (or iterates over the room's set in Python) to broadcast that event **only** to other users in that specific room. Crucially, we exclude the sender (they already know they moved the card because of Optimistic UI!).

### 🔀 ASCII / Architecture Flow

```text
[ Client A (Board 1) ]           [ Client B (Board 1) ]          [ Client C (Board 2) ]
        | (joins board:1)                | (joins board:1)               | (joins board:2)
        v                                v                               v
+-----------------------------------------------------------------------------------+
|                            WebSocket Server Gateway                               |
|                                                                                   |
|  [ Room: board:1 ] <=================================> [ Room: board:2 ]          |
|  - Client A Socket                                     - Client C Socket          |
|  - Client B Socket                                                                |
+-----------------------------------------------------------------------------------+
        ^
        | (emits 'card_moved')
[ Client A ]
        |
    Server receives, sees target room 'board:1'
    Broadcasts ONLY to Client B. Client C hears nothing.
```

### ⚠️ Noob Trap vs 👑 Pro Tip
* **Noob Trap**: Attempting to stick WebSockets behind a standard auto-scaling HTTP load balancer without sticky sessions. If Client A connects to Server 1, and Client B connects to Server 2, Server 1 doesn't know about Client B. They cannot communicate in the same "room" even if they pass the same `boardId`.
* **Pro Tip**: When scaling WebSockets beyond a single Node/Python process, you MUST introduce a Pub/Sub backplane (usually **Redis**). Socket.io has a `redis-adapter` for this exact purpose. When Server 1 receives an event for a room, it publishes it to Redis, and Server 2 subscribes to Redis to forward it to its own connected clients.

## Phase B: Engineering Challenges

### 🟢 Level 1: Warm-Up
**Task:** Implement connection heartbeats. The server should periodically ping the client every 30 seconds to ensure the connection isn't a "zombie" (a dropped TCP connection that didn't trigger a disconnect event).
<details>
<summary>💡 Hint</summary>
Socket.io handles `ping/pong` automatically under the hood via Engine.io! For raw WebSockets (FastAPI), implement an `asyncio` background task loop that sends a `{"type": "ping"}` frame, and expect a `"pong"` response from the client within a timeout window.
</details>

### 🟡 Level 2: Real-World
**Task:** Implement robust reconnection logic on the client side. If the server restarts, the client should automatically attempt to reconnect with exponential backoff and, upon successful reconnection, automatically re-join the room they were in.
<details>
<summary>💡 Hint</summary>
Use the `connect` event listener on the client. Keep track of the current `boardId` in React state. Inside `socket.on('connect', ...)`, emit the `join_board` event using that state. Socket.io handles exponential backoff automatically via `reconnectionDelay` options.
</details>

### 🔴 Level 3: Boss Level
**Task:** Scale the room architecture across multiple server instances using Redis Pub/Sub. Simulate a scenario where User A is connected to Server 1, User B is connected to Server 2, and they both join `board:x`. Ensure moving a card on Server 1 updates User B on Server 2.
<details>
<summary>💡 Hint & Solution</summary>
You must use a Redis Adapter.

**Solution (Node.js + Socket.io + Redis):**
```bash
npm install @socket.io/redis-adapter redis
```

```typescript
import { createAdapter } from "@socket.io/redis-adapter";
import { createClient } from "redis";

// Inside your server setup:
const pubClient = createClient({ url: "redis://localhost:6379" });
const subClient = pubClient.duplicate();

Promise.all([pubClient.connect(), subClient.connect()]).then(() => {
  io.adapter(createAdapter(pubClient, subClient));
  // The rest of your code remains EXACTLY the same.
  // socket.to('board:1').emit(...) will now transparently use Redis
  // to reach clients connected to other server processes!
});
```
</details>

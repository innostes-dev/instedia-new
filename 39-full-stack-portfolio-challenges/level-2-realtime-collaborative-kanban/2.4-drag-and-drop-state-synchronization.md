# 2.4 Drag and Drop State Synchronization

## Phase A: The Core Concept

### 🚨 Real-World Pain Point (The Why)
A user drags a Kanban card from "To Do" to "In Progress". If the UI waits for the backend database `UPDATE` query to finish before moving the card visually on screen, the drag-and-drop animation stutters, drops frames, or feels completely broken if the user has high latency. Conversely, if you update the UI instantly but don't handle network failures properly, the card might visually sit in "In Progress", but upon refreshing the page, it snaps back to "To Do" (Silent Data Loss).

### 💡 Plain English Metaphor (The What)
State Synchronization is like **moving furniture with a moving company**.
1. **Optimistic UI:** You draw on a floor plan where you want the couch to go (Instant visual update).
2. **Network Request:** You tell the movers to move it (The API Call).
3. **Graceful Rollback:** If the movers discover the couch doesn't fit through the door (Network Error/Validation Failure), you have to erase your drawing and put the couch back on the floor plan where it started.

### 💻 Complete Runnable Architecture/Code Example (React, dnd-kit & Zustand)

**Frontend (React with Zustand for State Management)**
```tsx
import React, { useEffect } from 'react';
import { create } from 'zustand';
import { DndContext, DragEndEvent, useDraggable, useDroppable } from '@dnd-kit/core';

// 1. Define State and Actions (Zustand Store)
interface BoardState {
  columns: Record<string, string[]>; // columnId -> array of cardIds
  moveCardOptimistic: (cardId: string, fromCol: string, toCol: string) => { previousState: any };
  rollbackState: (previousState: any) => void;
}

const useBoardStore = create<BoardState>((set, get) => ({
  columns: {
    'todo': ['card-1', 'card-2'],
    'in-progress': [],
    'done': []
  },
  moveCardOptimistic: (cardId, fromCol, toCol) => {
    const previousState = get().columns; // Snapshot for rollback

    set((state) => {
      const newFrom = state.columns[fromCol].filter(id => id !== cardId);
      const newTo = [...state.columns[toCol], cardId];
      return { columns: { ...state.columns, [fromCol]: newFrom, [toCol]: newTo } };
    });

    return { previousState };
  },
  rollbackState: (previousState) => set({ columns: previousState })
}));

// Mock API Call
const apiMoveCard = async (cardId: string, toCol: string) => {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      // Simulate 20% failure rate
      Math.random() > 0.8 ? reject(new Error('Network drop')) : resolve('OK');
    }, 800);
  });
};

export default function KanbanBoard() {
  const { columns, moveCardOptimistic, rollbackState } = useBoardStore();

  // 2. Handle the Drag End Event
  const handleDragEnd = async (event: DragEndEvent) => {
    const { active, over } = event;
    if (!over) return; // Dropped outside a valid column

    const cardId = active.id as string;
    const toCol = over.id as string;

    // Find where it came from (simple linear search for demo)
    const fromCol = Object.keys(columns).find(col => columns[col].includes(cardId));
    if (!fromCol || fromCol === toCol) return;

    // 3. Optimistic UI Update (Synchronous, 60fps)
    const { previousState } = moveCardOptimistic(cardId, fromCol, toCol);

    try {
      // 4. Background Network Synchronization
      await apiMoveCard(cardId, toCol);
      // Success! WebSocket will handle broadcasting this to OTHER users.
    } catch (error) {
      // 5. Graceful Rollback on Failure
      console.error("Failed to sync move, rolling back UI");
      rollbackState(previousState);
      alert("Network error: Failed to move card.");
    }
  };

  return (
    <DndContext onDragEnd={handleDragEnd}>
      <div style={{ display: 'flex', gap: '20px', padding: '20px' }}>
        {Object.entries(columns).map(([colId, cardIds]) => (
          <Column key={colId} id={colId} cardIds={cardIds} />
        ))}
      </div>
    </DndContext>
  );
}

// Minimal Column and Card Components for dnd-kit
function Column({ id, cardIds }: { id: string, cardIds: string[] }) {
  const { setNodeRef } = useDroppable({ id });
  return (
    <div ref={setNodeRef} style={{ background: '#f4f4f4', padding: '10px', width: '200px', minHeight: '300px' }}>
      <h3>{id.toUpperCase()}</h3>
      {cardIds.map(cId => <Card key={cId} id={cId} />)}
    </div>
  );
}

function Card({ id }: { id: string }) {
  const { attributes, listeners, setNodeRef, transform } = useDraggable({ id });
  const style = transform ? { transform: `translate3d(${transform.x}px, ${transform.y}px, 0)` } : undefined;
  return (
    <div ref={setNodeRef} style={{ ...style, background: 'white', padding: '10px', margin: '10px 0', border: '1px solid #ccc', cursor: 'grab' }} {...listeners} {...attributes}>
      {id}
    </div>
  );
}
```

### 🪜 Progressive Step-by-Step Breakdown

#### Step 1: Snapshot the State
Before modifying anything, the store (`moveCardOptimistic`) takes a complete copy of the `columns` object. This is our safety net.

#### Step 2: Optimistic Mutation (Synchronous)
We immediately mutate the React state (via Zustand), removing the card from `fromCol` and appending it to `toCol`. Because this happens synchronously in the `onDragEnd` handler, the browser renders the card in its new position instantly at 60fps.

#### Step 3: Network Await & Rollback
We fire the asynchronous API call. The user is unblocked and can continue using the app. If the `await` throws an error, the `catch` block fires, triggering `rollbackState(previousState)`. React immediately re-renders the columns based on the original snapshot, visually snapping the card back to its starting position.

### 🔀 ASCII / Architecture Flow

```text
[ User Drops Card ]
        |
        |---> 1. Snapshot State: { todo: [1], in-progress: [] }
        |
        |---> 2. Optimistic Update: { todo: [], in-progress: [1] }
        |        (UI Renders Instantly)
        |
        v
[ Network Request: PUT /cards/1 { status: 'in-progress' } ]
        |
    [ Success? ]
    /          \
  YES           NO (Timeout/500 Error)
   |            |
(Do nothing,    |---> 3. Rollback UI using Snapshot:
 UI is correct)          { todo: [1], in-progress: [] }
                         (Shows Error Alert)
```

### ⚠️ Noob Trap vs 👑 Pro Tip
* **Noob Trap**: Storing the exact array index (order) of a card as an integer in the database (e.g., `position: 1`, `position: 2`). If you drag a card to the top of a list of 1000 cards, you have to run `UPDATE cards SET position = position + 1 WHERE position >= 1` on 1000 rows. This causes massive database locks and latency.
* **Pro Tip**: Use **Lexicographical Sorting (String based ordering)** or **Fractional Indexing**.
If Card A is position `1000` and Card B is `2000`, and you drop Card C between them, you calculate `(1000 + 2000) / 2 = 1500`. Now you only update **one** row in the database! Libraries like `fractional-indexing` generate strings (e.g., `a`, `b`, between them is `a5`) to prevent float precision issues.

## Phase B: Engineering Challenges

### 🟢 Level 1: Warm-Up
**Task:** Prevent rapid-fire visual glitches. If a user quickly drags a card, it fails, and rolls back 2 seconds later, they might have moved other cards in the meantime. The rollback will erase the *other* valid moves! Modify the `rollbackState` to only revert the *specific card* that failed, not the entire board snapshot.
<details>
<summary>💡 Hint</summary>
Instead of saving a snapshot of the whole `columns` object, change `rollbackState(cardId, originalFromCol, originalToCol)`. Inside the Zustand store, write logic to remove `cardId` from wherever it currently is, and push it back to `originalFromCol`.
</details>

### 🟡 Level 2: Real-World
**Task:** Integrate WebSocket broadcasting. When `moveCardOptimistic` fires, also emit a WebSocket event. If the API fails and you roll back, emit *another* WebSocket event to tell everyone else to roll back that specific card too.
<details>
<summary>💡 Hint</summary>
Pass a socket instance into the component.
`socket.emit('card_moved', { cardId, toCol })`.
In the catch block: `socket.emit('card_moved', { cardId, toCol: originalFromCol })`.
</details>

### 🔴 Level 3: Boss Level
**Task:** Implement Lexicographical sorting (Fractional Indexing) on the frontend. When dropping a card between two other cards, calculate the new position string mathematically without relying on backend logic to determine the order.

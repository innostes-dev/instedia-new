# 2.2 Live Presence and Cursor Broadcast

## Phase A: The Core Concept

### 🚨 Real-World Pain Point (The Why)
In a collaborative Kanban board, if two users are editing the same card description simultaneously without knowing the other is there, they will overwrite each other's changes. Even worse, if you track "active users" purely by database connection status, a dropped internet connection leaves a "Ghost User" permanently marked as online because the disconnect event never reached the server.

### 💡 Plain English Metaphor (The What)
Live presence is like an **Office Meeting Room**. When you walk in, everyone sees you immediately (Presence Join). If you point a laser pointer at the whiteboard, everyone tracks where your dot is moving (Cursor Broadcast). If you suddenly vanish into thin air, the room needs a way to realize you are gone after a few seconds of silence, rather than assuming you are just standing perfectly still (Ephemeral State with TTL).

### 💻 Complete Runnable Architecture/Code Example (TypeScript & Redis)

**TypeScript (Node.js & Redis for Presence)**
```typescript
import { createClient } from 'redis';
import { Server, Socket } from 'socket.io';

const redis = createClient({ url: 'redis://localhost:6379' });
redis.connect();

const io = new Server(3000, { cors: { origin: '*' } });

// Presence Expiration (Time-To-Live)
const PRESENCE_TTL_SECONDS = 30;

io.on('connection', (socket: Socket) => {
  const userId = socket.handshake.query.userId as string;
  const boardId = socket.handshake.query.boardId as string;

  if (!userId || !boardId) return socket.disconnect();

  const roomKey = `board:${boardId}:presence`;
  const userKey = `user:${userId}:status`;

  // 1. Join Room & Set Ephemeral Presence in Redis
  socket.join(`board:${boardId}`);

  const updatePresence = async () => {
    // Add user to the board's active set
    await redis.sAdd(roomKey, userId);
    // Set a TTL on the user's specific status (e.g., last seen, typing)
    await redis.set(userKey, JSON.stringify({ lastSeen: Date.now(), socketId: socket.id }), {
      EX: PRESENCE_TTL_SECONDS
    });

    // Broadcast updated active list to everyone in the room
    const activeUsers = await redis.sMembers(roomKey);
    io.to(`board:${boardId}`).emit('presence_update', activeUsers);
  };

  updatePresence();

  // 2. Cursor Broadcast (Ephemeral, high-frequency, NOT stored in DB)
  socket.on('cursor_move', (payload: { x: number, y: number }) => {
    // Volatile emit means: "If this message drops, don't retry. It's okay."
    socket.volatile.to(`board:${boardId}`).emit('cursor_update', {
      userId,
      x: payload.x,
      y: payload.y
    });
  });

  // Client must send a heartbeat every 15s to keep TTL alive
  socket.on('heartbeat', () => {
    updatePresence();
  });

  // 3. Graceful Disconnect
  socket.on('disconnect', async () => {
    await redis.sRem(roomKey, userId);
    await redis.del(userKey);

    const activeUsers = await redis.sMembers(roomKey);
    io.to(`board:${boardId}`).emit('presence_update', activeUsers);
  });
});
```

**Frontend (React Snippet for Cursors)**
```tsx
import React, { useEffect, useState, useRef } from 'react';
import { io, Socket } from 'socket.io-client';

export default function CollaborativeCanvas({ boardId, userId }: { boardId: string, userId: string }) {
  const [cursors, setCursors] = useState<Record<string, {x: number, y: number}>>({});
  const socketRef = useRef<Socket | null>(null);

  useEffect(() => {
    const socket = io('http://localhost:3000', { query: { boardId, userId } });
    socketRef.current = socket;

    socket.on('cursor_update', (data: { userId: string, x: number, y: number }) => {
      setCursors(prev => ({ ...prev, [data.userId]: { x: data.x, y: data.y } }));
    });

    // Heartbeat loop
    const interval = setInterval(() => socket.emit('heartbeat'), 15000);

    return () => {
      clearInterval(interval);
      socket.disconnect();
    };
  }, [boardId, userId]);

  const handleMouseMove = (e: React.MouseEvent) => {
    // Throttle this in production! (e.g., using lodash.throttle to max 30fps)
    socketRef.current?.emit('cursor_move', { x: e.clientX, y: e.clientY });
  };

  return (
    <div onMouseMove={handleMouseMove} style={{ width: '100vw', height: '100vh', position: 'relative' }}>
      <h1>Kanban Board</h1>
      {Object.entries(cursors).map(([id, pos]) => (
        <div key={id} style={{
          position: 'absolute', left: pos.x, top: pos.y,
          width: 10, height: 10, backgroundColor: 'red', borderRadius: '50%'
        }} />
      ))}
    </div>
  );
}
```

### 🪜 Progressive Step-by-Step Breakdown

#### Step 1: Redis TTL for Ghost User Prevention
If a user closes their laptop lid, the TCP connection drops, but the server's `disconnect` event might not fire immediately. By requiring the client to send a `heartbeat` every 15 seconds, we constantly reset a 30-second TTL (Time-To-Live) on their Redis presence key. If they vanish, Redis automatically deletes their key after 30 seconds, allowing a background worker to detect and clean up "Ghost Users" from the room.

#### Step 2: Cursor Broadcasting (Volatile Messages)
Cursor movements happen at 60fps. Sending every single coordinate over TCP with guaranteed delivery creates massive network backpressure if the connection slows down. We use `socket.volatile.emit`. This tells the WebSocket layer: "Send this as fast as possible, but if the network buffer is full, just drop the frame. We only care about the *latest* position anyway."

#### Step 3: Frontend Throttling
We never emit a WebSocket message on every single pixel movement of the mouse in React. That would freeze the browser. The frontend must throttle the `handleMouseMove` event to max 20-30 times per second before emitting.

### 🔀 ASCII / Architecture Flow

```text
[ Client 1 Mouse Move ] --(throttle 30fps)--> [ WebSocket 'cursor_move' ]
                                                   |
                                            (Volatile UDP-like drop behavior)
                                                   |
                                                   v
                                          [ Server Gateway ]
                                                   |
                                     (Broadcasts to Room: boardId)
                                                   |
                                                   v
                                 [ Client 2 React State Update ]
                                 (Renders Red Dot at X, Y instantly)
```

### ⚠️ Noob Trap vs 👑 Pro Tip
* **Noob Trap**: Saving user presence or cursor locations to a Postgres/MySQL database. Relational DBs are not designed for thousands of writes per second of ephemeral state that expires in 30 seconds. You will lock the database.
* **Pro Tip**: Use Redis for all ephemeral presence state. Use WebRTC data channels (P2P) for cursor movements if you want to completely bypass the server to save bandwidth, keeping the server only for the initial handshake and DB persistence.

## Phase B: Engineering Challenges

### 🟢 Level 1: Warm-Up
**Task:** Add a "Typing Indicator" feature. When a user focuses on a text input, broadcast a `typing_start` event. When they blur, broadcast `typing_end`.
<details>
<summary>💡 Hint</summary>
Add standard `onFocus` and `onBlur` handlers to your React input. Emit the corresponding events via the socket. On the server side, listen for these events and broadcast them to the room, similar to `cursor_move`.
</details>

### 🟡 Level 2: Real-World
**Task:** Implement a cron job or background worker that runs every 10 seconds, scans Redis for the `roomKey` set, and removes any `userId` whose `userKey` (with the TTL) has expired, effectively cleaning up Ghost Users.
<details>
<summary>💡 Hint</summary>
Use `setInterval` on the server. Iterate through `await redis.sMembers(roomKey)`. For each `userId`, check `await redis.exists(userKey)`. If it returns 0, remove the ID from the set using `sRem`, and emit a new `presence_update` to the room.
</details>

### 🔴 Level 3: Boss Level
**Task:** Interpolate cursor movements on the frontend for ultra-smooth 60fps rendering, even if the WebSocket only receives updates at 10fps.
<details>
<summary>💡 Hint & Solution</summary>
You must decouple network updates from the render loop. Use standard game-dev linear interpolation (Lerp).

**Solution Approach (Frontend):**
1. Maintain two states for a cursor: `targetPosition` (from WebSocket) and `currentRenderPosition`.
2. Do NOT update React state on every animation frame (too slow). Use a direct DOM `ref` for the cursor div.
3. Use `requestAnimationFrame`. In the loop, move the `currentRenderPosition` 20% closer to the `targetPosition` (Lerp).
```typescript
// Pseudo-code for Lerp in requestAnimationFrame
const lerp = (start, end, factor) => start + (end - start) * factor;

function animate() {
   currentX = lerp(currentX, targetX, 0.2);
   currentY = lerp(currentY, targetY, 0.2);
   cursorRef.current.style.transform = `translate(${currentX}px, ${currentY}px)`;
   requestAnimationFrame(animate);
}
```
</details>

# 1.4 Frontend Dashboard and Optimistic UI

## Phase A: The Core Concept

### 🚨 Real-World Pain Point (The Why)
A user adds a new $50 expense in their financial dashboard. They click "Save", the screen freezes for 1.5 seconds with a spinning loader, and finally, the table updates. It feels sluggish and "clunky." Furthermore, the total balance calculation on the frontend uses standard JavaScript math, resulting in `$150.00 - $50.00 = $99.999999999`.

### 💡 Plain English Metaphor (The What)
Optimistic UI is like a **Restaurant Waiter taking your order**. When you order a coffee, the waiter immediately says "Coming right up!" and writes it on your bill (Optimistic Update). They don't make you stare at them silently until the barista finishes brewing the coffee (Waiting for Server Response). If the espresso machine is broken (Network Error), the waiter comes back, apologizes, and removes the coffee from your bill (Rollback).

### 💻 Complete Runnable Architecture/Code Example (React & TypeScript)

```tsx
import React, { useState } from 'react';

// Mock API Call
const apiCreateTransaction = async (amount: number): Promise<{ id: string }> => {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      // Simulate 10% chance of network failure
      Math.random() > 0.9 ? reject(new Error('Network Error')) : resolve({ id: crypto.randomUUID() });
    }, 1000);
  });
};

type Transaction = { id: string; amount: number; status: 'syncing' | 'success' | 'error' };

export default function FinancialDashboard() {
  const [transactions, setTransactions] = useState<Transaction[]>([
    { id: '1', amount: 150000, status: 'success' } // Stored in cents!
  ]);
  const [inputValue, setInputValue] = useState('');

  // Safe Currency Math: Always calculate in cents
  const totalBalanceCents = transactions.reduce((sum, t) => sum + t.amount, 0);
  const formattedBalance = new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: 'USD'
  }).format(totalBalanceCents / 100);

  const handleAddExpense = async (e: React.FormEvent) => {
    e.preventDefault();
    const amountInDollars = parseFloat(inputValue);
    if (isNaN(amountInDollars)) return;

    // Convert to cents for safe math
    const amountInCents = -Math.round(amountInDollars * 100);
    const optimisticId = `temp-${Date.now()}`;

    // 1. Optimistic Update: Instantly update UI before network request
    setTransactions((prev) => [
      { id: optimisticId, amount: amountInCents, status: 'syncing' },
      ...prev
    ]);
    setInputValue('');

    try {
      // 2. Network Request
      const response = await apiCreateTransaction(amountInCents);

      // 3. Success: Replace temp ID with real ID, update status
      setTransactions((prev) =>
        prev.map((t) => (t.id === optimisticId ? { ...t, id: response.id, status: 'success' } : t))
      );
    } catch (error) {
      // 4. Rollback: Mark as error or remove from list
      setTransactions((prev) =>
        prev.map((t) => (t.id === optimisticId ? { ...t, status: 'error' } : t))
      );
      alert('Failed to save transaction. Please try again.');
    }
  };

  return (
    <div className="p-6 max-w-xl mx-auto font-sans">
      <h1 className="text-2xl font-bold mb-4">Total Balance: {formattedBalance}</h1>

      <form onSubmit={handleAddExpense} className="mb-6 flex gap-2">
        <input
          type="number"
          step="0.01"
          placeholder="Expense Amount (e.g. 50.00)"
          value={inputValue}
          onChange={(e) => setInputValue(e.target.value)}
          className="border p-2 rounded flex-1"
          required
        />
        <button type="submit" className="bg-blue-600 text-white px-4 py-2 rounded">
          Add Expense
        </button>
      </form>

      <ul className="space-y-2">
        {transactions.map((t) => (
          <li
            key={t.id}
            className={`p-3 border rounded flex justify-between items-center transition-opacity ${
              t.status === 'syncing' ? 'opacity-50' : t.status === 'error' ? 'bg-red-50 border-red-200' : 'bg-white'
            }`}
          >
            <span className={t.status === 'error' ? 'line-through' : ''}>
              ${Math.abs(t.amount / 100).toFixed(2)}
            </span>
            <span className="text-sm text-gray-500">
              {t.status === 'syncing' && '⏳ Saving...'}
              {t.status === 'error' && '❌ Failed'}
              {t.status === 'success' && '✅ Saved'}
            </span>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

### 🪜 Progressive Step-by-Step Breakdown

#### Step 1: Handling Currency Math (Cents)
Notice `amountInCents = -Math.round(amountInDollars * 100)`. We **never** do math on floating-point dollars. We convert user input to integers (cents), do all additions/subtractions as integers, and only format it back to dollars `totalBalanceCents / 100` right before rendering. This completely eliminates IEEE 754 floating-point rounding errors.

#### Step 2: The Optimistic Update
Before `apiCreateTransaction` is even called, we update the React state with a temporary ID and a status of `syncing`. The user instantly sees their balance update and the item appear in the list. This creates a perceived performance of 0ms latency.

#### Step 3: Resolution and Rollback
We wait for the API. If it succeeds, we swap the temporary ID with the real database UUID. If it fails (caught in the `catch` block), we don't just leave broken data; we update the state to mark the item as `error` (or remove it entirely), and inform the user.

### 🔀 ASCII / Architecture Flow

```text
User Submits Form
       |
       v
1. Generate Temp ID
2. Update Local State (Status: Syncing) ----> UI Renders Instantly (Fast UX)
       |
       |---(Async API Call)---> [ Backend Server ]
                                      |
     (Wait...) <----------------------+
       |
   [Success?]
   /        \
YES          NO
 |            |
 v            v
Update ID   Mark Status: Error (Rollback UI)
Status: OK  Show Alert
```

### ⚠️ Noob Trap vs 👑 Pro Tip
* **Noob Trap**: Managing complex optimistic state manually with generic `useState` and `useEffect` as the application grows. It leads to race conditions if multiple requests fire simultaneously.
* **Pro Tip**: Use a specialized data-fetching library like **TanStack Query (React Query)** or **SWR**. They have built-in APIs for Optimistic Updates (`onMutate`), automatic rollbacks on error, and background refetching to ensure eventual consistency with the server.

const mutation = useMutation({
  mutationFn: apiCreateTransaction,
  onMutate: async (newTx) => {
    await queryClient.cancelQueries({ queryKey: ['transactions'] });
    const previous = queryClient.getQueryData(['transactions']);
    queryClient.setQueryData(['transactions'], (old) => [newTx, ...old]);
    return { previous }; // context for rollback
  },
  onError: (err, newTx, context) => {
    queryClient.setQueryData(['transactions'], context.previous); // Rollback
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['transactions'] }); // Ensure sync
  }
});

### 🔴 Level 3: Boss Level
**Task:** Implement an "Undo" feature for deletions. When a user clicks delete, optimistically remove it from the UI, but wait 5 seconds before actually sending the `DELETE` network request. If they click "Undo" within 5 seconds, cancel the request and restore the UI.
<details>
<summary>💡 Hint & Solution</summary>
You need to manage timers (`setTimeout`) and keep track of pending deletions.

**Solution Approach:**
1. User clicks Delete on ID `123`.
2. Add `123` to a `pendingDeletions` state array.
3. Update the UI to filter out any IDs present in `pendingDeletions`.
4. Start a `setTimeout` for 5000ms. Store the timer ID.
5. If the timer fires: execute the API call, and remove `123` from `pendingDeletions` on success.
6. If the user clicks Undo: `clearTimeout(timerId)`, and remove `123` from `pendingDeletions`. The UI will re-render and the item reappears.
</details>

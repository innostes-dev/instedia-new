# 4.2 Structured Concurrency & Scoped Values

## Phase A: Understanding the Mechanics

### 1. Real-World Pain Point (The Why)
You are building a Travel Aggregator. When a user searches for a trip, you need to query three different APIs concurrently: Flights, Hotels, and Car Rentals. You use standard `CompletableFuture` or an `ExecutorService`. Suddenly, the Hotel API goes down and throws an Exception after 100ms. Your main thread sees the error and returns a 500 to the user. However, the Flight and Car Rental threads are *still running in the background*, waiting for 5 seconds for network responses that nobody cares about anymore. You are leaking threads and burning CPU cycles on abandoned requests. You need a way to group concurrent tasks together so that if one fails (or the main task is cancelled), the entire group is instantly and automatically short-circuited and cleaned up.

### 2. Plain English Metaphor (The What)
- **Unstructured Concurrency (`ExecutorService`):** A manager (Main Thread) hires three contractors (Worker Threads) to paint three rooms. The manager says "Go!" and then sits in their office. If the manager suddenly gets fired, the contractors don't know—they just keep painting. If the first contractor breaks his leg and stops, the other two contractors don't know—they just keep painting. There is no structural link between their lifecycles.
- **Structured Concurrency (`StructuredTaskScope`):** The manager creates a strict "Task Group". If *anything* goes wrong—if the manager is fired, or if one contractor fails their job—an alarm bell rings instantly. The other contractors immediately drop their paintbrushes, clean up, and go home. The group's lifecycle is fundamentally tied together.
- **Scoped Values (`ScopedValue`):** A safer, faster replacement for `ThreadLocal`. Instead of handing a contractor an ID badge that they accidentally take home forever (memory leak), the manager explicitly hands them a badge at the door, and the badge physically vanishes the moment the task group finishes.

### 3. Complete Runnable Code
Here is a complete, runnable example demonstrating the power of Structured Concurrency to prevent "thread leaks" via automatic short-circuiting. *(Note: `StructuredTaskScope` is a preview feature in Java 21, requiring `--enable-preview`)*

```java
import java.util.concurrent.StructuredTaskScope;
import java.util.concurrent.StructuredTaskScope.Subtask;
import java.time.Duration;

public class StructuredConcurrencyDemo {

    public static void main(String[] args) {
        System.out.println("Starting Travel Aggregator Search...");
        long start = System.currentTimeMillis();

        try {
            TravelPackage result = fetchTravelPackage();
            System.out.println("Success! " + result);
        } catch (Exception e) {
            System.err.println("Search Failed: " + e.getMessage());
        }

        System.out.println("Total time: " + (System.currentTimeMillis() - start) + "ms");
        // Because of short-circuiting, total time will be ~500ms (the time of the failure),
        // NOT 3000ms (the time of the slowest task).
    }

    private static TravelPackage fetchTravelPackage() throws InterruptedException {

        // 1. Create a Scope.
        // ShutdownOnFailure means: If ANY subtask fails, cancel all other running subtasks!
        try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {

            // 2. Fork the subtasks. These run concurrently on Virtual Threads.
            Subtask<String> flightTask = scope.fork(() -> fetchFlight());
            Subtask<String> hotelTask  = scope.fork(() -> fetchHotel());
            Subtask<String> carTask    = scope.fork(() -> fetchCar());

            // 3. Wait for all to succeed, OR for the first one to fail.
            scope.join();

            // 4. If any task threw an exception, rethrow it here.
            scope.throwIfFailed();

            // 5. If we reach here, ALL tasks succeeded.
            return new TravelPackage(flightTask.get(), hotelTask.get(), carTask.get());
        }
    }

    private static String fetchFlight() throws InterruptedException {
        Thread.sleep(3000); // Very slow API
        return "Delta Flight 123";
    }

    private static String fetchHotel() throws InterruptedException {
        Thread.sleep(500); // Fails quickly!
        throw new RuntimeException("Hotel API is down!");
    }

    private static String fetchCar() throws InterruptedException {
        Thread.sleep(2000); // Slow API
        return "Hertz Rental";
    }

    record TravelPackage(String flight, String hotel, String car) {}
}
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Lexical Scope**
```java
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) { ... }
```
*Rationale:* Why `try-with-resources`? Because it strictly defines the boundaries of concurrency. When the code execution leaves this `try` block, you have an absolute mathematical guarantee that *no background threads spawned by this scope are still running*. They are either finished, or they have been forcefully interrupted.

**Step 2: Forking (Branching)**
```java
Subtask<String> flightTask = scope.fork(() -> fetchFlight());
```
*Rationale:* `scope.fork()` uses Virtual Threads under the hood. It returns a `Subtask`. You should NOT call `.get()` on a Subtask immediately, because that would block the current thread and ruin the concurrency.

**Step 3: Joining and Short-Circuiting**
```java
scope.join();
scope.throwIfFailed();
```
*Rationale:* `scope.join()` blocks the main thread.
- If all three APIs respond successfully, `join()` finishes, and you process the results.
- If the Hotel API throws an Exception at 500ms, the `ShutdownOnFailure` policy immediately fires an `InterruptedException` to the Flight and Car tasks. They stop sleeping/waiting on the network immediately. `join()` finishes at 500ms, and `throwIfFailed()` throws the Hotel Exception up the stack. No threads are leaked. Zero wasted CPU.

### 5. ASCII / Architecture Data Flow

```text
+-------------------------------------------------------------+
|               STRUCTURED TASK SCOPE (ShutdownOnFailure)     |
|                                                             |
|   Main Thread (try-with-resources)                          |
|        |                                                    |
|        +-- fork() --> [Virtual Thread 1] fetchFlight (3s)   |
|        |                                                    |
|        +-- fork() --> [Virtual Thread 2] fetchHotel (0.5s)  |
|        |                                                    |
|        +-- fork() --> [Virtual Thread 3] fetchCar (2s)      |
|        |                                                    |
|      join()                                                 |
|        |                                                    |
|        |   * 500ms later...                                 |
|        |   * VT 2 throws Exception!                         |
|        |   * Scope automatically sends interrupt() to VT 1! |
|        |   * Scope automatically sends interrupt() to VT 3! |
|        |                                                    |
|  throwIfFailed() <--- Re-throws Hotel Exception             |
|        |                                                    |
|    (Scope ends. ALL threads guaranteed dead).               |
+-------------------------------------------------------------+
```

### 6. Noob Trap vs Pro Tip
- **Noob Trap:** Swallowing `InterruptedException`. If you write a helper method like `catch (InterruptedException e) { log("Oops"); }` inside your worker task, Structured Concurrency breaks! When the scope tries to cancel a slow task, it sends an interrupt. If your task catches it, ignores it, and keeps doing work, you have leaked a thread. Always restore the interrupt flag: `Thread.currentThread().interrupt()`.
- **Pro Tip:** There is another policy: `StructuredTaskScope.ShutdownOnSuccess()`. Use this for redundancy. If you need a currency conversion and you have 3 different APIs (ExchangeRate-API, Fixer, OpenExchangeRates), fork all three! The *first* one to respond successfully will instantly cancel the other two, ensuring the lowest possible latency for your user.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**The Challenge:** Write a function that fetches the weather from two different services concurrently (`fetchWeatherUsApi()` and `fetchWeatherEuApi()`). Return the result of whichever one responds first. If both fail, throw an exception.
<details>
<summary><b>Hint</b></summary>
Use `StructuredTaskScope.ShutdownOnSuccess()`.
</details>
<details>
<summary><b>Solution Walkthrough</b></summary>

```java
import java.util.concurrent.StructuredTaskScope;
import java.util.concurrent.ExecutionException;

public class WeatherAggregator {

    public String getFastestWeather() throws InterruptedException, ExecutionException {
        // ShutdownOnSuccess cancels all other tasks as soon as ONE task returns a result.
        try (var scope = new StructuredTaskScope.ShutdownOnSuccess<String>()) {

            scope.fork(this::fetchWeatherUsApi);
            scope.fork(this::fetchWeatherEuApi);

            // Wait for the first success, or wait for all to fail
            scope.join();

            // Returns the result of the winning task
            return scope.result();
        }
    }

    private String fetchWeatherUsApi() throws InterruptedException {
        Thread.sleep(1000);
        return "72F";
    }

    private String fetchWeatherEuApi() throws InterruptedException {
        Thread.sleep(500); // This one wins!
        return "22C";
    }
}
```
</details>

### Level 2: Real-World
**The Challenge:** You have a `SecurityContext` containing the current logged-in `UserId`. You need to pass this ID to 10 concurrent Virtual Threads fetching database records, so the DAO layer knows who is querying. `ThreadLocal` is dangerous because Virtual Threads are so numerous they can cause memory bloat. Implement this using Java 21 `ScopedValue`.
<details>
<summary><b>Hint</b></summary>
`ScopedValue.newInstance()` creates a key. `ScopedValue.where(key, value).run(...)` binds the value to the current thread *and all child threads spawned within that block*.
</details>
<details>
<summary><b>Solution Walkthrough</b></summary>

```java
import java.util.concurrent.StructuredTaskScope;

public class SecureDatabaseQuery {

    // 1. Declare the Scoped Value (Immutable, thread-safe, auto-cleaned)
    public static final ScopedValue<String> USER_ID = ScopedValue.newInstance();

    public void handleHttpRequest(String authenticatedUserId) {

        // 2. Bind the value to a specific Lexical Scope
        ScopedValue.where(USER_ID, authenticatedUserId).run(() -> {

            // INSIDE this block, USER_ID is available.
            // Any Virtual Threads created here inherit the ScopedValue automatically!
            try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
                scope.fork(this::fetchAccountDetails);
                scope.fork(this::fetchRecentOrders);
                scope.join();
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }

        });
        // 3. OUTSIDE this block, the binding is immediately destroyed. Zero memory leaks.
    }

    private Object fetchAccountDetails() {
        // The DAO layer can read the value directly from the scope!
        String currentUserId = USER_ID.get();
        System.out.println("Fetching account for: " + currentUserId);
        return new Object();
    }

    private Object fetchRecentOrders() {
        System.out.println("Fetching orders for: " + USER_ID.get());
        return new Object();
    }
}
```
</details>

### Level 3: Boss Level
**The Challenge:** Build a `MultiVendorFlightPricer` that implements a custom "Deadline" policy. You need to search 5 airlines concurrently. You must return all successful quotes. However, if the entire operation takes longer than 2 seconds, you must short-circuit, cancel any airlines still searching, and just return the quotes you successfully gathered within the 2 seconds.
<details>
<summary><b>Hint</b></summary>
You don't want `ShutdownOnFailure` or `ShutdownOnSuccess`. You need all results. Use a standard `StructuredTaskScope<String>`. Call `scope.joinUntil(Instant.now().plusSeconds(2))`. Then manually iterate through your subtasks and collect the `.state() == Subtask.State.SUCCESS` results.
</details>
<details>
<summary><b>Solution Walkthrough</b></summary>

```java
import java.time.Instant;
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.StructuredTaskScope;
import java.util.concurrent.StructuredTaskScope.Subtask;
import java.util.concurrent.TimeoutException;

public class MultiVendorFlightPricer {

    public List<String> getQuotesDeadline() throws InterruptedException {

        // Standard scope: Doesn't auto-cancel on success or failure
        try (var scope = new StructuredTaskScope<String>()) {

            List<Subtask<String>> tasks = new ArrayList<>();

            // Fork 5 airline searches
            for (int i = 1; i <= 5; i++) {
                final int airlineId = i;
                tasks.add(scope.fork(() -> fetchPrice(airlineId)));
            }

            // JOIN WITH TIMEOUT!
            // If 2 seconds pass, it throws TimeoutException AND auto-cancels all pending tasks!
            try {
                scope.joinUntil(Instant.now().plusSeconds(2));
            } catch (TimeoutException e) {
                System.out.println("Deadline reached! Cancelling slow airlines...");
            }

            // Gather whatever succeeded before the deadline
            List<String> successfulQuotes = new ArrayList<>();
            for (Subtask<String> task : tasks) {
                if (task.state() == Subtask.State.SUCCESS) {
                    successfulQuotes.add(task.get());
                }
            }

            return successfulQuotes;
        }
    }

    private String fetchPrice(int airlineId) throws InterruptedException {
        // Simulate Airlines 1 and 2 being fast, and 3,4,5 being too slow
        long delay = airlineId <= 2 ? 500 : 5000;
        Thread.sleep(delay);
        return "Airline " + airlineId + " : $199";
    }

    public static void main(String[] args) throws InterruptedException {
        MultiVendorFlightPricer pricer = new MultiVendorFlightPricer();
        List<String> quotes = pricer.getQuotesDeadline();
        System.out.println("Final Quotes: " + quotes);
        // Expected: Only Airlines 1 and 2 are printed!
    }
}
```
This demonstrates the ultimate power of Structured Concurrency: precise, leak-free control over massive parallel fan-out operations.
</details>

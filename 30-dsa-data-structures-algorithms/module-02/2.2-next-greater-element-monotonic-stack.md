# 2.2 Next Greater Element & Monotonic Stacks

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are building a High-Frequency Trading dashboard. For every second of the trading day, you need to know exactly how many seconds it took for a stock price to spike *higher* than its current value.
If you have an array of 100,000 tick prices, and you use a nested loop to look ahead for the next higher price for *every single tick*, you are running an **O(N^2)** algorithm. Your system will calculate the data so slowly that the market will close before your chart finishes rendering.

### 2. Plain English Metaphor (The What)
Imagine people of various heights standing in a line facing right. You want to know who is the first person taller than you looking right.
Instead of walking down the line yourself, imagine a waiting room (a **Stack**). People enter the waiting room one by one. If a tall person enters, they look at everyone currently sitting in the waiting room. Anyone shorter than the tall person says, "Aha! You are my next taller person!" and leaves the room. The tall person then takes a seat. This ensures the waiting room only ever contains people arranged in decreasing order of height (a **Monotonic** property).

### 3. Complete Runnable Code
```javascript
/**
 * Wall Street Next Stock Price Spike Detector
 * Returns an array where output[i] is the number of ticks until the price exceeds prices[i].
 * If it never exceeds, returns 0.
 */
function calculateDaysToSpike(prices) {
  const result = new Array(prices.length).fill(0);

  // The Monotonic Stack will store INDICES, not values.
  // It maintains a strictly decreasing (or equal) invariant based on price values.
  const stack = [];

  for (let currentIndex = 0; currentIndex < prices.length; currentIndex++) {
    const currentPrice = prices[currentIndex];

    // Check if the current price is the "Next Greater Element" for those in the waiting room
    while (stack.length > 0 && currentPrice > prices[stack[stack.length - 1]]) {
      // We found a spike for the person at 'poppedIndex'!
      const poppedIndex = stack.pop();

      // The distance is the difference in their indices
      result[poppedIndex] = currentIndex - poppedIndex;
    }

    // The current day enters the waiting room to wait for its future spike
    stack.push(currentIndex);
  }

  return result;
}

// Example Execution
const stockPrices = [73, 74, 75, 71, 69, 72, 76, 73];
console.log(calculateDaysToSpike(stockPrices));
// Output: [1, 1, 4, 2, 1, 1, 0, 0]
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Index Stack**
```javascript
  const result = new Array(prices.length).fill(0);
  const stack = [];
```
*Rationale:* We pre-fill the result array with `0`s to handle the cases where a price never spikes. Crucially, our `stack` stores **indices**, not the actual prices. We need the indices to calculate the "distance" (time) between the current price and the future spike.

**Step 2: The Monotonic Invariant Engine**
```javascript
  for (let currentIndex = 0; currentIndex < prices.length; currentIndex++) {
    const currentPrice = prices[currentIndex];

    while (stack.length > 0 && currentPrice > prices[stack[stack.length - 1]]) {
```
*Rationale:* As we iterate through the array, we compare the `currentPrice` to the price associated with the index at the *top* of the stack (the most recent unresolved day). The `while` loop is the engine: as long as the current price is *greater* than the top of the stack, the current price is the answer to that stacked day's question.

**Step 3: Resolving History**
```javascript
      const poppedIndex = stack.pop();
      result[poppedIndex] = currentIndex - poppedIndex;
    }
    stack.push(currentIndex);
  }
```
*Rationale:* We pop the index off the stack, record the distance in our `result` array, and keep checking the next item down the stack. Once the `currentPrice` is no longer greater than the top of the stack (or the stack is empty), the `currentPrice` itself gets pushed onto the stack to wait for its own future spike. Because every element is pushed exactly once and popped at most once, the time complexity is **O(N)**.

### 5. ASCII / Architecture Data Flow

```text
Idx 0 (73): Stack is empty. Push 0.
Stack: [0]

Idx 1 (74): 74 > prices[0] (73).
  - Pop 0. Result[0] = 1 - 0 = 1.
  - Push 1.
Stack: [1]

Idx 2 (75): 75 > prices[1] (74).
  - Pop 1. Result[1] = 2 - 1 = 1.
  - Push 2.
Stack: [2]

Idx 3 (71): 71 < prices[2] (75). No spike. Push 3.
Stack: [2, 3]

Idx 4 (69): 69 < prices[3] (71). No spike. Push 4.
Stack: [2, 3, 4]  -> Notice prices: [75, 71, 69]. Strictly decreasing!

Idx 5 (72): 72 > prices[4] (69).
  - Pop 4. Result[4] = 5 - 4 = 1.
  - 72 > prices[3] (71).
  - Pop 3. Result[3] = 5 - 3 = 2.
  - 72 < prices[2] (75). Stop loop.
  - Push 5.
Stack: [2, 5] -> Notice prices: [75, 72]. Monotonic invariant restored.
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Assuming Stacks are only good for parsing HTML tags or reversing strings. Any problem asking for the "next greater", "next smaller", "previous greater", or "previous smaller" element in an array is almost always screaming for a Monotonic Stack.
**Pro Tip:** You can enforce different invariances depending on the problem.
- To find Next Greater Element: Stack stores elements in Decreasing order.
- To find Next Smaller Element: Stack stores elements in Increasing order.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Given a string containing just the characters `'(', ')', '{', '}', '[' and ']'`, determine if the input string is valid (brackets must close in the correct order).
<details>
<summary>👀 Hint</summary>
This is the classic stack usage. Push opening brackets onto the stack. When you encounter a closing bracket, pop the top of the stack and check if it's the matching opening bracket.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function isValid(s) {
  const stack = [];
  const map = {
    ')': '(',
    '}': '{',
    ']': '['
  };

  for (let i = 0; i < s.length; i++) {
    const char = s[i];

    // If it's a closing bracket
    if (map[char]) {
      // Pop top of stack (or dummy value if empty)
      const topElement = stack.length > 0 ? stack.pop() : '#';
      // If the mapped opening bracket doesn't match the popped element, invalid
      if (map[char] !== topElement) {
        return false;
      }
    } else {
      // It's an opening bracket, push to stack
      stack.push(char);
    }
  }

  // If stack is empty, all brackets matched
  return stack.length === 0;
}
```
**Walkthrough:** We use a Hash Map to quickly look up the corresponding opening bracket for any closing bracket. We use a Stack to track the order of opening brackets. Because a stack is Last-In-First-Out (LIFO), the most recently opened bracket is always evaluated first, ensuring correct hierarchical closure.
</details>

### Level 2: Real-World
**Task:** The `Discount Applicator`. You are given an array of item prices in a store. For each item, you receive a discount equal to the price of the **next item to its right that costs less than or equal to it**. If no such item exists, there is no discount. Return an array of final prices you will pay for each item.
<details>
<summary>👀 Hint</summary>
"Next item that is less than or equal to". This is a Monotonic Stack seeking the Next *Smaller* Element. Maintain a strictly *increasing* stack of indices.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function finalPrices(prices) {
  // Start with a copy of original prices (default state if no discount found)
  const result = [...prices];
  const stack = []; // Monotonic increasing stack (stores indices)

  for (let i = 0; i < prices.length; i++) {
    const currentPrice = prices[i];

    // While current price is less than or equal to the top of the stack
    while (stack.length > 0 && currentPrice <= prices[stack[stack.length - 1]]) {
      const poppedIndex = stack.pop();
      // The discount is applied!
      result[poppedIndex] = prices[poppedIndex] - currentPrice;
    }

    stack.push(i);
  }

  return result;
}
```
**Walkthrough:** Similar to our stock spike example, we push indices onto the stack. However, our `while` loop condition is reversed: we look for future elements that are *smaller* (or equal) to the stacked elements. When we find one, we pop the index, subtract the current smaller price from the original price, and update the result array.
</details>

### Level 3: Boss Level
**Task:** Build a `Skyline Histogram Area Calculator` (Largest Rectangle in Histogram). Given an array of heights representing a histogram's bar height where the width of each bar is 1, return the area of the largest rectangle in the histogram.
<details>
<summary>👀 Hint</summary>
A rectangle's height is bound by the *shortest* bar within its width. Use a monotonic strictly *increasing* stack. When you hit a bar shorter than the stack top, you know the right boundary for the rectangle formed by the popped bar. The left boundary is the new top of the stack.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function largestRectangleArea(heights) {
  let maxArea = 0;
  const stack = []; // Stores indices of strictly increasing heights
  // Append a 0 height at the end to force all remaining blocks in stack to pop
  const h = [...heights, 0];

  for (let i = 0; i < h.length; i++) {
    const currentHeight = h[i];

    // When we find a shorter bar, the taller bars in stack cannot expand further right
    while (stack.length > 0 && currentHeight < h[stack[stack.length - 1]]) {
      // The height of the rectangle we are evaluating
      const height = h[stack.pop()];

      // Calculate width
      // If stack is empty, the rectangle spans from index 0 to current index
      // Otherwise, it spans from the new top of stack to current index
      const width = stack.length === 0 ? i : i - stack[stack.length - 1] - 1;

      maxArea = Math.max(maxArea, height * width);
    }

    stack.push(i);
  }

  return maxArea;
}
```
**Walkthrough:** This is a notorious FAANG interview question. A rectangle's expansion is stopped when it encounters a bar shorter than itself. Our strictly increasing Monotonic Stack tracks bars waiting to be stopped.
When we encounter a shorter bar (`currentHeight`), we pop the taller bar off the stack. We know its height. We know its right boundary is `i` (the current shorter bar). We know its left boundary is the *new* top of the stack (because the stack is increasing, the new top is the first bar to the left that was shorter than the popped bar). We calculate `height * width`, update `maxArea`, and continue. We append a `0` to the end of the heights array to force all remaining bars in the stack to evaluate and pop at the very end.
</details>

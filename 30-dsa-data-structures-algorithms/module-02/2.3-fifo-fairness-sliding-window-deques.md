# 2.3 FIFO Fairness & Sliding Window Deques

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are monitoring an IoT sensor mesh that reports voltage readings every millisecond. You need a dashboard that shows the *absolute peak voltage* across the rolling window of the last 10,000 milliseconds.
If you use a simple Array and `Math.max()` over 10,000 elements for every incoming tick, your CPU is performing 10 million comparisons per second. The system will melt down. A sliding window alone doesn't fix this because when the maximum value drops out of the left side of the window, you have to rescan the *entire* window to find the new second-highest value.

### 2. Plain English Metaphor (The What)
Imagine a waiting room for a roller coaster. You only want to remember the tallest person currently in the room.
If a new person walks in (enqueue) who is taller than everyone currently in the room, all the shorter people leave immediately—they will *never* be the tallest person because the new tall person arrived after them and will stay in the room longer.
However, if a short person walks in, they wait patiently at the back, because when the tall person leaves (dequeue), the short person *might* become the tallest person left.
This queue where people enter at the back, but can force people out of the back, and leave from the front, is a **Double-Ended Queue (Deque)**.

### 3. Complete Runnable Code
```javascript
/**
 * Real-Time IoT Sensor Peak Voltage Window Filter
 * Finds the maximum value in every sliding window of size K.
 */
function maxSlidingWindow(voltages, k) {
  const results = [];

  // The Deque stores INDICES, not values.
  // It maintains a strictly decreasing invariant based on voltage values.
  const deque = [];

  for (let i = 0; i < voltages.length; i++) {
    // 1. Remove elements that are no longer in the window (outdated)
    // The head of the deque is the index of the oldest, largest element
    if (deque.length > 0 && deque[0] < i - k + 1) {
      deque.shift(); // Remove from the front
    }

    // 2. Remove smaller elements in k range as they are useless
    // If the incoming voltage is larger than the tail of the deque, pop the tail
    while (deque.length > 0 && voltages[i] >= voltages[deque[deque.length - 1]]) {
      deque.pop(); // Remove from the back
    }

    // 3. Add the incoming element's index
    deque.push(i);

    // 4. Record the max for the current window
    // (Only start recording once we've processed at least 'k' elements)
    if (i >= k - 1) {
      results.push(voltages[deque[0]]); // The front is ALWAYS the max
    }
  }

  return results;
}

// Example Execution
const stream = [1, 3, -1, -3, 5, 3, 6, 7];
const windowSize = 3;
console.log(maxSlidingWindow(stream, windowSize));
// Output: [3, 3, 5, 5, 6, 7]
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Aging Out the Old Data**
```javascript
    if (deque.length > 0 && deque[0] < i - k + 1) {
      deque.shift();
    }
```
*Rationale:* Because the window slides, the biggest number we are tracking will eventually fall out of the window. We check the index at the *front* of our deque. If it's too old (less than `i - k + 1`), we evict it.

**Step 2: The Monotonic Deque Engine**
```javascript
    while (deque.length > 0 && voltages[i] >= voltages[deque[deque.length - 1]]) {
      deque.pop();
    }
```
*Rationale:* This is the core logic. When a new voltage arrives, we compare it against the *back* of the deque. If the new voltage is larger, we immediately delete the smaller, older voltages from the back. They are completely useless because the new voltage is both larger AND will remain in the window longer.

**Step 3: Enqueue and Record**
```javascript
    deque.push(i);
    if (i >= k - 1) {
      results.push(voltages[deque[0]]);
    }
```
*Rationale:* The new voltage's index is added to the back. Because we violently destroyed all smaller numbers in Step 2, the deque is guaranteed to be sorted in strictly decreasing order. The maximum value for the current window is *always* safely sitting at `deque[0]`.

### 5. ASCII / Architecture Data Flow

```text
         Window: [1, 3, -1]. MAX = voltages[deque[0]] = 3.

i=3 (-3): -3 < -1. Push 3. Deque: [1, 2, 3].
         Window: [3, -1, -3]. MAX = voltages[1] = 3.

i=4 (5): 5 > -3. Pop 3. 5 > -1. Pop 2. 5 > 3. Pop 1. Push 4. Deque: [4].
         Window: [-1, -3, 5]. MAX = voltages[4] = 5.

         Window: [-3, 5, 3]. MAX = voltages[4] = 5.

```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using a Heap (Priority Queue) to track the sliding maximum. While a Max-Heap gives O(1) access to the max element, removing a specific *aged-out* element from the middle of a Heap takes O(N) time. The Deque solves this in **O(N)** overall time (amortized O(1) per element).
**Pro Tip:** In JavaScript, `Array.shift()` is actually O(N) because it requires memory shifting. For production-grade high-frequency Deques in JS, you should build a custom Deque class using a Linked List or a circular buffer Array with Head/Tail pointers to ensure true O(1) operations.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Build a `Moving Average Data Stream`. Create a class that accepts integers from a data stream and returns the average of the last `size` integers.
<details>
<summary>👀 Hint</summary>
You don't need a monotonic deque for this. A standard Queue (First-In-First-Out) is perfect. Maintain a running sum. When the queue size exceeds `size`, dequeue the oldest element, subtract it from the sum, enqueue the new element, add it to the sum, and divide by `size`.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
class MovingAverage {
  constructor(size) {
    this.size = size;
    this.queue = [];
    this.windowSum = 0;
  }

  next(val) {
    this.queue.push(val); // Enqueue
    this.windowSum += val;

    // If we exceed the window size, dequeue the oldest element
    if (this.queue.length > this.size) {
      const oldest = this.queue.shift();
      this.windowSum -= oldest;
    }

    return this.windowSum / this.queue.length;
  }
}
```
**Walkthrough:** This is a classic FIFO (First-In-First-Out) queue implementation. We keep a rolling sum to avoid recalculating the entire queue every time. The queue merely serves as memory to tell us exactly *which* value needs to be subtracted from our rolling sum when the window gets too large.
</details>

### Level 2: Real-World
**Task:** The `Continuous Stock Ticker Subarray`. Given an array of integers representing stock prices, and an integer `limit`, return the size of the longest non-empty continuous subarray where the absolute difference between any two elements is less than or equal to `limit`. (e.g., max element in window - min element in window <= limit).
<details>
<summary>👀 Hint</summary>
You need to track *both* the maximum and minimum elements in a sliding window dynamically. Use TWO Deques! One Monotonic Decreasing Deque to track the max, and one Monotonic Increasing Deque to track the min.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function longestSubarray(prices, limit) {
  let maxDeque = []; // Tracks maximums (strictly decreasing)
  let minDeque = []; // Tracks minimums (strictly increasing)
  let left = 0;
  let maxLength = 0;

  for (let right = 0; right < prices.length; right++) {
    const price = prices[right];

    // Maintain Max Deque
    while (maxDeque.length > 0 && price > maxDeque[maxDeque.length - 1]) {
      maxDeque.pop();
    }
    maxDeque.push(price);

    // Maintain Min Deque
    while (minDeque.length > 0 && price < minDeque[minDeque.length - 1]) {
      minDeque.pop();
    }
    minDeque.push(price);

    // Dynamic Window Validation
    // If the difference between the current max and min exceeds the limit
    while (maxDeque[0] - minDeque[0] > limit) {
      // We must shrink the window from the left
      if (prices[left] === maxDeque[0]) maxDeque.shift();
      if (prices[left] === minDeque[0]) minDeque.shift();
      left++;
    }

    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
}
```
**Walkthrough:** This combines a Dynamic Sliding Window (1.2) with a Monotonic Deque (2.3). We expand our window by moving `right`. We keep our two Deques updated. If our dynamic window breaks the `limit` rule (max - min > limit), we *must* shrink the window by moving `left` forward. When moving `left`, if the element we are dropping happens to be the current max or min, we must also evict it from the front of the respective Deque.
</details>

### Level 3: Boss Level
**Task:** Build an `O(1) Access LRU (Least Recently Used) Cache`. Design a cache with a set capacity. `get(key)` returns the value if it exists, otherwise -1. `put(key, value)` adds or updates the key. If the cache reaches capacity, the least recently accessed item is evicted. Both operations MUST be O(1) time complexity.
<details>
<summary>👀 Hint</summary>
A Hash Map gives you O(1) `get` and `put`. But a Hash Map doesn't maintain an order of "recency". An Array maintains order, but rearranging elements takes O(N).
Combine a Hash Map with a Doubly Linked List! The Hash Map stores `{ key: Node }`. The Doubly Linked List acts as a queue, tracking usage order (Most Recent at Head, Least Recent at Tail).
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
class Node {
  constructor(key, value) {
    this.key = key;
    this.value = value;
    this.prev = null;
    this.next = null;
  }
}

class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;
    this.cacheMap = new Map();

    // Sentinel Dummy Nodes to avoid null checks
    this.head = new Node("head", "head");
    this.tail = new Node("tail", "tail");
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  // Helper: Add a node right after the head (Most Recently Used)
  _addNode(node) {
    node.prev = this.head;
    node.next = this.head.next;
    this.head.next.prev = node;
    this.head.next = node;
  }

  // Helper: Remove a node from anywhere in the list
  _removeNode(node) {
    let prev = node.prev;
    let next = node.next;
    prev.next = next;
    next.prev = prev;
  }

  // Helper: Move an accessed node to the front
  _moveToHead(node) {
    this._removeNode(node);
    this._addNode(node);
  }

  // Helper: Pop the node just before the tail (Least Recently Used)
  _popTail() {
    let lru = this.tail.prev;
    this._removeNode(lru);
    return lru;
  }

  get(key) {
    const node = this.cacheMap.get(key);
    if (!node) return -1;

    // It was accessed, so it becomes the Most Recently Used!
    this._moveToHead(node);
    return node.value;
  }

  put(key, value) {
    let node = this.cacheMap.get(key);

    if (node) {
      // Update existing
      node.value = value;
      this._moveToHead(node);
    } else {
      // Create new
      let newNode = new Node(key, value);
      this.cacheMap.set(key, newNode);
      this._addNode(newNode);

      if (this.cacheMap.size > this.capacity) {
        // Evict LRU from list and Map
        let tailNode = this._popTail();
        this.cacheMap.delete(tailNode.key);
      }
    }
  }
}
```
**Walkthrough:** This is the undisputed champion of software engineering interviews.
1. The **Hash Map** gives us O(1) lookup. When we `get("user1")`, the map returns a direct memory pointer to the exact Node in the Doubly Linked List.
2. The **Doubly Linked List** gives us O(1) restructuring. Because we have a direct pointer to the Node, we can surgically detach it by tying its `prev` and `next` neighbors together, and then teleport it to the `head` of the list (making it Most Recently Used).
3. **Capacity Eviction:** If we exceed capacity, we simply look at `this.tail.prev` (the oldest untouched Node), remove it from the list in O(1) time, and delete its key from the Map in O(1) time.
</details>

# 3.2 Lowest Common Ancestor & Tree Paths

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
Imagine a massive corporate org chart for a Fortune 500 company (which is a Tree data structure). Employee A and Employee B get into a dispute.
You need to find the lowest-level manager who is the boss of *both* of them to resolve the escalation.
If you start from the CEO and search down, you might pick a VP, but there might be a Director further down who manages both. You need an algorithm that can efficiently locate the most specific shared parent node between any two nodes in a hierarchy.

### 2. Plain English Metaphor (The What)
Think of a family tree. You and your second cousin want to find your most recent shared relative.
You both trace your ancestry backward (up the tree). You hit your parents, then grandparents. Your cousin hits their parents, then grandparents. The very first person you both point to is your shared grandparent.
In Computer Science, this most recent shared relative is called the **Lowest Common Ancestor (LCA)**.

### 3. Complete Runnable Code
```javascript
/**
 * Corporate Org Chart Escalation Resolver
 * Finds the Lowest Common Ancestor (LCA) of two nodes in a Binary Tree.
 */
class EmployeeNode {
  constructor(name) {
    this.name = name;
    this.left = null;
    this.right = null;
  }
}

function findLCA(root, employee1, employee2) {
  // 1. Base Case: Hit bottom, or found one of the targets
  if (root === null || root.name === employee1 || root.name === employee2) {
    return root;
  }

  // 2. Delegate the search to the left and right departments
  const leftSearch = findLCA(root.left, employee1, employee2);
  const rightSearch = findLCA(root.right, employee1, employee2);

  // 3. The Resolution Logic

  // If BOTH departments found someone, the current root MUST be the shared boss
  if (leftSearch !== null && rightSearch !== null) {
    return root;
  }

  // Otherwise, pass up whoever was found (or null if nobody was found)
  return leftSearch !== null ? leftSearch : rightSearch;
}

// Example Execution
const ceo = new EmployeeNode("CEO");
ceo.left = new EmployeeNode("VP_Sales");
ceo.right = new EmployeeNode("VP_Eng");
ceo.left.left = new EmployeeNode("Alice"); // Sales Rep
ceo.left.right = new EmployeeNode("Bob");  // Sales Rep

const sharedBoss = findLCA(ceo, "Alice", "Bob");
console.log(sharedBoss.name); // Output: VP_Sales
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Base Case (The Anchor)**
```javascript
  if (root === null || root.name === employee1 || root.name === employee2) {
    return root;
  }
```
*Rationale:* Every recursive function needs an exit condition. If we hit `null`, it means we reached the bottom without finding the employee. If the current root *is* one of the employees, we return that employee's node upwards to tell the previous caller, "I found them!"

**Step 2: The Recursive Delegation**
```javascript
  const leftSearch = findLCA(root.left, employee1, employee2);
  const rightSearch = findLCA(root.right, employee1, employee2);
```
*Rationale:* The current manager (root) doesn't know where the employees are, so they delegate the task: "Hey Left Sub-Manager, do you have Employee1 or 2? Hey Right Sub-Manager, do you?" We wait for their responses.

**Step 3: The Intersection Logic**
```javascript
  if (leftSearch !== null && rightSearch !== null) {
    return root;
  }
  return leftSearch !== null ? leftSearch : rightSearch;
```
*Rationale:* This is the core magic. If `leftSearch` found Alice, and `rightSearch` found Bob, then the current node is the exact junction where their paths merge! The current node is the LCA, so we return `root`.
If only one side found something (e.g., Alice was found on the left, but Bob wasn't found at all in this subtree), we just bubble up the one we *did* find (`leftSearch`).

### 5. ASCII / Architecture Data Flow
```text
Tree:
       CEO
      /   \
  VP_S     VP_E
  /  \
Alice Bob

findLCA(CEO, "Alice", "Bob")
|-- findLCA(VP_S)
|   |-- findLCA(Alice) -> Returns [Alice] (Base Case)
|   |-- findLCA(Bob)   -> Returns [Bob] (Base Case)
|   |-- Both are non-null! VP_S returns [VP_S] up to CEO.
|
|-- findLCA(VP_E)
|   |-- Left is null, Right is null. VP_E returns [null].
|
CEO receives [VP_S] from left, [null] from right.
CEO returns [VP_S].
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Trying to solve tree problems using iterative `while` loops and stacks unless explicitly required (like BFS). Tree data structures are inherently recursive. Fighting recursion on trees leads to massive, buggy, unreadable code.
**Pro Tip:** The standard LCA algorithm works for *any* Binary Tree. However, if the tree is specifically a **Binary Search Tree (BST)**, you don't need recursion! You can find the LCA in O(1) space just by checking values: If both targets are less than the root, go left. If both are greater, go right. The first time they split (one is less, one is greater), you are at the LCA!

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Build a `Max Depth Calculator`. Given the root of a binary tree, return its maximum depth (the number of nodes along the longest path from the root node down to the farthest leaf node).
<details>
<summary>👀 Hint</summary>
Recursion. The maximum depth of a tree is simply `1 (for the current node) + max(depth of left subtree, depth of right subtree)`. Base case: if root is null, depth is 0.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function maxDepth(root) {
  // Base case: empty tree has 0 depth
  if (root === null) {
    return 0;
  }

  // Recursively find the depth of both sides
  const leftDepth = maxDepth(root.left);
  const rightDepth = maxDepth(root.right);

  // Return the larger of the two, plus 1 for the current level
  return 1 + Math.max(leftDepth, rightDepth);
}
```
**Walkthrough:** This is the "Hello World" of tree recursion. We ask the left child for its depth, and the right child for its depth. We take the winner, add 1 for ourselves, and pass that number up to our parent. This collapses from the leaves up to the root.
</details>

### Level 2: Real-World
**Task:** Build an `API Request Router Identifier` (Path Sum). Given the root of a binary tree (representing routing cost weights) and an integer `targetSum`, return `true` if the tree has a root-to-leaf path such that adding up all the values along the path equals `targetSum`.
<details>
<summary>👀 Hint</summary>
As you traverse down the tree, subtract the current node's value from `targetSum`. When you reach a leaf node (both left and right are null), check if the remaining `targetSum` exactly equals the leaf node's value.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function hasPathSum(root, targetSum) {
  if (root === null) return false;

  // Check if we are at a leaf node
  if (root.left === null && root.right === null) {
    // Does the remaining sum equal this leaf's value?
    return targetSum === root.value;
  }

  // Deduct current node's value and pass the new target down to children
  const remainingSum = targetSum - root.value;

  // We only need ONE valid path, so we use logical OR
  return hasPathSum(root.left, remainingSum) || hasPathSum(root.right, remainingSum);
}
```
**Walkthrough:** Instead of maintaining a running sum (which requires passing an extra state variable down), we pass the *required remaining sum* downwards. When we hit the absolute bottom (a leaf node), we simply check if the value of that leaf perfectly covers the remaining debt. If the left branch finds a valid path, the `||` short-circuits and we instantly return true!
</details>

### Level 3: Boss Level
**Task:** Build a `Maximum Profit Path Analyzer` (Binary Tree Maximum Path Sum). A path in a binary tree is a sequence of nodes where each pair of adjacent nodes has an edge connecting them. The path does not need to pass through the root. Calculate the maximum sum of *any* path in the tree. (Note: Nodes can have negative values!).
<details>
<summary>👀 Hint</summary>
At any given node, a path can do one of two things:
1) Form an inverted "V" shape (Left child + Node + Right child). This path terminates here and cannot be passed up to the parent!
2) Form a straight line (Node + max(Left, Right)). This CAN be passed up to the parent to continue the path.
Maintain a global `maxSum` variable to track the "V" shapes, but only return the straight line upward.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function maxPathSum(root) {
  let globalMax = -Infinity;

  function calculateBranchSum(node) {
    if (node === null) return 0;

    // If a branch sum is negative, it's toxic!
    // We are better off not including it at all (hence Math.max with 0)
    const leftBranchMax = Math.max(0, calculateBranchSum(node.left));
    const rightBranchMax = Math.max(0, calculateBranchSum(node.right));

    // Option 1: The path peaks at this node (Left + Node + Right)
    // We update the global maximum if this local inverted "V" is the best we've seen
    const localPeakSum = node.value + leftBranchMax + rightBranchMax;
    globalMax = Math.max(globalMax, localPeakSum);

    // Option 2: The path must continue up to the parent
    // We can only pick ONE branch (left or right) to continue a valid path
    return node.value + Math.max(leftBranchMax, rightBranchMax);
  }

  calculateBranchSum(root);
  return globalMax;
}
```
**Walkthrough:** This is a hard FAANG problem because it requires returning one thing to the recursive caller, while tracking a completely different thing globally.
The recursive function `calculateBranchSum` answers the question: "What is the maximum straight-line path I can provide to my parent?" (Option 2).
However, *while* computing that, we pause and check Option 1: "What if the ultimate best path in the entire tree actually bridges across me, utilizing both my left and right children?" We calculate that `localPeakSum` and see if it beats our `globalMax`.
Crucially, `Math.max(0, ...)` saves us from negative nodes. If a child branch is a net negative, we essentially prune it by treating its value as 0.
</details>

# 3.3 Dependency Deadlocks (Topological Sort)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are building an NPM package manager (like `npm install`). Package A requires Package B to run. Package B requires Package C.
If you install them in the wrong order (A -> B -> C), the installation fails because A's dependencies don't exist yet! Furthermore, what if a malicious user makes Package C require Package A? This creates a **Cyclic Dependency** (an infinite loop).
You need an algorithm that can take a massive list of rules ("X must come before Y") and output a valid, linear execution order, while detecting deadlocks.

### 2. Plain English Metaphor (The What)
Imagine you are planning your college courses. You can't take Calculus 2 until you pass Calculus 1.
You write down every course and draw arrows pointing from prerequisites to the advanced classes.
To figure out your schedule, you first look for courses that have *zero arrows pointing at them* (no prerequisites). You take those first. When you finish one, you erase it from the board, along with all its arrows. Suddenly, new courses have zero arrows pointing at them! You repeat this until the board is empty. This is **Kahn's Algorithm for Topological Sort**.

### 3. Complete Runnable Code
```javascript
/**
 * Production Package Manager Build Dependency Resolver
 * Takes a number of packages and a list of [dependent, prerequisite] pairs.
 * Returns a valid installation order, or throws an error if a cycle exists.
 */
function resolveBuildDependencies(numPackages, prerequisites) {
  // 1. Build the Graph (Adjacency List) and In-Degree Array
  const graph = new Map();
  const inDegree = new Array(numPackages).fill(0);

  for (let i = 0; i < numPackages; i++) {
    graph.set(i, []);
  }

  // Populate graph and count incoming arrows (in-degrees)
  for (const [course, prereq] of prerequisites) {
    graph.get(prereq).push(course); // prereq -> course
    inDegree[course]++;             // course has one more prerequisite
  }

  // 2. Find all packages with NO prerequisites (In-Degree === 0)
  const queue = [];
  for (let i = 0; i < numPackages; i++) {
    if (inDegree[i] === 0) {
      queue.push(i);
    }
  }

  // 3. Process the Queue (Kahn's Algorithm - BFS)
  const buildOrder = [];

  while (queue.length > 0) {
    const currentPkg = queue.shift();
    buildOrder.push(currentPkg);

    // "Erase" the current package's arrows pointing to neighbors
    const dependents = graph.get(currentPkg);
    for (const dependent of dependents) {
      inDegree[dependent]--; // Arrow erased!

      // If a dependent now has 0 prerequisites, add it to the queue!
      if (inDegree[dependent] === 0) {
        queue.push(dependent);
      }
    }
  }

  // 4. Cycle Detection Check
  if (buildOrder.length !== numPackages) {
    throw new Error("Deadlock detected! Cyclic dependency found.");
  }

  return buildOrder;
}

// Example Execution
// Packages: 0, 1, 2, 3
// Rules: [1,0] means 1 requires 0.
const rules = [[1, 0], [2, 0], [3, 1], [3, 2]];
console.log(resolveBuildDependencies(4, rules));
// Output: [0, 1, 2, 3] (or [0, 2, 1, 3])
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Graph Representation and In-Degrees**
```javascript
  const graph = new Map();
  const inDegree = new Array(numPackages).fill(0);
```
*Rationale:* A Graph is just a network of nodes connected by edges. We use a Hash Map (`graph`) where `Key = Node`, `Value = [Array of Nodes it points to]` (Adjacency List). Crucially, we maintain an `inDegree` array to track exactly how many prerequisites every node currently has.

**Step 2: Bootstrapping the Queue**
```javascript
  for (let i = 0; i < numPackages; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }
```
*Rationale:* We must have a starting point. Any node with an `inDegree` of 0 has no dependencies. They are safe to execute immediately. We push them all into our execution queue.

**Step 3: Breadth-First Search (BFS) Resolution**
```javascript
    const currentPkg = queue.shift();
    buildOrder.push(currentPkg);

    for (const dependent of graph.get(currentPkg)) {
      inDegree[dependent]--;
      if (inDegree[dependent] === 0) queue.push(dependent);
    }
```
*Rationale:* We pop a node off the queue and "install" it. Because it's installed, we notify all nodes that depend on it that one of their prerequisites is fulfilled (`inDegree[dependent]--`). If any dependent node hits 0 prerequisites, it is now unlocked! We push it to the queue.

**Step 4: Cycle Detection**
```javascript
  if (buildOrder.length !== numPackages)
```
*Rationale:* If there is a cycle (A -> B -> A), A and B will start with an `inDegree` of 1. Because neither starts at 0, neither will ever enter the queue. The `while` loop will finish early, and our `buildOrder` will not contain all the packages. This perfectly detects deadlocks!

### 5. ASCII / Architecture Data Flow
```text
Graph:
0 -> [1, 2]
1 -> [3]
2 -> [3]
3 -> []

In-Degree Array: [0, 1, 1, 2]  (Node 0 has 0 prereqs, Node 3 has 2)

Step 1: Queue = [0]
Step 2: Pop 0. BuildOrder = [0].
        Neighbors of 0 are 1, 2. Decrement their in-degrees.
        In-Degree Array: [0, 0, 0, 2].
        Node 1 and 2 hit 0! Push to queue.
Step 3: Queue = [1, 2]
Step 4: Pop 1. BuildOrder = [0, 1].
        Neighbors of 1 is 3. Decrement in-degree.
        In-Degree Array: [0, 0, 0, 1].
Step 5: Queue = [2]
Step 6: Pop 2. BuildOrder = [0, 1, 2].
        Neighbors of 2 is 3. Decrement in-degree.
        In-Degree Array: [0, 0, 0, 0].
        Node 3 hit 0! Push to queue.
Step 7: Queue = [3]. Pop 3. BuildOrder = [0, 1, 2, 3]. Done.
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using an Adjacency Matrix (a 2D grid) instead of an Adjacency List for large graphs. If you have 10,000 packages, a Matrix creates a 10,000 x 10,000 grid (100 million cells). An Adjacency List only stores actual connections, saving massive amounts of memory.
**Pro Tip:** Topological Sort only works on **Directed Acyclic Graphs (DAGs)**. "Directed" meaning arrows have one direction. "Acyclic" meaning no loops. If you need to detect a cycle in a graph, Kahn's algorithm is often cleaner and easier to write than Depth-First Search (DFS) coloring.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** `Course Schedule Check`. Given `numCourses` and an array of `prerequisites`, simply return `true` if it is possible to finish all courses, or `false` if there is a cycle. You don't need to return the order.
<details>
<summary>👀 Hint</summary>
This is exactly the core concept code, just stripped down. Run Kahn's algorithm. Instead of building an array of the order, just keep a `count` variable. Increment it every time you pop from the queue. At the end, return `count === numCourses`.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function canFinish(numCourses, prerequisites) {
  const graph = new Map();
  const inDegree = new Array(numCourses).fill(0);

  for (let i = 0; i < numCourses; i++) graph.set(i, []);

  for (let [course, prereq] of prerequisites) {
    graph.get(prereq).push(course);
    inDegree[course]++;
  }

  const queue = [];
  for (let i = 0; i < numCourses; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  let count = 0;
  while (queue.length > 0) {
    const current = queue.shift();
    count++; // Course taken!

    for (let neighbor of graph.get(current)) {
      inDegree[neighbor]--;
      if (inDegree[neighbor] === 0) {
        queue.push(neighbor);
      }
    }
  }

  return count === numCourses;
}
```
**Walkthrough:** We don't care about the final schedule, just the boolean result. By tracking how many nodes we successfully processed through the queue, we can verify if the graph is a DAG (Directed Acyclic Graph). If `count` falls short of `numCourses`, some nodes were trapped in a cycle and never reached an in-degree of 0.
</details>

### Level 2: Real-World
**Task:** `Alien Dictionary`. You receive a sorted dictionary of an alien language (e.g., `["wrt","wrf","er","ett","rftt"]`). The letters are in an unknown order. You must return a string representing the correct alphabetical order of the alien letters.
<details>
<summary>👀 Hint</summary>
Compare adjacent words to find the FIRST differing letter. (e.g., "wrt" before "wrf" means 't' comes before 'f'. This is a directed edge `t -> f`). Build a graph from these rules, then run a Topological Sort!
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function alienOrder(words) {
  const graph = new Map();
  const inDegree = new Map();

  // Initialize graph for all unique characters
  for (let word of words) {
    for (let char of word) {
      if (!graph.has(char)) {
        graph.set(char, new Set());
        inDegree.set(char, 0);
      }
    }
  }

  // Build the graph by comparing adjacent words
  for (let i = 0; i < words.length - 1; i++) {
    const word1 = words[i];
    const word2 = words[i + 1];

    // Edge case: "abc" before "ab" is invalid sorting
    if (word1.length > word2.length && word1.startsWith(word2)) return "";

    // Find the first differing character
    for (let j = 0; j < Math.min(word1.length, word2.length); j++) {
      if (word1[j] !== word2[j]) {
        const u = word1[j];
        const v = word2[j];
        // If we haven't recorded this exact rule yet
        if (!graph.get(u).has(v)) {
          graph.get(u).add(v);
          inDegree.set(v, inDegree.get(v) + 1);
        }
        break; // Only the first difference matters!
      }
    }
  }

  // Kahn's Algorithm
  const queue = [];
  for (let [char, degree] of inDegree.entries()) {
    if (degree === 0) queue.push(char);
  }

  let result = "";
  while (queue.length > 0) {
    const char = queue.shift();
    result += char;

    for (let neighbor of graph.get(char)) {
      inDegree.set(neighbor, inDegree.get(neighbor) - 1);
      if (inDegree.get(neighbor) === 0) queue.push(neighbor);
    }
  }

  // Cycle check
  return result.length === inDegree.size ? result : "";
}
```
**Walkthrough:** This is a fantastic mapping of a string problem into a graph problem. We extract dependency rules by realizing that in a sorted dictionary, the *first* mismatch between two adjacent words dictates the alphabetical order of those two specific characters. Once we extract all `char1 -> char2` edges, it just becomes standard Topological Sort.
</details>

### Level 3: Boss Level
**Task:** `Parallel Task DAG Executor`. You are given `numTasks` and `prerequisites`. Additionally, you are given an array `time` where `time[i]` is the integer time it takes to complete task `i`.
Multiple tasks can run in parallel if their prerequisites are met. Return the *minimum total time* required to complete all tasks.
<details>
<summary>👀 Hint</summary>
This is Kahn's algorithm combined with Dynamic Programming! Maintain an array `maxTime` where `maxTime[i]` stores the earliest time task `i` can finish.
When task `u` completes and unlocks neighbor `v`, update `maxTime[v] = Math.max(maxTime[v], maxTime[u] + time[v])`.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function minimumTime(numTasks, prerequisites, time) {
  const graph = new Map();
  const inDegree = new Array(numTasks).fill(0);

  // Array to track the absolute finish time of every task
  const maxTime = new Array(numTasks).fill(0);

  for (let i = 0; i < numTasks; i++) graph.set(i, []);

  for (let [task, prereq] of prerequisites) {
    // Note: Adjusting for 1-indexed tasks if problem states so.
    // Assuming 0-indexed for this code.
    graph.get(prereq).push(task);
    inDegree[task]++;
  }

  const queue = [];
  for (let i = 0; i < numTasks; i++) {
    if (inDegree[i] === 0) {
      queue.push(i);
      maxTime[i] = time[i]; // Base tasks finish in their own time
    }
  }

  while (queue.length > 0) {
    const current = queue.shift();

    for (let neighbor of graph.get(current)) {
      // The neighbor cannot finish until THIS prerequisite finishes
      // AND it takes its own time to run.
      // We must wait for the LONGEST prerequisite to finish (Math.max)
      maxTime[neighbor] = Math.max(maxTime[neighbor], maxTime[current] + time[neighbor]);

      inDegree[neighbor]--;
      if (inDegree[neighbor] === 0) {
        queue.push(neighbor);
      }
    }
  }

  // The total time is the time of the task that finishes dead last
  return Math.max(...maxTime);
}
```
**Walkthrough:** Standard Topological Sort gives us the execution order, but it doesn't handle time. Because tasks run in parallel, a task cannot start until its *slowest* prerequisite finishes.
When we traverse edge `A -> B`, we say "B finishes at either its current known finish time, OR A's finish time plus B's duration, whichever is longer". By the time `inDegree[B]` hits 0, it has been compared against all its prerequisites, and `maxTime[B]` securely holds the exact millisecond B will complete. We return the maximum value in the `maxTime` array.
</details>

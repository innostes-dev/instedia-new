# 3.1 The Log(N) Search (Binary Search Trees)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are building an indexing engine for a NoSQL database. Users frequently run "Range Queries" (e.g., `SELECT * WHERE age BETWEEN 25 AND 35`).
If you use an Array, you must scan millions of rows to find every matching age (O(N)). If you use a Hash Table, it is useless for ranges! A Hash Table can instantly tell you if `age == 25` exists, but it has zero concept of "greater than" or "less than." You need a data structure that maintains ordered relationships while allowing extremely fast lookups.

### 2. Plain English Metaphor (The What)
Imagine playing a guessing game where I am thinking of a number between 1 and 100.
If you guess 1, 2, 3... it could take 100 guesses (Linear Array Search).
Instead, you guess 50. I say "Higher". You instantly eliminate 1 through 50! Your next guess is 75. I say "Lower". You just eliminated 75-100.
By dividing the search space in half with every step, you can find any number out of 100 in just 7 guesses, or out of 1,000,000 in just 20 guesses. This partitioning strategy is a **Binary Search**, and when structured into memory objects, it forms a **Binary Search Tree (BST)**.

### 3. Complete Runnable Code
```javascript
/**
 * Range-Query Database Index Engine
 * A Binary Search Tree implementation to store and retrieve sequential data.
 */
class TreeNode {
  constructor(value) {
    this.value = value;
    this.left = null;  // Strictly smaller values
    this.right = null; // Strictly larger values
  }
}

class BSTIndex {
  constructor() {
    this.root = null;
  }

  // O(log N) Insertion
  insert(value) {
    const newNode = new TreeNode(value);

    if (this.root === null) {
      this.root = newNode;
      return;
    }

    let current = this.root;
    while (true) {
      if (value < current.value) {
        // Go Left
        if (current.left === null) {
          current.left = newNode;
          return;
        }
        current = current.left;
      } else {
        // Go Right
        if (current.right === null) {
          current.right = newNode;
          return;
        }
        current = current.right;
      }
    }
  }

  // O(log N) Search
  exists(target) {
    let current = this.root;

    while (current !== null) {
      if (target === current.value) return true;

      if (target < current.value) {
        current = current.left; // Discard right half
      } else {
        current = current.right; // Discard left half
      }
    }

    return false;
  }
}

// Example Execution
const dbIndex = new BSTIndex();
dbIndex.insert(50);
dbIndex.insert(25);
dbIndex.insert(75);
dbIndex.insert(10);
console.log(dbIndex.exists(75)); // Output: true
console.log(dbIndex.exists(99)); // Output: false
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Node Definition (The Invariant)**
```javascript
class TreeNode {
  constructor(value) {
    this.value = value;
    this.left = null;
    this.right = null;
  }
}
```
*Rationale:* A tree node holds a value and up to two children. The fundamental mathematical invariant of a BST is: *Everything* in the left subtree must be smaller than the node, and *everything* in the right subtree must be larger.

**Step 2: Tree Navigation (Traversal)**
```javascript
    let current = this.root;
    while (current !== null) {
      if (target === current.value) return true;
```
*Rationale:* We start at the top of the tree (`root`). If the root is our target, we are done.

**Step 3: The Log(N) Discard**
```javascript
      if (target < current.value) {
        current = current.left;
      } else {
        current = current.right;
      }
```
*Rationale:* If the target is smaller than the current node, we know with 100% certainty that it cannot be in the right branch. We set `current = current.left`. In that single line of code, we just deleted half of the remaining database from our search space! This halving behavior gives us **O(log N)** time complexity.

### 5. ASCII / Architecture Data Flow
```text
Insertions: 50, 25, 75, 10, 30, 60, 90

Tree Structure:
       50
     /    \
   25      75
  /  \    /  \
 10  30  60  90

Search Target: 30
1. current = 50. Target(30) < 50. Go Left.
   (Discarded 75, 60, 90 instantly)
2. current = 25. Target(30) > 25. Go Right.
   (Discarded 10 instantly)
3. current = 30. Target(30) == 30. Return TRUE.
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Assuming a BST is *always* O(log N). If you insert sorted data into a basic BST (e.g., 10, 20, 30, 40), it just builds a straight line to the right. It becomes a Linked List! Lookups collapse back to O(N).
**Pro Tip:** Production databases never use a basic BST. They use **Balanced Trees** (like AVL Trees, Red-Black Trees, or B-Trees). These data structures automatically detect if one side is getting too heavy and perform "rotations" to guarantee the tree remains shallow, enforcing a strict O(log N) height constraint.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Given the root of a binary tree, write a function that performs an **In-Order Traversal** and returns an array of the node values.
<details>
<summary>👀 Hint</summary>
Recursion is your best friend with trees. For In-Order traversal, the pattern is: 1) Recursively visit Left child. 2) Visit Current Node (push to array). 3) Recursively visit Right child. In a BST, this guarantees a perfectly sorted array output!
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function inorderTraversal(root) {
  const result = [];

  function traverse(node) {
    if (node === null) return;

    traverse(node.left);    // 1. Dig as far left as possible
    result.push(node.value); // 2. Record the value
    traverse(node.right);   // 3. Dig right
  }

  traverse(root);
  return result;
}
```
**Walkthrough:** Tree problems heavily rely on recursion because trees are recursive by nature (a subtree is just another tree). By visiting the left child *before* recording the current value, and the right child *after*, we ensure that smaller numbers are always processed before larger numbers.
</details>

### Level 2: Real-World
**Task:** Build a `Valid BST Verifier`. Given the root of a binary tree, determine if it is a valid Binary Search Tree.
<details>
<summary>👀 Hint</summary>
A common mistake is just checking if `left < current < right`. This is false! A right child's *left* child might be smaller than the root, which violates the BST rule. You must pass down a `min` and `max` boundary for every node as you traverse.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function isValidBST(root) {

  function validate(node, min, max) {
    // An empty node doesn't violate rules
    if (node === null) return true;

    // The node MUST be between the known boundaries
    if ((min !== null && node.value <= min) || (max !== null && node.value >= max)) {
      return false;
    }

    // When going left, the current node's value becomes the new MAX ceiling
    // When going right, the current node's value becomes the new MIN floor
    return validate(node.left, min, node.value) &&
           validate(node.right, node.value, max);
  }

  // Start with no boundaries
  return validate(root, null, null);
}
```
**Walkthrough:** As we traverse down the tree, the constraints get tighter. If the root is `50`, and we move to the right child, we know that *every single node* in this entire right subtree MUST be greater than `50`. We pass `50` down as the `min` parameter. If we ever find a node that breaks these inherited boundaries, the entire tree is invalid.
</details>

### Level 3: Boss Level
**Task:** Build the `Range Query Executor`. Given the root of a BST and two integers `low` and `high`, return the sum of values of all nodes with a value in the inclusive range `[low, high]`. Optimize it to not visit unnecessary branches.
<details>
<summary>👀 Hint</summary>
Do a recursive traversal, but use the BST properties to prune branches. If a node's value is less than `low`, there is absolutely no reason to search its left children. If it's greater than `high`, don't search its right children.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function rangeSumBST(root, low, high) {
  let sum = 0;

  function traverse(node) {
    if (node === null) return;

    // If node is within range, add to sum
    if (node.value >= low && node.value <= high) {
      sum += node.value;
    }

    // Optimization: Only traverse left if there could be valid values there
    // i.e., current value is greater than the low boundary
    if (node.value > low) {
      traverse(node.left);
    }

    // Optimization: Only traverse right if there could be valid values there
    // i.e., current value is less than the high boundary
    if (node.value < high) {
      traverse(node.right);
    }
  }

  traverse(root);
  return sum;
}
```
**Walkthrough:** This is exactly why databases use BSTs for range queries. We do a standard traversal, but we conditionally prune branches. If `low = 25` and our current node is `20`, we know that going to the left child will only give us numbers smaller than `20`, which are useless. So we skip the entire left subtree and only traverse right. This pruning drastically reduces the number of operations compared to scanning an array.
</details>

# 3.4 Shortest Path Routing (Dijkstra & BFS)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are building the dispatch engine for a food delivery app. A driver at Node A needs to reach the customer at Node Z. The city is a graph of intersections (nodes) and roads (edges).
If you just use Depth-First Search (DFS) to find a path, the algorithm might take the driver down a massive, spiraling detour just because it blindly followed the first road it saw.
You need an algorithm guaranteed to find the *absolute shortest* path. If all roads take the exact same time (unweighted), you use **Breadth-First Search (BFS)**. If roads have different traffic delays (weighted), you use **Dijkstra's Algorithm**.

### 2. Plain English Metaphor (The What)
Imagine you are at the center of a maze and you drop a stone into a puddle of water.
The ripple expands outward evenly in a perfect circle. It hits all locations 1 meter away at the exact same time. Then it hits all locations 2 meters away.
The very first time the water touches the exit of the maze, you know *for a fact* that it took the shortest possible route to get there, because the water expanded equally in all directions. This expanding ripple is exactly how **Breadth-First Search (BFS)** operates on an unweighted graph.

### 3. Complete Runnable Code
```javascript
/**
 * Real-Time City Dispatch & Shortest Delivery Route Navigator (Unweighted)
 * Finds the shortest path in terms of number of intersections using BFS.
 */
function findShortestDeliveryRoute(graph, startNode, endNode) {
  // A Queue handles the "ripple effect" (First In, First Out)
  const queue = [startNode];

  // Keep track of visited intersections to avoid infinite loops
  const visited = new Set();
  visited.add(startNode);

  let intersectionsCrossed = 0;

  while (queue.length > 0) {
    // How many intersections are currently on the outer edge of our ripple?
    const rippleSize = queue.length;

    // Process the entire outer edge before moving outward again
    for (let i = 0; i < rippleSize; i++) {
      const currentIntersection = queue.shift();

      if (currentIntersection === endNode) {
        return intersectionsCrossed; // Target found!
      }

      // Expand the ripple to adjacent intersections
      for (const neighbor of graph[currentIntersection]) {
        if (!visited.has(neighbor)) {
          visited.add(neighbor);
          queue.push(neighbor);
        }
      }
    }

    // The ripple expands one layer deeper
    intersectionsCrossed++;
  }

  return -1; // Target unreachable
}

// Example Execution
// Graph represented as an Adjacency List
const cityMap = {
  'A': ['B', 'C'],
  'B': ['A', 'D', 'E'],
  'C': ['A', 'F'],
  'D': ['B'],
  'E': ['B', 'F'], // E connects to F!
  'F': ['C', 'E']
};

console.log(findShortestDeliveryRoute(cityMap, 'A', 'F'));
// Output: 2 (Path: A -> C -> F)
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Queue and Visited Set**
```javascript
  const queue = [startNode];
  const visited = new Set();
  visited.add(startNode);
```
*Rationale:* BFS strictly requires a First-In-First-Out (FIFO) Queue to maintain the ripple. We process nodes in the exact order they were discovered. The `visited` set prevents us from walking back and forth between A and B infinitely.

**Step 2: Processing the Ripple (Level by Level)**
```javascript
    const rippleSize = queue.length;
    for (let i = 0; i < rippleSize; i++) {
      const currentIntersection = queue.shift();
```
*Rationale:* By capturing `queue.length` before the loop starts, we isolate the current "layer" of the search. We empty all nodes in this layer, while simultaneously pushing the *next* layer's nodes onto the back of the queue.

**Step 3: State Expansion**
```javascript
      for (const neighbor of graph[currentIntersection]) {
        if (!visited.has(neighbor)) {
          visited.add(neighbor);
          queue.push(neighbor);
        }
      }
```
*Rationale:* For every valid neighbor we find, we immediately mark it as visited and add it to the queue to be processed in the next ripple. Because we process level by level, the very first time we `shift()` our target node from the queue, we have mathematically proven it is the shortest path.

### 5. ASCII / Architecture Data Flow
```text
Target: F

Level 0: Queue=[A]
Pop A. Neighbors: B, C.
Visited: A, B, C.
Next Queue=[B, C]

Level 1 (Distance 1): Queue=[B, C]
Pop B. Neighbors: A(visited), D, E.
Next Queue=[C, D, E]
Pop C. Neighbors: A(visited), F!
Target F found! We are at Level 1, expanding to Level 2.
Return distance 2 (A->C->F).
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using DFS (recursion or a Stack) to find the shortest path. DFS dives deep down a single path until it hits a dead end, completely missing the shorter path right next to the start node. Only use DFS if you need to visit *every* node or find *any* path, not the *shortest* path.
**Pro Tip:** If the graph has weights (e.g., Road A takes 5 mins, Road B takes 20 mins), BFS fails. You must upgrade to **Dijkstra's Algorithm**, which replaces the standard Queue with a **Min-Priority Queue (Min-Heap)**. Instead of processing nodes level-by-level, Dijkstra always processes the node with the lowest total travel time first.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** `Rotting Oranges`. You have a grid where `0` is empty, `1` is a fresh orange, and `2` is a rotten orange. Every minute, any fresh orange adjacent (4-directionally) to a rotten orange becomes rotten. Return the minimum minutes until no cell has a fresh orange (or -1 if impossible).
<details>
<summary>👀 Hint</summary>
This is a Multi-Source BFS. Instead of starting the queue with just one node, scan the grid and push the coordinates of *all* rotten oranges into the queue at Level 0. Then, run BFS level by level.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function orangesRotting(grid) {
  const queue = [];
  let freshCount = 0;
  const rows = grid.length;
  const cols = grid[0].length;

  // Step 1: Multi-source setup
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === 2) queue.push([r, c]);
      if (grid[r][c] === 1) freshCount++;
    }
  }

  if (freshCount === 0) return 0; // Already done!

  let minutes = 0;
  const directions = [[1, 0], [-1, 0], [0, 1], [0, -1]];

  // Step 2: Level-by-level BFS
  while (queue.length > 0 && freshCount > 0) {
    const size = queue.length;

    for (let i = 0; i < size; i++) {
      const [r, c] = queue.shift();

      for (let [dr, dc] of directions) {
        const nr = r + dr;
        const nc = c + dc;

        // If it's a valid fresh orange
        if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] === 1) {
          grid[nr][nc] = 2; // Make it rotten
          freshCount--;
          queue.push([nr, nc]);
        }
      }
    }
    minutes++; // One minute passes per ripple
  }

  return freshCount === 0 ? minutes : -1;
}
```
**Walkthrough:** We initialize the queue with all originally rotten oranges. We also count how many fresh oranges exist. As the BFS "ripple of rot" expands outwards, we decrement the `freshCount`. If the BFS finishes but `freshCount` is still > 0, it means some oranges were isolated behind empty cells and can never rot (return -1).
</details>

### Level 2: Real-World
**Task:** `Word Ladder`. Given two words (`beginWord` and `endWord`), and a `wordList`, find the length of the shortest transformation sequence from `begin` to `end`. Only one letter can be changed at a time, and every intermediate word must exist in the `wordList`.
<details>
<summary>👀 Hint</summary>
This is an unweighted shortest-path problem! The nodes are strings. An edge exists between two words if they differ by exactly one character. Use BFS. To find neighbors efficiently, change each character of the current word from 'a' to 'z' and check if the resulting word is in a `Set` created from `wordList`.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function ladderLength(beginWord, endWord, wordList) {
  const wordSet = new Set(wordList);
  if (!wordSet.has(endWord)) return 0;

  const queue = [beginWord];
  let level = 1; // Count includes the beginWord

  while (queue.length > 0) {
    const size = queue.length;

    for (let i = 0; i < size; i++) {
      const currentWord = queue.shift();
      if (currentWord === endWord) return level;

      // Find all valid neighbors
      for (let j = 0; j < currentWord.length; j++) {
        for (let charCode = 97; charCode <= 122; charCode++) { // 'a' to 'z'
          const newChar = String.fromCharCode(charCode);

          if (newChar === currentWord[j]) continue; // Skip identical

          const newWord = currentWord.slice(0, j) + newChar + currentWord.slice(j + 1);

          if (wordSet.has(newWord)) {
            queue.push(newWord);
            wordSet.delete(newWord); // Mark as visited to prevent cycles
          }
        }
      }
    }
    level++;
  }

  return 0; // Target unreachable
}
```
**Walkthrough:** We treat the dictionary as an implicit graph. The BFS ripple expands by trying all possible single-character mutations of the current word. If a mutation exists in our dictionary `Set`, it's a valid path! We immediately delete it from the Set (which serves as our `visited` tracker) and add it to the queue.
</details>

### Level 3: Boss Level
**Task:** `Network Delay Time`. You are given a network of `n` nodes, labeled from `1` to `n`. You are also given `times`, a list of travel times as directed edges `times[i] = (source, target, time)`.
We send a signal from a certain node `k`. Return the minimum time it takes for all `n` nodes to receive the signal. If it is impossible for all nodes to receive the signal, return `-1`.
<details>
<summary>👀 Hint</summary>
This graph is WEIGHTED (the travel times vary). BFS will not work. You MUST use **Dijkstra's Algorithm**.
Use a Min-Priority Queue to always process the node with the absolute lowest current time elapsed.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
// NOTE: JavaScript doesn't have a built-in Priority Queue.
// In an interview, you can often assume a MinPriorityQueue class exists.
// For completion, here is a simplified conceptual implementation using an array.
// In production, ALWAYS use a real Binary Heap for the Queue to get O(log V) popping.

function networkDelayTime(times, n, k) {
  // 1. Build Adjacency List: { source: [ [target, weight], ... ] }
  const graph = new Map();
  for (let i = 1; i <= n; i++) graph.set(i, []);

  for (const [u, v, w] of times) {
    graph.get(u).push([v, w]);
  }

  // 2. Track the minimum time to reach each node
  const minTimes = new Map();

  // 3. Min-Priority Queue: stores [node, time_from_start]
  // Sorted by time_from_start (lowest first)
  const pq = [[k, 0]];

  while (pq.length > 0) {
    // (In a real Heap, this is O(log N). With array sort, it's O(N log N))
    pq.sort((a, b) => a[1] - b[1]);
    const [currentNode, timeElapsed] = pq.shift();

    // If we've already found a faster way to this node, skip it
    if (minTimes.has(currentNode)) continue;

    // We found the absolute shortest path to this node! Lock it in.
    minTimes.set(currentNode, timeElapsed);

    // Expand to neighbors
    for (const [neighbor, travelTime] of graph.get(currentNode)) {
      if (!minTimes.has(neighbor)) {
        pq.push([neighbor, timeElapsed + travelTime]);
      }
    }
  }

  // 4. Check if all nodes were reached
  if (minTimes.size !== n) return -1;

  // 5. The total time is dictated by the last node to receive the signal
  let maxTime = 0;
  for (const time of minTimes.values()) {
    maxTime = Math.max(maxTime, time);
  }

  return maxTime;
}
```
**Walkthrough:** This is Dijkstra's Algorithm in action. Instead of a standard FIFO queue, we use a Min-Priority Queue.
When we sit at Node A, and see a path to B (weight 10) and C (weight 2), we put both in the PQ. The PQ *guarantees* that C will be processed first. By the time we actually pop a node out of the PQ and lock it into our `minTimes` map, it is mathematically impossible to find a shorter path to it later (assuming no negative weights). The signal finishes when the very last node receives it, which is the maximum value in our `minTimes` map.
</details>

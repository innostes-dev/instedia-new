# 1.3 Instant Lookups & Hash Tables

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
Imagine an e-commerce platform where users submit thousands of promo codes per second. You have an array of 5 million valid promo codes.
If a user submits "SUMMER50", checking if it exists in an array requires scanning every item one by one (Linear Scan, **O(N)**). At 5 million items and 10,000 requests per second, your database will completely lock up doing simple existence checks.

### 2. Plain English Metaphor (The What)
Searching an array is like looking for a specific book in a library by reading the spine of every single book starting from the front door.
A Hash Table (or Hash Map / Dictionary) is like asking the librarian, "Where is the book titled 'SUMMER50'?" The librarian instantly gives you the exact aisle and shelf number. You walk directly to it. This is **O(1)** (constant time) lookup.

### 3. Complete Runnable Code
```javascript
/**
 * Live E-Commerce Inventory Lookup & Deduplication Cache
 * Checks for duplicate product IDs in real-time.
 */
function containsDuplicateInventory(productIds) {
  // Initialize our Hash Table (in JS, a Set or Map is commonly used)
  const seenProducts = new Set();

  for (let i = 0; i < productIds.length; i++) {
    const currentProduct = productIds[i];

    // O(1) Instant Lookup
    if (seenProducts.has(currentProduct)) {
      return true; // We found a duplicate!
    }

    // Add to Hash Table for future O(1) lookups
    seenProducts.add(currentProduct);
  }

  return false; // No duplicates found
}

// Example Execution
const incomingBatch = ["prod_1A", "prod_9B", "prod_4C", "prod_9B"];
console.log(containsDuplicateInventory(incomingBatch)); // Output: true
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Initialize the Data Structure**
```javascript
  const seenProducts = new Set();
```
*Rationale:* Arrays are for ordered data you want to iterate over. Sets and Maps are for unordered data where you need instant lookups. We use a Set here because we only care about *existence*, not associating a value with a key.

**Step 2: The Linear Pass**
```javascript
  for (let i = 0; i < productIds.length; i++) {
    const currentProduct = productIds[i];
```
*Rationale:* We still have to look at every item in the input array at least once. This makes the overall algorithm O(N) time. The magic happens inside the loop.

**Step 3: The O(1) Check and State Update**
```javascript
    if (seenProducts.has(currentProduct)) {
      return true;
    }
    seenProducts.add(currentProduct);
```
*Rationale:* Instead of a nested loop checking `currentProduct` against the rest of the array (which would be O(N^2)), we ask the Set: "Have you seen this before?" The Set answers instantly in O(1) time. If no, we add it to the Set memory so future iterations know about it.

### 5. ASCII / Architecture Data Flow
```text
Batch: ["prod_1A", "prod_9B", "prod_4C", "prod_9B"]

Iteration 1: "prod_1A"
Set: {}
Check: has("prod_1A")? -> False
Action: add("prod_1A")

Iteration 2: "prod_9B"
Set: {"prod_1A"}
Check: has("prod_9B")? -> False
Action: add("prod_9B")

Iteration 3: "prod_4C"
Set: {"prod_1A", "prod_9B"}
Check: has("prod_4C")? -> False
Action: add("prod_4C")

Iteration 4: "prod_9B"
Set: {"prod_1A", "prod_9B", "prod_4C"}
Check: has("prod_9B")? -> TRUE! Return true instantly.
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using JavaScript arrays and the `.includes()` or `.indexOf()` methods inside a `for` loop. `.includes()` is just a hidden loop! It is O(N). Doing an O(N) check inside an O(N) loop results in an O(N^2) algorithm.
**Pro Tip:** Under the hood, Hash Tables work by taking the key (e.g., "prod_1A"), running it through a math function (a hash function) to generate a number, and using that number as an array index. This is why lookups are instant! Be aware of *Hash Collisions* (when two keys generate the same number), which most modern languages resolve automatically under the hood via chaining or probing.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Given a string of text, find the first non-repeating character and return its index. If it doesn't exist, return -1.
<details>
<summary>👀 Hint</summary>
Use a Hash Map to count the frequencies of every character in pass 1. In pass 2, iterate through the string again and check the Map. The first character with a count of 1 is your answer.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function firstUniqueChar(text) {
  const charCounts = new Map();

  // Pass 1: Build the frequency map
  for (let i = 0; i < text.length; i++) {
    const char = text[i];
    charCounts.set(char, (charCounts.get(char) || 0) + 1);
  }

  // Pass 2: Find the first char with frequency 1
  for (let i = 0; i < text.length; i++) {
    if (charCounts.get(text[i]) === 1) {
      return i;
    }
  }

  return -1;
}
```
**Walkthrough:** We trade space for time. We use extra memory (a Map) to store the count of every character. This takes O(N) time. We then loop through the string again, looking up each character's count in O(1) time. The first one we hit with a count of `1` is our guaranteed first unique character.
</details>

### Level 2: Real-World
**Task:** The classic Two Sum, reimagined. You are given an array of user balances and a target `cartTotal`. Find if there are two balances that sum exactly to the target, returning their indices. Unlike 1.1, **the array is NOT sorted**.
<details>
<summary>👀 Hint</summary>
As you iterate through the array, calculate the `complement` needed (target - currentBalance). Check if that complement already exists in your Hash Map. If not, store the current balance and its index in the Map.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function twoSumUnsorted(balances, cartTotal) {
  // Map stores { balanceValue: index }
  const balanceMap = new Map();

  for (let i = 0; i < balances.length; i++) {
    const currentBalance = balances[i];
    const complement = cartTotal - currentBalance;

    // Do we have the missing piece in our past?
    if (balanceMap.has(complement)) {
      return [balanceMap.get(complement), i];
    }

    // Store current state for future iterations
    balanceMap.set(currentBalance, i);
  }

  return [];
}
```
**Walkthrough:** This is the most famous algorithm pattern in the world. Instead of sorting the array and using two pointers (O(N log N)), we use extra memory. At each step, we figure out exactly what number we *need* to hit the target. We look in our Map to see if we've seen it before. Because Map lookups are O(1), the entire algorithm runs in a blazing fast O(N) time.
</details>

### Level 3: Boss Level
**Task:** Build an `Anagram Grouping Engine`. Given an array of strings, group the anagrams together. (e.g., "eat", "tea", "ate" are grouped together).
<details>
<summary>👀 Hint</summary>
How do you know if two words are anagrams? If you sort the characters in the string, they will end up exactly the same ("eat" -> "aet", "tea" -> "aet"). Use this sorted string as the Key in a Hash Map, and store an array of the original strings as the Value.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function groupAnagrams(words) {
  const anagramGroups = new Map();

  for (let i = 0; i < words.length; i++) {
    const originalWord = words[i];

    // Sort the string to create a universal identifier
    const sortedKey = originalWord.split('').sort().join('');

    // If key doesn't exist, create a new array
    if (!anagramGroups.has(sortedKey)) {
      anagramGroups.set(sortedKey, []);
    }

    // Push the original word into its anagram family bucket
    anagramGroups.get(sortedKey).push(originalWord);
  }

  // Return just the grouped arrays
  return Array.from(anagramGroups.values());
}
```
**Walkthrough:** We need a common identifier for anagrams. Sorting the characters of a string provides a perfect, standardized key. We use a Hash Map where the Key is this sorted string (e.g., "aet") and the Value is an array containing all words that match that signature (e.g., `["eat", "tea", "ate"]`). We iterate through the input, process each word, and drop it into its respective bucket in the Map.
</details>

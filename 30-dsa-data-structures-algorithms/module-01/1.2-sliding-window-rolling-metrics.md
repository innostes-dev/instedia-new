# 1.2 Sliding Window & Rolling Metrics

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are monitoring a high-traffic API server. You need to calculate the total number of requests in the last 60 seconds, updated every single second.
If you recalculate the sum of the last 60 seconds from scratch every second, you are doing 60 additions per second. Now imagine a rolling window of 1 hour (3600 seconds), calculated per millisecond. You are performing 3.6 million redundant additions every second. This overlapping work will instantly crash your telemetry systems.

### 2. Plain English Metaphor (The What)
Imagine you are looking at a long train through a narrow window in a fence. The window is exactly wide enough to see 3 train cars.
When the train moves forward by one car, you don't need to count all 3 cars again. You know that one car disappeared from the left side of your view, and one new car appeared on the right.
To get the new total weight of the cars in view, you just take your previous total, subtract the weight of the car that left, and add the weight of the new car. This is the **Sliding Window** technique.

### 3. Complete Runnable Code
```javascript
/**
 * Real-Time Rolling Revenue & Traffic Spike Detector
 * Finds the maximum revenue generated in any continuous 'k' minute window.
 */
function findMaxRollingRevenue(revenueStream, windowSizeK) {
  if (revenueStream.length < windowSizeK) return null;

  let currentWindowRevenue = 0;
  let maxRevenue = 0;

  // 1. Establish the initial window
  for (let i = 0; i < windowSizeK; i++) {
    currentWindowRevenue += revenueStream[i];
  }
  maxRevenue = currentWindowRevenue;

  // 2. Slide the window
  for (let i = windowSizeK; i < revenueStream.length; i++) {
    // Add the incoming element (right side)
    // Subtract the outgoing element (left side)
    currentWindowRevenue = currentWindowRevenue + revenueStream[i] - revenueStream[i - windowSizeK];

    // Update maximum if the new window is larger
    maxRevenue = Math.max(maxRevenue, currentWindowRevenue);
  }

  return maxRevenue;
}

// Example Execution: Revenue per minute
const stream = [100, 200, 300, 400, 100, 50, 600, 100];
const windowSize = 3;
console.log(findMaxRollingRevenue(stream, windowSize)); // Output: 900 (from [300, 400, 100] or [400, 100, 50]? No, wait. [100,50,600] = 750. [300,400,100] = 800.)
// Wait, manual check: [200,300,400] = 900.
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Bootstrap the First Window**
```javascript
  for (let i = 0; i < windowSizeK; i++) {
    currentWindowRevenue += revenueStream[i];
  }
  maxRevenue = currentWindowRevenue;
```
*Rationale:* Before we can slide a window, we need a window to slide. We manually calculate the sum of the very first `k` elements to establish our baseline `currentWindowRevenue`.

**Step 2: Start the Slide**
```javascript
  for (let i = windowSizeK; i < revenueStream.length; i++) {
```
*Rationale:* We start our loop exactly where the initial window ended (at index `windowSizeK`). This pointer represents the *new* element entering the right side of our window.

**Step 3: The O(1) State Update**
```javascript
    currentWindowRevenue = currentWindowRevenue + revenueStream[i] - revenueStream[i - windowSizeK];
    maxRevenue = Math.max(maxRevenue, currentWindowRevenue);
```
*Rationale:* This is the magic. Instead of a nested loop recalculating everything, we take the old sum, add the new element `revenueStream[i]`, and subtract the element that fell out the back `revenueStream[i - windowSizeK]`. We update the state in exactly **O(1) time** per step, regardless of how massive `windowSizeK` is.

### 5. ASCII / Architecture Data Flow
```text
Stream: [100, 200, 300, 400, 100]
Window (K=3)

Initial Window (Sum = 600)
[100, 200, 300], 400, 100

Slide Right by 1:
Out: 100 (Left index: 3 - 3 = 0)
In:  400 (Right index: 3)
New Sum = 600 - 100 + 400 = 900
100, [200, 300, 400], 100

Slide Right by 1:
Out: 200
In:  100
New Sum = 900 - 200 + 100 = 800
100, 200, [300, 400, 100]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `array.slice(i, i+k).reduce((a,b)=>a+b)` inside a loop. This creates a brand new array and iterates through it every single time, destroying the O(1) performance benefit of a sliding window.
**Pro Tip:** Sliding windows can be **Fixed** (like above, size K is constant) or **Dynamic** (the window expands and contracts based on a condition, like "expand while sum < X, shrink when sum > X").

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Given an array of daily login counts, find the average number of logins in a continuous `K` day period. Return the maximum average found.
<details>
<summary>👀 Hint</summary>
This is exactly the fixed sliding window pattern. Calculate the max sum for size K, and at the end, just divide the max sum by K.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function findMaxAverageLogins(logins, k) {
  let currentSum = 0;

  for (let i = 0; i < k; i++) {
    currentSum += logins[i];
  }

  let maxSum = currentSum;

  for (let i = k; i < logins.length; i++) {
    currentSum = currentSum + logins[i] - logins[i - k];
    maxSum = Math.max(maxSum, currentSum);
  }

  return maxSum / k;
}
```
**Walkthrough:** We build the first window of size `k`. We then iterate through the rest of the array, updating the sum by adding the new element and dropping the oldest element. Finally, we divide the largest sum we encountered by `k`.
</details>

### Level 2: Real-World
**Task:** Build an `API Rate Limiter Analyzer` (Dynamic Window). Given an array of positive integers representing request sizes, find the minimal length of a contiguous subarray where the sum of request sizes is greater than or equal to a target payload size.
<details>
<summary>👀 Hint</summary>
Use two pointers (`left` and `right`) to form a dynamic window. Expand the `right` pointer to add elements. Once your sum is >= target, record the window size, then shrink the window by moving the `left` pointer to see if you can find a smaller valid window.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function minWindowForPayload(requestSizes, targetPayload) {
  let minLength = Infinity;
  let windowSum = 0;
  let left = 0;

  for (let right = 0; right < requestSizes.length; right++) {
    windowSum += requestSizes[right]; // Expand the window

    // While the window is valid, try to shrink it
    while (windowSum >= targetPayload) {
      minLength = Math.min(minLength, right - left + 1);
      windowSum -= requestSizes[left]; // Remove left element
      left++; // Shrink the window
    }
  }

  return minLength === Infinity ? 0 : minLength;
}
```
**Walkthrough:** The `right` pointer aggressively expands the window to capture enough requests. The `while` loop is the dynamic shrinking mechanism. As soon as the condition is met (sum >= target), we log the size, and then slowly move `left` inward, discarding elements, to see how tight we can make the window while still satisfying the condition.
</details>

### Level 3: Boss Level
**Task:** Build a `Longest Unique Session Token Identifier`. Given a string of server log characters, find the length of the longest substring without repeating characters.
<details>
<summary>👀 Hint</summary>
Dynamic window using a Hash Map (or Set). Expand right. If the character at `right` is already in the window, shrink from the `left` until the duplicate character is removed from the window.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function longestUniqueSession(logString) {
  let charSet = new Set();
  let left = 0;
  let maxLength = 0;

  for (let right = 0; right < logString.length; right++) {
    // If character exists, shrink window from left until it doesn't
    while (charSet.has(logString[right])) {
      charSet.delete(logString[left]);
      left++;
    }

    // Add current character to window state
    charSet.add(logString[right]);

    // Update maximum length
    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
}
```
**Walkthrough:** We use a `Set` to track the state of characters currently inside our window. The `right` pointer marches forward. If it encounters a character that is already in the Set (a collision), our window is invalid. We enter a `while` loop, incrementing `left` and removing characters from the Set until the colliding character is purged. Then we add the new character and recalculate the max length.
</details>

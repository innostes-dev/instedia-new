# 4.1 The Exponential Explosion (1D Dynamic Programming)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are building a Cloud Compute Cost Optimizer. You have an exact budget `B` (e.g., $1000) and you want to deploy a cluster of servers exactly matching that budget using available server tiers costing `[$10, $50, $100, $500]`. You need to find the *minimum* number of servers to hit the budget exactly.
If you use brute-force recursion to try every possible combination, you will recalculate the answer for "What is the best way to spend $500?" thousands of times. This overlapping work creates an **O(2^N)** exponential time complexity. The server will freeze and crash before calculating a $2000 budget.

### 2. Plain English Metaphor (The What)
Imagine I ask you: "What is 1 + 1 + 1 + 1 + 1 + 1 + 1 + 1?" You count them up and say "8".
Then I append "+ 1" to the end and ask: "What is the new total?"
Do you recount the first 8 numbers from scratch? No! You just take your previous answer (8) and add 1 to get 9.
**Dynamic Programming (DP)** is simply the act of remembering the answers to smaller problems so you never have to calculate them again. This is called **Memoization** (Top-Down caching) or **Tabulation** (Bottom-Up array building).

### 3. Complete Runnable Code
```javascript
/**
 * Cloud Compute Cost Optimizer (Coin Change)
 * Finds the minimum number of servers needed to exactly hit the target budget.
 */
function minServersForBudget(serverCosts, targetBudget) {
  // 1. Tabulation Array Initialization
  // We need an array from 0 to targetBudget.
  // Fill it with Infinity, because we are looking for the MINIMUM.
  const dp = new Array(targetBudget + 1).fill(Infinity);

  // Base Case: It takes exactly 0 servers to hit a $0 budget.
  dp[0] = 0;

  // 2. Bottom-Up Calculation
  // We solve for every budget starting from $1 up to targetBudget.
  for (let currentBudget = 1; currentBudget <= targetBudget; currentBudget++) {

    // For this specific budget, try using one of every available server tier
    for (const serverCost of serverCosts) {

      // If we can afford this server at the current budget level
      if (currentBudget - serverCost >= 0) {

        // We take 1 server (the current one), and look at our DP table to find
        // the minimum servers needed for the REMAINING budget.
        const remainingBudget = currentBudget - serverCost;
        const potentialServers = 1 + dp[remainingBudget];

        // Is this combination better than our current best for this budget?
        dp[currentBudget] = Math.min(dp[currentBudget], potentialServers);
      }
    }
  }

  // If the target budget still has Infinity, it's impossible to hit exactly
  return dp[targetBudget] === Infinity ? -1 : dp[targetBudget];
}

// Example Execution
const availableTiers = [10, 50, 100];
const target = 260; // Optimal: two $100s, one $50, one $10 -> 4 servers
console.log(minServersForBudget(availableTiers, target)); // Output: 4
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The State Array (Tabulation)**
```javascript
  const dp = new Array(targetBudget + 1).fill(Infinity);
  dp[0] = 0;
```
*Rationale:* We create an array where the `index` represents the budget amount, and the `value` at that index represents the minimum servers needed. We start by solving the smallest possible subproblem: A budget of 0 requires 0 servers. We set the rest to `Infinity` as a placeholder because we are going to use `Math.min()` to find better answers.

**Step 2: Bottom-Up Iteration**
```javascript
  for (let currentBudget = 1; currentBudget <= targetBudget; currentBudget++) {
    for (const serverCost of serverCosts) {
```
*Rationale:* We don't try to solve $260 immediately. We solve $1. Then $2. Then $3... all the way up to $260. By the time we ask "How do I make $260?", we have already permanently solved all smaller components (like $160 or $210) and can look them up instantly.

**Step 3: The State Transition (The Optimal Substructure)**
```javascript
      if (currentBudget - serverCost >= 0) {
        const remainingBudget = currentBudget - serverCost;
        dp[currentBudget] = Math.min(dp[currentBudget], 1 + dp[remainingBudget]);
      }
```
*Rationale:* This is the heart of Dynamic Programming. The best way to make $260 using a $50 server is: `1 (the $50 server) + the best way to make $210`. Where do we find the best way to make $210? We just look at `dp[210]`! It was calculated 50 steps ago.

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using Greed algorithms when DP is required. A greedy approach for the above would be "Always pick the biggest server possible." If tiers are `[1, 3, 4]` and target is `6`. Greedy picks `4`, leaving `2`. It then picks two `1`s. Total servers: 3. But the optimal answer is two `3`s (Total servers: 2). Greedy fails when local maximums don't lead to global maximums.
**Pro Tip:** If a recursive algorithm has a `Set` or `Map` called `memo` being passed down, that is **Top-Down DP**. If it uses a `for` loop to build an array from 0 to N, that is **Bottom-Up DP (Tabulation)**. Tabulation is generally preferred in production because it avoids recursion limit (call stack size exceeded) errors.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** `Climbing Stairs`. You are climbing a staircase. It takes `n` steps to reach the top. Each time you can either climb 1 or 2 steps. In how many distinct ways can you climb to the top?
<details>
<summary>👀 Hint</summary>
To get to step `N`, you either came from step `N-1` (by taking a 1-step) or from step `N-2` (by taking a 2-step). Therefore, the number of ways to get to `N` is exactly `ways(N-1) + ways(N-2)`. Does this sound like the Fibonacci sequence? It is!
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function climbStairs(n) {
  if (n <= 2) return n;

  // Space-optimized DP!
  // We only need the last two values, so we don't need a full array.
  let prev2 = 1; // ways to reach step 1
  let prev1 = 2; // ways to reach step 2

  for (let i = 3; i <= n; i++) {
    let current = prev1 + prev2;
    prev2 = prev1;
    prev1 = current;
  }

  return prev1;
}
```
**Walkthrough:** This is the most fundamental DP problem. The relation `dp[i] = dp[i-1] + dp[i-2]` defines the state transition. We start at the bottom and work our way up. Because we *only* ever look exactly two steps backward, we can optimize the O(N) memory requirement down to O(1) by just keeping two variables, dropping the `dp` array entirely!
</details>

### Level 2: Real-World
**Task:** `Maximum Subarray Revenue` (Kadane's Algorithm). Given an array of integers representing daily revenue (which can be negative due to operational losses), find the contiguous subarray containing at least one number which has the largest sum and return its sum.
<details>
<summary>👀 Hint</summary>
At any day `i`, you have a choice: Do I append today's revenue to the running streak from yesterday? Or is the running streak so negative that I am better off completely abandoning it and starting a brand new streak starting today?
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function maxSubArray(revenues) {
  // DP State: dp[i] represents the max subarray ending exactly at index i
  // But we can optimize space to just track the previous state!
  let currentStreak = revenues[0];
  let maxGlobal = revenues[0];

  for (let i = 1; i < revenues.length; i++) {
    const today = revenues[i];

    // DP Transition:
    // Is it better to add today to the streak, or start fresh with today?
    currentStreak = Math.max(today, currentStreak + today);

    // Track the best streak we've ever seen
    maxGlobal = Math.max(maxGlobal, currentStreak);
  }

  return maxGlobal;
}
```
**Walkthrough:** This is Kadane's Algorithm, which is actually a highly space-optimized DP solution. The core DP concept is asking, "What is the optimal state ending *at this specific index*?"
If yesterday's streak is `-5`, and today's revenue is `10`. `Math.max(10, -5 + 10)` -> `Math.max(10, 5)`. The answer is `10`. We cut off the toxic past and start fresh. If yesterday's streak was `5`, `Math.max(10, 5 + 10)` -> `Math.max(10, 15)`. We keep the streak alive.
</details>

### Level 3: Boss Level
**Task:** `Longest Increasing Subsequence`. Given an integer array `nums`, return the length of the longest strictly increasing subsequence. (A subsequence is derived by deleting some or no elements without changing the order of the remaining elements).
<details>
<summary>👀 Hint</summary>
Use a 1D `dp` array where `dp[i]` stores the length of the longest increasing subsequence that *ends exactly* at index `i`.
To calculate `dp[i]`, you must look back at EVERY previous element `j` (where `j < i`). If `nums[i] > nums[j]`, you can attach `nums[i]` to the subsequence ending at `j`.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function lengthOfLIS(nums) {
  if (nums.length === 0) return 0;

  // dp[i] = length of LIS ending exactly at nums[i]
  // Every element is an increasing subsequence of length 1 (itself)
  const dp = new Array(nums.length).fill(1);
  let maxLength = 1;

  for (let i = 1; i < nums.length; i++) {
    // For current element i, look back at all previous elements j
    for (let j = 0; j < i; j++) {

      // If the current element is greater, we can extend the subsequence at j
      if (nums[i] > nums[j]) {
        // We take the max of what we currently have at dp[i],
        // OR the length of the subsequence at j, plus 1 (for the current element)
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }

    // Keep track of the global maximum found anywhere in the array
    maxLength = Math.max(maxLength, dp[i]);
  }

  return maxLength;
}
```
**Walkthrough:** This is the quintessential O(N^2) Dynamic Programming problem.
Array: `[10, 9, 2, 5, 3, 7, 101, 18]`
When we are evaluating `7` (at index 5), we look backwards.
- Is `7 > 10`? No.
- Is `7 > 9`? No.
- Is `7 > 2`? Yes! `dp[2]` is 1. We could make a sequence of length 2 (`[2, 7]`).
- Is `7 > 5`? Yes! `dp[3]` is 2 (`[2, 5]`). We could make a sequence of length 3 (`[2, 5, 7]`).
- Is `7 > 3`? Yes! `dp[4]` is 2 (`[2, 3]`). We could make a sequence of length 3 (`[2, 3, 7]`).
We store `3` at `dp[5]`. The DP table remembers this, so when `101` evaluates `7`, it instantly knows `7` carries a chain of length 3 behind it!
</details>

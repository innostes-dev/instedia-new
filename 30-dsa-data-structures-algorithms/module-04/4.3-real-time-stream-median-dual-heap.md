# 4.3 Real-Time Stream Median (Dual-Heap)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are building the Live System Latency SLA Tracker for AWS. Every millisecond, a new server response time (latency) is logged. You need to display the exact **median** latency on a live dashboard.
If you append to an Array and run `.sort()` every time a new ping arrives, your time complexity is `O(N log N)` per tick. As millions of logs stream in, sorting the entire history for every single new log will bring the entire monitoring infrastructure to a grinding halt. You need a data structure that maintains sorted properties in real-time.

### 2. Plain English Metaphor (The What)
Imagine you have an unsorted pile of test scores. You want to find the middle score.
Instead of sorting the whole pile, you hire two people: Bob (who only likes small numbers) and Alice (who only likes big numbers).
As every score comes in, if it's smaller than the median, give it to Bob. If it's bigger, give it to Alice.
Crucially, Bob and Alice always keep their piles exactly the same size (or Bob has 1 extra). Also, Bob always keeps his *biggest* number on top of his pile (Max-Heap), and Alice always keeps her *smallest* number on top of hers (Min-Heap).
When you need the median, you just look at the top of Bob's pile and the top of Alice's pile. You don't care about the millions of numbers underneath!

### 3. Complete Runnable Code
```javascript
/**
 * Live System Latency SLA Tracker & Stream Median Engine
 * Uses a Dual-Heap architecture to maintain the median of a data stream in O(log N) time.
 * (Note: Uses a mock Heap class for demonstration, as JS lacks native Heaps)
 */

// Mock Priority Queue implementation for demonstration
class PriorityQueue {
  constructor(comparator = (a, b) => a > b) {
    this.heap = [];
    this.compare = comparator;
  }
  size() { return this.heap.length; }
  peek() { return this.heap[0]; }

  // O(log N) insertion
  push(val) {
    this.heap.push(val);
    this.heap.sort((a,b) => this.compare(a, b) ? -1 : 1); // Mock sorting
  }

  // O(log N) extraction
  pop() {
    const val = this.heap.shift();
    this.heap.sort((a,b) => this.compare(a, b) ? -1 : 1); // Mock sorting
    return val;
  }
}

class MedianFinder {
  constructor() {
    // Max-Heap for the lower half of numbers (Largest number on top)
    this.lowers = new PriorityQueue((a, b) => a > b);

    // Min-Heap for the upper half of numbers (Smallest number on top)
    this.uppers = new PriorityQueue((a, b) => a < b);
  }

  // O(log N) Time per insertion
  addNum(num) {
    // 1. Add to Lowers (Max-Heap) by default
    this.lowers.push(num);

    // 2. Balance the Values
    // If the largest number in Lowers is strictly greater than the smallest in Uppers,
    // they are in the wrong halves! Move it over.
    if (this.uppers.size() > 0 && this.lowers.peek() > this.uppers.peek()) {
      this.uppers.push(this.lowers.pop());
    }

    // 3. Balance the Sizes
    // Keep sizes equal, or favor Lowers by exactly 1 element
    if (this.lowers.size() > this.uppers.size() + 1) {
      this.uppers.push(this.lowers.pop());
    } else if (this.uppers.size() > this.lowers.size()) {
      this.lowers.push(this.uppers.pop());
    }
  }

  // O(1) Time for retrieval
  findMedian() {
    // If total elements is odd, Lowers has the 1 extra element (the exact median)
    if (this.lowers.size() > this.uppers.size()) {
      return this.lowers.peek();
    }
    // If even, the median is the average of the tops of both heaps
    return (this.lowers.peek() + this.uppers.peek()) / 2.0;
  }
}

// Example Execution
const stream = new MedianFinder();
stream.addNum(10); // [10] | [] -> Median 10
stream.addNum(20); // [10] | [20] -> Median 15
stream.addNum(30); // [10, 20] | [30] -> Median 20 (Wait, balances to [10, 20], [30]? Actually [10, 20] is lowers, top is 20. Median is 20.)
console.log(stream.findMedian());
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Dual-Heap Setup**
```javascript
    this.lowers = new PriorityQueue((a, b) => a > b); // Max-Heap
    this.uppers = new PriorityQueue((a, b) => a < b); // Min-Heap
```
*Rationale:* A Heap is a tree-based structure that guarantees the min (or max) element is *always* at the root, accessible in O(1) time. Inserting/removing takes O(log N) to rebalance the tree. We split our data exactly in half using two heaps.

**Step 2: Value Validation**
```javascript
    this.lowers.push(num);
    if (this.uppers.size() > 0 && this.lowers.peek() > this.uppers.peek()) {
      this.uppers.push(this.lowers.pop());
    }
```
*Rationale:* We blindly throw the new number into the `lowers` pile. But what if the number was 1,000,000? It doesn't belong in the lower half! We check if the biggest number in `lowers` is larger than the smallest in `uppers`. If so, an intruder is in the lower half. We pop it out and push it to `uppers`.

**Step 3: Size Balancing**
```javascript
    if (this.lowers.size() > this.uppers.size() + 1) {
      this.uppers.push(this.lowers.pop());
    } else if (this.uppers.size() > this.lowers.size()) {
      this.lowers.push(this.uppers.pop());
    }
```
*Rationale:* The median only exists at the exact middle. If one heap gets too large, the middle shifts. We forcibly rebalance them so that `lowers` either equals `uppers` in size (even total), or `lowers` has exactly 1 more element than `uppers` (odd total).

### 5. ASCII / Architecture Data Flow
```text
Stream: [41, 35, 62, 5, 97, 108]

1. addNum(41)
   Lowers: [41] (Max: 41) | Uppers: []
   Median: 41

2. addNum(35)
   Push Lowers: [41, 35]
   Balance Size: Lowers > Uppers+1. Pop 41 -> Uppers.
   Lowers: [35] (Max: 35) | Uppers: [41] (Min: 41)
   Median: (35 + 41) / 2 = 38

3. addNum(62)
   Push Lowers: [35, 62] (Max: 62)
   Value Check: 62 > Uppers.Min(41). Pop 62 -> Uppers.
   Lowers: [35] | Uppers: [41, 62]
   Balance Size: Uppers > Lowers. Pop 41 -> Lowers.
   Lowers: [41, 35] (Max: 41) | Uppers: [62] (Min: 62)
   Median: 41

... The tops of the heaps forever guard the middle threshold!
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using arrays and binary search to find the insertion index (e.g., `array.splice(index, 0, num)`). While finding the index with binary search is O(log N), `splice` requires shifting all elements in memory, which is O(N). Doing this for every element results in O(N^2) total time.
**Pro Tip:** JavaScript and TypeScript **do not have built-in Priority Queues**. If you are doing a coding interview in JS, you must know how to implement a basic Min-Heap from scratch using an Array and math formulas for parent/child indices (`parent = Math.floor((i-1)/2)`, `left = 2i+1`, `right = 2i+2`), OR politely ask the interviewer if you can assume a `PriorityQueue` class exists for the sake of time.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** `Kth Largest Element in a Stream`. Design a class to find the `kth` largest element in a stream. Note that it is the `kth` largest element in the sorted order, not the `kth` distinct element.
<details>
<summary>👀 Hint</summary>
You don't need two heaps for this. You only need one **Min-Heap**. Keep the heap size exactly equal to `k`. As numbers stream in, if the heap is smaller than `k`, add the number. If the heap is at `k` and the new number is *larger* than the top of the heap (the smallest number in the top K), pop the heap and push the new number. The top of the heap is always the answer!
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
class KthLargest {
  constructor(k, nums) {
    this.k = k;
    this.minHeap = new MinPriorityQueue(); // Assume available

    for (const num of nums) {
      this.add(num);
    }
  }

  add(val) {
    // If we haven't reached K elements yet, just push
    if (this.minHeap.size() < this.k) {
      this.minHeap.enqueue(val);
    }
    // If the new value is bigger than the SMALLEST of our top K elements
    else if (val > this.minHeap.front().element) {
      this.minHeap.dequeue(); // Kick out the smallest
      this.minHeap.enqueue(val); // Insert the new bigger one
    }

    // The Kth largest is exactly the smallest element in our top K
    return this.minHeap.front().element;
  }
}
```
**Walkthrough:** This is the ultimate memory optimization trick. We have an infinite stream of numbers, but we only use `O(K)` memory. By using a Min-Heap, the smallest number out of our "Top K" is always sitting right at the front, perfectly positioned to act as a bouncer. If a new number is smaller than the bouncer, it's rejected. If it's bigger, it kicks the bouncer out and enters the club.
</details>

### Level 2: Real-World
**Task:** `Top K Frequent Words`. Given an array of strings `words` and an integer `k`, return the `k` most frequent strings. Return the answer sorted by the frequency from highest to lowest. Sort the words with the same frequency by their lexicographical order.
<details>
<summary>👀 Hint</summary>
Step 1: Use a Hash Map to count frequencies (O(N)).
Step 2: Dump the map into a **Max-Heap** where the comparison function sorts primarily by frequency (descending), and secondarily by string comparison (alphabetical).
Step 3: Pop from the heap `k` times.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function topKFrequent(words, k) {
  // Step 1: Count Frequencies
  const countMap = new Map();
  for (const word of words) {
    countMap.set(word, (countMap.get(word) || 0) + 1);
  }

  // Step 2: Custom Heap/Sort
  // Note: Since JS lacks heaps, we can push to array and sort.
  // In a real interview, describe this as building a Max-Heap based on custom rules.
  const uniqueWords = Array.from(countMap.keys());

  uniqueWords.sort((a, b) => {
    const countA = countMap.get(a);
    const countB = countMap.get(b);

    if (countA === countB) {
      // Lexicographical sort (alphabetical ascending)
      return a.localeCompare(b);
    }

    // Frequency sort (descending)
    return countB - countA;
  });

  // Step 3: Return top K
  return uniqueWords.slice(0, k);
}
```
**Walkthrough:** The logic here is split into processing (Hash Map) and querying (Heap/Sort). The trick is handling the tie-breaker. When frequencies are identical, we must fall back to a completely different type of comparison (`localeCompare` for strings). If you implement this with an actual Heap of size `K`, the time complexity drops from O(N log N) for full sorting to **O(N log K)**, which is vastly superior when `K` is small.
</details>

### Level 3: Boss Level
**Task:** `Sliding Window Median`. You are given an integer array `nums` and an integer `k`. There is a sliding window of size `k` moving from the left to the right. Return the median array for each window.
<details>
<summary>👀 Hint</summary>
This is the ultimate combination of **1.2 Dynamic Sliding Window** and **4.3 Dual-Heap Median**.
You use the exact Dual-Heap structure, but as the window slides, elements fall out of the back. You cannot easily `remove(val)` from the middle of a Heap in O(log N). You must use "Lazy Deletion": keep a Hash Map tracking how many of a specific value need to be deleted, and only actually pop them when they bubble up to the `peek()` position!
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
/**
 * Note: This is an architectural pseudo-solution.
 * Implementing Lazy Deletion Heaps from scratch in JS is ~150 lines of code.
 */
class SlidingMedianDualHeap {
  constructor() {
    this.lowers = new MaxHeap();
    this.uppers = new MinHeap();
    this.delayedDeletions = new Map(); // Tracks elements outside window
    this.balance = 0; // Tracks size difference
  }

  insert(num) {
    if (this.lowers.isEmpty() || num <= this.lowers.peek()) {
      this.lowers.push(num);
      this.balance++;
    } else {
      this.uppers.push(num);
      this.balance--;
    }
    this.rebalance();
  }

  remove(num) {
    // We don't search the heap. We just record that it needs deletion.
    this.delayedDeletions.set(num, (this.delayedDeletions.get(num) || 0) + 1);

    // Adjust balance based on which heap the number *should* be in
    if (num <= this.lowers.peek()) {
      this.balance--;
    } else {
      this.balance++;
    }
    this.rebalance();
    this.prune(); // Check if top elements are overdue for deletion
  }

  getMedian(k) {
    if (k % 2 === 1) return this.lowers.peek();
    return (this.lowers.peek() + this.uppers.peek()) / 2;
  }

  // Internal helpers (rebalance, prune) ensure O(1) peek accuracy
}

function medianSlidingWindow(nums, k) {
  const result = [];
  const engine = new SlidingMedianDualHeap();

  // Bootstrap first window
  for (let i = 0; i < k; i++) {
    engine.insert(nums[i]);
  }
  result.push(engine.getMedian(k));

  // Slide window
  for (let i = k; i < nums.length; i++) {
    engine.insert(nums[i]); // Add incoming
    engine.remove(nums[i - k]); // Lazy-delete outgoing
    result.push(engine.getMedian(k));
  }

  return result;
}
```
**Walkthrough:** This is a pinnacle FAANG problem. It requires architecting a completely custom Data Structure.
The magic is **Lazy Deletion**. Searching a tree for `val=5` takes O(N). We can't do that. Instead, when `5` falls out of the window, we add it to a Hash Map: `{ 5: 1 }`.
Our `prune()` function runs every tick. It looks at `peek()`. If the top of the heap is `5`, it checks the map. "Ah, `5` is supposed to be deleted!" It pops `5` off the heap in O(log N), decrements the map, and checks the new top. If the number we need to delete is buried deep in the heap, we just ignore it! It doesn't affect our median calculation. We only delete it when it naturally rises to the top and threatens the accuracy of `peek()`.
</details>

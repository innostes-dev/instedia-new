# 4.2 Bounded Cargo & 2D Dynamic Programming

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are building the loadout engine for a logistics company. You have a cargo plane with a maximum weight capacity `W`. You have a list of shipping containers, each with a specific `weight` and `revenue`.
You cannot split containers in half (this is the **0/1 Knapsack** rule—you take it or leave it). If you try every combination of taking or leaving each container, it's `O(2^N)`. For 100 containers, that's more calculations than there are atoms in the universe. You must find the absolute maximum revenue without exceeding the weight limit.

### 2. Plain English Metaphor (The What)
Imagine you are at an all-you-can-eat buffet, but you only have a plate that holds 10 ounces of food.
For every dish (e.g., a 4oz steak worth 10 "tastiness" points, or a 2oz salad worth 3 points), you ask yourself a question:
"If I have exactly `X` ounces of room left on my plate, am I better off ignoring this dish, or should I take it and combine its tastiness with the best possible combination of food I could fit in the *remaining* `X - dishWeight` ounces?"
By building a 2D chart where rows are the dishes and columns are the plate sizes (1oz, 2oz... 10oz), you can perfectly calculate the best meal.

### 3. Complete Runnable Code
```javascript
/**
 * Logistics Cargo Weight & Revenue Maximization Engine (0/1 Knapsack)
 * Uses a 2D DP array to find the maximum revenue for a given weight capacity.
 */
function maximizeCargoRevenue(weights, revenues, maxCapacity) {
  const numItems = weights.length;

  // 1. Initialize 2D DP Grid
  // dp[itemIndex][currentCapacity]
  const dp = Array.from({ length: numItems + 1 }, () =>
    new Array(maxCapacity + 1).fill(0)
  );

  // 2. Build the DP table bottom-up
  // i represents the number of items we are considering (1 to numItems)
  for (let i = 1; i <= numItems; i++) {
    const currentWeight = weights[i - 1]; // 0-indexed offset
    const currentRevenue = revenues[i - 1];

    // w represents every possible weight capacity from 1 up to maxCapacity
    for (let w = 1; w <= maxCapacity; w++) {

      // Option 1: We LEAVE the current item
      // The revenue is exactly the same as if we only had the previous items
      const revenueIfLeft = dp[i - 1][w];

      // Option 2: We TAKE the current item (only if it fits!)
      let revenueIfTaken = 0;
      if (currentWeight <= w) {
        // We add its revenue, PLUS the best revenue we could get from the
        // previous items using the *remaining* weight capacity.
        const remainingCapacity = w - currentWeight;
        revenueIfTaken = currentRevenue + dp[i - 1][remainingCapacity];
      }

      // The DP transition: Take the maximum of Option 1 and Option 2
      dp[i][w] = Math.max(revenueIfLeft, revenueIfTaken);
    }
  }

  // The bottom-right cell contains the answer using ALL items and MAX capacity
  return dp[numItems][maxCapacity];
}

// Example Execution
const containerWeights = [1, 3, 4, 5];
const containerRevenues = [10, 40, 50, 70];
const planeCapacity = 7;
console.log(maximizeCargoRevenue(containerWeights, containerRevenues, planeCapacity));
// Output: 90 (Take item 2 (w:3, r:40) and item 3 (w:4, r:50))
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The 2D Grid Setup**
```javascript
  const dp = Array.from({ length: numItems + 1 }, () =>
    new Array(maxCapacity + 1).fill(0)
  );
```
*Rationale:* We need two dimensions of state. Row `i` means "considering only the first `i` items". Column `w` means "if our maximum plane capacity was exactly `w`". The extra `+ 1` is for the base cases (0 items considered, or 0 capacity available, which both naturally result in 0 revenue).

**Step 2: The Two Options**
```javascript
      const revenueIfLeft = dp[i - 1][w];
      // ...
      if (currentWeight <= w) {
        const remainingCapacity = w - currentWeight;
        revenueIfTaken = currentRevenue + dp[i - 1][remainingCapacity];
      }
```
*Rationale:* This is the core 0/1 decision. If we leave it, our capacity stays `w`, but we drop down to row `i-1` (the best we did without this item). If we take it, we gain `currentRevenue`, but we *must* subtract `currentWeight` from our capacity. We look up `dp[i - 1][remainingCapacity]` to see the optimal way to pack the remaining space using only the previous items.

**Step 3: The State Transition**
```javascript
      dp[i][w] = Math.max(revenueIfLeft, revenueIfTaken);
```
*Rationale:* We simply write the winner into the current cell. Because we are iterating `w` from 1 to `maxCapacity`, we guarantee that `dp[i - 1][remainingCapacity]` has already been calculated and is ready for O(1) lookup.

```text
                      ^ Take (40+dp[1][0]) vs Leave (10)
                            ^ Take (40+dp[1][1]=50) vs Leave (10)

i=3  0    10    10    40    50   (Item 3 [w:4, r:50])
                            ^ Take (50+dp[2][0]=50) vs Leave (50). Tie.

```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using a 2D array when you don't actually need the full history! Notice in the code: `dp[i][w]` only ever looks at `dp[i - 1][...]`. It only looks *one row up*.
**Pro Tip:** You can collapse the 2D Knapsack into a 1D array to save massive amounts of memory! You just use a single array of size `Capacity + 1`, and iterate backwards (from `maxCapacity` down to `currentWeight`) so you don't accidentally overwrite the data from the previous item before you need it.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** `Unique Paths in a Grid`. A robot is located at the top-left corner of a `m x n` grid. The robot can only move either down or right at any point in time. It is trying to reach the bottom-right corner. How many possible unique paths are there?
<details>
<summary>👀 Hint</summary>
If you are at cell `[r, c]`, how did you get there? You must have come from either the cell directly above you `[r-1, c]` or directly to your left `[r, c-1]`. Therefore, `paths[r, c] = paths[r-1, c] + paths[r, c-1]`.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function uniquePaths(m, n) {
  // Initialize a 2D DP grid filled with 1s
  // (The entire top row and left column only have 1 possible path: straight line)
  const dp = Array.from({ length: m }, () => new Array(n).fill(1));

  // Start at row 1, col 1 (skipping the 1-filled borders)
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      // The number of ways to reach this cell is the sum of ways to reach
      // the cell above it + the cell to the left of it.
      dp[r][c] = dp[r - 1][c] + dp[r][c - 1];
    }
  }

  // The bottom-right corner contains the total unique paths
  return dp[m - 1][n - 1];
}
```
**Walkthrough:** This is DP applied to geometry. Because movement is strictly restricted (only Right or Down), the grid forms a Directed Acyclic Graph (DAG). The state transition is simply addition. `dp[2][2]` requires the answers to `dp[1][2]` and `dp[2][1]`, which were already solved in earlier loop iterations.
</details>

### Level 2: Real-World
**Task:** `Longest Common Subsequence (LCS)`. Given two strings `text1` and `text2`, return the length of their longest common subsequence. (e.g., "abcde" and "ace" -> "ace", length 3). This is the foundation of `git diff`!
<details>
<summary>👀 Hint</summary>
Use a 2D grid where rows are characters of `text1` and columns are `text2`.
If the characters match: `dp[r][c] = 1 + dp[r-1][c-1]` (diagonal up-left).
If they don't match: `dp[r][c] = Math.max(dp[r-1][c], dp[r][c-1])` (inherit the best from above or left).
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function longestCommonSubsequence(text1, text2) {
  const m = text1.length;
  const n = text2.length;

  // dp[i][j] represents the LCS of text1[0...i-1] and text2[0...j-1]
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {

      if (text1[i - 1] === text2[j - 1]) {
        // Characters match!
        // Add 1 to the LCS of the prefixes before this match (diagonal)
        dp[i][j] = 1 + dp[i - 1][j - 1];
      } else {
        // No match.
        // The best we can do is either drop current char of text1 OR text2
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }

  return dp[m][n];
}
```
**Walkthrough:** Let's look at `dp[i][j]`. If the characters match, they form a link in our subsequence! We add 1 to the best subsequence we found *before* we included these two characters (which is stored at `dp[i-1][j-1]`).
If they don't match, we can't form a link. But we don't lose our progress! We just pull forward the longest subsequence found so far by either looking at the string without the current `text1` character (`dp[i-1][j]`), or without the current `text2` character (`dp[i][j-1]`).
</details>

### Level 3: Boss Level
**Task:** `Partition Equal Subset Sum`. Given a non-empty array `nums` containing only positive integers, find if the array can be partitioned into two subsets such that the sum of elements in both subsets is equal.
<details>
<summary>👀 Hint</summary>
If the total sum is odd, it's impossible. If it's even, the target sum for ONE subset is exactly `totalSum / 2`.
This just became the 0/1 Knapsack problem! Can you pick a combination of items whose weight exactly equals `totalSum / 2`? Try to implement it using a **1D Space-Optimized Array** instead of a 2D grid.
</details>

<details>
<summary>✅ Full Solution Walkthrough</summary>

```javascript
function canPartition(nums) {
  let totalSum = 0;
  for (const num of nums) totalSum += num;

  // If total is odd, cannot be split evenly
  if (totalSum % 2 !== 0) return false;

  const target = totalSum / 2;

  // Space-Optimized 1D DP Array
  // dp[w] will be a boolean: "Is it possible to make sum 'w'?"
  const dp = new Array(target + 1).fill(false);
  dp[0] = true; // Base case: We can always make sum 0 with 0 elements

  // Iterate through available numbers (items)
  for (const num of nums) {

    // CRITICAL: We must iterate backwards!
    // If we iterate forward, we might reuse the same 'num' multiple times
    // in the same pass, which violates the 0/1 (use once) rule.
    for (let w = target; w >= num; w--) {
      // If we could make the sum (w - num) previously,
      // we can now make sum 'w' by adding 'num' to it.
      dp[w] = dp[w] || dp[w - num];
    }
  }

  // Returns true if we found a combination that perfectly hits the target
  return dp[target];
}
```
**Walkthrough:** This is a brilliant reduction. We take a partitioning problem and turn it into a Knapsack problem.
The space optimization is the key here. Instead of a 2D grid `dp[item][capacity]`, we just use `dp[capacity]`.
Why must we iterate `w` backwards? Suppose `num = 2`. If `dp[0]` is true, and we go forwards: `w=2` becomes true (because `dp[2-2]` is true). Then when `w=4`, `dp[4]` becomes true (because `dp[4-2]` was just set to true). We accidentally used the same `2` twice!
By iterating backwards from `target` down to `num`, we ensure that `dp[w - num]` only contains the state from the *previous* item's iteration, perfectly preserving the 0/1 Knapsack constraints while dropping O(N * Target) memory down to O(Target).
</details>

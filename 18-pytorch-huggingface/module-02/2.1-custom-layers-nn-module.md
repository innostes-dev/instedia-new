# Custom Layers & nn.Module

## Phase A: Object-Oriented Neural Networks

### 1. Real-World Pain Point (The Why)
In Module 1, we manually created weight tensors, added biases, and managed gradients. Doing this for a modern neural network with 100 layers and millions of parameters is insane. You need a structured, object-oriented way to group weights, biases, and operations into reusable "blocks" (layers) that PyTorch can automatically manage and move to the GPU together.

### 2. Plain English Metaphor (The What)
Think of building a car. You don't build an engine by buying raw iron and casting individual gears every time. You use pre-built modules: an Engine block, a Transmission block, etc. `nn.Module` is the base template for any "part" of your neural network. You just slot in pre-built layers (like `nn.Linear`), and define how data flows through them.

### 3. Complete Runnable Code
```python
import torch
import torch.nn as nn

# 1. Define the network blueprint by subclassing nn.Module
class SimpleMLP(nn.Module):
    def __init__(self, input_size, hidden_size, num_classes):
        super().__init__() # CRITICAL: Initialize the parent class

        # Define the building blocks (layers)
        self.layer1 = nn.Linear(input_size, hidden_size)
        self.activation = nn.ReLU()
        self.layer2 = nn.Linear(hidden_size, num_classes)

    def forward(self, x):
        # Define the data flow (how inputs become outputs)
        x = self.layer1(x)
        x = self.activation(x)
        x = self.layer2(x)
        return x

def build_and_run_model():
    # 2. Instantiate the model
    model = SimpleMLP(input_size=10, hidden_size=32, num_classes=2)

    # 3. Create dummy data
    # Batch size 4, input features 10
    dummy_input = torch.randn(4, 10)

    # 4. Pass data through the model
    # Note: We call the object directly model(x), NOT model.forward(x)
    predictions = model(dummy_input)

    print(f"Model Architecture:\n{model}")
    print(f"\nInput shape: {dummy_input.shape}")
    print(f"Output shape: {predictions.shape}") # Should be (4, 2)

if __name__ == "__main__":
    build_and_run_model()
```

### 4. Progressive Step-by-Step Breakdown

#### Step 1: Subclassing & Initialization
```python
class SimpleMLP(nn.Module):
    def __init__(self):
        super().__init__()
```
Every custom model must inherit from `nn.Module`. You **must** call `super().__init__()` first. This registers your class internally so PyTorch can track all the internal weights.

#### Step 2: Defining Layers
```python
self.layer1 = nn.Linear(input_size, hidden_size)
```
Inside `__init__`, you create the layers. `nn.Linear` automatically creates the weight and bias tensors and sets `requires_grad=True` for them. Because you assigned it to `self.layer1`, `nn.Module` automatically discovers these parameters.

#### Step 3: The Forward Pass
```python
def forward(self, x):
```
The `forward` method is the blueprint for data flow. When you run `model(data)`, PyTorch handles some background hooks and then calls this `forward` method. You never call `model.forward(data)` directly.

### 5. ASCII Data Flow
```text
[ Input Batch ]  Shape: (4, 10)
      |
      V
[ nn.Linear ]    Weights: (10 -> 32)
      |
      V
[ nn.ReLU ]      (Non-linear activation)
      |
      V
[ nn.Linear ]    Weights: (32 -> 2)
      |
      V
[ Output Logits ] Shape: (4, 2)
```

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Forgetting to call `super().__init__()` in your custom module. Your code will crash immediately with an obscure error about missing attributes when you try to define a layer.
* **Pro Tip:** Use `nn.Sequential` if your `forward` pass is literally just running data through layers in a straight line. It saves boilerplate code.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Challenge:** Re-write the `SimpleMLP` from the main example using `nn.Sequential` to eliminate the need for an explicit `forward` method.
<details>
<summary>Hint</summary>
Pass the layers directly into `nn.Sequential()`.
</details>

<details>
<summary>Solution</summary>
```python
import torch.nn as nn

class SequentialMLP(nn.Module):
    def __init__(self, input_size, hidden_size, num_classes):
        super().__init__()
        self.network = nn.Sequential(
            nn.Linear(input_size, hidden_size),
            nn.ReLU(),
            nn.Linear(hidden_size, num_classes)
        )

    def forward(self, x):
        return self.network(x)
```
</details>

### Level 2: Real-World
**Challenge:** You want to print out the shapes of tensors as they pass through your network for debugging. Create a custom `DebugLayer` that inherits from `nn.Module`, prints the shape of the input tensor, and returns the tensor unchanged. Insert this layer between two linear layers.
<details>
<summary>Hint</summary>
The `forward` method of your custom layer should just print `x.shape` and return `x`.
</details>

<details>
<summary>Solution</summary>
```python
import torch
import torch.nn as nn

class DebugLayer(nn.Module):
    def __init__(self, name="Debug"):
        super().__init__()
        self.name = name

    def forward(self, x):
        print(f"[{self.name}] Tensor shape: {x.shape}")
        return x

model = nn.Sequential(
    nn.Linear(10, 20),
    DebugLayer("After L1"),
    nn.ReLU(),
    nn.Linear(20, 5)
)

dummy = torch.randn(2, 10)
out = model(dummy)
```
</details>

### Level 3: Boss Level
**Challenge:** Create a "Residual Block", a core component of modern architectures like ResNet. A Residual Block takes an input, passes it through a linear layer and a ReLU, and then *adds the original input back to the output* before returning. Create this block, and handle the edge case where the input dimension and output dimension of the block are different (by applying a projection linear layer to the residual connection).
<details>
<summary>Hint</summary>
In `forward(self, x)`, keep a copy of `x`. Process `x` through the main layers to get `out`. If input dim != output dim, process the copied `x` through a projection layer. Finally, return `out + x`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
import torch
import torch.nn as nn

class ResidualBlock(nn.Module):
    def __init__(self, in_features, out_features):
        super().__init__()

        # Main path
        self.main_path = nn.Sequential(
            nn.Linear(in_features, out_features),
            nn.ReLU(),
            nn.Linear(out_features, out_features) # Keep dim same for addition
        )

        # Shortcut (Residual) path
        self.shortcut = nn.Identity() # Default: do nothing
        if in_features != out_features:
            # Projection required to match dimensions for addition
            self.shortcut = nn.Linear(in_features, out_features)

        self.final_relu = nn.ReLU()

    def forward(self, x):
        # 1. Compute main path
        main_out = self.main_path(x)

        # 2. Compute shortcut path
        res_out = self.shortcut(x)

        # 3. Add them together (The "Residual Connection")
        out = main_out + res_out

        # 4. Final activation
        return self.final_relu(out)

# Test the block
block = ResidualBlock(in_features=64, out_features=128)
dummy_x = torch.randn(4, 64)
output = block(dummy_x)
print(f"Output shape: {output.shape}") # Should be (4, 128)
```
Residual connections solve the "vanishing gradient" problem in deep networks by providing a direct mathematical shortcut for gradients to flow backward, allowing networks to be hundreds of layers deep!
</details>

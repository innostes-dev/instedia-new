# DataLoaders & Batching

## Phase A: Managing the Data Pipeline

### 1. Real-World Pain Point (The Why)
Real-world datasets (like 100,000 images) do not fit in RAM, let alone GPU VRAM. You need a system that can load data from a hard drive on the fly, shuffle it, group it into small manageable "batches", and feed it to the GPU *exactly* when the GPU is ready for the next batch, without causing a bottleneck.

### 2. Plain English Metaphor (The What)
Think of a busy restaurant kitchen.
* The **Dataset** is the pantry and walk-in fridge (holds all raw ingredients).
* The **DataLoader** is the team of prep cooks. They go to the fridge, grab ingredients (fetching), chop them up (preprocessing), put them on a tray together (batching), and hand them to the Head Chef.
* The **GPU** is the Head Chef. If the prep cooks are too slow, the Head Chef stands around doing nothing. If they are fast and parallelized, the kitchen hums efficiently.

### 3. Complete Runnable Code
```python
import torch
from torch.utils.data import Dataset, DataLoader

# 1. Create a Custom Dataset class
class CustomNumberDataset(Dataset):
    def __init__(self, size=1000):
        # Initialize data (could be paths to images, text files, etc.)
        self.x_data = torch.randn(size, 5) # 1000 items, 5 features each
        self.y_data = torch.randint(0, 2, (size,)) # 1000 labels (0 or 1)
        self.size = size

    def __len__(self):
        # PyTorch needs to know the total size
        return self.size

    def __getitem__(self, idx):
        # How to fetch exactly ONE item at index 'idx'
        x = self.x_data[idx]
        y = self.y_data[idx]
        return x, y

def run_data_pipeline():
    # 2. Instantiate the Dataset
    dataset = CustomNumberDataset(size=100)

    # 3. Wrap it in a DataLoader
    dataloader = DataLoader(
        dataset,
        batch_size=16,   # Group 16 items together
        shuffle=True,    # Randomize order (critical for training)
        num_workers=0,   # Use 0 for Windows compatibility in simple scripts, 2-4 for real training
        drop_last=True   # Drop the final incomplete batch if size % 16 != 0
    )

    # 4. Iterate through the DataLoader (like in a training loop)
    for batch_idx, (inputs, labels) in enumerate(dataloader):
        print(f"Batch {batch_idx+1}: Inputs Shape: {inputs.shape} | Labels Shape: {labels.shape}")

        # Stop after 3 batches just for demonstration
        if batch_idx == 2:
            break

if __name__ == "__main__":
    run_data_pipeline()
```

### 4. Progressive Step-by-Step Breakdown

#### Step 1: Subclassing `Dataset`
```python
class CustomNumberDataset(Dataset):
```
You must inherit from `torch.utils.data.Dataset`. This forces you to define how your data is accessed.

#### Step 2: The Magic Methods
```python
def __len__(self): return self.size
def __getitem__(self, idx): return self.x[idx], self.y[idx]
```
These are the only two methods PyTorch requires. `__len__` tells the DataLoader how many items exist. `__getitem__` is where you write the logic to load *one single item* from disk/RAM and return it.

#### Step 3: The DataLoader
```python
dataloader = DataLoader(dataset, batch_size=16, shuffle=True)
```
The DataLoader is an engine. It takes your Dataset, generates 16 random indices, calls your `__getitem__` method 16 times in the background, takes those 16 items, and uses `torch.stack` to combine them into a single tensor of shape `(16, 5)` before yielding it to your training loop.

### 5. ASCII Data Flow
```text
[ Dataset ] -> __getitem__(3) -> (Tensor 3)
[ Dataset ] -> __getitem__(8) -> (Tensor 8)  --> DataLoader batches them --> [ Batch Tensor ]
[ Dataset ] -> __getitem__(1) -> (Tensor 1)                                   Shape: (3, 5)
```

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Putting `.to('cuda')` inside the `__getitem__` method of your Dataset. Datasets run on the CPU (often across multiple cores via `num_workers`). GPUs hate multi-processing. Always load data to the CPU, batch it, and *then* move the final batch to the GPU inside the training loop.
* **Pro Tip:** Set `pin_memory=True` in your DataLoader. This pre-allocates the CPU tensors in a special page-locked memory area, making the transfer to the GPU much faster.

**Challenge:** Write a custom dataset class `ImagePathsDataset` that takes a list of filepaths. In `__getitem__`, simulate loading an image by creating a random tensor of shape `(3, 224, 224)`. This simulates how you handle data that is too big for RAM.

<details>
<summary>Solution</summary>
```python
import torch
from torch.utils.data import Dataset

class ImagePathsDataset(Dataset):
    def __init__(self, filepaths):
        self.paths = filepaths

    def __len__(self):
        return len(self.paths)

    def __getitem__(self, idx):
        path = self.paths[idx]
        # In reality: image = Image.open(path); tensor = transform(image)
        # Simulation:
        image_tensor = torch.randn(3, 224, 224)
        label = 0 if "cat" in path else 1
        return image_tensor, label

paths = ["cat1.jpg", "dog1.jpg", "cat2.jpg"]
ds = ImagePathsDataset(paths)
print(ds[0][0].shape) # torch.Size([3, 224, 224])
```

### Level 3: Boss Level
**Challenge:** Create a **Custom Collate Function**. A Dataloader normally just uses `torch.stack` to batch items. But what if your `__getitem__` returns sequences of different lengths (like sentences)? `torch.stack` will crash because dimensions must match.
Write a custom `collate_fn` that takes a list of tensors of different lengths, pads the shorter ones with zeros so they all match the longest one in the batch, and then stacks them.
<details>
<summary>Hint</summary>
Define a function `pad_collate(batch)`. The `batch` is a list of tuples `(sequence_tensor, label)`. Use `torch.nn.utils.rnn.pad_sequence` with `batch_first=True`. Pass this function to the DataLoader's `collate_fn` argument.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
import torch
from torch.utils.data import Dataset, DataLoader
from torch.nn.utils.rnn import pad_sequence

class VariableLengthDataset(Dataset):
    def __init__(self):
        # Tensors of lengths 3, 5, and 2
        self.data = [torch.tensor([1,2,3]),
                     torch.tensor([1,2,3,4,5]),
                     torch.tensor([1,2])]
        self.labels = [0, 1, 0]

    def __len__(self): return len(self.data)
    def __getitem__(self, idx): return self.data[idx], self.labels[idx]

def custom_pad_collate(batch):
    # batch is a list of tuples: [(tensor1, label1), (tensor2, label2), ...]
    sequences = [item[0] for item in batch]
    labels = [item[1] for item in batch]

    # Pad sequences with 0
    padded_seqs = pad_sequence(sequences, batch_first=True, padding_value=0)

    # Convert labels to a single tensor
    labels_tensor = torch.tensor(labels)

    return padded_seqs, labels_tensor

dataset = VariableLengthDataset()

# Pass the custom collate function!
dataloader = DataLoader(dataset, batch_size=3, collate_fn=custom_pad_collate)

for batched_seqs, batched_labels in dataloader:
    print("Batched Sequences:\n", batched_seqs)
    print("Shape:", batched_seqs.shape)
    # Notice how the shorter sequences are padded with 0s at the end!
```
This is a critical NLP engineering skill. Text is inherently variable-length. `collate_fn` gives you a hook into the exact moment the prep cooks put the items on the tray, allowing you to re-arrange or pad them before handing them to the Chef!
</details>

# Tokenizers & BPE Encoding

## Phase A: Breaking Down Language for Machines

### 1. Real-World Pain Point (The Why)
Neural networks do not understand the letters "A", "B", or "C". They only understand numbers (tensors). Furthermore, standard English has millions of words, and new words are created daily. If you map every known word to a unique ID (1=hello, 2=world), your vocabulary size becomes unmanageably huge, and the model crashes when it encounters a new word it hasn't seen before ("out-of-vocabulary").

### 2. Plain English Metaphor (The What)
Think of translating English into a set of LEGO blocks.
* A simple model breaks sentences by whole words (too many unique LEGO sets required).
* Another model breaks sentences by individual letters (only 26 LEGO blocks, but building a sentence takes too long).
* **BPE (Byte-Pair Encoding) Tokenization** is the goldilocks zone. It breaks text into common syllables or sub-words. "Unhappiness" isn't one block, nor 11 blocks. It's three blocks: "Un", "happi", "ness". The model learns that "Un" usually means "not", and can apply that knowledge to new words like "Unbelievable".

### 3. Complete Runnable Code
```python
from transformers import AutoTokenizer

def investigate_tokenization():
    # 1. Load the tokenizer for a specific model (e.g., GPT-2 or BERT)
    # AutoTokenizer automatically fetches the correct logic/vocabulary
    model_name = "bert-base-uncased"
    tokenizer = AutoTokenizer.from_pretrained(model_name)

    text = "The unexplainable phenomenon!"

    # 2. Let's see how it splits the words (Tokens)
    tokens = tokenizer.tokenize(text)
    print(f"Original Text: {text}")
    print(f"Tokens (Sub-words): {tokens}")

    # 3. Convert those sub-words into integer IDs (Input IDs)
    # The model uses these IDs to look up vector representations (embeddings)
    token_ids = tokenizer.convert_tokens_to_ids(tokens)
    print(f"Token IDs: {token_ids}")

    # 4. The standard production way: call the tokenizer like a function
    # This adds special model-specific tokens (like [CLS] or [SEP])
    # and generates an attention mask.
    encoded_input = tokenizer(text, return_tensors="pt")

    print("\n--- Production Encoded Output ---")
    print(f"Input IDs Tensor:\n{encoded_input['input_ids']}")
    print(f"Attention Mask Tensor:\n{encoded_input['attention_mask']}")

    # 5. Decode back to text to see the special tokens
    decoded = tokenizer.decode(encoded_input['input_ids'][0])
    print(f"\nDecoded Text:\n{decoded}")

if __name__ == "__main__":
    investigate_tokenization()
```

### 4. Progressive Step-by-Step Breakdown

#### Step 1: `AutoTokenizer`
```python
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
```
Every model has a specific tokenizer it was trained with. You cannot mix them! If a model was trained using GPT's tokenizer, feeding it BERT's token IDs will result in garbage. `AutoTokenizer` ensures you always get the exact matching dictionary.

#### Step 2: Sub-word Splitting
```python
tokens = tokenizer.tokenize("unexplainable")
# Output: ['un', '##ex', '##plain', '##able']
```
Notice the `##`. BERT uses a WordPiece tokenizer (similar to BPE). The `##` denotes that this token is a continuation of a word, not the start of a new one. This is how the model handles rare or made-up words!

#### Step 3: `return_tensors="pt"` and Special Tokens
```python
encoded = tokenizer(text, return_tensors="pt")
```
When called directly, the tokenizer wraps your text in special tokens. For BERT, it adds `[CLS]` (ID 101) at the beginning and `[SEP]` (ID 102) at the end. It also converts the output directly into PyTorch tensors (`pt`) so it's instantly ready to be pushed to the GPU.

### 5. ASCII Data Flow
```text
"The unexplainable"
        |
   (Tokenizer)
        |
[CLS] the un ##ex ##plain ##able [SEP]  <-- (Sub-word Tokens)
  |    |   |   |     |      |      |
 101 1996 4895 4372 21085  3085   102   <-- (Input IDs)
```

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Forgetting to pass the `attention_mask` to the model. When you batch multiple sentences together, you have to pad the shorter ones with zeros. The model will try to read the zeros unless the `attention_mask` tells it to ignore them (1 = read, 0 = ignore).
* **Pro Tip:** Set `padding=True` and `truncation=True` when calling the tokenizer on a batch of texts. It automatically handles uniform batch sizes and prevents sequences from exceeding the model's maximum context length.

### Level 2: Real-World
**Challenge:** You are creating a batch processing pipeline. You have two sentences: "Short." and "This is a much longer sentence." Tokenize them together in a list, ensuring they are returned as PyTorch tensors, padded to the length of the longest sentence, and truncated if they somehow exceed 10 tokens.
<details>
<summary>Hint</summary>
Pass the list of strings to the tokenizer. Add arguments `padding=True`, `truncation=True`, `max_length=10`, and `return_tensors="pt"`.
</details>

<details>
<summary>Solution</summary>
```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
texts = ["Short.", "This is a much longer sentence that keeps going."]

batch = tokenizer(
    texts,
    padding=True,
    truncation=True,
    max_length=10,
    return_tensors="pt"
)

print(batch["input_ids"])
print(batch["attention_mask"])
# Notice the 0s in the first row padding it to the length of the second row!
```
</details>

### Level 3: Boss Level
**Challenge:** You are training a specialized coding model and need it to understand a new keyword `[COMPANY_SECRET]` as a single token, rather than splitting it up into `['[', 'company', '_', 'secret', ']']`.
Load a tokenizer, add `[COMPANY_SECRET]` as a new special token, and verify that the tokenizer now keeps it as a single ID when tokenizing "Deploying [COMPANY_SECRET] to production".
<details>
<summary>Hint</summary>
Use `tokenizer.add_special_tokens({'additional_special_tokens': ['[COMPANY_SECRET]']})`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
text = "Deploying [COMPANY_SECRET] to production."

# Before adding token
print("Before:", tokenizer.tokenize(text))
# Splits into: ['deploying', '[', 'company', '_', 'secret', ']', ...]

# Add the new token
new_tokens_added = tokenizer.add_special_tokens(
    {'additional_special_tokens': ['[COMPANY_SECRET]']}
)

# After adding token
print("After:", tokenizer.tokenize(text))
# Output: ['deploying', '[COMPANY_SECRET]', 'to', 'production', '.']

print("New Token ID:", tokenizer.convert_tokens_to_ids("[COMPANY_SECRET]"))

# Note: If you do this before training a model, you MUST resize
# the model's embedding layer using: model.resize_token_embeddings(len(tokenizer))
```
Expanding vocabularies is essential for domain adaptation (e.g., medical jargon, code syntax). Remember that adding a new token means the model needs to learn a new embedding for it, which requires retraining the embedding layer!
</details>

# Autograd & Backpropagation

## Phase A: Computational Graphs and Derivatives

### 1. Real-World Pain Point (The Why)
In machine learning, you define an error function (how wrong the model is) and want to adjust millions of weights to minimize that error. To know *how* to adjust them, you need the derivative (gradient) of the error with respect to every single weight. Manually deriving and coding the calculus for a 100-layer neural network is humanly impossible and highly error-prone.

### 2. Plain English Metaphor (The What)
Imagine you are adjusting knobs on an analog soundboard to get the perfect mix. Autograd is like a magical invisible wire connected to every knob. As you turn the knobs and produce a final sound (the output), the wires track exactly how every tiny adjustment influenced the final audio. When you realize the sound is bad (loss), the system instantly tells you exactly which way to turn every single knob to make it better.

### 3. Complete Runnable Code
```python
import torch

def linear_regression_autograd():
    # 1. Training Data: y = 2x + 1
    x = torch.tensor([1.0, 2.0, 3.0, 4.0])
    y_true = torch.tensor([3.0, 5.0, 7.0, 9.0])

    # 2. Initialize weights randomly WITH gradient tracking
    w = torch.tensor(0.0, requires_grad=True)
    b = torch.tensor(0.0, requires_grad=True)

    learning_rate = 0.01

    print("Initial weights:", w.item(), b.item())

    for epoch in range(10):
        # Forward pass: Compute predicted y
        y_pred = w * x + b

        # Compute loss (Mean Squared Error)
        loss = torch.mean((y_pred - y_true)**2)

        # Backward pass: Compute gradients
        loss.backward()

        # Update weights (Gradient Descent)
        # We use torch.no_grad() so this update step isn't tracked in the graph
        with torch.no_grad():
            w -= learning_rate * w.grad
            b -= learning_rate * b.grad

        # CLEAR gradients for the next loop!
        w.grad.zero_()
        b.grad.zero_()

        if epoch % 2 == 0:
            print(f"Epoch {epoch} | Loss: {loss.item():.4f} | w: {w.item():.4f}, b: {b.item():.4f}")

if __name__ == "__main__":
    linear_regression_autograd()
```

### 4. Progressive Step-by-Step Breakdown

#### Step 1: Tracking History
```python
w = torch.tensor(0.0, requires_grad=True)
```
By setting `requires_grad=True`, you tell PyTorch: "Start recording every mathematical operation performed on this tensor." PyTorch begins building a directed acyclic graph (DAG) in the background.

#### Step 2: The Backward Pass
```python
loss.backward()
```
This is the heart of deep learning. Starting from the `loss` tensor, PyTorch traverses the computational graph backward using the Chain Rule of calculus. It computes the partial derivatives and populates the `.grad` attribute of every tensor that had `requires_grad=True`.

#### Step 3: Zeroing Gradients
```python
w.grad.zero_()
```
By default, `.backward()` *accumulates* (adds) gradients into the `.grad` attribute. If you don't zero them out at the end of each training step, the gradients from epoch 1 will be added to epoch 2, destroying your math.

### 5. ASCII Data Flow
```text
(w)      (x)
  \      /
   \    /
    [ * ] (Multiply) --> tracked in graph
      |
      V      (b)
   (w * x)    /
        \   /
         [ + ] (Add) --> tracked in graph
           |
           V
        (y_pred)
```
*Forward pass builds this graph. `.backward()` traverses it bottom-to-top to compute gradients.*

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Forgetting `optimizer.zero_grad()` or `tensor.grad.zero_()`. Your loss will explode or stagnate, and you'll spend hours debugging your model architecture when the issue was just accumulating gradients.
* **Pro Tip:** Use `with torch.no_grad():` during inference (evaluation/testing). It shuts off the computational graph machinery, halving memory usage and significantly speeding up predictions.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Challenge:** Compute the gradient of $y = x^2$ with respect to $x$ at $x = 3$.
<details>
<summary>Hint</summary>
Create a tensor for $x$, set `requires_grad=True`, calculate $y$, call `y.backward()`, and print `x.grad`.
</details>

<details>
<summary>Solution</summary>
```python
import torch
x = torch.tensor(3.0, requires_grad=True)
y = x**2
y.backward()
print(x.grad) # 6.0 (since dy/dx = 2x)
```
</details>

### Level 2: Real-World
**Challenge:** You are fine-tuning a massive model, but you only want to train the *last* layer (a linear layer). Freeze the weights of an earlier tensor by disabling gradient calculation for it.
<details>
<summary>Hint</summary>
Set `.requires_grad = False` for the tensors you want to freeze.
</details>

<details>
<summary>Solution</summary>
```python
import torch

feature_weights = torch.randn(10, 10, requires_grad=True)
classifier_weights = torch.randn(2, 10, requires_grad=True)

# Freeze the feature extractor
feature_weights.requires_grad = False

# Only classifier_weights will have gradients computed
x = torch.randn(10)
features = torch.matmul(feature_weights, x)
logits = torch.matmul(classifier_weights, features)
loss = logits.sum()
loss.backward()

print(feature_weights.grad) # None
print(classifier_weights.grad) # Has values
```
</details>

### Level 3: Boss Level
**Challenge:** Implement a custom non-linear activation function using PyTorch's `torch.autograd.Function`. Create a custom ReLU function where the forward pass acts like standard ReLU ($max(0, x)$), but the backward pass passes gradients through unchanged (as if it was a linear function). This is a technique sometimes used in custom estimators (like the Straight-Through Estimator).
<details>
<summary>Hint</summary>
Subclass `torch.autograd.Function`. Implement static methods `forward(ctx, input)` and `backward(ctx, grad_output)`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
import torch

class StraightThroughReLU(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        # Standard ReLU forward pass
        return torch.clamp(x, min=0.0)

    @staticmethod
    def backward(ctx, grad_output):
        # Trick the network: pass the gradient straight through,
        # ignoring the zero-gradient property of ReLU for x < 0.
        return grad_output

# Test it
x = torch.tensor([-2.0, -1.0, 1.0, 2.0], requires_grad=True)
# Call the custom function using .apply
y = StraightThroughReLU.apply(x)
loss = y.sum()
loss.backward()

# Even though x had negative values, the gradients passed through!
print(f"Input: {x}")
print(f"Output: {y}")
print(f"Gradients: {x.grad}") # Will be [1., 1., 1., 1.]
```
This demonstrates complete control over the Autograd engine. By overriding the backward pass, you can implement custom mathematical estimators crucial for advanced research like quantizing neural networks.
</details>

# Tensors & GPU Acceleration

## Phase A: Tensors and GPU Device Management

### 1. Real-World Pain Point (The Why)
In machine learning, you are constantly multiplying massive arrays of numbers (weights and inputs). If you do this on a standard CPU, training even a small model can take weeks. You need a way to perform thousands of matrix operations simultaneously and easily move data to specialized hardware (GPUs) without rewriting all your math logic.

### 2. Plain English Metaphor (The What)
Think of a standard Python list as a single delivery van. It can carry data, but delivering 10,000 packages (doing 10,000 math operations) takes a long time because it has to deliver them one by one. A **Tensor** on a **GPU** is like a fleet of 10,000 delivery drones. They all take off at the same time, delivering all the packages instantly.

### 3. Complete Runnable Code
```python
import torch
import time

def benchmark_cpu_vs_gpu():
    # Size of the matrix
    N = 5000

    # 1. Create tensors on CPU
    print("Running on CPU...")
    tensor_a_cpu = torch.randn(N, N)
    tensor_b_cpu = torch.randn(N, N)

    start_time = time.time()
    result_cpu = torch.matmul(tensor_a_cpu, tensor_b_cpu)
    cpu_time = time.time() - start_time
    print(f"CPU Time: {cpu_time:.4f} seconds")

    # 2. Check for GPU and move tensors
    if torch.cuda.is_available():
        device = torch.device("cuda")
        print(f"\nRunning on GPU: {torch.cuda.get_device_name(0)}")

        # Move tensors to GPU
        tensor_a_gpu = tensor_a_cpu.to(device)
        tensor_b_gpu = tensor_b_cpu.to(device)

        # Warm-up (initialization overhead)
        _ = torch.matmul(tensor_a_gpu, tensor_b_gpu)

        start_time = time.time()
        result_gpu = torch.matmul(tensor_a_gpu, tensor_b_gpu)
        torch.cuda.synchronize() # Wait for GPU to finish
        gpu_time = time.time() - start_time

        print(f"GPU Time: {gpu_time:.4f} seconds")
        print(f"Speedup: {cpu_time/gpu_time:.2f}x")
    else:
        print("\nNo GPU available. Try Google Colab or Kaggle!")

if __name__ == "__main__":
    benchmark_cpu_vs_gpu()
```

### 4. Progressive Step-by-Step Breakdown

#### Step 1: Creating Tensors
```python
tensor_a_cpu = torch.randn(N, N)
```
We generate a massive $5000 \times 5000$ matrix filled with random numbers drawn from a normal distribution. By default, PyTorch creates this in the system's RAM (CPU).

#### Step 2: Defining the Device
```python
device = torch.device("cuda")
```
We define a target "device". `"cuda"` refers to NVIDIA's Compute Unified Device Architecture. If you had an Apple Silicon Mac, you'd use `"mps"`.

#### Step 3: Moving Data to GPU
```python
tensor_a_gpu = tensor_a_cpu.to(device)
```
This is the magic command. `.to(device)` physically transfers the gigabytes of data from your computer's RAM over the PCIe bus into the GPU's VRAM. Once there, any operations on `tensor_a_gpu` will execute on the GPU processors.

### 5. ASCII Data Flow
```text
[ System RAM (CPU) ]                   [ GPU VRAM (CUDA) ]
+------------------+                   +-----------------+
| tensor_a_cpu     | --- .to(cuda) --> | tensor_a_gpu    |
| (5000x5000)      |                   | (5000x5000)     |
+------------------+                   +-----------------+
        |                                      |
   torch.matmul                           torch.matmul
        V                                      V
    Very Slow                              Blazing Fast!
```

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Using `.cpu()` or `.cuda()` directly everywhere (e.g., `tensor.cuda()`). If you run this code on a machine without a GPU, it will crash.
* **Pro Tip:** Always use device-agnostic code: `device = torch.device("cuda" if torch.cuda.is_available() else "cpu")` and use `tensor.to(device)`.

### Level 2: Real-World
**Challenge:** Write a function `safe_tensor_add(a, b)` that takes two tensors, ensures they are on the same device (using `a`'s device), adds them together, and returns the result.
<details>
<summary>Hint</summary>
Check <code>a.device</code> and use `.to()` on <code>b</code>.
</details>

<details>
<summary>Solution</summary>
```python
import torch

def safe_tensor_add(a: torch.Tensor, b: torch.Tensor) -> torch.Tensor:
    b_on_a_device = b.to(a.device)
    return a + b_on_a_device
```
</details>

### Level 3: Boss Level
**Challenge:** Simulate a data loading bottleneck. Create a list of 100 large matrices on the CPU. Measure the time it takes to move them one-by-one to the GPU and multiply them by a pre-existing GPU matrix, versus concatenating them all into one massive tensor on the CPU, moving it to the GPU once, and doing a single batch matrix multiplication (`torch.bmm`).
<details>
<summary>Hint</summary>
Use <code>torch.stack()</code> to combine the list of tensors before moving them to the GPU.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
import torch
import time

def boss_level_benchmark():
    if not torch.cuda.is_available():
        return "Requires GPU"

    device = torch.device("cuda")
    N = 100
    size = 1000

    # 100 separate tensors on CPU
    cpu_tensors = [torch.randn(size, size) for _ in range(N)]
    weights_gpu = torch.randn(size, size, device=device)

    # Method 1: Iterative transfer and compute
    start = time.time()
    results = []
    for t in cpu_tensors:
        t_gpu = t.to(device)
        res = torch.matmul(t_gpu, weights_gpu)
        results.append(res)
    torch.cuda.synchronize()
    time1 = time.time() - start

    # Method 2: Batch transfer and compute
    start2 = time.time()
    # Stack into shape (100, 1000, 1000)
    batched_cpu = torch.stack(cpu_tensors)
    batched_gpu = batched_cpu.to(device)
    # Broadcast weights for bmm or just use matmul broadcasting
    res_batched = torch.matmul(batched_gpu, weights_gpu)
    torch.cuda.synchronize()
    time2 = time.time() - start2

    print(f"Iterative Time: {time1:.4f}s")
    print(f"Batched Time: {time2:.4f}s")

if __name__ == "__main__":
    boss_level_benchmark()
```
The walkthrough shows that transferring data over the PCIe bus has significant overhead. Batching minimizes this overhead by sending a large payload at once!
</details>

# 1.3 Reflexion and Self-Correction

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Imagine a Junior Developer writing code. They write a function, run the tests, and see a syntax error. A bad developer throws their hands up and says "It's broken!" A good developer reads the error trace, *reflects* on what caused it, and *corrects* the code.
Standard LLMs act like bad developers. If they generate Python code and it fails, they stop. We need to build a loop where the LLM evaluates its own output against an environment (like a Python interpreter), critiques its mistakes, and tries again. This is called **Reflexion**.

### 2. Plain English Metaphor (The What)
Think of **Reflexion** like a golfer hitting a ball.
1. **Initial Action:** The golfer swings and hits the ball into a sand trap.
2. **Evaluation (Observation):** The golfer sees the ball is in the sand.
3. **Critique:** "I swung too hard and aimed too far left."
4. **Correction:** On the next swing, they adjust their stance and power.
Reflexion agents maintain a memory of their past failed attempts and critiques to avoid repeating the same mistakes.

### 3. Complete Runnable Code

```python
import os
from langchain_openai import ChatOpenAI
from langchain.prompts import PromptTemplate
from langchain.schema.output_parser import StrOutputParser

os.environ["OPENAI_API_KEY"] = "your-api-key"
llm = ChatOpenAI(model="gpt-4", temperature=0) # GPT-4 is much better at coding

# A mock function to test generated code
def run_python_tests(code: str) -> str:
    """Executes code and returns success or the error message."""
    try:
        # DANGER: exec() is unsafe in production. Used here for educational concept.
        # We inject a test case to see if the generated function works.
        test_suite = code + "\nassert add_two(2) == 4\nassert add_two(-1) == 1"
        exec(test_suite, {})
        return "SUCCESS"
    except Exception as e:
        return f"ERROR: {type(e).__name__}: {str(e)}"

# The Generation Prompt
gen_prompt = PromptTemplate.from_template("""
Write a Python function named `add_two` that takes a number and adds 2.
Previous attempts and feedback:
{history}
Output ONLY the raw python code.
""")
gen_chain = gen_prompt | llm | StrOutputParser()

# The Reflexion Loop
if __name__ == "__main__":
    history = "No previous attempts."
    max_retries = 3

    for attempt in range(max_retries):
        print(f"\n--- Attempt {attempt + 1} ---")

        # 1. Generate Code
        code = gen_chain.invoke({"history": history})
        print(f"Generated Code:\n{code}")

        # 2. Evaluate against environment
        result = run_python_tests(code)
        print(f"Test Result: {result}")

        # 3. Success Check
        if result == "SUCCESS":
            print("Agent succeeded!")
            break

        # 4. Critique and Update History (Self-Correction)
        history += f"\nAttempt {attempt+1} Code:\n{code}\nResult: {result}\nCritique: Fix the error mentioned above."
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Environment (The Test)**
Reflexion requires an external environment to provide deterministic feedback. Here, `run_python_tests` acts as the environment. It runs the LLM's code against `assert` statements. If it fails, it captures the exact Python Exception.

**Step 2: The History Injection**
Look at the `gen_prompt`. It includes a `{history}` variable. If the agent fails attempt 1, attempt 2 will see *exactly* what code it wrote in attempt 1 and the exact error it caused. This prevents the LLM from hallucinating the same wrong answer twice.

**Step 3: The Iterative Loop**
We use a standard Python `for` loop to cap the retries (to prevent infinite loops and massive API bills). In each iteration, the agent generates, tests, and appends the failure to its growing history.

### 5. ASCII Data Flow

```text
       ┌──────────► [LLM Code Generator] ──────────┐
       │                                           │
[History/Critiques]                           [Generated Code]
       ▲                                           │
       │                                           ▼
       └──────── [Environment Tester] ◄────────────┘
                 (Pass? Exit loop)
                 (Fail? Extract Error)
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `exec()` or `eval()` on LLM-generated code on your local machine without a sandbox. An LLM hallucinating `os.system('rm -rf /')` will destroy your computer.
**Pro Tip:** In production, use Docker containers (like Dockerode) or specialized sandboxes (like E2B or modal) to execute LLM code safely.

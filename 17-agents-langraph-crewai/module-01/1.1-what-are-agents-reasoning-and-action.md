# 1.1 What are Agents? Reasoning and Action (ReAct)

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Imagine you built a "Trip Planner" using standard LLM chains. A chain executes a fixed sequence: 1) Generate destination, 2) Get weather, 3) Book hotel. But what if step 2 reveals a hurricane? The linear chain proceeds to step 3 anyway and blindly books a hotel in a disaster zone. Chains lack **autonomy**—they cannot adjust their behavior based on intermediate observations. We need a system that can "think, act, observe, and adjust" dynamically.

### 2. Plain English Metaphor (The What)
Think of a **Chain** like a factory assembly line. Everything moves forward in a rigid, predetermined sequence.
Think of an **Agent** like a human executive assistant. If you ask them to plan a trip, they don't follow a rigid script. They check the weather, and *if* it's bad, they *decide* to change the destination before booking a flight. They use a **Thought-Action-Observation loop**.

### 3. Complete Runnable Code

```python
import os
from langchain_openai import ChatOpenAI
from langchain.agents import initialize_agent, AgentType
from langchain.tools import tool

# Set up the LLM
os.environ["OPENAI_API_KEY"] = "your-api-key"
llm = ChatOpenAI(model="gpt-3.5-turbo", temperature=0)

# Define custom tools
@tool
def get_weather(location: str) -> str:
    """Returns the weather for a given location."""
    if "Miami" in location:
        return "Hurricane warning active."
    return "Sunny and clear."

@tool
def book_hotel(location: str) -> str:
    """Books a hotel in the specified location."""
    return f"Successfully booked a hotel in {location}."

# Initialize the Agent
tools = [get_weather, book_hotel]
agent = initialize_agent(
    tools,
    llm,
    agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION,
    verbose=True
)

# Run the agent
if __name__ == "__main__":
    response = agent.run("Plan a trip to Miami. Check the weather first, and if there is a hurricane, book a hotel in Denver instead.")
    print(f"Final Output: {response}")
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Define Tools as Capabilities**
We give the agent `get_weather` and `book_hotel`. Without tools, an LLM is a brain in a jar. With tools, it gains "hands" and "eyes." The docstrings (`"""..."""`) are crucial because they tell the LLM *when* and *how* to use the tool.

**Step 2: Initialize the ReAct Loop**
`AgentType.ZERO_SHOT_REACT_DESCRIPTION` tells the agent to use the ReAct (Reasoning + Acting) framework. It prompts the LLM to output its thought process, decide on an action, use a tool, and then observe the result.

**Step 3: Execution and Dynamic Adjustment**
When the agent runs, it first calls `get_weather("Miami")`. The observation returns "Hurricane warning active." The agent's next *Thought* will recognize the hurricane and dynamically pivot to call `book_hotel("Denver")` instead of blindly booking Miami.

### 5. ASCII Data Flow

```text
[User Prompt]
      │
      ▼
┌───────────────────────────────────────┐
│              AGENT LOOP               │
│                                       │
│  1. THOUGHT: "I need weather info."   │
│         │                             │
│  2. ACTION: Call get_weather("Miami") │
│         │                             │
│  3. OBSERVATION: "Hurricane!"         │
│         │                             │
│  4. THOUGHT: "I must switch to Denver"│
│         │                             │
│  5. ACTION: Call book_hotel("Denver") │
└───────────────────────────────────────┘
      │
      ▼
[Final Answer to User]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Giving an agent tools without writing descriptive docstrings. The LLM won't know when to use them, causing the agent to hallucinate tool usage or fail entirely.
**Pro Tip:** Treat your tool docstrings as mini-prompts. Be extremely explicit about the inputs, outputs, and edge cases (e.g., `"Input must be a fully qualified city name like 'Miami, FL'."`).

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Create a simple ReAct agent with a single tool that calculates the length of a string. Ask it to find the length of the word "Supercalifragilisticexpialidocious".
<details>
<summary>Hint</summary>
Use the `@tool` decorator in LangChain to define a function `get_string_length(text: str) -> int`.
</details>

<details>
<summary>Solution</summary>
```python
from langchain_openai import ChatOpenAI
from langchain.agents import initialize_agent, AgentType
from langchain.tools import tool

@tool
def get_string_length(text: str) -> int:
    """Calculates the length of a string."""
    return len(text)

llm = ChatOpenAI(temperature=0)
agent = initialize_agent([get_string_length], llm, agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION)
print(agent.run("How many characters are in Supercalifragilisticexpialidocious?"))
```
</details>

### Level 2 Real-World
**Task:** Build an e-commerce assistant agent with two tools: `check_inventory(item_id)` and `place_order(item_id)`. If the item is out of stock, it should apologize to the user and NOT place an order.
<details>
<summary>Hint</summary>
Mock the `check_inventory` to return "Out of stock" for item ID 123. Watch the ReAct trace to ensure it skips the order tool.
</details>

<details>
<summary>Solution</summary>
```python
from langchain_openai import ChatOpenAI
from langchain.agents import initialize_agent, AgentType
from langchain.tools import tool

@tool
def check_inventory(item_id: str) -> str:
    """Checks if an item is in stock."""
    if item_id == "123": return "Out of stock."
    return "In stock (10 remaining)."

@tool
def place_order(item_id: str) -> str:
    """Places an order for an item. Do not call this if the item is out of stock."""
    return f"Order placed for {item_id}."

llm = ChatOpenAI(temperature=0)
agent = initialize_agent([check_inventory, place_order], llm, agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION, verbose=True)
agent.run("I want to buy item 123.")
```
</details>

### Level 3 Boss Level (Cumulative)
**Task:** Build a "Trip Planning Agent" that dynamically responds to budget constraints. Give it a `get_flight_price(destination)` tool and a `book_flight(destination)` tool. If the price exceeds $500, the agent should dynamically use a `search_alternatives(region)` tool to find a cheaper city and book that instead.
<details>
<summary>Hint</summary>
You need 3 tools. The prompt must instruct the agent on the $500 limit rule.
</details>

<details>
<summary>Solution</summary>
```python
from langchain_openai import ChatOpenAI
from langchain.agents import initialize_agent, AgentType
from langchain.tools import tool

@tool
def get_flight_price(destination: str) -> int:
    """Returns the flight price in USD for a destination."""
    prices = {"Paris": 800, "London": 750, "Madrid": 400}
    return prices.get(destination, 1000)

@tool
def search_alternatives(region: str) -> str:
    """Finds alternative destinations in a region."""
    return "Madrid is a cheaper alternative in Europe."

@tool
def book_flight(destination: str) -> str:
    """Books a flight to the destination."""
    return f"Flight booked to {destination}!"

llm = ChatOpenAI(temperature=0)
tools = [get_flight_price, search_alternatives, book_flight]
agent = initialize_agent(tools, llm, agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION, verbose=True)

prompt = """
Plan a trip to Paris. You have a budget of $500 for flights.
If Paris is too expensive, find an alternative in Europe and book that instead.
"""
print(agent.run(prompt))
```
</details>

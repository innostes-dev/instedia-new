# 2.1 Why Graphs? StateGraph Fundamentals

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
In standard LLM chains (like LCEL or Directed Acyclic Graphs - DAGs), data flows one way. Step A -> Step B -> Step C. But what if Step C fails and we need to go back to Step A to retry? DAGs strictly forbid cycles (loops). Agents *require* loops to function (like ReAct: Reason -> Act -> Observe -> Reason again). To build robust agentic loops in production without writing messy `while True` scripts, we need a framework that natively supports cyclical graph execution.

### 2. Plain English Metaphor (The What)
Think of a standard pipeline (DAG) like a water slide: once you go down, you can only go forward until you hit the pool. You cannot go back up the slide.
Think of LangGraph (`StateGraph`) like a board game (e.g., Monopoly). You roll the dice, move to a square (a Node), follow the rules on that square, and depending on the outcome, you might go forward, go to jail, or loop all the way back to "GO" (an Edge). The board game maintains the current state of play (where everyone is, how much money they have) at all times.

### 3. Complete Runnable Code

```python
import os
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

os.environ["OPENAI_API_KEY"] = "your-api-key"
llm = ChatOpenAI(model="gpt-3.5-turbo")

# 1. Define the State (The Board Game's Memory)
class AgentState(TypedDict):
    input_text: str
    processed_text: str

# 2. Define the Nodes (The Squares on the Board)
def uppercase_node(state: AgentState):
    """A simple node that uppercases the input."""
    return {"processed_text": state["input_text"].upper()}

def llm_node(state: AgentState):
    """A node that asks an LLM to add an exclamation."""
    response = llm.invoke([HumanMessage(content=f"Add an enthusiastic exclamation to: {state['processed_text']}")])
    return {"processed_text": response.content}

# 3. Build the Graph (The Board)
graph_builder = StateGraph(AgentState)

# Add nodes
graph_builder.add_node("uppercase", uppercase_node)
graph_builder.add_node("llm", llm_node)

# Add edges (The paths between squares)
graph_builder.set_entry_point("uppercase")
graph_builder.add_edge("uppercase", "llm")
graph_builder.add_edge("llm", END) # END is a special node meaning "stop"

# 4. Compile and Run
app = graph_builder.compile()

if __name__ == "__main__":
    initial_state = {"input_text": "hello langgraph"}
    result = app.invoke(initial_state)
    print(f"Final State: {result['processed_text']}")
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Define the State (`TypedDict`)**
Every LangGraph application starts with a State. This is a dictionary that gets passed between every node. When a node returns a dictionary, LangGraph updates the main State with those new values.

**Step 2: Define Nodes (Python Functions)**
Nodes are just Python functions that take the current `state` as an argument, do some work, and return a dictionary containing updates to the state. They don't have to use LLMs; they can just be standard Python code (like `uppercase_node`).

**Step 3: Build the Graph (Nodes and Edges)**
You initialize the `StateGraph` passing in your State definition. You add your nodes, and then draw the lines (edges) between them. `set_entry_point` tells the graph where to start. `END` tells it where to stop.

**Step 4: Compile**
`.compile()` freezes the graph structure so it can be executed. Once compiled, it acts like a standard Runnable, meaning you can call `.invoke()` on it.

### 5. ASCII Data Flow

```text
       [Initial State]
       {"input_text": "hello"}
              │
              ▼
      (Entry Point)
              │
              ▼
   ┌─────────────────────┐
   │ NODE: uppercase     │──► returns {"processed_text": "HELLO"}
   └─────────────────────┘
              │ (State updates)
              ▼
   ┌─────────────────────┐
   │ NODE: llm           │──► returns {"processed_text": "HELLO WOW!"}
   └─────────────────────┘
              │ (State updates)
              ▼
           (END)
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Forgetting to return a dictionary from a Node function. If a node returns `None` or just a string, LangGraph will throw an error because it doesn't know how to update the `TypedDict` state.
**Pro Tip:** Use graph visualization tools! You can visualize your compiled graph by calling `app.get_graph().draw_mermaid()`. This generates a Mermaid diagram string you can paste into a visualizer to debug your flow.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Create a graph with three nodes: `add_one`, `multiply_two`, and `subtract_three`. The state should just be `{"number": int}`. Route the graph sequentially through all three and print the final result if you start with `number: 5`.
<details>
<summary>Hint</summary>
Define `class MathState(TypedDict): number: int`. Each node function should take state, modify the number, and return `{"number": new_val}`.
</details>

<details>
<summary>Solution</summary>
```python
from typing import TypedDict
from langgraph.graph import StateGraph, END

class MathState(TypedDict):
    number: int

def add_one(state): return {"number": state["number"] + 1}
def multiply_two(state): return {"number": state["number"] * 2}
def subtract_three(state): return {"number": state["number"] - 3}

builder = StateGraph(MathState)
builder.add_node("n1", add_one)
builder.add_node("n2", multiply_two)
builder.add_node("n3", subtract_three)

builder.set_entry_point("n1")
builder.add_edge("n1", "n2")
builder.add_edge("n2", "n3")
builder.add_edge("n3", END)

app = builder.compile()
print(app.invoke({"number": 5})) # (5+1)*2-3 = 9
```
</details>

### Level 2 Real-World
**Task:** Build a Data Cleaning pipeline. State is `{"raw_data": str, "clean_data": str}`. Node 1 removes whitespace. Node 2 uses an LLM to correct spelling in `clean_data`.
<details>
<summary>Hint</summary>
Node 1 should read `raw_data`, `.strip()` it, and write to `clean_data`. Node 2 reads `clean_data`, prompts the LLM to fix spelling, and overwrites `clean_data`.
</details>

<details>
<summary>Solution</summary>
```python
import os
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

class CleanState(TypedDict):
    raw_data: str
    clean_data: str

def trim_node(state):
    return {"clean_data": state["raw_data"].strip()}

def spell_node(state):
    llm = ChatOpenAI(temperature=0)
    res = llm.invoke([HumanMessage(content=f"Fix spelling: {state['clean_data']}")])
    return {"clean_data": res.content}

b = StateGraph(CleanState)
b.add_node("trim", trim_node)
b.add_node("spell", spell_node)
b.set_entry_point("trim")
b.add_edge("trim", "spell")
b.add_edge("spell", END)

app = b.compile()
print(app.invoke({"raw_data": "   helo worlld   "}))
```
</details>

### Level 3 Boss Level (Cumulative)
**Task:** Build a cyclic graph (a loop) without conditional edges (we haven't learned those yet, so we will use a manual counter). Build a state with `{"count": int, "text": str}`. Node 1 adds an "A" to `text` and increments `count`. Loop Node 1 to itself. *Wait, LangGraph will infinitely loop!* To fix this, LangGraph has a `recursion_limit` parameter on `.invoke()`. Set it to 5 and catch the `GraphRecursionError`.
<details>
<summary>Hint</summary>
`builder.add_edge("n1", "n1")`. When running, use `app.invoke(state, {"recursion_limit": 5})`.
</details>

<details>
<summary>Solution</summary>
```python
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langgraph.errors import GraphRecursionError

class LoopState(TypedDict):
    count: int
    text: str

def loop_node(state):
    return {"count": state["count"] + 1, "text": state["text"] + "A"}

b = StateGraph(LoopState)
b.add_node("looper", loop_node)
b.set_entry_point("looper")
b.add_edge("looper", "looper") # Explicit cycle!

app = b.compile()

try:
    # It will loop until it hits the recursion limit
    app.invoke({"count": 0, "text": ""}, {"recursion_limit": 5})
except GraphRecursionError:
    print("Hit recursion limit! Graph successfully looped.")
```
</details>

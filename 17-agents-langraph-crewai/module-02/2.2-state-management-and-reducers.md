# 2.2 State Management and Reducers

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
In a standard dictionary, if a key holds a string and you update that key with a new string, the old string is overwritten and lost. But in conversational agents, if Node A generates a message, and Node B generates another message, you don't want to *overwrite* Node A's message. You want to *append* Node B's message to a list of messages. Managing how state updates happen (Overwrite vs. Append) is critical for agent memory.

### 2. Plain English Metaphor (The What)
Think of a Reducer like a clerk filing paperwork.
- **Overwrite (Default):** You hand the clerk a new "Current Address" form. The clerk throws away your old address form and puts the new one in the folder.
- **Append (Reducer):** You hand the clerk a new "Medical Record" form. The clerk does *not* throw away your old records; they *staple* the new record to the back of the stack.
In LangGraph, you use `Annotated` and `operator.add` to tell the graph to act like the second clerk.

### 3. Complete Runnable Code

```python
import operator
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, END

# 1. Define State with a Reducer
class UberState(TypedDict):
    driver_name: str # Default behavior: Overwrite
    # Annotated[type, reducer_function]
    # operator.add on lists means: old_list + new_list (append)
    status_updates: Annotated[list[str], operator.add]

# 2. Nodes
def assign_driver(state: UberState):
    # Returns a new driver_name (overwriting old one if it existed)
    # Returns a list of updates (which the reducer will append to the existing list)
    return {
        "driver_name": "Alice",
        "status_updates": ["Driver Alice assigned."]
    }

def driver_arriving(state: UberState):
    # Notice we don't return driver_name here, so it remains unchanged in state.
    # We return a new update, which gets appended.
    return {
        "status_updates": [f"Driver {state.get('driver_name')} is 2 mins away."]
    }

# 3. Build Graph
builder = StateGraph(UberState)
builder.add_node("assign", assign_driver)
builder.add_node("arrive", driver_arriving)

builder.set_entry_point("assign")
builder.add_edge("assign", "arrive")
builder.add_edge("arrive", END)

app = builder.compile()

if __name__ == "__main__":
    # Initial state
    start = {"driver_name": "Pending", "status_updates": ["Ride requested."]}

    final_state = app.invoke(start)

    print(f"Final Driver: {final_state['driver_name']}")
    print("Updates Log:")
    for update in final_state['status_updates']:
        print(f" - {update}")
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Default Behavior (Overwrite)**
The `driver_name: str` field has no annotations. When the initial state is `{"driver_name": "Pending"}` and `assign_driver` returns `{"driver_name": "Alice"}`, LangGraph simply overwrites "Pending" with "Alice".

**Step 2: The Reducer (`Annotated` and `operator.add`)**
The `status_updates` field is declared as `Annotated[list[str], operator.add]`.
When `assign_driver` returns `{"status_updates": ["Driver Alice assigned."]}`, LangGraph takes the existing list `["Ride requested."]`, runs `operator.add` against the new list, resulting in `["Ride requested.", "Driver Alice assigned."]`.

**Step 3: Partial Updates**
Look at the `driver_arriving` node. It returns `{"status_updates": [...]}` but *does not* return `driver_name`. In LangGraph, if a node doesn't return a key, that key is left untouched in the master state. You only return what you want to change.

### 5. ASCII Data Flow

```text
       [Initial State]
       name: "Pending"
       updates: ["Req"]
              │
              ▼
   ┌──────────────────────┐
   │ NODE: assign         │──► returns {"name": "Alice", "updates": ["Assign"]}
   └──────────────────────┘
              │
              ▼ (LangGraph applies reducers)
       [State Updated]
       name: "Alice" (Overwritten)
       updates: ["Req", "Assign"] (Appended)
              │
              ▼
   ┌──────────────────────┐
   │ NODE: arrive         │──► returns {"updates": ["Arriving"]}
   └──────────────────────┘
              │
              ▼ (LangGraph applies reducers)
       [Final State]
       name: "Alice" (Untouched)
       updates: ["Req", "Assign", "Arriving"] (Appended)
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `operator.add` on a string. If state is `name: Annotated[str, operator.add]`, and you return `{"name": "Smith"}`, it will concatenate strings! "Alice" + "Smith" = "AliceSmith". Only use `operator.add` on Lists!
**Pro Tip:** For managing chat histories with LLMs, LangGraph provides a built-in reducer. You can use `from langgraph.graph.message import add_messages`. So your state looks like `messages: Annotated[list[AnyMessage], add_messages]`. It handles appending messages and preventing duplicate IDs automatically.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Build a "Bank Account" graph. State has `balance: int` and `transactions: Annotated[list[int], operator.add]`. Create a `deposit_50` node and a `withdraw_20` node.
<details>
<summary>Hint</summary>
When depositing 50, return `{"balance": state["balance"] + 50, "transactions": [50]}`.
</details>

<details>
<summary>Solution</summary>
```python
import operator
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, END

class BankState(TypedDict):
    balance: int
    transactions: Annotated[list[int], operator.add]

def dep(state): return {"balance": state["balance"] + 50, "transactions": [50]}
def withd(state): return {"balance": state["balance"] - 20, "transactions": [-20]}

b = StateGraph(BankState)
b.add_node("d", dep)
b.add_node("w", withd)
b.set_entry_point("d")
b.add_edge("d", "w")
b.add_edge("w", END)

app = b.compile()
print(app.invoke({"balance": 100, "transactions": []}))
# output balance 130, transactions [50, -20]
```
</details>

### Level 2 Real-World
**Task:** Create a Chatbot state using `add_messages`. Create a node that takes a user message and generates an AI response, appending it to the state.
<details>
<summary>Hint</summary>
Import `add_messages` from `langgraph.graph.message`. The state should have `messages: Annotated[list, add_messages]`. Pass the state's message list directly to the LLM.
</details>

<details>
<summary>Solution</summary>
```python
import os
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, END
from langgraph.graph.message import add_messages
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

class ChatState(TypedDict):
    messages: Annotated[list, add_messages]

def chat_node(state: ChatState):
    llm = ChatOpenAI(temperature=0)
    response = llm.invoke(state["messages"])
    # return the new message, add_messages will append it
    return {"messages": [response]}

b = StateGraph(ChatState)
b.add_node("chat", chat_node)
b.set_entry_point("chat")
b.add_edge("chat", END)

app = b.compile()
res = app.invoke({"messages": [HumanMessage(content="Hello AI")]})
print(res["messages"][-1].content)
```
</details>

### Level 3 Boss Level (Cumulative)
**Task:** Build a Custom Reducer. Suppose you want a `top_3_scores` state field that keeps only the highest 3 integers it has ever seen, no matter what node returns what. Create a custom reducer function `keep_top_3(old_list, new_list)` and use it in `Annotated`.
<details>
<summary>Hint</summary>
A reducer function takes `(left, right)` (i.e., `old_value, new_value`). Combine them, sort descending, and slice `[:3]`.
</details>

<details>
<summary>Solution</summary>
```python
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, END

def keep_top_3(left: list[int], right: list[int]) -> list[int]:
    """Custom reducer to maintain top 3 scores."""
    if not left: left = []
    if not right: right = []
    combined = left + right
    return sorted(combined, reverse=True)[:3]

class GameState(TypedDict):
    scores: Annotated[list[int], keep_top_3]

def play_game_1(state): return {"scores": [10, 50]}
def play_game_2(state): return {"scores": [5, 100, 20]}

b = StateGraph(GameState)
b.add_node("p1", play_game_1)
b.add_node("p2", play_game_2)
b.set_entry_point("p1")
b.add_edge("p1", "p2")
b.add_edge("p2", END)

app = b.compile()
# Initially empty. p1 adds 10, 50. p2 adds 5, 100, 20. Total: 100, 50, 20, 10, 5. Top 3 is 100, 50, 20.
print(app.invoke({"scores": []}))
```
</details>

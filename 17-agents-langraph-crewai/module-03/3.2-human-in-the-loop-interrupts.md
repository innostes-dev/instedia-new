# 3.2 Human-in-the-Loop & Interrupts

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Imagine building an Autonomous Agent that has access to a company's Stripe API to issue refunds. The LLM handles the conversation, decides a refund is valid, and executes the tool. But what if it hallucinates and issues a $10,000 refund instead of $10? For high-risk actions, we cannot rely on 100% autonomy. We need the graph to pause execution right before the critical node, alert a human manager, allow the manager to inspect the proposed action (the state), and either approve it, edit it, or cancel it.

### 2. Plain English Metaphor (The What)
Think of a production line making cars. The robots (Nodes) assemble the chassis, put in the engine, and attach the doors automatically. But before the car is sent to the dealership, it reaches a Quality Assurance gate. The assembly line **halts**. A human inspector walks up, looks at the car (reads the state), signs a clipboard (approves the state), and hits a button to **resume** the line.

### 3. Complete Runnable Code

```python
import os
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

# 1. Define State
class RefundState(TypedDict):
    user_id: str
    refund_amount: int
    human_approved: bool

# 2. Nodes
def draft_refund(state: RefundState):
    """Agent decides on a refund amount."""
    # Mocking LLM logic
    print("Agent: Drafting refund for $1000...")
    return {"refund_amount": 1000, "human_approved": False}

def execute_refund(state: RefundState):
    """High-risk tool node."""
    if state["human_approved"]:
        print(f"Executing REAL refund of ${state['refund_amount']} to {state['user_id']}")
    else:
        print("Refund rejected by human.")
    return {}

# 3. Build Graph
builder = StateGraph(RefundState)
builder.add_node("draft", draft_refund)
builder.add_node("execute", execute_refund)

builder.set_entry_point("draft")
builder.add_edge("draft", "execute")
builder.add_edge("execute", END)

# 4. Compile with interrupt_before
memory = MemorySaver()
# YOU MUST HAVE A CHECKPOINTER TO USE INTERRUPTS!
app = builder.compile(
    checkpointer=memory,
    interrupt_before=["execute"] # Graph pauses BEFORE entering the 'execute' node
)

if __name__ == "__main__":
    config = {"configurable": {"thread_id": "refund_case_1"}}

    # 5. Run Graph (It will pause)
    print("--- First Run ---")
    app.invoke({"user_id": "cust_123"}, config)

    # 6. Human Review
    current_state = app.get_state(config).values
    print(f"\n[HUMAN REVIEW REQUIRED]")
    print(f"Agent wants to refund: ${current_state['refund_amount']}")

    # Human decides to approve it, but ONLY for $500. We UPDATE the state manually.
    app.update_state(config, {"refund_amount": 500, "human_approved": True})
    print("[HUMAN]: Updated amount to $500 and approved.\n")

    # 7. Resume Graph
    print("--- Resuming Graph ---")
    # To resume, invoke with None (no new input) and the same config
    app.invoke(None, config)
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Checkpointer Requirement**
You cannot use `interrupt_before` or `interrupt_after` without a Checkpointer. Why? Because when the graph pauses, the Python script technically finishes that specific `.invoke()` call. The only way it knows where it was when you try to resume it is by saving that "paused state" to the database.

**Step 2: `interrupt_before`**
By passing `interrupt_before=["execute"]` into `.compile()`, LangGraph runs `draft_refund`, updates the state, and then *stops*. The `.invoke()` returns. The graph is now in a suspended state.

**Step 3: `app.update_state()`**
This is the magic. While the graph is paused, the human can call `.get_state()` to see what the AI planned to do. Then, they use `.update_state(config, {"key": "new_value"})` to literally overwrite the AI's variables in the database before letting the graph continue.

**Step 4: Resuming with `None`**
To unpause the graph, you call `app.invoke(None, config)`. Passing `None` tells LangGraph: "I don't have a new message for the start of the graph. Just load the paused thread and keep going from exactly where you stopped."

### 5. ASCII Data Flow

```text
       invoke({"user_id": "cust_123"})
                   │
                   ▼
         ┌───────────────────┐
         │   NODE: draft     │──► Sets refund_amount = 1000
         └───────────────────┘
                   │
      [ INTERRUPT: paused in DB ] ◄── (Python script stops here)


       (Human inspects DB via get_state)
       (Human edits DB via update_state)


       invoke(None)
                   │
         [ RESUME from pause ]
                   │
                   ▼
         ┌───────────────────┐
         │  NODE: execute    │──► Reads edited DB: refund = 500
         └───────────────────┘
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `update_state` as a specific node name when meaning to edit data. `update_state` modifies the *current* node's output in the state history. If you want it to act as if a specific node outputted the data, you can pass an `as_node` parameter: `app.update_state(config, {"data": "val"}, as_node="human_node")`.
**Pro Tip:** You can also use `interrupt_after=["some_node"]`. This is useful if you want a tool to execute, but then pause the graph so a human can review the *result* of the tool before the LLM formulates an answer to the user.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Build a Two-Step math graph. Node 1 adds 10 to a number. Node 2 multiplies by 2. Pause before Node 2. Start with number 5. Node 1 makes it 15. The human reviews it, uses `update_state` to change the number to 20. Resume. Final output should be 40.
<details>
<summary>Hint</summary>
State is `{"num": int}`. `interrupt_before=["multiply"]`.
</details>

<details>
<summary>Solution</summary>
```python
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

class Num(TypedDict): num: int
def add10(s): return {"num": s["num"] + 10}
def mult2(s): return {"num": s["num"] * 2}

b = StateGraph(Num)
b.add_node("a", add10)
b.add_node("m", mult2)
b.set_entry_point("a")
b.add_edge("a", "m")
b.add_edge("m", END)

app = b.compile(checkpointer=MemorySaver(), interrupt_before=["m"])
c = {"configurable": {"thread_id": "1"}}

app.invoke({"num": 5}, c)
app.update_state(c, {"num": 20})
res = app.invoke(None, c)
print(res["num"]) # 40
```
</details>

### Level 2 Real-World
**Task:** Email Drafting Agent. Node 1 (LLM) drafts an angry email to a competitor. Pause before Node 2 (Send). A human reads the draft via `get_state`, gets terrified, and uses `update_state` to replace the draft text with "Have a great day!". Resume to send.

<summary>Hint</summary>
Just mock the LLM and the send tool with print statements.
</details>

<details>
<summary>Solution</summary>
```python
class Email(TypedDict): text: str

def draft(s): return {"text": "You guys are the worst!"}
def send(s): print(f"Sending: {s['text']}"); return {}

b = StateGraph(Email)
b.add_node("d", draft)
b.add_node("s", send)
b.set_entry_point("d")
b.add_edge("d", "s")
b.add_edge("s", END)

app = b.compile(checkpointer=MemorySaver(), interrupt_before=["s"])
c = {"configurable": {"thread_id": "email_1"}}

app.invoke({"text": ""}, c)
print(f"Draft: {app.get_state(c).values['text']}")
app.update_state(c, {"text": "Have a great day!"})
app.invoke(None, c)
```

### Level 3 Boss Level (Cumulative)
**Task:** Stripe High-Risk Wire Transfer Flow.
State: `amount: int`, `risk_level: str`, `status: str`.
1. `AssessNode`: Sets `risk_level` to "HIGH" if amount > $50,000, else "LOW".
2. `Router`: If LOW -> `ExecuteNode`. If HIGH -> `HumanApprovalNode`.
3. `HumanApprovalNode`: Doesn't do anything computationally! It just exists as a target for `interrupt_before`.
4. Compile with `interrupt_before=["HumanApprovalNode"]`.
5. Run with $100,000. It will route to HumanApprovalNode and pause. The human updates `status` to "APPROVED". Resume. Next edge goes to `ExecuteNode`.
<details>
<summary>Hint</summary>
`HumanApprovalNode` is basically a dummy node: `def human_node(state): return {}`. Its only purpose is to act as a breakpoint.
</details>

<details>
<summary>Solution</summary>
```python
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

class WireState(TypedDict):
    amount: int
    risk_level: str
    status: str

def assess(state):
    risk = "HIGH" if state["amount"] > 50000 else "LOW"
    return {"risk_level": risk, "status": "PENDING"}

def dummy_human(state): return {} # Just a breakpoint

def execute(state):
    if state["status"] == "APPROVED" or state["risk_level"] == "LOW":
        print("Wire transfer executed!")
    else:
        print("Wire transfer denied.")
    return {}

def route(state):
    if state["risk_level"] == "HIGH": return "human"
    return "execute"

b = StateGraph(WireState)
b.add_node("assess", assess)
b.add_node("human", dummy_human)
b.add_node("execute", execute)

b.set_entry_point("assess")
b.add_conditional_edges("assess", route)
b.add_edge("human", "execute")
b.add_edge("execute", END)

app = b.compile(checkpointer=MemorySaver(), interrupt_before=["human"])
c = {"configurable": {"thread_id": "wire_1"}}

print("Initiating $100k wire...")
app.invoke({"amount": 100000, "risk_level": "", "status": ""}, c)

current = app.get_state(c).values
print(f"Paused. State: {current}")

print("Human approving...")
app.update_state(c, {"status": "APPROVED"})
app.invoke(None, c)
```
</details>

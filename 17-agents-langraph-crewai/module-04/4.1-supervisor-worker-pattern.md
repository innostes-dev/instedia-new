# 4.1 Supervisor-Worker Pattern

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Imagine a software agency. If a client wants a website, you don't give the job to one "Omni-Agent" and tell it to write the code, design the logo, and write the copy. It will get confused, lose context, and fail. You need a hierarchical structure: A Project Manager (Supervisor) talks to the client, breaks the project into tasks, and delegates them to specialized workers (a Coder, a Designer, a Writer). The Supervisor reviews their work and compiles the final product.

### 2. Plain English Metaphor (The What)
Think of the **Supervisor** as the conductor of an orchestra. They don't play any instruments themselves.
Think of the **Workers** as the musicians (violins, cellos).
The conductor reads the sheet music (the user's prompt), points to the violin section (routes to Worker A), listens to what they play (observes the state), and then points to the cellos (routes to Worker B), until the symphony is complete.

### 3. Complete Runnable Code

```python
import os
import operator
from typing import TypedDict, Annotated, Literal
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

os.environ["OPENAI_API_KEY"] = "your-api-key"
llm = ChatOpenAI(model="gpt-3.5-turbo", temperature=0)

# 1. State (Must have a reducer for a shared scratchpad)
class TeamState(TypedDict):
    task: str
    scratchpad: Annotated[list[str], operator.add]
    next_worker: str

# 2. Worker Nodes (The Specialists)
def researcher_node(state: TeamState):
    """Specializes in gathering facts."""
    print("-> Researcher working...")
    # Mocking actual research
    result = "Research: The market for AI is growing 30% YoY."
    return {"scratchpad": [result]}

def writer_node(state: TeamState):
    """Specializes in formatting text."""
    print("-> Writer working...")
    # Mocking writing
    result = "Writing: Here is a drafted report based on the research."
    return {"scratchpad": [result]}

# 3. The Supervisor Node (The Conductor)
def supervisor_node(state: TeamState):
    """Reads the scratchpad and decides who should act next, or if we are done."""
    print("-> Supervisor deciding...")
    sys_prompt = """You are a supervisor managing a Researcher and a Writer.
    Based on the task and current scratchpad, who should act next?
    Output ONLY: 'Researcher', 'Writer', or 'FINISH'."""

    prompt = f"Task: {state['task']}\nScratchpad: {state['scratchpad']}"

    response = llm.invoke([
        SystemMessage(content=sys_prompt),
        HumanMessage(content=prompt)
    ]).content.strip()

    return {"next_worker": response}

# 4. The Router (Connects Supervisor's decision to actual graph edges)
def supervisor_router(state: TeamState) -> Literal["researcher", "writer", "__end__"]:
    if state["next_worker"] == "Researcher": return "researcher"
    if state["next_worker"] == "Writer": return "writer"
    return END

# 5. Build Graph
builder = StateGraph(TeamState)

builder.add_node("supervisor", supervisor_node)
builder.add_node("researcher", researcher_node)
builder.add_node("writer", writer_node)

builder.set_entry_point("supervisor")

# Supervisor routes to workers
builder.add_conditional_edges("supervisor", supervisor_router)

# Workers always report BACK to the supervisor
builder.add_edge("researcher", "supervisor")
builder.add_edge("writer", "supervisor")

app = builder.compile()

if __name__ == "__main__":
    initial_state = {
        "task": "Research the AI market and write a short report.",
        "scratchpad": [],
        "next_worker": ""
    }

    final_state = app.invoke(initial_state, {"recursion_limit": 10})
    print("\nFinal Scratchpad:")
    for note in final_state["scratchpad"]:
        print(note)
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Shared State (`scratchpad`)**
The `TeamState` acts as a shared conference table. Because we use `operator.add`, when the Researcher returns a string, it gets appended to the list. When the Writer returns a string, it gets appended.

**Step 2: The Supervisor Logic**
The Supervisor doesn't do the work. It takes the user's `task` and looks at the current `scratchpad`. If the scratchpad is empty, the LLM will logically deduce it needs to call the Researcher. If the scratchpad has research but no draft, it will call the Writer. If both exist, it will output "FINISH".

**Step 3: The Hub-and-Spoke Topology**
Notice the edges: `supervisor -> (conditional) -> worker`. And `worker -> supervisor`. Every worker node strictly points back to the supervisor. The supervisor acts as a central hub routing traffic.

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using standard OpenAI function calling/tool calling to create the Supervisor. While possible, returning standard JSON from a tool call can be flaky for routing. It's often better to instruct the LLM to output a single specific string (like `"Researcher"`) and use a standard Python router function to map that string to the LangGraph node name.
**Pro Tip:** If you have many workers, passing the *entire* scratchpad to every worker wastes tokens. You can write custom logic in your conditional edges to pass a filtered sub-state to specific workers.

### Level 2 Real-World
**Task:** Ensure deterministic routing without LLM hallucination. Sometimes the LLM outputs "Researcher " (with a space) or "Call the Researcher". This breaks the router. Modify the `supervisor_node` to use LangChain's `.with_structured_output()` to force the LLM to return a Pydantic model with a strict enum.
<details>
<summary>Hint</summary>
```python
from pydantic import BaseModel, Field
from typing import Literal

class RouteDecision(BaseModel):
    next: Literal["Researcher", "Writer", "FINISH"]
```
</details>

<details>
<summary>Solution</summary>
```python
from pydantic import BaseModel
from typing import Literal

class RouteDecision(BaseModel):
    next: Literal["Researcher", "Writer", "FINISH"]

def supervisor_node(state):
    structured_llm = llm.with_structured_output(RouteDecision)
    sys = "You are a supervisor. Decide next step."
    # The LLM is forced to return the Pydantic object
    decision = structured_llm.invoke([SystemMessage(content=sys), HumanMessage(content=str(state))])
    return {"next_worker": decision.next}
```
</details>

### Level 3 Boss Level (Cumulative)
**Task:** Competitive Intelligence Multi-Agent Team (Parallel Workers).
Instead of the supervisor calling one worker at a time, what if the task is "Research Apple, Google, and Microsoft"? It's slow to do sequentially. We can use LangGraph's `Send` API to spawn multiple worker nodes in parallel!
Create a Supervisor that extracts a list of companies from the prompt. Create a `research_company` node. The router should return a list of `Send` objects, one for each company.
<details>
<summary>Hint</summary>
You need to import `Send` from `langgraph.constants`.
In your router: `return [Send("research_company", {"company_name": c}) for c in list_of_companies]`.
</details>

<details>
<summary>Solution</summary>
```python
import operator
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, END
from langgraph.constants import Send

class MainState(TypedDict):
    prompt: str
    companies: list[str]
    reports: Annotated[list[str], operator.add]

# Note: Parallel worker needs its own strict state schema
class WorkerState(TypedDict):
    company_name: str

def supervisor(state: MainState):
    # Mock extracting companies from prompt
    return {"companies": ["Apple", "Google", "Microsoft"]}

def research_company(state: WorkerState):
    # This runs in parallel for each company!
    return {"reports": [f"Report on {state['company_name']} done."]}

def parallel_router(state: MainState):
    if not state["companies"]: return END
    # Spawns a 'research_company' node for EVERY item in the list
    return [Send("research_company", {"company_name": c}) for c in state["companies"]]

b = StateGraph(MainState)
b.add_node("super", supervisor)
b.add_node("research_company", research_company)
b.set_entry_point("super")
b.add_conditional_edges("super", parallel_router)
# Parallel nodes automatically merge their 'reports' back into MainState via the reducer
b.add_edge("research_company", END)

app = b.compile()
print(app.invoke({"prompt": "Research big tech", "companies": [], "reports": []}))
```
</details>

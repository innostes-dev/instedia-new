# 3.4 Linear History: `git rebase` & Squashing

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
Over three days, you made 8 commits on your feature branch: `WIP`, `fix typo`, `WIP again`, `broken tests`, `fixed tests`, etc.
When you finally merge this branch into `main`, all 8 messy commits are dumped into the production history. Multiply this by 10 developers, and the `main` branch history becomes an unreadable garbage dump of "WIP" commits, making it impossible to read the history or figure out when a bug was introduced. We need a way to clean up our messy local history *before* we merge it into the cloud.

### 2. Plain English Metaphor (The What)
Think of `git rebase` as rewriting a messy diary before publishing it as a book.
- **Squashing:** You take 8 messy, rambling diary entries from Tuesday and compress them into one single, beautifully written paragraph: "Tuesday: Finished the authentication feature."
- **Rebasing (vs Merging):** Instead of tying two timelines together with an ugly knot (Merge Commit), rebasing lifts your feature timeline entirely and physically moves it to the very tip of the `main` timeline, making it look like you wrote all your code in a perfectly straight line just five minutes ago.

### 3. Complete Runnable Code
```bash
# Setup: 3 messy commits on a feature branch
git init
echo "v1" > app.js && git add app.js && git commit -m "feat: start auth"
echo "v2" > app.js && git add app.js && git commit -m "wip: typo fix"
echo "v3" > app.js && git add app.js && git commit -m "fix: actually working auth"

# Let's squash the last 3 commits interactively
git rebase -i HEAD~3

# Git opens a text editor showing:
# pick 12345 feat: start auth
# pick 67890 wip: typo fix
# pick abcde fix: actually working auth

# You edit the text to:
# pick 12345 feat: start auth
# squash 67890 wip: typo fix
# squash abcde fix: actually working auth

# Save and close. Git then asks for a new commit message.
# You write: "feat: complete authentication module"

git log --oneline
# Only ONE clean commit remains!
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Start Interactive Rebase**
```bash
git rebase -i HEAD~N
```
Replace `N` with the number of recent commits you want to rewrite. Git pauses time and opens a text editor.

**Step 2: Give Instructions**
In the editor, you tell Git what to do with each commit.
- `pick`: Keep it exactly as is.
- `squash` (or `s`): Meld this commit into the one above it.
- `reword` (or `r`): Keep the commit, but let me change its message.
- `drop` (or `d`): Completely delete this commit from history.

**Step 3: Write the Final Message**
If you choose `squash`, Git will open a second editor window asking you to write the new, combined commit message. Save and close. Git applies the changes.

### 5. ASCII Data Flow

**Before Squash:**
```text
(Commit A) <- [main]
      \
       (feat) -> (wip) -> (fix) <- [feature-branch]
```

**After Squash:**
```text
(Commit A) <- [main]
      \
       (Clean: "feat: complete authentication") <- [feature-branch]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Rebasing commits that you have *already pushed to GitHub and shared with other developers*. If you rewrite history that someone else has already downloaded, Git will create duplicate, conflicting timelines, and your team will hate you.
**Pro Tip:** The Golden Rule of Rebase: **Never rebase public history.** Only ever squash or rebase commits that exist locally on your machine and have not been pushed to a shared branch yet. Rebase is for cleaning your room before company comes over, not re-arranging the furniture while they are sitting on it.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Objective:** Reword a typo in the last commit message.
**Instructions:** Create a commit with the message "fix: porduction crsah". Use interactive rebase to fix the typo in the message without changing the code.

<details>
<summary>Hint</summary>
Use `git rebase -i HEAD~1` and change `pick` to `reword`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
echo "data" > file.txt
git add file.txt
git commit -m "fix: porduction crsah"

git rebase -i HEAD~1
# Editor opens:
# pick 12345 fix: porduction crsah

# Change to:
# reword 12345 fix: porduction crsah
# Save/close.

# Second editor opens. Change message to:
# fix: production crash
# Save/close.
git log --oneline
```
</details>

### Level 2 Real-World
**Objective:** Squash 3 WIP commits into 1.
**Instructions:** Make 3 sequential commits changing `readme.md`. Use interactive rebase to squash the 2nd and 3rd commits into the 1st commit. Provide a clean final commit message.

<details>
<summary>Hint</summary>
Use `git rebase -i HEAD~3`. The first commit must remain `pick`, the others become `squash` (or `s`).
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
echo "step 1" > readme.md && git add readme.md && git commit -m "wip 1"
echo "step 2" >> readme.md && git commit -am "wip 2"
echo "step 3" >> readme.md && git commit -am "wip 3"

git rebase -i HEAD~3
# Change text to:
# pick aaaaa wip 1
# squash bbbbb wip 2
# squash ccccc wip 3

# Save/close. Next editor opens. Delete old messages, write:
# docs: complete readme documentation
# Save/close.
```
</details>

### Level 3 Boss Level (Cumulative)
**Objective:** Feature Branch Cleanup before Push.
**Instructions:**
1. You are on branch `feature/profile`.
2. Commit 1: Add `profile.html`.
3. Commit 2: Add `profile.css`.
4. Commit 3: Fix a typo in `profile.html`.
5. You want to push this to GitHub, but you want it to be ONE perfect commit.
6. Squash them all into one commit named `feat: user profile page`.
7. (Simulation) Assume `main` on GitHub moved forward by 1 commit while you were doing this. Instead of a Merge Commit, use `git pull --rebase origin main` to fetch the cloud changes and perfectly stack your single clean commit on top of them.

<details>
<summary>Hint</summary>
Squash locally first. Then run `git pull --rebase origin main`. This fetches `main` and replays your local commit neatly on top of it, keeping a completely linear history.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
# Setup remote simulation
git commit --allow-empty -m "base"
git remote add origin fake_url
git switch -c feature/profile

touch profile.html && git add profile.html && git commit -m "add html"
touch profile.css && git add profile.css && git commit -m "add css"
echo "fixed" > profile.html && git commit -am "fix typo"

# 6. Squash locally
git rebase -i HEAD~3
# pick ... add html
# squash ... add css
# squash ... fix typo
# Final message: feat: user profile page

# 7. Pull with rebase
# (Assuming origin main advanced)
# git pull --rebase origin main
# Git fetches main, unwinds your feature commit, moves your branch to the tip of main,
# and replays your feature commit. A perfectly straight line!
```
</details>

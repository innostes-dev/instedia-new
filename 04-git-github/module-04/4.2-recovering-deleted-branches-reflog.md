# 4.2 Recovering Deleted Branches: The `reflog`

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You worked on a `feature/payment` branch all week. You committed your code, but you haven't pushed to GitHub yet.
You switch back to `main`. You accidentally type `git branch -D feature/payment` instead of your intended command.
Git says: `Deleted branch feature/payment`.
Your branch is gone. The commits are gone from `git log`. You have no cloud backup. You feel absolute panic because you think you just lost a week of work.

### 2. Plain English Metaphor (The What)
Think of `git log` as a map of the roads (branches) that currently exist. If you bulldoze a road, it's removed from the map.
Think of `git reflog` (Reference Log) as a hidden GPS tracker attached to your car. It doesn't care about roads. It records a chronological list of *every single location your car has ever parked in the last 30 days*.
Even if you delete the road, the GPS tracker still knows exactly where you parked yesterday. You can simply look at the coordinates in the reflog, teleport to those coordinates, and instantly rebuild the road. Git almost never permanently deletes code unless you force it to garbage collect.

### 3. Complete Runnable Code
```bash
# Setup: Create a branch and a commit
git init
git commit --allow-empty -m "base"
git switch -c feature/payment
echo "payment code" > pay.js
git add pay.js && git commit -m "feat: complete payment"

# Disaster strikes
git switch main
git branch -D feature/payment
# The branch is dead. 'git log' shows nothing.

# Consult the hidden GPS tracker
git reflog
# Output looks like:
# e3f1a2b HEAD@{0}: checkout: moving from feature/payment to main
# 7a8b9c0 HEAD@{1}: commit: feat: complete payment
# 1111111 HEAD@{2}: checkout: moving from main to feature/payment

# We see our missing commit hash is 7a8b9c0!
# Rebuild the branch exactly at that coordinate
git branch feature/payment-recovered 7a8b9c0

# You got your code back!
git log feature/payment-recovered --oneline
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Don't Panic and Open the Reflog**
```bash
git reflog
```
This lists every time `HEAD` (your current position) changed. It tracks commits, checkouts, merges, resets, and rebases.

**Step 2: Identify the Lost Commit Hash**
Read the messages on the right side of the output. Look for the last action you took on the deleted branch (e.g., `commit: feat: complete payment`). Find the 7-character hash on the left (e.g., `7a8b9c0`).

**Step 3: Resurrect the Branch**
```bash
git branch <new-branch-name> <commit-hash>
```
This command tells Git, "Create a new branch pointer and stick it onto this exact hidden commit in the database." The commits become visible again.

### 5. ASCII Data Flow
```text
(Disaster)
[main] (A)
           (B) <-- (Orphaned commit, no branch pointing to it)

(git reflog reveals B is at hash '7a8b9c0')

(git branch recovered 7a8b9c0)
[main] (A)
        \
         (B) <-- [recovered]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Assuming a hard reset (`git reset --hard HEAD~1`) or a branch deletion permanently destroys code immediately and trying to rewrite the code from scratch.
**Pro Tip:** The reflog is local only. It is a log of *your* actions on *your* machine. You cannot use the reflog to recover a branch that your coworker deleted on their laptop. Default reflog entries expire after 30 to 90 days, so recover lost code promptly.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Objective:** View the reflog and understand HEAD movements.
**Instructions:** In an empty folder, `git init`. Make a base commit. Branch to `dev`, switch to it, make a commit. Switch back to `main`. Run `git reflog`. Identify which index (e.g., `HEAD@{2}`) represents the commit made on `dev`.

<details>
<summary>Hint</summary>
The reflog lists the most recent action at `HEAD@{0}`. Read down the list to find the "commit" action.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
git commit --allow-empty -m "base"
git switch -c dev
git commit --allow-empty -m "dev work"
git switch main
git reflog
# HEAD@{0} will be the switch to main.
# HEAD@{1} will be "commit: dev work".
```
</details>

### Level 2 Real-World
**Objective:** Recover a branch deleted by a bad `git branch -D` command.
**Instructions:** Create a branch `ui-fix`. Add `style.css` and commit it. Switch to `main`. Force delete `ui-fix`. Use `git reflog` to find the commit hash, and recreate the branch as `ui-fix-restored`.

<details>
<summary>Hint</summary>
Follow the exact steps in the Core Concept section.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init && git commit --allow-empty -m "base"
git switch -c ui-fix
touch style.css && git add style.css && git commit -m "fix ui"

git switch main
git branch -D ui-fix

git reflog
# Find the hash for "commit: fix ui" (e.g., 999abcd)

git branch ui-fix-restored 999abcd
git log ui-fix-restored --oneline
```
</details>

### Level 3 Boss Level (Cumulative)
**Objective:** Recover from a disastrous Hard Reset.
**Instructions:**
1. You are working on `main`.
2. Make a commit: "Step 1".
3. Make a commit: "Step 2".
4. You mistakenly think "Step 2" is garbage. You run `git reset --hard HEAD~1` (which forces your branch back in time and destroys the working directory).
5. You realize "Step 2" contained the cure for a critical bug. It's gone from `git log`.
6. Use the reflog to find "Step 2", and instantly move `main` back to it.

<details>
<summary>Hint</summary>
A hard reset is just another HEAD movement. It is tracked in the reflog! Find the hash of "Step 2", and then run `git reset --hard <hash>` to jump *forward* in time.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
git commit --allow-empty -m "Step 1"
git commit --allow-empty -m "Step 2"

# The mistake
git reset --hard HEAD~1
git log --oneline
# Only Step 1 is visible!

# The rescue
git reflog
# Output:
# 1111111 HEAD@{0}: reset: moving to HEAD~1
# 2222222 HEAD@{1}: commit: Step 2

# Jump back to the future!
git reset --hard 2222222

git log --oneline
# Step 2 is back!
```
</details>

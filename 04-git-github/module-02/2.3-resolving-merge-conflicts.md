# 2.3 Resolving Merge Conflicts: When Universes Collide

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You branch off `main` to update the API endpoint URL in `config.js` to `v2.api.com`. Meanwhile, your coworker branches off `main` and updates that exact same line in `config.js` to `beta.api.com` and merges it into `main`.
When you try to merge your branch into `main`, Git panics. Git is smart enough to combine different files, or edits on different lines, but it cannot read your mind. It does not know if production should use `v2` or `beta`. It stops the merge and screams for human intervention.

### 2. Plain English Metaphor (The What)
Think of a merge conflict like two authors co-writing a book. Author A edits Chapter 1, Paragraph 1. Author B also edits Chapter 1, Paragraph 1. When the editor tries to bind the book, they see two different versions of the exact same paragraph.
Git will literally pause the merge, write *both* versions into the file, draw giant arrows around them, and say, "You fix this text, and tell me when you're done."

### 3. Complete Runnable Code
```bash
# Setup conflict scenario
git init
echo "API_URL=v1.api.com" > config.js
git add config.js && git commit -m "base"

# Branch A
git switch -c feature-v2
echo "API_URL=v2.api.com" > config.js
git commit -am "v2 endpoint"

# Branch B (Simulating main moving forward)
git switch main
echo "API_URL=beta.api.com" > config.js
git commit -am "beta endpoint"

# Attempt to Merge (BOOM!)
git merge feature-v2
# Output: CONFLICT (content): Merge conflict in config.js
# Automatic merge failed; fix conflicts and then commit the result.
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Identify the Conflict**
Run `git status`. Git will highlight the files listed under "Unmerged paths" in red. These are the files containing conflict markers.

**Step 2: Open the File and Anatomy of a Conflict**
Open `config.js` in your editor. You will see this:
```text
<<<<<<< HEAD
API_URL=beta.api.com
=======
API_URL=v2.api.com
>>>>>>> feature-v2
```
- `<<<<<<< HEAD`: The start of what is currently on your active branch (the one you are standing on, `main`).
- `=======`: The dividing line between the two versions.
- `>>>>>>> feature-v2`: The end of what is trying to be merged in.

**Step 3: Resolve the Conflict**
You must manually delete the `<<<<<<<`, `=======`, and `>>>>>>>` markers, and edit the code to the final desired state.
*Corrected file:*
```text
API_URL=v2.api.com
```

**Step 4: Finalize the Merge**
Once the file is correct, tell Git you have resolved it by staging the file, then finalize the merge commit.
```bash
git add config.js
git commit -m "Merge feature-v2: resolve config conflict"
```

### 5. ASCII Data Flow
```text
[main] edits line 1  -->  [feature] edits line 1
           \                  /
             MERGE ATTEMPTED
                    |
           Git Inserts Markers (<<<< === >>>>)
                    |
           Human Edits File + git add
                    |
               git commit
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Seeing a conflict and panicking, trying to `git checkout` random things, or using `git push -f` to overwrite the remote repository violently.
**Pro Tip:** If a conflict is too complicated and you want to completely abort the merge and go back in time to before you typed `git merge`, simply run `git merge --abort`. This safely resets your working directory to its previous clean state so you can try again later.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Objective:** Intentionally cause a merge conflict.
**Instructions:** Create a repo. Create `poem.txt` with "Roses are red". Branch `dev1`, change it to "Roses are blue", commit. Branch `dev2` from `main`, change it to "Roses are yellow", commit. Merge `dev1` into `dev2`.

<details>
<summary>Hint</summary>
You must make the commits on the exact same line of the same file on two different branches, then merge them.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
echo "Roses are red" > poem.txt
git add poem.txt && git commit -m "base"

git switch -c dev1
echo "Roses are blue" > poem.txt
git commit -am "blue"

git switch main
git switch -c dev2
echo "Roses are yellow" > poem.txt
git commit -am "yellow"

git merge dev1
# CONFLICT!
```
</details>

### Level 2 Real-World
**Objective:** Resolve the conflict from Level 1.
**Instructions:** Open `poem.txt`, observe the markers. Resolve the conflict so the final text reads "Roses are purple". Finalize the merge.

<details>
<summary>Hint</summary>
Edit the file to remove the `<<<<`, `====`, `>>>>` lines. Then `git add` and `git commit`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
# Open poem.txt, it looks like:
# <<<<<<< HEAD
# Roses are yellow
# =======
# Roses are blue
# >>>>>>> dev1

# Edit the file so it only contains:
echo "Roses are purple" > poem.txt

# Finalize
git add poem.txt
git commit -m "Merge dev1 into dev2: resolve color conflict"
```
</details>

### Level 3 Boss Level (Cumulative)
**Objective:** Combine atomic commits, branching, ignoring files, and conflict resolution in one scenario.
**Instructions:**
1. Init repo, add `server.js` with `port = 8000`, commit.
2. Branch to `feature-env`. Ignore `.env` files. Change `server.js` to `port = process.env.PORT`, commit.
3. Switch `main`. A hotfix is needed! Change `server.js` to `port = 8080`, commit.
4. Merge `feature-env` into `main`.
5. A conflict occurs. You realize you messed up and don't want to deal with it right now. Abort the merge entirely.

<details>
<summary>Hint</summary>
Follow the steps carefully. When the conflict hits, use `git merge --abort`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
echo "port = 8000" > server.js
git add server.js && git commit -m "base port"

# Branch
git switch -c feature-env
echo ".env" > .gitignore
git add .gitignore
git commit -m "chore: ignore env"

echo "port = process.env.PORT" > server.js
git commit -am "feat: use env var"

# Hotfix on main
git switch main
echo "port = 8080" > server.js
git commit -am "fix: update default port"

# Merge attempt
git merge feature-env
# CONFLICT (content): Merge conflict in server.js

# Bail out!
git merge --abort
git status
# Back to clean main branch, ready to try again later.
```
</details>

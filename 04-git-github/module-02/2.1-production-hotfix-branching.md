# 2.1 Production Hotfix Branching: `git branch` & `git switch`

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are halfway through developing a massive new "Shopping Cart v2" feature on your `main` branch. Suddenly, your manager bursts in: "The production checkout page is down right now! Fix it immediately!"
If you fix the bug on `main`, you are forced to deploy your half-finished, broken Shopping Cart v2 code along with the bug fix. You need a way to hit "pause" on your current work, travel back to the stable production state, fix the bug in isolation, and deploy *only* the bug fix.

### 2. Plain English Metaphor (The What)
Think of Git branches like parallel universes in a sci-fi movie.
The `main` branch is Universe A (production). When you create a new branch, you are spawning Universe B. Both universes start identical. However, any changes you make in Universe B (like fixing a bug) do not affect Universe A. You can freely switch between these universes, working on different problems in complete isolation.

### 3. Complete Runnable Code
```bash
# Setup: We have a stable main branch
git init
echo "Checkout v1 - STABLE" > checkout.js
git add checkout.js
git commit -m "feat: stable checkout"

# Create and switch to a parallel universe for the hotfix
git switch -c hotfix/checkout-crash

# Fix the bug in isolation
echo "Checkout v1 - FIXED" > checkout.js
git add checkout.js
git commit -m "fix: resolve production crash in checkout"

# Switch back to the main universe
git switch main
# You will see the file revert to "Checkout v1 - STABLE"
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Check Current Branches (`git branch`)**
```bash
git branch
```
This lists all parallel universes. The one with the asterisk (`*`) is the one you are currently standing in.

**Step 2: Create a New Branch (`git branch <name>`)**
```bash
git branch hotfix/checkout-crash
```
This spawns the new universe, but it does *not* teleport you there. You are still standing in the `main` branch.

**Step 3: Switch to the Branch (`git switch <name>`)**
```bash
git switch hotfix/checkout-crash
```
This teleports your working directory into the new universe. The files on your hard drive will instantly update to reflect the state of this branch.
*(Note: `git switch -c <name>` combines Step 2 and Step 3 into a single command).*

### 5. ASCII Data Flow
```text
(Commit A) -- (Commit B)  <-- [main] (Stable Production)
                   \
                    \-- (Commit C) <-- [hotfix/checkout-crash] (Isolated Bug Fix)
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using the legacy command `git checkout -b <branch>` to create and switch branches. While it works, `checkout` is an old, overloaded command used for both changing branches and restoring files.
**Pro Tip:** Use modern Git commands: `git switch` specifically for moving between branches, and `git switch -c` for creating/moving. It makes your intentions clear and prevents accidental file destruction. Always run `git status` before switching branches to ensure you don't carry uncommitted changes over by accident.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Objective:** Create a branch and switch to it.
**Instructions:** In a new repository, make an initial commit. Create a branch named `feature/dark-mode`. Switch to it and verify using `git branch`.

<details>
<summary>Hint</summary>
Use <code>git switch -c feature/dark-mode</code>.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
touch index.html
git add index.html
git commit -m "initial commit"

git switch -c feature/dark-mode
git branch
# Output should show * feature/dark-mode
```
</details>

### Level 2 Real-World
**Objective:** Prove branch isolation.
**Instructions:** Create a branch `dev`. Add a file `dev-notes.txt` and commit it. Switch back to `main`. Prove that `dev-notes.txt` does not exist on `main`.

<details>
<summary>Hint</summary>
Use `ls` after switching back to `main` to show the file is missing in that universe.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git switch -c dev
echo "secret notes" > dev-notes.txt
git add dev-notes.txt
git commit -m "add dev notes"

git switch main
ls
# dev-notes.txt will not be listed. It only exists in the 'dev' universe.
```
</details>

### Level 3 Boss Level (Cumulative)
**Objective:** Simulate a Hotfix Branch Workflow for a Broken Checkout while handling an uncommitted `.env` file via `.gitignore`.
**Instructions:**
1. Setup: Commit `app.js` on `main`.
2. Start working on a new file `cart.js` on `main` (do not commit it).
3. Also create a `.env` file (do not commit it).
4. EMERGENCY: `app.js` is crashing in production.
5. You must ignore the `.env` file permanently.
6. You must create and switch to a branch `hotfix/app-crash`.
7. Notice what happens to your uncommitted `cart.js`.
8. Fix `app.js` on the hotfix branch and commit the fix.
9. Switch back to `main` to resume working on the cart.

<details>
<summary>Hint</summary>
Uncommitted files "float" with you when you switch branches unless they conflict. Secure the `.env` first using `.gitignore` and commit it so it stops floating as an untracked file.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
# 1. Setup
git init
echo "stable" > app.js
git add app.js
git commit -m "stable app"

# 2 & 3. WIP and Secrets
touch cart.js
echo "SECRET=123" > .env

# 5. Ignore secrets
echo ".env" > .gitignore
git add .gitignore
git commit -m "chore: ignore env"

# 6. Emergency Branch
git switch -c hotfix/app-crash
# Notice: cart.js floats over with you because it's untracked.

# 8. Fix the bug
echo "fixed" > app.js
git add app.js
git commit -m "fix: app crash"

# 9. Switch back to resume work
git switch main
# app.js goes back to "stable", and cart.js is still sitting here waiting for you!
```
</details>

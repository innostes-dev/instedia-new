# 2.2 Fast-Forward and Three-Way Merging: `git merge`

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You successfully isolated that production hotfix in the `hotfix/checkout-crash` branch and verified that the code works perfectly. But right now, the `main` branch (which runs production) still contains the broken code. You need a safe, programmatic way to combine the isolated fix back into the main universe without manually copy-pasting code between folders.

### 2. Plain English Metaphor (The What)
Merging is how you collapse parallel universes back together.
You are the commander standing on the `main` spaceship. You radio down to the `hotfix` ship and say, "Bring your cargo up to me."
- **Fast-Forward Merge:** If the `main` ship hasn't moved since the `hotfix` ship departed, `main` simply drives forward along the exact path the `hotfix` ship took to catch up. No new "merge" event is needed.
- **Three-Way Merge:** If the `main` ship *has* moved (someone else committed code to `main` while you were fixing the bug), Git has to intelligently stitch the two different timelines together, creating a brand new "Merge Snapshot" to tie them off.

### 3. Complete Runnable Code
```bash
# -- Fast-Forward Example --
git init
echo "baseline" > file.txt
git add file.txt
git commit -m "Commit A: baseline"

# Create a branch and add a commit
git switch -c feature/auth
echo "auth code" >> file.txt
git commit -am "Commit B: add auth"

# Switch back to main and merge
git switch main
git merge feature/auth
# Result: Fast-forward. Main simply moves up to Commit B.
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Switch to the Target Branch**
You must always stand in the universe that is *receiving* the code.
```bash
git switch main
```

**Step 2: Execute the Merge**
You tell Git which universe to pull *into* your current one.
```bash
git merge feature/auth
```

**Step 3: Understand the Output**
If Git says `Fast-forward`, it means the history was linear. Git just updated your `main` branch pointer.
If Git opens a text editor asking for a commit message (e.g., `Merge branch 'feature/auth'`), it means a **Three-Way Merge** happened because both branches had diverging commits. Git automatically created a new commit to bind them.

### 5. ASCII Data Flow

**Fast-Forward (Linear History)**
```text
Before Merge:
[main] ---> (Commit A)
                      \
                       \---> (Commit B) <--- [feature/auth]

After `git merge feature/auth` (standing on main):
(Commit A) ---> (Commit B) <--- [main], [feature/auth]
```

**Three-Way Merge (Diverged History)**
```text
Before Merge:
[main] ---> (Commit A) ---> (Commit C)
                      \
                       \---> (Commit B) <--- [feature/auth]

After `git merge feature/auth` (standing on main):
            ---> (Commit C) ----
           /                    \
(Commit A)                        (Merge Commit D) <--- [main]
           \                    /
            ---> (Commit B) ----  <--- [feature/auth]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Merging while standing on the wrong branch. (e.g., Standing on `feature/auth` and running `git merge main`). This accidentally pollutes your feature branch with all the unrelated code from main, when your goal was to deploy your feature to production.
**Pro Tip:** Always run `git branch` to confirm you are on the receiver (usually `main`) before typing `git merge`. If you want to force a Three-Way Merge even when a Fast-Forward is possible (to retain the historical context that a feature branch existed), use `git merge --no-ff <branch>`.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Objective:** Perform a Fast-Forward Merge.
**Instructions:** Create a repo with a commit on `main`. Branch to `dev`, add a new commit. Return to `main` and merge `dev`. Verify the fast-forward.

<details>
<summary>Hint</summary>
Follow the exact sequence from the "Complete Runnable Code" section.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
touch base.txt && git add base.txt && git commit -m "base"
git switch -c dev
touch new.txt && git add new.txt && git commit -m "new"
git switch main
git merge dev
# Output will explicitly say "Fast-forward"
```
</details>

### Level 2 Real-World
**Objective:** Trigger a true Three-Way Merge (without conflicts).
**Instructions:**
1. Create a repo, add `core.js`, commit.
2. Branch to `feature-a`, modify `core.js` (add a line at the top), commit.
3. Switch to `main`. Modify `core.js` (add a line at the bottom), commit.
4. Merge `feature-a` into `main`.

<details>
<summary>Hint</summary>
Because `main` has advanced with a new commit, Git cannot fast-forward. It will create a merge commit.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
echo -e "line2" > core.js
git add core.js && git commit -m "base"

git switch -c feature-a
echo -e "line1\nline2" > core.js
git commit -am "feature a top"

git switch main
echo -e "line2\nline3" > core.js
git commit -am "main bottom"

git merge feature-a
# A text editor might open for the merge commit message. Save and close it.
# Git automatically merges because the edits were far apart in the file.
```
</details>

### Level 3 Boss Level (Cumulative)
**Objective:** Isolate a bug fix, advance main with feature work, merge the bug fix using a non-fast-forward merge, and verify the graph.
**Instructions:**
1. Initialize repo, create `app.py`, commit to `main`.
2. A bug is reported! Create branch `hotfix/1`.
3. Meanwhile, another developer commits a new file `docs.md` directly to `main`. (Simulate this by switching to `main`, making the commit, then switching back to the hotfix).
4. On the hotfix branch, modify `app.py` and commit the fix.
5. Switch to `main` and merge `hotfix/1`. Force Git to create a merge commit even if it could fast-forward (use `--no-ff`).
6. View the history graph.

<details>
<summary>Hint</summary>
Use `git merge --no-ff hotfix/1`. To view the graph, use `git log --oneline --graph --all`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```bash
git init
echo "def run(): pass" > app.py
git add app.py && git commit -m "init"

# The Hotfix timeline
git switch -c hotfix/1

# The Main timeline advances
git switch main
touch docs.md
git add docs.md && git commit -m "add docs"

# Back to fix the bug
git switch hotfix/1
echo "def run(): return True" > app.py
git commit -am "fix bug"

# Merge back
git switch main
git merge --no-ff hotfix/1
# Save/close the commit message editor

# Verify the beautiful branch graph
git log --oneline --graph --all
```
</details>

# 1.2 Custom Providers, Scopes, and Configuration

## Phase A: Concept & Implementation

### Real-World Pain Point (The Why)
Imagine your app connects to AWS S3. You hardcode the credentials inside your `S3StorageService`. Later, you deploy to production and realize you need different credentials. You switch to using `process.env`, but now your service has hidden dependencies on the environment and is hard to test. Furthermore, what if you need to connect to S3 for some users, but Google Cloud Storage for others? Standard `@Injectable()` gives you a single, static instance (singleton). It can't handle dynamic configuration or swapping implementations based on runtime values.

### Plain English Metaphor (The What)
Standard Dependency Injection is like a vending machine that always dispenses Coca-Cola when you press the button. **Custom Providers** let you rewire the machine so that pressing the button might dispense Pepsi (`useClass`), a mix of two drinks you create on the spot (`useFactory`), or a pre-made canned drink you hand it (`useValue`). **Provider Scopes** dictate whether everyone shares the exact same can (Singleton, default), everyone gets their own new can (Transient), or each group (Request) shares one can.

### Complete Runnable Code
```typescript
import { Module, Injectable, Scope, Controller, Get, Inject } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';

// --- Token Definition ---
export const STORAGE_CLIENT_TOKEN = 'STORAGE_CLIENT_TOKEN';

// --- Interfaces & Implementations ---
export interface StorageClient {
  upload(file: string): string;
}

@Injectable() // Standard Singleton
export class S3StorageClient implements StorageClient {
  upload(file: string) { return `Uploaded ${file} to S3`; }
}

export class GCSStorageClient implements StorageClient {
  upload(file: string) { return `Uploaded ${file} to GCS`; }
}

// --- Request Scoped Service ---
@Injectable({ scope: Scope.REQUEST })
export class AuditLogService {
  constructor() {
    console.log('AuditLogService initialized (New instance per request!)');
  }
  log(action: string) { console.log(`Audit: ${action}`); }
}

// --- Controller ---
@Controller('files')
export class FileController {
  constructor(
    @Inject(STORAGE_CLIENT_TOKEN) private readonly storageClient: StorageClient,
    private readonly auditLogger: AuditLogService
  ) {}

  @Get('upload')
  uploadFile(): string {
    this.auditLogger.log('File upload started');
    return this.storageClient.upload('invoice.pdf');
  }
}

// --- Module with Custom Providers ---
@Module({
  controllers: [FileController],
  providers: [
    AuditLogService, // Scoped provider
    {
      provide: STORAGE_CLIENT_TOKEN,
      useFactory: () => {
        // Logic to dynamically choose provider
        const useGcp = process.env.CLOUD_PROVIDER === 'GCP';
        return useGcp ? new GCSStorageClient() : new S3StorageClient();
      },
    },
    {
      provide: 'APP_VERSION',
      useValue: 'v2.1.0', // Constant value provider
    }
  ],
})
export class StorageModule {}

// Bootstrap omitted for brevity
```

### Progressive Step-by-Step Breakdown

**Step 1: The String Token and `useValue`**
```typescript
{
  provide: 'APP_VERSION',
  useValue: 'v2.1.0',
}
```
*Rationale:* Sometimes you just need to inject a simple constant (like an API key or config string). You use a string token (`'APP_VERSION'`) to identify it, and `useValue` provides the exact value to be injected whenever someone asks for that token using `@Inject('APP_VERSION')`.

**Step 2: Dynamic Instantiation with `useFactory`**
```typescript
{
  provide: STORAGE_CLIENT_TOKEN,
  useFactory: () => {
    return process.env.CLOUD_PROVIDER === 'GCP' ? new GCSStorageClient() : new S3StorageClient();
  },
}
```
*Rationale:* When a provider requires logic to be created (e.g., checking environment variables to decide which class to instantiate, or making an async database call), `useFactory` is perfect. It executes the function and registers the returned value as the provider for that token.

**Step 3: Provider Scopes (`Scope.REQUEST`)**
```typescript
@Injectable({ scope: Scope.REQUEST })
export class AuditLogService {}
```
*Rationale:* By default, NestJS providers are singletons (one instance shared across the entire app). If you need a fresh instance for *every incoming HTTP request* (e.g., to track request-specific user IDs or transaction IDs), you change the scope to `Scope.REQUEST`.

### ASCII / Architecture Data Flow
```text
[Module Configuration]
       │
       ├─► 'APP_VERSION' ──(useValue)──► 'v2.1.0'
       │
       ├─► STORAGE_CLIENT_TOKEN ──(useFactory)──► [ S3 Client OR GCS Client ]
       │                                            (Determined at runtime)
       │
       └─► AuditLogService ──(Scope.REQUEST)──► [ New Instance ] per Request
```

### Noob Trap vs Pro Tip
* **Noob Trap:** Overusing `Scope.REQUEST`. Request-scoped providers bubble up! If a Controller injects a Request-scoped Service, the Controller automatically becomes Request-scoped too. This means NestJS will instantiate a new Controller and Service on *every single HTTP request*, killing your application's performance and garbage collector.
* **Pro Tip:** Use `useFactory` in combination with the `inject` array property to inject other services into your factory function (e.g., injecting a `ConfigService` into a database connection factory).

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Create a constant provider named `MAX_RETRIES` with a value of `5`, and inject it into a `WorkerService` using the `@Inject()` decorator.
<details>
<summary>Hint</summary>
Use `useValue` in the module providers. Use `@Inject('MAX_RETRIES')` in the service constructor.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Injectable, Inject, Module } from '@nestjs/common';

@Injectable()
export class WorkerService {
  constructor(@Inject('MAX_RETRIES') private readonly retries: number) {}
  getRetries() { return this.retries; }
}

@Module({
  providers: [
    WorkerService,
    { provide: 'MAX_RETRIES', useValue: 5 }
  ]
})
export class WorkerModule {}
```
</details>

### Level 2 Real-World
**Task:** Create a dynamic database connection string using a custom provider. Create a `ConfigService` that holds the base URL, and use `useFactory` to construct the full string by injecting `ConfigService` into the factory.
<details>
<summary>Hint</summary>
The custom provider should have a `provide: 'DB_CONNECTION'`, a `useFactory` function that accepts `config: ConfigService`, and an `inject: [ConfigService]` array.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Injectable, Inject, Module } from '@nestjs/common';

@Injectable()
export class ConfigService {
  getDbHost() { return 'localhost:5432'; }
}

@Injectable()
export class DatabaseService {
  constructor(@Inject('DB_CONNECTION') private readonly connStr: string) {}
  connect() { console.log(`Connecting to ${this.connStr}`); }
}

@Module({
  providers: [
    ConfigService,
    DatabaseService,
    {
      provide: 'DB_CONNECTION',
      useFactory: (config: ConfigService) => {
        return `postgresql://admin:password@${config.getDbHost()}/mydb`;
      },
      inject: [ConfigService], // Tells Nest to pass ConfigService into the factory
    }
  ]
})
export class DatabaseModule {}
```
</details>

### Level 3 Boss Level
**Task:** Build a `TenantConnectionService` that must be isolated per tenant. It should be Request-Scoped. It should extract a `X-Tenant-Id` header from the incoming request to set its internal state. Inject it into a controller to return the current tenant.
<details>
<summary>Hint</summary>
Use `@Injectable({ scope: Scope.REQUEST })`. Inject the Express Request object using `@Inject(REQUEST)` (from `@nestjs/core`).
</details>
<details>
<summary>Solution</summary>

```typescript
import { Injectable, Scope, Inject, Controller, Get, Module } from '@nestjs/common';
import { REQUEST } from '@nestjs/core';
import { Request } from 'express';

@Injectable({ scope: Scope.REQUEST })
export class TenantConnectionService {
  private tenantId: string;

  constructor(@Inject(REQUEST) private readonly request: Request) {
    // Extract tenant ID from headers on every new request
    this.tenantId = this.request.headers['x-tenant-id'] as string || 'public';
    console.log(`Initialized Connection for Tenant: ${this.tenantId}`);
  }

  getTenantSchema() {
    return `schema_${this.tenantId}`;
  }
}

@Controller('data')
export class DataController {
  // Controller implicitly becomes Request-scoped because of its dependency
  constructor(private readonly tenantService: TenantConnectionService) {}

  @Get()
  getData() {
    return { schemaUsed: this.tenantService.getTenantSchema() };
  }
}

@Module({
  controllers: [DataController],
  providers: [TenantConnectionService]
})
export class TenantModule {}
```
</details>

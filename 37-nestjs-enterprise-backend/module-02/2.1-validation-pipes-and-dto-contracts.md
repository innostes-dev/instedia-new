# 2.1 Validation Pipes and DTO Contracts

## Phase A: Concept & Implementation

### Real-World Pain Point (The Why)
In a plain Express app, receiving a POST request means manually inspecting `req.body`. You write endless `if (!req.body.email || !req.body.email.includes('@')) { return res.status(400) }` blocks. This clutters your controllers, is prone to human error, and makes it incredibly easy for injection attacks or malformed payloads to slip past your checks and crash your database or compromise your system.

### Plain English Metaphor (The What)
Think of a nightclub with a strict dress code. The people trying to enter are the incoming HTTP requests. The **DTO (Data Transfer Object)** is the dress code manual (e.g., "Must wear shoes", "No hats"). The **ValidationPipe** is the bouncer standing at the door. If someone doesn't match the dress code (the DTO contract), the bouncer immediately rejects them with a clear reason ("Missing shoes") before they ever make it onto the dance floor (your controller logic).

### Complete Runnable Code
```typescript
import { Module, Controller, Post, Body, ValidationPipe, UsePipes } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { IsString, IsInt, IsEmail, Min, Max, IsDefined } from 'class-validator';
import { Type } from 'class-transformer';

// 1. Define the DTO (Data Transfer Object) Contract
export class CreateOrderDto {
  @IsEmail({}, { message: 'Must provide a valid buyer email' })
  buyerEmail: string;

  @IsString()
  productId: string;

  @IsInt()
  @Min(1)
  @Max(100)
  @Type(() => Number) // Ensure string payloads are transformed to numbers
  quantity: number;
}

// 2. Apply Validation at the Controller
@Controller('orders')
export class OrderController {

  @Post('create')
  @UsePipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true }))
  createOrder(@Body() payload: CreateOrderDto) {
    // If we reach here, the payload is 100% guaranteed to match CreateOrderDto
    return {
      status: 'Order Placed',
      totalItems: payload.quantity,
      buyer: payload.buyerEmail
    };
  }
}

// 3. Module & Bootstrap
@Module({
  controllers: [OrderController],
})
export class OrderModule {}

async function bootstrap() {
  const app = await NestFactory.create(OrderModule);
  // Alternatively, apply it globally:
  // app.useGlobalPipes(new ValidationPipe({ transform: true }));
  await app.listen(3000);
}
bootstrap();
```

### Progressive Step-by-Step Breakdown

**Step 1: The DTO and `class-validator`**
```typescript
export class CreateOrderDto {
  @IsEmail() buyerEmail: string;
  @IsInt() @Min(1) quantity: number;
}
```
*Rationale:* We define a class that acts as a schema. We decorate properties with validators from `class-validator`. This clearly separates *what* the data should look like from the business logic.

**Step 2: Type Transformation with `class-transformer`**
```typescript
@Type(() => Number)
quantity: number;
```
*Rationale:* HTTP bodies often come in as strings (especially form data or query params). `@Type()` tells the framework to explicitly attempt to convert the incoming string into a JavaScript `Number` before running the `@IsInt()` validation.

**Step 3: The `ValidationPipe`**
```typescript
@UsePipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true }))
```
*Rationale:* The pipe intercepts the request. `whitelist: true` strips out any properties from the JSON that don't have decorators in the DTO (preventing mass-assignment attacks). `forbidNonWhitelisted: true` goes further and instantly throws a 400 Bad Request error if a user tries to send extra, unknown data.

### ASCII / Architecture Data Flow
```text
[Incoming HTTP POST { email: "bad", amount: "5" }]
      │
      ▼
┌──────────────┐
│ Validation   │ (Checks class-validator rules)
│ Pipe         │ ───► Invalid Email? -> Throw 400 Bad Request
└──────┬───────┘ ───► Convert "5" to Number 5
       │ (Valid Payload)
       ▼
┌──────────────┐
│  Controller  │ (Safe to process)
└──────────────┘
```

### Noob Trap vs Pro Tip
* **Noob Trap:** Using interfaces instead of classes for DTOs. TypeScript interfaces are erased at compilation time! The NestJS ValidationPipe relies on metadata, meaning it absolutely requires a `class` to know what to validate at runtime.
* **Pro Tip:** Register the `ValidationPipe` globally in your `bootstrap()` function with `{ transform: true, whitelist: true }`. This saves you from writing `@UsePipes` on every controller and guarantees a baseline level of security across your entire application.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Create a `RegisterUserDto` that requires a `username` (string, min 3 chars, max 20 chars) and a `password` (string). Apply it to a POST route.
<details>
<summary>Hint</summary>
Use `class-validator` decorators `@IsString()`, `@Length(3, 20)`, and `@IsDefined()`. Apply the DTO to the `@Body()` of the controller method.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Controller, Post, Body, ValidationPipe, UsePipes } from '@nestjs/common';
import { IsString, Length, IsDefined } from 'class-validator';

export class RegisterUserDto {
  @IsString()
  @Length(3, 20)
  username: string;

  @IsString()
  @IsDefined()
  password: string;
}

@Controller('users')
export class UserController {
  @Post('register')
  @UsePipes(new ValidationPipe())
  register(@Body() dto: RegisterUserDto) {
    return { msg: 'User registered', user: dto.username };
  }
}
```
</details>

### Level 2 Real-World
**Task:** Create an `UpdateProfileDto` where `age` and `bio` are both optional. However, if `age` is provided, it must be an integer > 18. If `bio` is provided, it must be a string. Ensure that any extra fields sent in the request are stripped out automatically.
<details>
<summary>Hint</summary>
Use `@IsOptional()` from `class-validator`. Configure the `ValidationPipe` with `whitelist: true`.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Controller, Patch, Body, ValidationPipe, UsePipes } from '@nestjs/common';
import { IsString, IsInt, Min, IsOptional } from 'class-validator';

export class UpdateProfileDto {
  @IsOptional()
  @IsInt()
  @Min(18)
  age?: number;

  @IsOptional()
  @IsString()
  bio?: string;
}

@Controller('profile')
export class ProfileController {
  @Patch()
  @UsePipes(new ValidationPipe({ whitelist: true }))
  update(@Body() dto: UpdateProfileDto) {
    // If { age: 25, bio: "Hi", admin: true } is sent,
    // `admin` is stripped.
    return { updated: dto };
  }
}
```
</details>

### Level 3 Boss Level
**Task:** Create a Strict E-Commerce Inbound Order Payload Validator. The payload has a nested array of items. The parent `CartDto` must have a `customerId`. The nested `ItemDto` must have a `sku` (string) and `price` (number). You must validate the nested array objects.
<details>
<summary>Hint</summary>
Use `@ValidateNested({ each: true })` on the array property in `CartDto`, and combine it with `@Type(() => ItemDto)` from `class-transformer` so Nest knows what class to validate the array elements against.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Controller, Post, Body, ValidationPipe, UsePipes } from '@nestjs/common';
import { IsString, IsNumber, ValidateNested, ArrayMinSize, IsDefined } from 'class-validator';
import { Type } from 'class-transformer';

export class ItemDto {
  @IsString()
  sku: string;

  @IsNumber()
  price: number;
}

export class CartDto {
  @IsString()
  customerId: string;

  @IsDefined()
  @ArrayMinSize(1)
  @ValidateNested({ each: true }) // Validate each item in array
  @Type(() => ItemDto)            // Tell class-transformer the type
  items: ItemDto[];
}

@Controller('cart')
export class CartController {
  @Post('checkout')
  @UsePipes(new ValidationPipe({ whitelist: true }))
  checkout(@Body() cart: CartDto) {
    // 100% type-safe nested validation!
    const total = cart.items.reduce((sum, item) => sum + item.price, 0);
    return { status: 'Success', total, customer: cart.customerId };
  }
}
```
</details>

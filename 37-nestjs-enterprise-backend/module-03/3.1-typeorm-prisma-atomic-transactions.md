# 3.1 TypeORM/Prisma Atomic Transactions

## Phase A: Concept & Implementation

### Real-World Pain Point (The Why)
Imagine a banking application where a user transfers $100 from Account A to Account B. You write code that subtracts $100 from Account A, and then adds $100 to Account B. But what if the database connection drops right after the subtraction, before the addition happens? Account A lost $100, but Account B never got it. The $100 simply vanished. Inconsistent multi-table writes are a massive data integrity risk.

### Plain English Metaphor (The What)
An **Atomic Transaction** is an "all or nothing" contract. Think of buying a house. You don't hand over a million dollars in cash and then hope the owner signs the deed. Instead, you put the money in an escrow account, the owner signs the deed, and then a lawyer executes the trade simultaneously. If *any* part of the agreement fails, the whole deal is canceled (rolled back). In databases, a transaction ensures that multiple queries either all succeed completely (commit), or all fail completely (rollback) as if nothing ever happened.

### Complete Runnable Code (TypeORM Example)
```typescript
import { Injectable, Controller, Post, Body, HttpException, HttpStatus } from '@nestjs/common';
import { InjectDataSource } from '@nestjs/typeorm';
import { DataSource } from 'typeorm';

// Note: Assume UserAccount entity exists with 'id' and 'balance' columns.

@Injectable()
export class BankTransferService {
  // Inject the raw TypeORM DataSource to manage transactions manually
  constructor(@InjectDataSource() private dataSource: DataSource) {}

  async transferFunds(fromAccountId: number, toAccountId: number, amount: number) {
    // 1. Create a QueryRunner to control the transaction lifecycle
    const queryRunner = this.dataSource.createQueryRunner();

    // 2. Connect and Start Transaction
    await queryRunner.connect();
    await queryRunner.startTransaction();

    try {
      // 3. Execute queries USING THE QUERYRUNNER, not the standard repository

      // Step A: Deduct from sender
      const sender = await queryRunner.manager.findOne('UserAccount', { where: { id: fromAccountId } });
      if (!sender || sender.balance < amount) {
        throw new Error('Insufficient funds or account not found');
      }
      sender.balance -= amount;
      await queryRunner.manager.save(sender);

      // Step B: Add to receiver (simulate failure risk here)
      const receiver = await queryRunner.manager.findOne('UserAccount', { where: { id: toAccountId } });
      if (!receiver) {
        throw new Error('Receiver account not found');
      }
      receiver.balance += amount;
      await queryRunner.manager.save(receiver);

      // 4. If we reach here, no errors were thrown. COMMIT the transaction.
      await queryRunner.commitTransaction();
      return { status: 'Transfer Successful' };

    } catch (err) {
      // 5. An error was thrown! ROLLBACK everything done in this queryRunner.
      await queryRunner.rollbackTransaction();
      throw new HttpException(err.message, HttpStatus.BAD_REQUEST);
    } finally {
      // 6. ALWAYS release the query runner to free the connection back to the pool
      await queryRunner.release();
    }
  }
}

@Controller('transfers')
export class TransferController {
  constructor(private readonly transferService: BankTransferService) {}

  @Post()
  async execute(@Body() body: { from: number, to: number, amount: number }) {
    return await this.transferService.transferFunds(body.from, body.to, body.amount);
  }
}
```

### Progressive Step-by-Step Breakdown

**Step 1: The QueryRunner**
```typescript
const queryRunner = this.dataSource.createQueryRunner();
await queryRunner.connect();
await queryRunner.startTransaction();
```
*Rationale:* When using standard TypeORM repositories, every `save()` creates its own tiny, isolated transaction. To group multiple saves together, we need to grab a single, dedicated connection from the pool (the `QueryRunner`) and tell the database "Hold on, I'm starting a transaction, don't finalize anything yet."

**Step 2: Using the EntityManager**
```typescript
await queryRunner.manager.save(sender);
```
*Rationale:* **Crucial Step!** Inside the try block, you *cannot* use your standard `@InjectRepository()` repositories. If you do, those queries will execute outside the transaction. You must execute your queries through `queryRunner.manager` so the database knows these specific queries belong to the open transaction.

**Step 3: Commit, Rollback, Release**
```typescript
} catch (err) {
  await queryRunner.rollbackTransaction();
} finally {
  await queryRunner.release();
}
```
*Rationale:* If successful, `commitTransaction()` finalizes the changes. If *any* error is thrown (even by your own validation logic), `rollbackTransaction()` undoes all queries executed by this runner. `release()` inside a `finally` block is mandatory; otherwise, your app will eventually crash from database connection starvation.

### ASCII / Architecture Data Flow
```text
[Transfer Request: A -> B, $100]
       │
[Start Transaction (QueryRunner)]
       │
       ├─► Deduct $100 from A ──► [DB: State held in memory, not finalized]
       │
       ├─► Network Error! / Account B not found!
       │
[Catch Block -> Rollback Transaction]
       │
       ▼
[DB: Discards changes, Account A retains $100]
       │
[Finally Block -> Release Connection]
```

### Noob Trap vs Pro Tip
* **Noob Trap:** Starting a transaction but forgetting the `finally { await queryRunner.release(); }` block. If a request throws an error and the connection isn't released, it stays permanently locked. After a few errors, your connection pool empties, and your entire application hangs indefinitely.
* **Pro Tip:** If you are using **Prisma**, transactions are simpler. You can use the `$transaction` API with an array of promises, or the interactive `$transaction(async (tx) => { ... })` method, which automatically handles commit/rollback without manually managing the connection lifecycle.

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Using Prisma ORM syntax, write a simple `$transaction` that takes an array of two Prisma promises: creating a `User` and creating a `Profile`.
<details>
<summary>Hint</summary>
Use `prisma.$transaction([ promise1, promise2 ])`.
</details>
<details>
<summary>Solution</summary>

```typescript
// Assuming PrismaClient is instantiated as 'prisma'
import { Injectable } from '@nestjs/common';

@Injectable()
export class UserService {
  constructor(private prisma: any) {} // Replace 'any' with PrismaClient

  async createUserWithProfile() {
    const createUserPromise = this.prisma.user.create({ data: { name: 'Alice' } });
    const createProfilePromise = this.prisma.profile.create({ data: { bio: 'Hello' } });

    // Both succeed or both fail
    const [user, profile] = await this.prisma.$transaction([
      createUserPromise,
      createProfilePromise
    ]);

    return { user, profile };
  }
}
```
</details>

### Level 2 Real-World
**Task:** Using TypeORM, write an interactive transaction. A user is placing an order. You must deduct the inventory count from `Product`, and create an `Order` record. Use the callback style `this.dataSource.transaction(async (manager) => { ... })` instead of a manual QueryRunner.
<details>
<summary>Hint</summary>
The callback provides an `EntityManager`. Use `manager.findOne`, `manager.save`, etc. If you throw an error inside the callback, TypeORM automatically rolls it back.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Injectable } from '@nestjs/common';
import { InjectDataSource } from '@nestjs/typeorm';
import { DataSource } from 'typeorm';

@Injectable()
export class OrderService {
  constructor(@InjectDataSource() private dataSource: DataSource) {}

  async placeOrder(productId: number, qty: number) {
    // Interactive transactions manage the runner and release for you
    return await this.dataSource.transaction(async (manager) => {

      const product = await manager.findOne('Product', { where: { id: productId } });
      if (product.stock < qty) throw new Error('Out of stock');

      product.stock -= qty;
      await manager.save(product);

      const order = manager.create('Order', { productId, qty });
      await manager.save(order);

      return order; // Automatic commit if we reach here
    });
  }
}
```
</details>

### Level 3 Boss Level
**Task:** Write an Atomic Banking Ledger using Prisma Interactive Transactions. You need to transfer funds. Within the `prisma.$transaction(async (tx) => { ... })` callback, you must: 1. Read sender balance. 2. Throw error if insufficient. 3. Update sender balance. 4. Update receiver balance. 5. Create a `Ledger` audit record tracking the transaction.
<details>
<summary>Hint</summary>
Use `tx.account.update` and `tx.ledger.create`. You must use the `tx` object passed into the callback, NOT the global `this.prisma` client!
</details>
<details>
<summary>Solution</summary>

```typescript
import { Injectable } from '@nestjs/common';

@Injectable()
export class BankingLedgerService {
  constructor(private prisma: any) {} // PrismaClient

  async executeLedgerTransfer(fromId: number, toId: number, amount: number) {
    try {
      // Interactive Transaction: Automatic Commit/Rollback
      const result = await this.prisma.$transaction(async (tx) => {

        // 1. Must use 'tx' object for all queries!
        const sender = await tx.account.findUnique({ where: { id: fromId } });

        // 2. Validate
        if (!sender || sender.balance < amount) {
          throw new Error('Insufficient Funds'); // Triggers Rollback
        }

        // 3. Deduct
        await tx.account.update({
          where: { id: fromId },
          data: { balance: { decrement: amount } }
        });

        // 4. Add
        await tx.account.update({
          where: { id: toId },
          data: { balance: { increment: amount } }
        });

        // 5. Audit
        const ledger = await tx.ledger.create({
          data: { fromId, toId, amount, status: 'COMPLETED' }
        });

        return ledger;
      });

      return result;
    } catch (error) {
      console.error('Transaction Failed & Rolled Back:', error.message);
      throw error;
    }
  }
}
```
</details>

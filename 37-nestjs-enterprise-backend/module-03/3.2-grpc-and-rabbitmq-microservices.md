# 3.2 gRPC and RabbitMQ Microservices

## Phase A: Concept & Implementation

### Real-World Pain Point (The Why)
In a growing system, your API gateway (HTTP) calls the Inventory Service (HTTP), which calls the Shipping Service (HTTP). If Shipping goes down, Inventory hangs waiting for a response, eventually timing out. The Gateway then times out. The user gets a generic 500 error. Synchronous HTTP chains are brittle, slow (due to JSON parsing overhead), and couple services tightly together. You need a way to communicate incredibly fast (gRPC) or asynchronously decouple services entirely (Message Brokers like RabbitMQ/Kafka).

### Plain English Metaphor (The What)
* **gRPC (Synchronous, High-Speed):** Think of a direct fiber-optic telephone line between two managers who speak a highly compressed, secret language (Protobuf). It is instant, extremely efficient, but both managers must be at their desks at the same time to talk.
* **RabbitMQ (Asynchronous, Decoupled):** Think of a post office box. Manager A drops a letter in Manager B's box. Manager A immediately goes back to work. Manager B can pick up the letter whenever they are ready. If Manager B is sick (offline), the letter waits safely in the box until they return.

### Complete Runnable Code (RabbitMQ Example)
```typescript
import { Controller, Post, Body, Inject, Module, Injectable } from '@nestjs/common';
import { ClientsModule, Transport, ClientProxy, MessagePattern, Payload } from '@nestjs/microservices';
import { NestFactory } from '@nestjs/core';

// ==========================================
// SERVICE A: The Producer (API Gateway)
// ==========================================
@Controller('orders')
export class OrderProducerController {
  // Inject the RabbitMQ client
  constructor(@Inject('INVENTORY_SERVICE') private client: ClientProxy) {}

  @Post()
  async placeOrder(@Body() body: { productId: string; qty: number }) {
    // 1. Emit an event (Fire and Forget)
    // The gateway doesn't wait for the inventory to finish.
    this.client.emit('order_placed', body);

    return { status: 'Order accepted, processing in background' };
  }
}

@Module({
  imports: [
    ClientsModule.register([
      {
        name: 'INVENTORY_SERVICE',
        transport: Transport.RMQ,
        options: {
          urls: ['amqp://localhost:5672'],
          queue: 'inventory_queue',
          queueOptions: { durable: false },
        },
      },
    ]),
  ],
  controllers: [OrderProducerController],
})
export class ProducerModule {}

// ==========================================
// SERVICE B: The Consumer (Inventory Service)
// ==========================================
@Controller()
export class InventoryConsumerController {

  // 2. Listen for the specific pattern (event)
  @MessagePattern('order_placed')
  async handleOrderPlaced(@Payload() data: { productId: string; qty: number }) {
    console.log(`[Inventory Service] Received order for ${data.qty} of ${data.productId}`);
    // Process inventory reduction logic here...

    // Simulating work
    await new Promise(resolve => setTimeout(resolve, 1000));
    console.log(`[Inventory Service] Processed ${data.productId}`);
  }
}

@Module({
  controllers: [InventoryConsumerController],
})
export class ConsumerModule {}

// ==========================================
// Bootstrap Functions
// ==========================================
async function bootstrapProducer() {
  const app = await NestFactory.create(ProducerModule);
  await app.listen(3000); // HTTP Server
  console.log('API Gateway listening on 3000');
}

async function bootstrapConsumer() {
  // 3. Create a Microservice, not a standard HTTP app
  const app = await NestFactory.createMicroservice(ConsumerModule, {
    transport: Transport.RMQ,
    options: {
      urls: ['amqp://localhost:5672'],
      queue: 'inventory_queue',
      queueOptions: { durable: false },
    },
  });
  await app.listen(); // Connects to RabbitMQ
  console.log('Inventory Microservice listening to RabbitMQ');
}

// In a real app, these would be in separate repos/processes.
// bootstrapProducer();
// bootstrapConsumer();
```

### Progressive Step-by-Step Breakdown

**Step 1: The ClientProxy (`emit` vs `send`)**
```typescript
this.client.emit('order_placed', body);
```
*Rationale:* When the API Gateway receives an HTTP request, it uses `ClientProxy` to push a message to RabbitMQ. We use `emit()` for event-based "fire-and-forget" behavior. (If we needed a response back, we would use `send()`, which returns an Observable).

**Step 2: The `@MessagePattern` Decorator**
```typescript
@MessagePattern('order_placed')
handleOrderPlaced(@Payload() data: any) { ... }
```
*Rationale:* On the receiving microservice, controllers don't use `@Get()` or `@Post()`. Instead, they use `@MessagePattern()`. NestJS automatically subscribes to the RabbitMQ queue, pulls messages that match the string `'order_placed'`, and routes them to this method, extracting the payload.

**Step 3: Bootstrapping a Microservice**
```typescript
const app = await NestFactory.createMicroservice(ConsumerModule, { transport: Transport.RMQ, ... });
```
*Rationale:* The consuming app doesn't need to expose an HTTP port (unless it's a hybrid app). `createMicroservice` tells NestJS to connect directly to the message broker instead of spinning up an Express server.

### ASCII / Architecture Data Flow
```text
[HTTP POST /orders]
       │
       ▼
┌──────────────┐          RabbitMQ          ┌──────────────┐
│ API Gateway  │ ─(emit)─► [Queue] ─(pull)─►│ Inventory Svc│
│ (Producer)   │                            │ (Consumer)   │
└──────────────┘                            └──────────────┘
  (Returns 202                               (Processes in
   Accepted)                                  Background)
```

### Noob Trap vs Pro Tip
* **Noob Trap:** Using HTTP for everything and trying to simulate async behavior with `setTimeout` or returning early before promises resolve. This leads to lost data if the server crashes before the background task completes. Message brokers guarantee the message survives a crash.
* **Pro Tip:** For RPC (Request-Response) across microservices where low latency is critical (e.g., fetching user profile data to attach to a post), use **gRPC**. For state changes where immediate consistency isn't required (e.g., sending welcome emails, recalculating inventory), use **RabbitMQ / Kafka** (`emit`).

## Phase B: Engineering Challenges

### Level 1 Warm-Up
**Task:** Configure a `MathMicroservice` using TCP (the default NestJS microservice transport). Create a controller that listens to the message pattern `{ cmd: 'sum' }` and returns the sum of an array of numbers provided in the payload.
<details>
<summary>Hint</summary>
Use `@MessagePattern({ cmd: 'sum' })`. The payload will be the array. Return the result directly.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Controller } from '@nestjs/common';
import { MessagePattern, Payload } from '@nestjs/microservices';

@Controller()
export class MathController {

  @MessagePattern({ cmd: 'sum' })
  accumulate(@Payload() data: number[]): number {
    return (data || []).reduce((a, b) => a + b, 0);
  }
}

// NestFactory.createMicroservice(AppModule, { transport: Transport.TCP });
```

### Level 2 Real-World
**Task:** Create a gateway controller that uses `ClientProxy.send()` (Request-Response) to call the MathMicroservice from Level 1. It should map the Observable result to a JSON object.
<details>
<summary>Hint</summary>
Use `@Inject('MATH_SERVICE') private client: ClientProxy`. Use `this.client.send({ cmd: 'sum' }, [1, 2, 3])`. Remember to `await lastValueFrom(...)` or return the Observable directly.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Controller, Get, Inject } from '@nestjs/common';
import { ClientProxy } from '@nestjs/microservices';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

@Controller('calc')
export class GatewayCalcController {
  constructor(@Inject('MATH_SERVICE') private client: ClientProxy) {}

  @Get('sum')
  calculateSum(): Observable<any> {
    // send() expects a response (unlike emit)
    const pattern = { cmd: 'sum' };
    const payload = [10, 20, 30];

    return this.client.send<number>(pattern, payload).pipe(
      map(result => ({ total: result }))
    );
  }
}
```
</details>

### Level 3 Boss Level
**Task:** gRPC Protobuf Integration. Write a gRPC Controller for a `HeroService`. It implements a method `FindOne` defined in a `.proto` file (which takes `{ id: number }` and returns `{ id, name }`).
<details>
<summary>Hint</summary>
Use `@GrpcMethod('HeroService', 'FindOne')`.
</details>
<details>
<summary>Solution</summary>

```typescript
import { Controller } from '@nestjs/common';
import { GrpcMethod } from '@nestjs/microservices';

interface HeroById { id: number; }
interface Hero { id: number; name: string; }

@Controller()
export class HeroGrpcController {

  // The heroes database
  private heroes: Hero[] = [
    { id: 1, name: 'Batman' },
    { id: 2, name: 'Superman' },
  ];

  // Maps to the 'FindOne' rpc method inside the 'HeroService' gRPC service defined in the .proto file
  @GrpcMethod('HeroService', 'FindOne')
  findOne(data: HeroById): Hero {
    return this.heroes.find(({ id }) => id === data.id) || { id: 0, name: 'Unknown' };
  }
}

// Expected proto file context:
// service HeroService {
//   rpc FindOne (HeroById) returns (Hero) {}
// }
```
</details>

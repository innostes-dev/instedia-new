# 1.2 Task Queues & Routing with RabbitMQ

## Phase A: Understanding the Concept

### 1. Real-World Pain Point (The Why)
Imagine a video sharing platform. When a user uploads a raw video, two things need to happen: 1) The video needs to be compressed (transcoded) into multiple formats (1080p, 720p). 2) An email notification must be sent to their subscribers. Transcoding is highly CPU-intensive and takes minutes. Emailing is lightweight but network-dependent. If you push all these tasks into a single generic queue, your fast email workers might get stuck behind massive video transcoding tasks, delaying notifications. You need a way to route different types of tasks to specialized workers.

### 2. Plain English Metaphor (The What)
Think of a post office (RabbitMQ). When you drop a letter in a generic blue mailbox (Producer), you don't hand it directly to the mail carrier (Consumer). Instead, the post office takes your letter, looks at the zip code (Routing Key), and sorts it into specific bins (Queues). Mail carriers responsible for specific neighborhoods only take mail from their assigned bins. The sorting center in the post office is the "Exchange", ensuring the right message gets to the right queue based on rules.

### 3. Complete Runnable Code
*Note: This example uses the `amqplib` library for Node.js. In a real environment, you would need a running RabbitMQ instance.*

```javascript
const amqp = require('amqplib');

// --- PRODUCER ---
async function uploadVideoProducer() {
  const connection = await amqp.connect('amqp://localhost');
  const channel = await connection.createChannel();

  const exchangeName = 'video_events';
  // 'direct' exchange routes messages based on exact routing key matches
  await channel.assertExchange(exchangeName, 'direct', { durable: true });

  const videoId = `vid_${Math.floor(Math.random() * 1000)}`;
  const payload = JSON.stringify({ videoId: videoId, user: 'creator_1' });

  // Route to the 'transcode' queue
  channel.publish(exchangeName, 'task.transcode', Buffer.from(payload));
  console.log(`[Producer] Published Transcode Task for ${videoId}`);

  // Route to the 'notify' queue
  channel.publish(exchangeName, 'task.notify', Buffer.from(payload));
  console.log(`[Producer] Published Notify Task for ${videoId}`);

  setTimeout(() => connection.close(), 500);
}

// --- CONSUMER 1: Heavy Video Worker ---
async function transcodeWorker() {
  const connection = await amqp.connect('amqp://localhost');
  const channel = await connection.createChannel();

  await channel.assertExchange('video_events', 'direct', { durable: true });
  const q = await channel.assertQueue('transcode_queue', { durable: true });

  // Bind queue to exchange with specific routing key
  await channel.bindQueue(q.queue, 'video_events', 'task.transcode');

  // Prefetch(1) ensures the worker only gets 1 heavy task at a time
  channel.prefetch(1);
  console.log('[Transcoder] Waiting for transcode tasks...');

  channel.consume(q.queue, async (msg) => {
    const data = JSON.parse(msg.content.toString());
    console.log(`[Transcoder] Processing video ${data.videoId} (Simulating heavy CPU work...)`);

    // Simulate slow transcoding
    await new Promise(resolve => setTimeout(resolve, 5000));

    console.log(`[Transcoder] Finished video ${data.videoId}`);
    channel.ack(msg); // Acknowledge completion!
  }, { noAck: false }); // Require explicit acks
}

// --- CONSUMER 2: Fast Email Worker ---
async function emailWorker() {
  const connection = await amqp.connect('amqp://localhost');
  const channel = await connection.createChannel();

  await channel.assertExchange('video_events', 'direct', { durable: true });
  const q = await channel.assertQueue('notify_queue', { durable: true });

  await channel.bindQueue(q.queue, 'video_events', 'task.notify');

  console.log('[EmailWorker] Waiting for notify tasks...');

  channel.consume(q.queue, (msg) => {
    const data = JSON.parse(msg.content.toString());
    console.log(`[EmailWorker] Sending emails for video ${data.videoId}... Done!`);
    channel.ack(msg);
  }, { noAck: false });
}
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Exchange (The Post Office Sorter)**
In RabbitMQ, producers never send messages directly to queues. They send them to an *Exchange*. The exchange `video_events` of type `direct` looks at the routing key attached to the message (e.g., `task.transcode`) to decide where it should go.

**Step 2: Bindings and Queues (The Mail Bins)**
Consumers create their own Queues (`transcode_queue`, `notify_queue`). They then create a *Binding* between their queue and the exchange, essentially telling the exchange: "I want all messages that have the routing key X".

**Step 3: Consumer Acknowledgements (Worker Acks)**
Notice `channel.ack(msg)` and `{ noAck: false }`. This is crucial. If the Transcode worker crashes halfway through a 5-minute video render, RabbitMQ won't receive the `ack`. RabbitMQ will realize the worker died and automatically put the message *back* on the queue so another worker can pick it up.

**Step 4: Prefetch / Quality of Service (QoS)**
`channel.prefetch(1)` tells RabbitMQ: "Don't give this worker more than 1 unacknowledged message at a time." Without this, RabbitMQ might dump 100 heavy video tasks onto a single worker at once, crashing it with out-of-memory errors, while other workers sit idle.

### 5. ASCII Data Flow

```text
                                       Routing Key: "task.transcode"
                                     +---------------------------------> [ transcode_queue ] -> (Transcoder Worker)
                                     |
[ Producer ] -> (Direct Exchange) ---+
                                     |
                                     +---------------------------------> [ notify_queue ]    -> (Email Worker)
                                       Routing Key: "task.notify"
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using auto-acknowledge (`{ noAck: true }`) for tasks that update databases or do external API calls. If the worker crashes mid-process, the message is permanently lost.
**Pro Tip:** Always use manual acknowledgements (`channel.ack(msg)`). Only ack the message *after* the database commit is successful or the file is fully written to disk.

### Level 2: Real-World
**Challenge:** Change the exchange type from `direct` to `topic`. A `topic` exchange allows wildcard routing.
Update the routing keys in the producer to include regions: `task.transcode.us` and `task.transcode.eu`.
Configure a `globalTranscodeWorker` to receive *all* transcode tasks regardless of region using the `#` (multi-word) wildcard.
<details>
<summary><strong>Hint</strong></summary>
Change `assertExchange(..., 'direct')` to `assertExchange(..., 'topic')` in all functions.
In the global transcoder binding, use `task.transcode.#` as the routing key. The `#` matches zero or more words.
</details>

<details>
<summary><strong>Solution Walkthrough</strong></summary>
```javascript
// Producer:
await channel.assertExchange('video_events', 'topic', { durable: true });
channel.publish('video_events', 'task.transcode.us', Buffer.from(payloadUS));
channel.publish('video_events', 'task.transcode.eu', Buffer.from(payloadEU));

// Consumer:
await channel.assertExchange('video_events', 'topic', { durable: true });
await channel.bindQueue(q.queue, 'video_events', 'task.transcode.#'); // The magic wildcard
```
Topic exchanges are incredibly powerful for routing events based on complex criteria (e.g., `logs.error.billing`, where a worker can bind to `logs.*.billing` or `logs.error.#`).
</details>


### Level 3: Boss Level
**Challenge:** Implement manual negative acknowledgement (`nack`) with requeueing. In your `transcodeWorker`, simulate a transient database failure using `Math.random() < 0.5`. If the failure occurs, catch the error and use `channel.nack(msg, false, true)` to reject the message and instruct RabbitMQ to put it back at the head of the queue.
<details>
<summary><strong>Hint</strong></summary>
Wrap your processing logic in a try/catch block. If an error is thrown, use the `nack` method on the channel. The third argument to `nack` is `requeue`, which must be `true`.
</details>

<details>
<summary><strong>Solution Walkthrough</strong></summary>
```javascript
  channel.consume(q.queue, async (msg) => {
    const data = JSON.parse(msg.content.toString());

    try {
      if (Math.random() < 0.5) throw new Error("Transient DB Connection Error");

      console.log(`[Transcoder] Processing video ${data.videoId}`);
      await new Promise(resolve => setTimeout(resolve, 2000));

      channel.ack(msg); // Success
    } catch (error) {
      console.log(`[Transcoder] Failed video ${data.videoId} - ${error.message}. Requeueing...`);
      // nack args: (message, allUpTo, requeue)
      channel.nack(msg, false, true);
    }
  }, { noAck: false });
```
This ensures that temporary glitches don't result in lost data. However, be careful: if the error is permanent (like a malformed payload), requeueing it will cause an infinite loop of failures. This necessitates Dead Letter Queues, covered in Module 2!
</details>

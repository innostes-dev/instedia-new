# 2.1 Managing Conversation Memory: Stateful Interactions

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
By default, LLM APIs are completely stateless. Every time you send a prompt, the model has amnesia; it remembers absolutely nothing about what you asked it 5 seconds ago. If a user asks "What's the weather in Tokyo?" and then follows up with "What about tomorrow?", the LLM will fail because "tomorrow" lacks context. Manually appending previous messages to every new prompt quickly exceeds token limits and becomes expensive and slow.

### 2. Plain English Metaphor (The What)
Think of Memory classes as a **court stenographer who occasionally writes summaries**. A `ConversationBufferMemory` keeps a perfect, verbatim transcript of everything said so far (good for short chats). A `ConversationSummaryMemory` is like a stenographer who, when the transcript gets too long, pauses to write a bulleted summary of the past hour, throwing away the exact words to save paper (tokens) while keeping the core facts.

### 3. Complete Runnable Code
```python
from langchain.memory import ConversationBufferMemory
from langchain.chains import ConversationChain
from langchain_openai import ChatOpenAI

# 1. Initialize the LLM
llm = ChatOpenAI(temperature=0)

# 2. Initialize Memory
memory = ConversationBufferMemory()

# 3. Create a Conversation Chain linking LLM and Memory
conversation = ConversationChain(
    llm=llm,
    memory=memory,
    verbose=True # Shows the internal prompt being built
)

# 4. First interaction
print("User: Hi, my name is Alice and I love hiking.")
response1 = conversation.predict(input="Hi, my name is Alice and I love hiking.")
print("AI:", response1)

# 5. Second interaction - Testing state
print("\nUser: What is my name and what do I like doing?")
response2 = conversation.predict(input="What is my name and what do I like doing?")
print("AI:", response2)
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: Initialization:** We start with our standard `ChatOpenAI` model.
*   **Step 2: Attaching Memory:** We create `ConversationBufferMemory`. Under the hood, this object stores a list of strings or `Message` objects representing the chat history.
*   **Step 3: Execution via ConversationChain:** When we call `.predict(input=...)`, the `ConversationChain` intercepts the request. It queries the `memory` object for the history, automatically injects that history into the prompt template alongside the new user input, sends it to the LLM, and then saves the new input/output pair back to the memory object for the next round.

### 5. ASCII Data Flow
```text
  Round 1:
  User: "I am Bob" ───► [ ConversationChain ] ───► LLM returns "Hi Bob"
                              │         ▲
                      (saves pair)      │ (empty history injected)
                              ▼         │
                        [ Memory Object ]

  Round 2:
  User: "Who am I?" ───► [ ConversationChain ]
                              │         ▲
                              │         │ (injects "Human: I am Bob... AI: Hi Bob")
                              ▼         │
                        [ Memory Object ]
                                        └───► LLM returns "You are Bob."
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Using `ConversationBufferMemory` in production for long-running chatbots. It will eventually crash when the transcript exceeds the model's context window (e.g., 4000 or 8000 tokens), and it costs more money per query as the history grows.
*   **Pro Tip:** Use `ConversationSummaryBufferMemory`. It keeps the last few messages verbatim for immediate context, but uses a background LLM call to summarize older messages, giving you the best of both worlds.

## Phase B: Engineering Challenges

### Level 1 Warm-Up: Inspecting the Buffer
**Task:** Create a `ConversationBufferMemory`. Save two interactions manually using `.save_context()`, then print the buffer variables.
<details>
<summary>Hint</summary>
Use `memory.save_context({"input": "Hello"}, {"output": "Hi"})` and then print `memory.load_memory_variables({})`.
</details>

**Solution:**
```python
from langchain.memory import ConversationBufferMemory

memory = ConversationBufferMemory()
memory.save_context({"input": "Hello AI"}, {"output": "Greetings human."})
memory.save_context({"input": "What's 2+2?"}, {"output": "4."})

print(memory.load_memory_variables({}))
# {'history': 'Human: Hello AI\nAI: Greetings human.\nHuman: What\'s 2+2?\nAI: 4.'}
```

### Level 2 Real-World: Using Messages instead of Strings
**Task:** By default, BufferMemory returns a giant string. For modern ChatModels, we want a list of `Message` objects. Initialize `ConversationBufferMemory` so that it returns messages.
<details>
<summary>Hint</summary>
Set `return_messages=True` when initializing `ConversationBufferMemory`.
</details>

**Solution:**
```python
from langchain.memory import ConversationBufferMemory

memory = ConversationBufferMemory(return_messages=True)
memory.save_context({"input": "Hello"}, {"output": "Hi"})

print(memory.load_memory_variables({}))
# {'history': [HumanMessage(content='Hello'), AIMessage(content='Hi')]}
```

### Level 3 Boss Level: Customer Support Bot with Context Window Memory
**Task:** Build a bot using `ConversationSummaryBufferMemory`. Set the `max_token_limit` very low (e.g., 50 tokens) so that it is forced to summarize almost immediately. Simulate a 3-turn conversation and print the final summarized history.
<details>
<summary>Hint</summary>
You need to pass an `llm` to `ConversationSummaryBufferMemory` because it needs an AI to generate the summaries.
</details>

**Solution:**
```python
from langchain.memory import ConversationSummaryBufferMemory
from langchain_openai import ChatOpenAI
from langchain.chains import ConversationChain

llm = ChatOpenAI(temperature=0)

# 1. Initialize Memory with a tiny token limit to force summarization
memory = ConversationSummaryBufferMemory(
    llm=llm,
    max_token_limit=50,
    return_messages=True
)

# 2. Create the chain
conversation = ConversationChain(
    llm=llm,
    memory=memory,
    verbose=False
)

# 3. Simulate a long conversation
conversation.predict(input="I am opening a new account for my business, TechCorp.")
conversation.predict(input="I want to add my co-founder, Sarah, to the account.")
conversation.predict(input="We will primarily be doing international wire transfers.")

# 4. View the memory state.
# Because the limit is 50 tokens, older messages are converted to a SystemMessage summary!
memory_vars = memory.load_memory_variables({})
for msg in memory_vars['history']:
    print(f"{type(msg).__name__}: {msg.content}\n")

# Output will show a SystemMessage containing the summary of the account creation,
# followed by the most recent Human/AI messages that fit in the buffer.
```

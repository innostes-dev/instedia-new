# 2.2 Equipping Chains with Tools: Agents

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
LLMs are frozen in time. They don't know today's weather, the current stock price, or the result of a complex math equation they haven't memorized. If you ask a standard LLM to multiply `293847 * 92834`, it will likely hallucinate an answer. You need a way to let the LLM reach out to the real world, execute code, query databases, or search the web.

### 2. Plain English Metaphor (The What)
An Agent is like an **Executive Manager**. The manager (the LLM) doesn't do the hard labor themselves. Instead, they are given a toolbox (Tools). When a complex task arrives, the manager looks at their tools, decides which one to use, writes instructions for it, waits for the result, and then decides if they have enough information to answer the user or if they need to use another tool.

### 3. Complete Runnable Code
```python
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate

# 1. Define a custom tool using the @tool decorator
@tool
def multiply(a: int, b: int) -> int:
    """Multiply two integers together. Use this for all multiplication."""
    return a * b

tools = [multiply]

# 2. Setup the Prompt and LLM
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful mathematical assistant."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"), # Required for the agent to think!
])
llm = ChatOpenAI(model="gpt-3.5-turbo", temperature=0)

# 3. Create the Agent and the Executor
agent = create_tool_calling_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# 4. Run the agent
result = agent_executor.invoke({"input": "What is 12345 times 67890?"})
print(result["output"])
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: The `@tool` Decorator:** This is magic. By wrapping a standard Python function with `@tool`, LangChain inspects the type hints (`int`) and the docstring (`"Multiply two integers..."`) and converts them into a JSON Schema. This schema is what the LLM reads to understand *how* and *why* to use the tool.
*   **Step 2: The Prompt & Scratchpad:** The `{agent_scratchpad}` placeholder is vital. It's where the AgentExecutor injects the intermediate steps (e.g., "I called the multiply tool with A and B, and the result was C").
*   **Step 3: The Executor Loop:** The `create_tool_calling_agent` binds the tools to the LLM. The `AgentExecutor` is the `while` loop that runs the agent: it asks the LLM what to do, parses the tool request, actually runs the Python function `multiply`, feeds the answer back to the LLM, and repeats until the LLM says "I have the final answer."

### 5. ASCII Data Flow
```text
User: "What is 5 * 5?"
      │
      ▼
[ AgentExecutor Loop Starts ]
      │
      ├─► LLM (thinks): "I need to multiply. I will use the `multiply` tool with a=5, b=5."
      │
      ├─► Executor catches tool request, runs Python `multiply(5, 5)` -> Returns 25.
      │
      ├─► Executor feeds `25` back to LLM via the {agent_scratchpad}.
      │
      ├─► LLM (thinks): "I have the answer. I will respond to the user."
      │
[ AgentExecutor Loop Ends ]
      ▼
Output: "The answer is 25."
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Writing poor docstrings for your tools. If your docstring just says `"Does math"`, the LLM will get confused. The docstring is the *only* way the LLM knows when to pick that tool over another.
*   **Pro Tip:** Use `create_tool_calling_agent` with modern models (OpenAI, Anthropic) that have native JSON tool-calling capabilities fine-tuned into them. It is vastly more reliable than older parsing agents like `ReAct`.

## Phase B: Engineering Challenges

### Level 1 Warm-Up: The String Reverser Tool
**Task:** Create a simple tool using the `@tool` decorator that takes a string and returns it reversed.
<details>
<summary>Hint</summary>
Define `def reverse_string(text: str) -> str:`, add a good docstring, and use `return text[::-1]`.
</details>

**Solution:**
```python
from langchain_core.tools import tool

@tool
def reverse_string(text: str) -> str:
    """Reverses a given string. Use this when asked to flip or reverse text."""
    return text[::-1]

print(reverse_string.name)
print(reverse_string.description)
print(reverse_string.invoke({"text": "hello"})) # "olleh"
```

### Level 2 Real-World: Weather API Mock Tool
**Task:** Create a tool that mocks a weather API. It should accept a `city` string. If city is "Seattle", return "Raining". If "Miami", return "Sunny". Otherwise, return "Unknown". Bind it to an agent.
<details>
<summary>Hint</summary>
Follow the core concept code block, but replace the `multiply` tool with your new `get_weather` tool.
</details>

**Solution:**
```python
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate

@tool
def get_weather(city: str) -> str:
    """Get the current weather for a specified city."""
    city = city.lower()
    if "seattle" in city: return "Raining heavily."
    if "miami" in city: return "Sunny and hot."
    return "Weather data unavailable."

tools = [get_weather]

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a weather assistant."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"),
])

agent = create_tool_calling_agent(ChatOpenAI(temperature=0), tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

agent_executor.invoke({"input": "Should I pack an umbrella for my trip to Seattle?"})
```

### Level 3 Boss Level: Math & Wikipedia Autonomous Research Chain
**Task:** Build an agent with TWO tools: one for math (calculating the square root of a number) and one for Wikipedia search. Ask the agent: "What is the square root of the year the Titanic sank?" (Note: You can use a mock function for Wikipedia if you don't have the `wikipedia` package installed, just returning "The Titanic sank in 1912.").
<details>
<summary>Hint</summary>
Create two `@tool` functions. Add both to the `tools` list. The agent will autonomously decide to use Wikipedia first, extract the year, and then use the math tool.
</details>

**Solution:**
```python
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate
import math

@tool
def calculate_square_root(number: float) -> float:
    """Calculates the square root of a given number."""
    return math.sqrt(number)

@tool
def search_wikipedia(query: str) -> str:
    """Searches Wikipedia for historical facts and dates."""
    # Mocking Wikipedia for this challenge
    if "titanic" in query.lower():
        return "RMS Titanic sank on 15 April 1912 after striking an iceberg."
    return "No results found."

tools = [calculate_square_root, search_wikipedia]

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a smart research assistant. Use tools to find facts and do math."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"),
])

agent = create_tool_calling_agent(ChatOpenAI(temperature=0), tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# The agent will: 1. Search wiki, 2. Parse out '1912', 3. Calculate sqrt(1912), 4. Answer.
result = agent_executor.invoke({"input": "What is the square root of the year the Titanic sank?"})
print("Final Answer:", result["output"])
```

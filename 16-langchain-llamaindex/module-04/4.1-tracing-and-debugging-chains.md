# 4.1 LangSmith: Tracing & Debugging Chains

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
When you build an AI application using LCEL or LlamaIndex, data flows through many hidden steps. A user asks a question, a retriever fetches 5 documents, a parser formats them, a system prompt is injected, and an LLM generates a response. If the final answer is wrong, hallucinates, or takes 15 seconds to load, how do you debug it? Printing to the console (`print(response)`) is useless for complex pipelines. You need a way to see inside the "black box" of the LLM execution.

### 2. Plain English Metaphor (The What)
Think of LangSmith as a **Flight Data Recorder (Black Box) for your AI**.
Just like a flight recorder tracks altitude, speed, and pilot conversations at every millisecond, LangSmith secretly records every single action in your chain. It logs exactly what prompt was sent to the LLM, exactly how many tokens were used (and how much they cost), how many milliseconds each step took, and what documents were retrieved. You can view all of this in a beautiful web UI.

### 3. Complete Runnable Code
```python
import os
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 1. Enable LangSmith Tracing via Environment Variables
# In production, you would set these in your terminal or .env file:
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_ENDPOINT"] = "https://api.smith.langchain.com"
os.environ["LANGCHAIN_API_KEY"] = "ls__your_api_key_here"
os.environ["LANGCHAIN_PROJECT"] = "Customer_Support_Bot_v1"

# 2. Build a standard LCEL Chain
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant. Keep answers under 20 words."),
    ("human", "{question}")
])
llm = ChatOpenAI(model="gpt-3.5-turbo")
parser = StrOutputParser()

chain = prompt | llm | parser

# 3. Execute the chain.
# Because tracing is ON, this execution is silently uploaded to LangSmith!
print("Executing chain...")
# response = chain.invoke({"question": "Why is the sky blue?"})
print("Done. Go check the LangSmith UI to see the trace!")
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: Environment Configuration:** LangSmith is entirely non-invasive. You don't need to wrap your code in special LangSmith classes. By simply setting `LANGCHAIN_TRACING_V2="true"`, LangChain intercepts its own executions and sends the telemetry to your project dashboard.
*   **Step 2: Chain Execution:** When `chain.invoke()` runs, LangSmith creates a "Run" tree. The root is the overall chain. The children are the prompt formatting, the LLM API call, and the output parsing.
*   **Step 3: The Dashboard:** In the web UI, you can click on this run and see the exact raw JSON payload sent to OpenAI, the latency of the API call, and the cost in fractions of a cent.

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Hardcoding API keys or turning tracing on by default in your code repo. Tracing adds a tiny bit of latency and should only be triggered via secure environment variables in production or testing environments.
*   **Pro Tip:** You can pass a `run_name` or `tags` when invoking a chain (e.g., `chain.invoke(..., config={"tags": ["beta-tester", "v2-prompt"]})`). This allows you to easily filter thousands of traces in LangSmith to find specific bugs.

### Level 1 Warm-Up: Tagging a Run
**Task:** Execute a chain and use the `config` dictionary to add a tag called `"test-run"` and set the run name to `"My Custom Run"`.
<details>
<summary>Hint</summary>
Use `chain.invoke({"question": "test"}, config={"tags": ["test-run"], "run_name": "My Custom Run"})`.
</details>

**Solution:**
```python
from langchain_core.runnables import RunnableLambda

# Mock chain
chain = RunnableLambda(lambda x: x["input"].upper())

# Execute with config
chain.invoke(
    {"input": "hello"},
    config={
        "tags": ["test-run"],
        "run_name": "Uppercase Transformer"
    }
)
```

### Level 2 Real-World: Decorator Tracing for Custom Code
**Task:** Sometimes you write custom Python functions that aren't native LangChain objects. Use the `@traceable` decorator from `langsmith` to trace a normal python function.
<details>
<summary>Hint</summary>
Import `@traceable` from `langsmith`. Apply it to a function `def my_custom_logic(text):`.
</details>

**Solution:**
```python
from langsmith import traceable

@traceable(name="Complex Data Processing")
def process_data(data: str):
    # This entire function's execution time and inputs/outputs
    # will now show up in LangSmith!
    return data[::-1]

process_data("Secret corporate data")
```

### Level 3 Boss Level: Full Trace & Latency Debugging of a Multi-Step Chain
**Task:** Build a chain that has an intentional bottleneck (e.g., a custom function that `time.sleep(2)`). Wrap it in `@traceable`, place it inside an LCEL chain, and explain how LangSmith helps you find the bottleneck.
<details>
<summary>Hint</summary>
Create a traceable function `slow_db_fetch`. Create an LCEL pipeline: `prompt | llm | slow_db_fetch`. Run it.
</details>

**Solution:**
```python
import time
from langsmith import traceable
from langchain_core.prompts import PromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.runnables import RunnableLambda

@traceable(name="Legacy Database Query")
def slow_db_fetch(llm_output: str) -> str:
    """Simulates a very slow API or DB call."""
    time.sleep(2)
    return f"DB Result attached to: {llm_output}"

prompt = PromptTemplate.from_template("Say hello to {name}")
llm = ChatOpenAI(temperature=0)
slow_step = RunnableLambda(slow_db_fetch)

# LCEL Pipeline
pipeline = prompt | llm | slow_step

# execution
# result = pipeline.invoke({"name": "Alice"})

"""
Explanation:
If this pipeline takes 3 seconds to run, a user might blame the LLM.
However, by looking at the LangSmith trace tree, we would clearly see:
- PromptTemplate: 1ms
- ChatOpenAI: 950ms
- Legacy Database Query: 2000ms <--- THE BOTTLENECK

LangSmith provides a visual Gantt chart of latency for every step in the pipeline,
making performance debugging trivial.
"""
```

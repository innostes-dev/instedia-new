# 3.3 Smart Multi-Document Routing

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
As your company scales, stuffing everything into one giant Vector Database becomes inefficient. You might have a database of technical manuals, a database of HR policies, and a database of financial reports. If a user asks "How do I reset the server?", querying the HR policy database is a waste of time, money, and might return irrelevant noise that confuses the LLM.

### 2. Plain English Metaphor (The What)
Think of a `RouterQueryEngine` as the **Front Desk Receptionist** at a large corporate building.
When a visitor (the query) walks in, the receptionist doesn't just send them to every floor simultaneously. The receptionist looks at the visitor's request ("I need to fix my laptop"), checks their directory of departments (the Tool Descriptions), and directs the visitor exclusively to the IT Department (the specific Query Engine).

### 3. Complete Runnable Code
```python
from llama_index.core import VectorStoreIndex, Document
from llama_index.core.tools import QueryEngineTool, ToolMetadata
from llama_index.core.query_engine import RouterQueryEngine
from llama_index.core.selectors import LLMSingleSelector

# 1. Create two separate indexes (representing different databases)
tech_docs = [Document(text="To restart the server, run `sudo systemctl restart nginx`.")]
hr_docs = [Document(text="Employees must submit expenses by the 15th of the month.")]

tech_index = VectorStoreIndex.from_documents(tech_docs)
hr_index = VectorStoreIndex.from_documents(hr_docs)

# 2. Convert indexes into Query Engines
tech_engine = tech_index.as_query_engine()
hr_engine = hr_index.as_query_engine()

# 3. Wrap engines in Tools with descriptions (The Receptionist's Directory)
tech_tool = QueryEngineTool(
    query_engine=tech_engine,
    metadata=ToolMetadata(
        name="tech_manuals",
        description="Useful for answering questions about IT, servers, and code."
    )
)

hr_tool = QueryEngineTool(
    query_engine=hr_engine,
    metadata=ToolMetadata(
        name="hr_policies",
        description="Useful for answering questions about rules, expenses, and benefits."
    )
)

# 4. Create the Router Query Engine
# LLMSingleSelector uses an LLM to pick exactly ONE best tool based on the descriptions
router_engine = RouterQueryEngine(
    selector=LLMSingleSelector.from_defaults(),
    query_engine_tools=[tech_tool, hr_tool],
)

# 5. Execute - Watch it route!
print("Querying about servers...")
response = router_engine.query("How do I restart the server?")
print(response) # Routes to tech_engine

print("\nQuerying about money...")
response = router_engine.query("When are my expenses due?")
print(response) # Routes to hr_engine
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: Distinct Indexes:** We create logically separated silos of information.
*   **Step 2 & 3: Tools & Metadata:** We convert the engines into `QueryEngineTool` objects. The `description` here is absolutely critical. This is the exact text the Router LLM will read to make its routing decision.
*   **Step 4: The Selector:** The `LLMSingleSelector` takes the user's query ("How do I restart..."), reads the tool descriptions, and generates a JSON decision indicating which tool is best. The `RouterQueryEngine` then executes the query against *only* that chosen engine.

### 5. ASCII Data Flow
```text
User Query: "When are expenses due?"
       │
       ▼
[ Router (LLM Selector) ]
       │ Reads Descriptions:
       │ - tech_manuals: "IT, servers, code"
       │ - hr_policies: "rules, expenses, benefits" ◄── MATCH!
       │
       ▼ (Routes execution only to HR)
[ HR Query Engine ]
       │
       ▼
[ HR Vector Store ] ──► Retrieves Nodes ──► [ Synthesis LLM ] ──► Answer
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Providing overlapping or vague tool descriptions (e.g., "Good for company info" and "Good for employee info"). The Selector will get confused and frequently route to the wrong index.
*   **Pro Tip:** If a user query might require information from multiple indexes (e.g., "What is the tech budget for servers?"), use `LLMMultiSelector` instead of `SingleSelector`. It can choose multiple tools, run them in parallel, and combine the answers!

### Level 3 Boss Level: Executive Enterprise Query Router
**Task:** Build a Router that sits on top of a standard Vector Index (for unstructured text) and a Keyword Index (for exact terminology matching). Route "What is the summary of the report?" to the vector engine, and "Find documents mentioning XYZ-992" to the keyword engine.
<details>
<summary>Hint</summary>
You don't need actual data. Just initialize a `VectorStoreIndex` and a `SimpleKeywordTableIndex` with dummy docs. Wrap both in tools with very distinct descriptions (semantic meaning vs exact keyword matching).
</details>

**Solution:**
```python
from llama_index.core import VectorStoreIndex, SimpleKeywordTableIndex, Document
from llama_index.core.tools import QueryEngineTool, ToolMetadata
from llama_index.core.query_engine import RouterQueryEngine
from llama_index.core.selectors import LLMSingleSelector

# 1. Data
docs = [Document(text="Project Titan uses part number XYZ-992. It is a secret initiative.")]

# 2. Indexes (Semantic vs Exact Match)
vector_index = VectorStoreIndex.from_documents(docs)
keyword_index = SimpleKeywordTableIndex.from_documents(docs)

# 3. Tools
vector_tool = QueryEngineTool(
    query_engine=vector_index.as_query_engine(),
    metadata=ToolMetadata(
        name="semantic_search",
        description="Use this for conceptual questions, summaries, and broad understanding."
    )
)

keyword_tool = QueryEngineTool(
    query_engine=keyword_index.as_query_engine(),
    metadata=ToolMetadata(
        name="exact_keyword_search",
        description="Use this ONLY when looking for specific part numbers, acronyms, or exact IDs like XYZ-992."
    )
)

# 4. Router
router = RouterQueryEngine(
    selector=LLMSingleSelector.from_defaults(),
    query_engine_tools=[vector_tool, keyword_tool]
)
```

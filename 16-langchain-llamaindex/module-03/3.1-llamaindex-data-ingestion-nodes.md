# 3.1 LlamaIndex Data Ingestion: Documents & Nodes

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
You have gigabytes of PDFs, Notion pages, and CSVs. An LLM context window can only hold a few pages of text at a time. You can't just copy-paste a 500-page employee handbook into ChatGPT and ask "What is the dental policy?" You need a way to read diverse file formats, extract the raw text, and chop that massive text into bite-sized, mathematically searchable pieces so the LLM only reads the relevant paragraphs.

### 2. Plain English Metaphor (The What)
Think of LlamaIndex data ingestion like **preparing ingredients for a restaurant service**.
A `Document` is the raw, unpeeled potato (the whole PDF file). The `SimpleDirectoryReader` is the delivery truck dropping off crates of potatoes. You can't cook a whole potato instantly, so you use a `NodeParser` (a kitchen knife) to chop the potato into bite-sized `Nodes` (chunks of text). These small chunks are what you finally put into the pot (the Vector Store) to cook up answers later.

### 3. Complete Runnable Code
```python
import os
from llama_index.core import SimpleDirectoryReader
from llama_index.core.node_parser import SentenceSplitter

# 1. Ensure we have a sample directory and file
os.makedirs("data", exist_ok=True)
with open("data/handbook.txt", "w") as f:
    f.write("Welcome to the company!\n\n" * 50) # Simulate a long document
    f.write("DENTAL POLICY: Employees get free cleanings twice a year.\n")
    f.write("Have a great day!\n\n" * 50)

# 2. Ingest: Read all files in the directory into Documents
reader = SimpleDirectoryReader(input_dir="./data")
documents = reader.load_data()
print(f"Loaded {len(documents)} document(s).")

# 3. Chunk: Parse the Document into smaller Nodes
# We split by sentences, ensuring each chunk is roughly 100 tokens
parser = SentenceSplitter(chunk_size=100, chunk_overlap=20)
nodes = parser.get_nodes_from_documents(documents)
print(f"Chopped into {len(nodes)} bite-sized nodes.")

# 4. Inspect a Node
print("\nSample Node Text:")
print(nodes[2].text)
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: The Loader (`SimpleDirectoryReader`):** This is LlamaIndex's Swiss Army knife. You point it at a folder, and it automatically detects file extensions (`.txt`, `.pdf`, `.csv`, `.md`) and extracts the text, returning a list of `Document` objects.
*   **Step 2: The Document:** A `Document` object holds the raw text *and* metadata (like the filename, creation date, or page number).
*   **Step 3: The Parser (`SentenceSplitter`):** This slices the massive `Document` into `Node` objects. `chunk_size` dictates the max size (in tokens), and `chunk_overlap` ensures we don't accidentally slice a sentence in half, losing context.

### 5. ASCII Data Flow
```text
[ data/policy.pdf ]  [ data/notes.txt ]
         │                  │
         ▼                  ▼
 ╭────────────────────────────────────╮
 │       SimpleDirectoryReader        │
 ╰─────────────────┬──────────────────╯
                   │
                   ▼
     [ Document ]      [ Document ]  <-- (Massive text strings + Metadata)
                   │
                   ▼
 ╭────────────────────────────────────╮
 │   NodeParser (SentenceSplitter)    │ <-- (The Chopping Block)
 ╰─────────────────┬──────────────────╯
                   │
                   ▼
 [Node 1] [Node 2] [Node 3] [Node 4] <-- (Bite-sized chunks ready for embeddings)
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Using a huge `chunk_size` (e.g., 2000) to fit more context. This dilutes the semantic meaning of the chunk, making the retrieval step (Vector Search) highly inaccurate.
*   **Pro Tip:** Always inject metadata into your Documents *before* chunking (e.g., `doc.metadata = {"author": "HR", "category": "benefits"}`). When chunked, every resulting Node inherits that metadata, allowing you to heavily filter your searches later (e.g., "Only search Nodes where author is HR").

### Level 2 Real-World: Custom Chunking Strategy
**Task:** Read a document using `SimpleDirectoryReader` but use a `TokenTextSplitter` with a tiny chunk size of 10 tokens and 0 overlap to see how violently it slices text.
<details>
<summary>Hint</summary>
Import `TokenTextSplitter` from `llama_index.core.node_parser`.
</details>

**Solution:**
```python
import os
from llama_index.core import SimpleDirectoryReader
from llama_index.core.node_parser import TokenTextSplitter

os.makedirs("temp", exist_ok=True)
with open("temp/short.txt", "w") as f: f.write("The quick brown fox jumps over the lazy dog.")

docs = SimpleDirectoryReader(input_dir="./temp").load_data()

splitter = TokenTextSplitter(chunk_size=10, chunk_overlap=0)
nodes = splitter.get_nodes_from_documents(docs)

for i, node in enumerate(nodes):
    print(f"Node {i}: {node.text}")
```

### Level 3 Boss Level: Enterprise PDF Knowledge Base Ingestion Pipeline
**Task:** Build a function that takes a directory path. It should load all files, attach a "processed_date" metadata tag to every document, chunk them into nodes (size 256, overlap 50), and return the list of nodes.
<details>
<summary>Hint</summary>
Loop through `reader.load_data()`. For each doc, update `doc.metadata["processed_date"]`. Then pass the whole list to `SentenceSplitter().get_nodes_from_documents()`.
</details>

**Solution:**
```python
import os
import datetime
from llama_index.core import SimpleDirectoryReader
from llama_index.core.node_parser import SentenceSplitter

def enterprise_ingestion_pipeline(directory_path: str):
    # 1. Load Data
    reader = SimpleDirectoryReader(input_dir=directory_path)
    try:
        documents = reader.load_data()
    except ValueError:
        return [] # Empty dir

    # 2. Enrich Metadata
    current_date = datetime.datetime.now().strftime("%Y-%m-%d")
    for doc in documents:
        doc.metadata["processed_date"] = current_date
        # Ensure metadata is visible to the LLM during generation
        doc.excluded_llm_metadata_keys = []

    # 3. Chunking Strategy
    parser = SentenceSplitter(chunk_size=256, chunk_overlap=50)
    nodes = parser.get_nodes_from_documents(documents)

    return nodes
```

# 1.3 File-Based Routing & Native Navigation: Expo Router

## Phase A: Concept & Implementation

### 1. Real-World Pain Point (The Why)
In web development, navigation is fundamentally linear (URLs). On mobile, navigation is a complex, multi-dimensional stack of cards. Users push screens onto a stack, pop them off, swipe back with gestures, or switch between isolated navigation stacks via persistent bottom tabs. Historically, developers had to manually wire up complex `react-navigation` boilerplates, leading to massive navigation files, fragile deep linking, and broken Android back-button behavior.

### 2. Plain English Metaphor (The What)
Imagine navigating a website is like walking down a hallway; you go forward and backward through doors. Mobile navigation is like dealing a deck of cards. When you tap a product, a new card (screen) is dealt on top of the pile. To go back, you pull that card off the top. A Bottom Tab Bar is like having multiple, distinct decks of cards side-by-side. Expo Router brings the magic of Next.js file-based routing (`app/index.tsx`, `app/product/[id].tsx`) to mobile, automatically translating your folder structure into these complex native card stacks and tab bars under the hood.

### 3. Complete Runnable Code
*Example: Multi-Screen Shopping App with Persistent Tab Bar*

**File Structure Setup:**
```text
app/
 ├── _layout.tsx           (Root layout wrapping everything)
 ├── (tabs)/               (Group folder, doesn't appear in URL)
 │    ├── _layout.tsx      (Tab Bar configuration)
 │    ├── index.tsx        (Home screen: /)
 │    └── profile.tsx      (Profile screen: /profile)
 └── product/
      └── [id].tsx         (Dynamic product screen: /product/123)
```

**`app/(tabs)/_layout.tsx` (Configuring the Native Tabs)**
```tsx
import { Tabs } from 'expo-router';
import { Ionicons } from '@expo/vector-icons';

export default function TabLayout() {
  return (
    <Tabs screenOptions={{ tabBarActiveTintColor: 'blue' }}>
      <Tabs.Screen
        name="index"
        options={{
          title: 'Shop',
          tabBarIcon: ({ color }) => <Ionicons name="cart" size={24} color={color} />,
        }}
      />
      <Tabs.Screen
        name="profile"
        options={{
          title: 'Profile',
          tabBarIcon: ({ color }) => <Ionicons name="person" size={24} color={color} />,
        }}
      />
    </Tabs>
  );
}
```

**`app/(tabs)/index.tsx` (Home Screen)**
```tsx
import { View, Text, StyleSheet, FlatList } from 'react-native';
import { Link } from 'expo-router';

const PRODUCTS = [
  { id: '1', name: 'Wireless Headphones' },
  { id: '2', name: 'Mechanical Keyboard' },
];

export default function HomeScreen() {
  return (
    <View style={styles.container}>
      <FlatList
        data={PRODUCTS}
        keyExtractor={(item) => item.id}
        renderItem={({ item }) => (
          // Link pushes a new screen onto the stack over the tabs
          <Link href={`/product/${item.id}`} style={styles.linkCard}>
            <Text style={styles.linkText}>View {item.name}</Text>
          </Link>
        )}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 16, backgroundColor: '#f5f5f5' },
  linkCard: { padding: 20, backgroundColor: 'white', marginBottom: 12, borderRadius: 8 },
  linkText: { fontSize: 16, fontWeight: 'bold' }
});
```

**`app/product/[id].tsx` (Dynamic Details Screen)**
```tsx
import { View, Text, StyleSheet, Button } from 'react-native';
import { useLocalSearchParams, useRouter, Stack } from 'expo-router';

export default function ProductDetails() {
  const { id } = useLocalSearchParams(); // Captures the [id] from the path
  const router = useRouter();

  return (
    <View style={styles.container}>
      {/* Configure the native header for this specific screen */}
      <Stack.Screen options={{ title: `Product #${id}` }} />

      <Text style={styles.title}>Details for Item {id}</Text>

      <View style={styles.buttonContainer}>
        {/* Programmatic navigation */}
        <Button title="Go Back" onPress={() => router.back()} />
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: 'center', justifyContent: 'center' },
  title: { fontSize: 24, fontWeight: 'bold', marginBottom: 20 },
  buttonContainer: { marginTop: 20 }
});
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Grouping with `(tabs)`**
Why this precedes the next: We need to define the foundational UI shell (the Tab Bar) before we create the screens that live inside it.
```text
app/(tabs)/_layout.tsx
```
*Rationale:* Folders with parentheses `()` are "Groups". They do not affect the routing URL (so `app/(tabs)/index.tsx` is still just `/`). This allows us to apply a layout (the `Tabs` component) to a specific group of screens without changing how we link to them.

**Step 2: Linking to Dynamic Routes**
Why this precedes the next: Once the shell is built, we need a way to navigate away from it to detailed views.
```tsx
<Link href={`/product/${item.id}`}>
```
*Rationale:* The `<Link>` component handles the native bridge. When tapped, it doesn't do a full page reload like a web browser. Instead, it instructs the Native Stack navigator to instantiate a new native View Controller (iOS) or Activity (Android) and slide it over the current screen.

**Step 3: Accessing Parameters and Overriding Headers**
Why this precedes the next: Once on the new screen, we must read the passed data to render correctly, and update the UI context (the header bar).
```tsx
const { id } = useLocalSearchParams();
<Stack.Screen options={{ title: `Product #${id}` }} />
```
*Rationale:* `useLocalSearchParams` is the Expo Router equivalent of React Router's `useParams`. `<Stack.Screen>` allows a child component to dynamically modify the native header provided by its parent `_layout.tsx`, ensuring the title updates contextually.

### 5. ASCII / Architecture Data Flow
```text
[ User Taps <Link href="/product/123"> ]
         |
[ Expo Router Engine parses path ]
         |
[ Matches app/product/[id].tsx ]
         |
[ Translates to React Navigation Native Stack ]
         |
    +----v----+
    |         |--> (iOS) Instantiates UIViewController, triggers Push Transition (Slide right-to-left)
    | Native  |
    | Layer   |--> (Android) Instantiates Fragment, triggers Push Transition (Fade/Slide up)
    |         |
    +----+----+
         |
[ Renders React Component ] --> Extracts `id` via useLocalSearchParams()
```

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Using `router.push('/home')` when you are already in the tabs, or manually trying to handle the Android hardware back button.
* **Pro Tip:** By default, Expo Router automatically integrates with the iOS swipe-to-go-back gesture and the Android hardware back button. Never override these unless strictly necessary for custom behavior (like a "Discard unsaved changes?" prompt). Use `router.replace()` instead of `push()` for auth flows (like Login -> Home) so the user cannot press "back" to return to the login screen.

### Level 2: Real-World
**Challenge:** Implement a "Native Modal". Create a route `/help` that slides up from the bottom of the screen instead of pushing horizontally from the side.
<details>
<summary>Hint</summary>
Create `app/help.tsx`. You need a root `app/_layout.tsx` that uses a `<Stack>`. In that Stack, configure the `help` screen with `presentation: 'modal'`.
</details>

<details>
<summary>Solution Walkthrough</summary>
In `app/_layout.tsx`:
```tsx
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    <Stack>
      <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
      <Stack.Screen
        name="help"
        options={{
          presentation: 'modal',
          title: 'Help & Support'
        }}
      />
    </Stack>
  );
}
```
Using `presentation: 'modal'` tells the native OS to use a modal sheet presentation (slide up) rather than a stack push.
</details>

### Level 3: Boss Level
**Challenge:** Combine File-Based Routing with Native Primitives and Pressables. Build a dynamic deep-linkable product list where tapping an item uses a custom `<Pressable>` (with haptics) to programmatically `router.push()` to a details screen.
<details>
<summary>Hint</summary>
Use `useRouter()` to get the router object. Create a custom Pressable card. In the `onPress`, trigger Haptics, then call `router.push(\`/product/\${id}\`)`.
</details>

<details>
<summary>Solution Walkthrough</summary>
This level combines Modules 1.1, 1.2, and 1.3 into a cohesive interactive flow.

```tsx
import { View, Text, Pressable, StyleSheet } from 'react-native';
import { useRouter } from 'expo-router';
import * as Haptics from 'expo-haptics';

export default function InteractiveProductCard({ id, name }) {
  const router = useRouter();

  const handlePress = () => {
    Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light);
    router.push(`/product/${id}`);
  };

  return (
    <Pressable
      onPress={handlePress}
      style={({ pressed }) => [
        styles.card,
        pressed && styles.cardPressed
      ]}
    >
      <Text style={styles.text}>{name}</Text>
    </Pressable>
  );
}

const styles = StyleSheet.create({
  card: { padding: 20, backgroundColor: 'white', borderRadius: 8, marginVertical: 8 },
  cardPressed: { opacity: 0.7, transform: [{ scale: 0.98 }] },
  text: { fontSize: 18, fontWeight: 'bold' }
});
```
This is the standard architectural pattern for modern, high-performance React Native application navigation.
</details>

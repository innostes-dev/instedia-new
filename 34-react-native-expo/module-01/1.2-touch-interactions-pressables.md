# 1.2 Touch Interactions & Feedback: Pressables and Haptics

## Phase A: Concept & Implementation

### 1. Real-World Pain Point (The Why)
Web developers often wire up `<div onClick={...}>` and assume it works gracefully on mobile. It doesn't. Native apps require immediate, tactile feedback when a user touches the screen. If a button doesn't dim (iOS) or ripple (Android) instantly, users assume the app is broken or frozen. Furthermore, "fat fingers" miss tiny tap targets constantly, leading to frustrating user experiences. Using the legacy `TouchableOpacity` solves some issues but lacks fine-grained control over touch phases and modern native feedback mechanics.

### 2. Plain English Metaphor (The What)
Think of a physical elevator button. When you press it, it physically depresses, a light turns on, and you hear a slight mechanical click. This confirms your intent. The `<Pressable>` component in React Native is your custom elevator button toolkit. It detects the exact moment a finger touches down, holds, and lifts off, allowing you to trigger lights (opacity/ripples) and clicks (haptic vibrations). `HitSlop` is like putting an invisible funnel around the button, ensuring that even if your finger is slightly off-target, the elevator still registers the press.

### 3. Complete Runnable Code
*Example: Interactive E-Commerce Add-to-Cart Button with Haptics*

```tsx
import React, { useState } from 'react';
import { View, Text, Pressable, StyleSheet, Platform } from 'react-native';
import * as Haptics from 'expo-haptics';

const AddToCartButton = () => {
  const [cartCount, setCartCount] = useState(0);

  const handlePressIn = () => {
    // Immediate physical feedback upon touch down
    if (Platform.OS !== 'web') {
      Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light);
    }
  };

  const handlePressOut = () => {
    // Different feedback on release
    if (Platform.OS !== 'web') {
      Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium);
    }
  };

  const handleAddToCart = () => {
    setCartCount(prev => prev + 1);
  };

  return (
    <View style={styles.container}>
      <Text style={styles.counterText}>Items in Cart: {cartCount}</Text>

      <Pressable
        onPressIn={handlePressIn}
        onPressOut={handlePressOut}
        onPress={handleAddToCart}
        // Expand the touchable area without changing visual size
        hitSlop={{ top: 20, bottom: 20, left: 20, right: 20 }}
        // Android native ripple effect
        android_ripple={{ color: 'rgba(255, 255, 255, 0.3)', borderless: false }}
        // Dynamic styling based on interaction state
        style={({ pressed }) => [
          styles.cartButton,
          pressed && styles.cartButtonPressed // iOS-style opacity feedback
        ]}
      >
        {({ pressed }) => (
          <Text style={[
            styles.buttonText,
            pressed && styles.buttonTextPressed
          ]}>
            {pressed ? 'Adding...' : 'Add to Cart'}
          </Text>
        )}
      </Pressable>
    </View>
  );
};

const styles = StyleSheet.create({
  container: {
    padding: 24,
    alignItems: 'center',
    justifyContent: 'center',
  },
  counterText: {
    fontSize: 18,
    fontWeight: '600',
    marginBottom: 24,
    color: '#374151',
  },
  cartButton: {
    backgroundColor: '#4F46E5',
    paddingVertical: 16,
    paddingHorizontal: 32,
    borderRadius: 12,
    alignItems: 'center',
    justifyContent: 'center',
    minWidth: 200,
  },
  cartButtonPressed: {
    // The "dimming" effect for iOS when pressed
    opacity: 0.8,
    transform: [{ scale: 0.98 }],
  },
  buttonText: {
    color: '#FFFFFF',
    fontSize: 16,
    fontWeight: '700',
  },
  buttonTextPressed: {
    color: '#E0E7FF',
  }
});

export default AddToCartButton;
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Core `<Pressable>` Foundation**
Why this precedes the next: We must establish the touchable surface before we can react to its state changes.
```tsx
<Pressable
  onPress={handleAddToCart}
  style={styles.cartButton}
>
  <Text>Add to Cart</Text>
</Pressable>
```
*Rationale:* `<Pressable>` replaces `<TouchableOpacity>`. It provides a blank slate for touch events without imposing default visual behaviors, giving us total architectural control.

**Step 2: Dynamic Styling and Feedback Mechanics**
Why this precedes the next: Users need visual confirmation before we introduce physical (haptic) confirmation.
```tsx
<Pressable
  android_ripple={{ color: 'rgba(255,255,255,0.3)' }}
  style={({ pressed }) => [
    styles.cartButton,
    pressed && { opacity: 0.8, transform: [{ scale: 0.98 }] }
  ]}
>
```
*Rationale:* We pass a function to the `style` prop. The `pressed` boolean tells us if the user's finger is currently down. We conditionally apply scale and opacity for iOS, while `android_ripple` taps into Android's native Material Design touch feedback system at the OS level.

**Step 3: Augmenting with HitSlop and Haptics**
Why this precedes the next: Visuals are complete; we now optimize for ergonomics (HitSlop) and sensory feedback (Haptics).
```tsx
  onPressIn={() => Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Light)}
  hitSlop={{ top: 20, bottom: 20, left: 20, right: 20 }}
```
*Rationale:* `hitSlop` extends the interactive area by 20 pixels in all directions invisibly, preventing frustration on smaller buttons. `Haptics` triggers the device's Taptic Engine (iOS) or vibration motor (Android) to simulate a physical click.

### 5. ASCII / Architecture Data Flow
```text
[ User Finger touches Screen ]
         |
[ OS Touch Event (UITouch / MotionEvent) ]
         |
[ React Native Touch Responder System ]
         |-- Checks hitSlop bounds (invisible expansion)
         |
    (Finger Down) --> onPressIn() triggered
         |          --> UI Thread updates {pressed: true}
         |          --> JS Bridge calls Haptics.impactAsync()
         |          --> Android Native UI renders Ripple
         |
    (Finger Up)   --> onPressOut() & onPress() triggered
                    --> UI Thread updates {pressed: false}
                    --> JS executes handleAddToCart()
```

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Using `<TouchableOpacity>` everywhere and accepting the default, sluggish 0.2 opacity fade. It feels non-native, especially on Android where users expect material ripples.
* **Pro Tip:** When passing functions to `<Pressable style={...}>`, wrap heavy child components in `React.memo()`. Constant `pressed` state changes trigger re-renders, which can cause frame drops if the button's children are complex.

### Level 1: Warm-Up
**Challenge:** Modify the button so it is disabled when `cartCount` reaches 5. A disabled button should be grayed out and ignore touches.
<details>
<summary>Hint</summary>
Use the `disabled` prop on `<Pressable>`. Add dynamic styling to change the `backgroundColor` when `disabled` is true.
</details>

<details>
<summary>Solution Walkthrough</summary>
1. Evaluate `disabled={cartCount >= 5}`.
2. In the style array, add conditional styling based on the cart count.
```tsx
<Pressable
  disabled={cartCount >= 5}
  style={({ pressed }) => [
    styles.cartButton,
    cartCount >= 5 && { backgroundColor: '#9CA3AF' },
    pressed && cartCount < 5 && styles.cartButtonPressed
  ]}
>
```
</details>

### Level 2: Real-World
**Challenge:** Build a "Long Press to Delete" interaction for a shopping cart item row. It should trigger heavy haptic feedback only after being held for 1 second.
<details>
<summary>Hint</summary>
Explore the `onLongPress` and `delayLongPress` props of `<Pressable>`. Use `Haptics.notificationAsync` on successful long press.
</details>

<details>
<summary>Solution Walkthrough</summary>
`delayLongPress={1000}` ensures the user must hold for a full second.
```tsx
const handleLongPress = () => {
  Haptics.notificationAsync(Haptics.NotificationFeedbackType.Warning);
  // Delete item logic here
};

<Pressable
  onLongPress={handleLongPress}
  delayLongPress={1000}
  style={styles.cartRow}
>
  <Text>Swipe or Hold to Delete</Text>
</Pressable>
```
</details>

### Level 3: Boss Level
**Challenge:** Create a Custom `AnimatedPressable` that gracefully scales down using React Native's `Animated` API when pressed in, and springs back up when released, completely independently of the `({ pressed })` state prop to ensure zero frame drops on complex buttons.
<details>
<summary>Hint</summary>
Use `useRef(new Animated.Value(1)).current`. Trigger `Animated.spring` inside `onPressIn` and `onPressOut`. Wrap a standard `<Pressable>` inside an `<Animated.View>`.
</details>

<details>
<summary>Solution Walkthrough</summary>
This bypasses standard React state re-renders for the animation.

```tsx
import React, { useRef } from 'react';
import { Animated, Pressable, Text } from 'react-native';

const AnimatedPressable = ({ onPress, children }) => {
  const scale = useRef(new Animated.Value(1)).current;

  const animateScale = (toValue) => {
    Animated.spring(scale, {
      toValue,
      friction: 5,
      useNativeDriver: true, // Pushes animation to UI thread
    }).start();
  };

  return (
    <Animated.View style={{ transform: [{ scale }] }}>
      <Pressable
        onPressIn={() => animateScale(0.95)}
        onPressOut={() => animateScale(1)}
        onPress={onPress}
      >
        {children}
      </Pressable>
    </Animated.View>
  );
};
```
This is how production apps create buttery-smooth, native-feeling interactions regardless of JS thread load.
</details>

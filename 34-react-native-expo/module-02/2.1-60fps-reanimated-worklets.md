# 2.1 High-Performance 60FPS Animations: Reanimated 3 Worklets

## Phase A: Concept & Implementation

### 1. Real-World Pain Point (The Why)
In React Native, your JavaScript logic runs on one thread, and the native UI rendering (iOS/Android) runs on another. When you try to animate a component by rapidly updating state (`setState`) inside a `requestAnimationFrame` loop, or even using the legacy `Animated` API for complex layouts, the JS thread becomes overwhelmed. If a network request or heavy calculation blocks the JS thread, the animation stutters, drops frames, and the app feels clunky and unresponsive.

### 2. Plain English Metaphor (The What)
Imagine you (the JS thread) are giving instructions via walkie-talkie to a construction worker (the UI thread) building a wall. If you have to say "move brick left 1 inch... move brick left 1 inch..." 60 times a second, any interruption on the radio means the worker stops. React Native Reanimated 3 uses "Worklets." A worklet is like handing the worker a blueprint (a tiny compiled function) that says, "Move this brick 10 feet to the left over 2 seconds." The worker takes the blueprint and executes the animation entirely on their own (on the UI thread) at a flawless 60 FPS, even if your radio cuts out completely.

### 3. Complete Runnable Code
*Example: Ultra-Smooth 60 FPS Swipeable Notification Card*

```tsx
import React from 'react';
import { View, Text, StyleSheet, Dimensions } from 'react-native';
import { Gesture, GestureDetector, GestureHandlerRootView } from 'react-native-gesture-handler';
import Animated, {
  useSharedValue,
  useAnimatedStyle,
  withSpring,
  withTiming,
  runOnJS
} from 'react-native-reanimated';
import * as Haptics from 'expo-haptics';

const { width: SCREEN_WIDTH } = Dimensions.get('window');
const SWIPE_THRESHOLD = SCREEN_WIDTH * 0.4;

const SwipeableNotification = ({ onDismiss }) => {
  // Shared values live on the UI thread
  const translateX = useSharedValue(0);
  const opacity = useSharedValue(1);
  const cardHeight = useSharedValue(80);

  // We must trigger JS-side actions (like state updates) explicitly from the UI thread
  const handleDismiss = () => {
    Haptics.notificationAsync(Haptics.NotificationFeedbackType.Success);
    if (onDismiss) onDismiss();
  };

  const panGesture = Gesture.Pan()
    .onChange((event) => {
      // Runs entirely on the UI thread
      translateX.value = event.translationX;
    })
    .onEnd((event) => {
      // Runs entirely on the UI thread
      const isSwipedOff = Math.abs(event.translationX) > SWIPE_THRESHOLD;

      if (isSwipedOff) {
        // Swipe it away
        const direction = Math.sign(event.translationX);
        translateX.value = withTiming(direction * SCREEN_WIDTH, { duration: 200 });
        opacity.value = withTiming(0, { duration: 200 });

        // Collapse the card space smoothly
        cardHeight.value = withTiming(0, { duration: 300 }, (isFinished) => {
          if (isFinished) {
            runOnJS(handleDismiss)();
          }
        });
      } else {
        // Spring back to center
        translateX.value = withSpring(0);
      }
    });

  // Animated styles react to shared value changes on the UI thread
  const animatedStyle = useAnimatedStyle(() => {
    return {
      transform: [{ translateX: translateX.value }],
      opacity: opacity.value,
      height: cardHeight.value,
      marginBottom: cardHeight.value > 0 ? 12 : 0, // Collapse margin too
    };
  });

  return (
    <GestureDetector gesture={panGesture}>
      <Animated.View style={[styles.card, animatedStyle]}>
        <View style={styles.content}>
          <Text style={styles.title}>System Update Available</Text>
          <Text style={styles.description}>Swipe to dismiss this notification.</Text>
        </View>
      </Animated.View>
    </GestureDetector>
  );
};

// Root Wrapper to enable Gesture Handler
export default function App() {
  return (
    <GestureHandlerRootView style={styles.container}>
      <SwipeableNotification onDismiss={() => console.log('Dismissed!')} />
    </GestureHandlerRootView>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: '#F3F4F6', padding: 20, paddingTop: 60 },
  card: {
    backgroundColor: '#FFFFFF',
    borderRadius: 12,
    justifyContent: 'center',
    overflow: 'hidden', // Important for smooth height collapse
    shadowColor: '#000',
    shadowOffset: { width: 0, height: 2 },
    shadowOpacity: 0.1,
    shadowRadius: 4,
    elevation: 3,
  },
  content: { padding: 16 },
  title: { fontSize: 16, fontWeight: '700', color: '#111827', marginBottom: 4 },
  description: { fontSize: 14, color: '#6B7280' },
});
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Establishing Shared Values**
Why this precedes the next: We need reactive variables that exist on the UI thread before we can attach gestures or styles to them.
```tsx
const translateX = useSharedValue(0);
const opacity = useSharedValue(1);
```
*Rationale:* `useSharedValue` is Reanimated's version of `useState`, but instead of triggering a React render cycle on the JS thread, it updates a value directly on the Native UI thread via JSI (JavaScript Interface).

**Step 2: Defining the UI-Thread Gesture Worklet**
Why this precedes the next: We must define how user input modifies the shared values.
```tsx
const panGesture = Gesture.Pan()
  .onChange((event) => {
    translateX.value = event.translationX;
  })
```
*Rationale:* The `.onChange` callback is a "worklet" (automatically compiled by the Reanimated Babel plugin). As the user's finger moves, `translateX.value` updates instantly, entirely bypassing the JS thread for zero latency.

**Step 3: Creating the Animated Style and Binding**
Why this precedes the next: The UI thread has updated values, but the view needs to know how to render them visually.
```tsx
const animatedStyle = useAnimatedStyle(() => {
  return { transform: [{ translateX: translateX.value }] };
});

<Animated.View style={[styles.card, animatedStyle]}>
```
*Rationale:* `useAnimatedStyle` listens to changes in `translateX.value`. It generates a style object natively, which is injected directly into `<Animated.View>`. This closed loop (Touch -> Shared Value -> Animated Style -> View) happens entirely on the native side at 60 or 120 FPS.

### 5. ASCII / Architecture Data Flow
```text
[ Classic Architecture (Slow) ]
JS Thread (Calculate state) <==> JSON over Async Bridge <==> UI Thread (Render)

[ Reanimated 3 JSI Architecture (Fast) ]
                [ JS Thread ]
                     | (Initialize Shared Values)
                     v
             [ JSI (Synchronous C++ Bridge) ]
                     |
       +-------------+-------------+
       |                           |
[ UI Thread Worklet ]     [ UI Thread Layout Engine ]
- gesture.onChange()      - useAnimatedStyle
- translateX = 50         - transform: translateX(50)
- withSpring()            - renders instantly at 60 FPS
```

### 6. Noob Trap vs Pro Tip
* **Noob Trap:** Attempting to call `setMyState(true)` directly inside a gesture `.onEnd` worklet. The app will crash with an error about calling JS functions on the UI thread.
* **Pro Tip:** Always use `runOnJS(myFunction)()` when you need to bridge back from the UI thread to the JS thread (e.g., updating a Redux store or React state after an animation completes).

### Level 1: Warm-Up
**Challenge:** Modify the notification card so that its background color shifts dynamically based on how far it is swiped.
<details>
<summary>Hint</summary>
Use `interpolateColor` from `react-native-reanimated`. Inside `useAnimatedStyle`, interpolate `translateX.value` from `[0, SWIPE_THRESHOLD]` to colors `['#FFFFFF', '#FF0000']`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```tsx
import { interpolateColor } from 'react-native-reanimated';

const animatedStyle = useAnimatedStyle(() => {
  const backgroundColor = interpolateColor(
    Math.abs(translateX.value),
    [0, SWIPE_THRESHOLD],
    ['#FFFFFF', '#FEE2E2'] // White to light red
  );

  return {
    transform: [{ translateX: translateX.value }],
    backgroundColor, // Apply interpolated color
  };
});
```
This runs effortlessly on the UI thread.
</details>

### Level 3: Boss Level
**Challenge:** Build an interactive draggable bottom sheet (like Apple Maps or Uber). It must have three snap points (25%, 50%, 90% of screen height) and use velocity tracking to intelligently spring to the nearest snap point when the user releases their swipe.
<details>
<summary>Hint</summary>
You need `event.translationY` and `event.velocityY` in `.onEnd`. Calculate the projected end position using a friction formula `projectedY = translationY + (velocityY * friction)`. Then find the nearest snap point and use `withSpring` to snap `translateY` there.
</details>

<details>
<summary>Solution Walkthrough</summary>
This requires combining gesture data, math, and spring physics natively.

```tsx
const translateY = useSharedValue(0);
const context = useSharedValue(0);
const SNAP_POINTS = [SCREEN_HEIGHT * 0.75, SCREEN_HEIGHT * 0.5, SCREEN_HEIGHT * 0.1];

const panGesture = Gesture.Pan()
  .onStart(() => {
    context.value = translateY.value; // Store starting point
  })
  .onChange((event) => {
    translateY.value = context.value + event.translationY;
  })
  .onEnd((event) => {
    // Incorporate velocity for natural "throwing" physics
    const projectedPosition = translateY.value + event.velocityY * 0.2;

    // Find closest snap point
    const closestSnapPoint = SNAP_POINTS.reduce((prev, curr) =>
      Math.abs(curr - projectedPosition) < Math.abs(prev - projectedPosition) ? curr : prev
    );

    translateY.value = withSpring(closestSnapPoint, {
      damping: 20,
      stiffness: 90
    });
  });
```
This is the core architecture powering nearly every modern draggable sheet on mobile.
</details>

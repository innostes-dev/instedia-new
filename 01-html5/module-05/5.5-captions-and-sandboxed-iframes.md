# Captions and Sandboxed Iframes

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
**Pain Point 1:** You write a news article and place an image of a politician with a `<p>` tag underneath it saying "Senator John Doe speaking at the rally." But when the screen resizes, the text detaches and floats away from the image, confusing the reader.
**Pain Point 2:** You embed a Google Map or a YouTube video using an `<iframe>` (a window into another website). The third-party site is suddenly hacked, and the malicious code inside the iframe breaks out, stealing your users' cookies and redirecting your entire page to a scam site.

### 2. Plain English Explanation & Physical Metaphor (The "What")
The `<figure>` and `<figcaption>` tags lock a piece of media and its caption together into a single, unbreakable semantic unit.
The `<iframe>` tag embeds another website into yours. The `sandbox` attribute places that iframe in a high-security prison, stripping the external site of its ability to run malicious scripts or break out of the window.
Think of `<figure>` like framing a photo and its plaque together inside one wooden border. Think of an `<iframe>` with a `sandbox` like putting a dangerous wild animal in a glass cage—you can look at it, but it cannot touch you.

### 3. Complete Working Runnable Code
```html
<article class="news-story">

  <!-- Semantic grouping of Media + Caption -->
  <figure>
    <img src="protest.jpg" alt="Crowd holding signs at city hall">
    <figcaption>Fig 1. - Protesters gather downtown demanding policy changes.</figcaption>
  </figure>

  <h2>Location of the Event</h2>

  <!-- High Security Third-Party Embed -->
  <iframe
    src="https://www.google.com/maps/embed"
    width="600"
    height="450"
    loading="lazy"
    sandbox="allow-scripts allow-same-origin"
    title="Map of downtown city hall area">
  </iframe>

</article>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Figure Wrapper**
```html
<figure>
  <img src="protest.jpg" alt="...">
</figure>
```
*Why this comes first:* The `<figure>` tag creates a self-contained unit of content. It tells the browser that anything inside this wrapper represents a single piece of referenced material (like a diagram, photo, or code snippet in a textbook).

**Step 2: The Figcaption**
```html
  <figcaption>Fig 1. - Protesters gather...</figcaption>
</figure>
```
*Why this is required next:* The `<figcaption>` provides the visible caption for the media. Because it is nested inside the `<figure>`, screen readers instantly understand that this specific text describes the preceding image, binding them together forever.

**Step 3: The Sandboxed Iframe**
```html
<iframe src="..." sandbox="allow-scripts"></iframe>
```
*Why this is critical for security:* An `<iframe>` without a sandbox has enormous power over your page. Adding `sandbox` with no values locks down *everything* (no scripts, no form submissions, no popups). By explicitly writing `allow-scripts`, we poke exactly one tiny hole in the glass cage, allowing Google Maps to run its internal panning/zooming JavaScript without compromising our parent page.

### 5. Behind-the-Scenes / Visual Data Flow
```text
IFRAME WITHOUT SANDBOX:
[ Your Safe Page ] <---[ Malicious Iframe JS accesses window.top.location ]---> Page Redirected! (HACKED)

IFRAME WITH SANDBOX:
[ Your Safe Page ]      [ Malicious Iframe JS attempts breakout ]---> Access Denied by Browser Engine!
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using `<div class="image-wrapper">` and `<div class="caption">` instead of `<figure>` and `<figcaption>`. Screen readers will just read the caption as a random, floating paragraph with no context. Also, forgetting the `title` attribute on an `<iframe>` fails WCAG accessibility audits immediately.
**Senior Pro Tip:** The `sandbox` attribute is one of the most powerful security features in HTML. Always start with a strict `sandbox=""` (empty) and only add exceptions (`allow-scripts`, `allow-popups`) if the embed explicitly breaks without them.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A chart in a financial report.
**Task:** Wrap `chart.png` and the text "Q3 Earnings" in a semantic figure structure.
<details>
<summary>Hint</summary>
Use `<figure>`, `<img>`, and `<figcaption>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<figure>
  <img src="chart.png" alt="Bar chart showing upward trend">
  <figcaption>Q3 Earnings</figcaption>
</figure>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** Embedding a YouTube video safely.
**Task:** Create an `<iframe>` pointing to `youtube.com/embed/123`. Add a descriptive `title`. Secure it so it can only run scripts and play media.
<details>
<summary>Hint</summary>
You need `title=".."` and `sandbox="allow-scripts allow-presentation"`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<iframe
  src="https://youtube.com/embed/123"
  title="Tutorial Video"
  sandbox="allow-scripts allow-presentation">
</iframe>
```
</details>

### Level 3: Boss Level
**Scenario:** Creating a rich media blog post (combining Module 1, 4, 5).
**Task:**
1. Create a `<figure>`.
2. Inside it, place a `<video>` with controls and an MP4 source.
3. Below the video, add a `<figcaption>`.
4. Inside the figcaption, write "Video by " and add a secure, new-tab hyperlink to the author's website.
<details>
<summary>Hint</summary>
You can nest a complex `<video>` and an `<a>` tag inside a `<figure>` and `<figcaption>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<figure>
  <video controls width="100%">
    <source src="interview.mp4" type="video/mp4">
  </video>
  <figcaption>
    Video by <a href="https://author.com" target="_blank" rel="noopener noreferrer">Jane Smith</a>
  </figcaption>
</figure>
```
This demonstrates master-level semantic composition!
</details>

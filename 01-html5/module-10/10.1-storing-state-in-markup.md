# Storing State in Markup (Data Attributes)

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building an e-commerce page with a grid of 50 product cards. You want a user to click a button that says "Filter: Under $50". To do this, your JavaScript needs to look at every product and check its price. But where does the JavaScript find the price? If it reads the visual text `<p>$49.99</p>`, it has to strip the dollar sign and convert it to a math number. What if the text says `Sale! $49.99`? The JavaScript crashes. You need a way to store strict, invisible data on HTML elements.

### 2. Plain English Explanation & Physical Metaphor (The "What")
The `data-*` attribute allows you to embed custom data attributes on any HTML element. You can invent any name you want (e.g., `data-price`, `data-category`, `data-user-id`). This data is invisible to the user but easily readable by CSS and JavaScript.
Think of the visible HTML as the beautiful showroom car (shiny paint, leather seats). Think of the `data-*` attribute as the barcode sticker stuck underneath the bumper. The customer never sees it, but the mechanic's scanner (JavaScript) can read it instantly to know exactly what engine is inside.

### 3. Complete Working Runnable Code
```html
<section class="product-grid">
  <!-- A product card embedding strict data for JS to read -->
  <article
    class="card"
    data-product-id="A101"
    data-category="electronics"
    data-price="299.99"
    data-in-stock="true"
  >
    <h2>Sony Headphones</h2>
    <p>Price: $299.99</p>
    <button onclick="addToCart(this)">Add to Cart</button>
  </article>

  <article
    class="card"
    data-product-id="A102"
    data-category="apparel"
    data-price="25.00"
    data-in-stock="false"
  >
    <h2>Cotton T-Shirt</h2>
    <p>Price: $25.00</p>
    <button disabled>Out of Stock</button>
  </article>
</section>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Prefix Rule**
```html
<article data-price="299.99">
```
*Why this works:* You cannot just invent a random attribute like `<article price="299">`. If the HTML specification updates tomorrow and officially adds a `price` attribute, your site breaks. By prefixing it with `data-`, you are legally reserving a safe namespace that HTML will never touch.

**Step 2: Naming Conventions**
```html
<article data-product-id="A101">
```
*Why this is required next:* The name after `data-` must be lowercase and separated by dashes (kebab-case). Do not use uppercase letters (`data-productId`).

**Step 3: How JavaScript Uses It**
*(Conceptual)*
When JS looks at that article, it accesses a special built-in object called the `dataset`. The dashes are automatically converted to camelCase.
`element.dataset.price` returns `"299.99"`.
`element.dataset.productId` returns `"A101"`.

### 5. Behind-the-Scenes / Visual Data Flow
```text
Goal: Filter items under $50.

JavaScript queries DOM: "Give me all elements with class 'card'".
For each element:
  Check `element.dataset.price`.
  Is 299.99 < 50? No. -> Hide element.
  Is 25.00 < 50? Yes. -> Show element.
(The JS never had to read the messy visual `<p>` tags!)
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Storing sensitive information like `data-user-password="123"` or `data-admin-token="xyz"`. Data attributes are 100% visible to anyone who right-clicks and inspects the page source.
**Senior Pro Tip:** Data attributes are incredibly powerful in CSS! You can style elements based on their data state without writing a single class name. Example CSS: `article[data-in-stock="false"] { opacity: 0.5; }` will automatically gray out out-of-stock items.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A user profile badge.
**Task:** Create a `<div>` and attach a custom data attribute to store the user's role ("admin").
**Expected Output:** HTML with a `data-*` attribute.
<details>
<summary>Hint</summary>
Use `data-role="admin"`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<div data-role="admin">Jane Doe</div>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** A multi-step form wizard.
**Task:** Create a `<section>` for step 2 of the form. Use a data attribute to store the step number mathematically (2), and another to store the completion status (false).
<details>
<summary>Hint</summary>
You can have multiple data attributes on one element.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<section data-step="2" data-completed="false">
  <h2>Payment Details</h2>
</section>
```
</details>

### Level 3: Boss Level
**Scenario:** Building an interactive table row (combining Mod 6.1, 10.1).
**Task:**
1. Create a `<table>` with a `<tr>`.
2. The row should have a data attribute for the employee ID ("E55") and department ("sales").
3. Inside the row, put a single `<td>` with the employee's name.
<details>
<summary>Hint</summary>
The `<tr>` is the perfect place to store data for an entire row!
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<table>
  <tr data-emp-id="E55" data-dept="sales">
    <td>John Smith</td>
  </tr>
</table>
```
When a manager clicks this row, JavaScript can instantly read `dataset.empId` to load John's full profile from the server.
</details>

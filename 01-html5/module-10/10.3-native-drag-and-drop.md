# Native Drag and Drop

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building a Trello or Jira Kanban board. Users want to click a "Task" card, hold down the mouse, drag it across the screen, and drop it into the "Done" column. Historically, developers had to write hundreds of lines of complex JavaScript math to calculate mouse coordinates, update CSS `top` and `left` properties 60 times a second, and manually detect if the mouse was hovering over a specific drop zone. It was slow and laggy.

### 2. Plain English Explanation & Physical Metaphor (The "What")
HTML5 introduced native Drag and Drop (DnD). By adding a single attribute `draggable="true"` to an element, the browser takes over. The browser natively handles creating a "ghost" image of the item attached to the mouse cursor. It fires specific events when you pick it up, drag it, and let it go.
Think of `draggable="true"` like attaching a Velcro handle to a heavy box. You don't have to build the handle yourself; the browser provides it. You just need to designate which tables (drop zones) have the corresponding Velcro strips to receive the box.

### 3. Complete Working Runnable Code
```html
<!-- The Kanban Board Layout -->
<main style="display: flex; gap: 20px;">

  <!-- Drop Zone 1: To Do -->
  <!-- Note: JS is required to actually move the DOM node, but HTML enables the UI behavior -->
  <section class="column" id="todo" ondragover="event.preventDefault()" ondrop="drop(event)">
    <h2>To Do</h2>

    <!-- The Draggable Item -->
    <!-- ondragstart packages the ID of this element into the drag event -->
    <article
      class="card"
      id="task-1"
      draggable="true"
      ondragstart="event.dataTransfer.setData('text/plain', event.target.id)"
    >
      <h3>Fix Login Bug</h3>
    </article>

  </section>

  <!-- Drop Zone 2: Done -->
  <section class="column" id="done" ondragover="event.preventDefault()" ondrop="drop(event)">
    <h2>Done</h2>
    <!-- Items will be dropped here -->
  </section>

</main>

<!-- Minimal JS to complete the illusion -->
<script>
  function drop(event) {
    event.preventDefault();
    const data = event.dataTransfer.getData("text/plain");
    event.currentTarget.appendChild(document.getElementById(data));
  }
</script>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: Making the Element Draggable**
```html
<article draggable="true">
```
*Why this comes first:* `draggable="true"` is an HTML5 global attribute. The moment you add this, the browser will allow the user to click and drag the element, showing a semi-transparent ghost image of it attached to the cursor. (Note: Links `<a>` and images `<img>` are draggable by default).

**Step 2: Packaging Data (dragstart)**
```html
ondragstart="event.dataTransfer.setData('text/plain', event.target.id)"
```
*Why this is required next:* When you pick up the card, you have to tell the browser's memory *what* you are holding. We use `dataTransfer` to store the ID of the card (`task-1`) into the drag event.

**Step 3: Preparing the Drop Zone (dragover & drop)**
```html
<section ondragover="event.preventDefault()" ondrop="...">
```
*Why this follows:* By default, browsers *reject* dropped items (if you drop an image into Chrome, it tries to navigate away to open the image!). We MUST use `event.preventDefault()` on the `dragover` event to tell the browser: "I am authorizing this zone to accept drops." Then `ondrop` triggers the actual transfer.

### 5. Behind-the-Scenes / Visual Data Flow
```text
1. User clicks and drags `<article>` (draggable="true").
2. Browser fires `dragstart` -> Saves "task-1" to memory.
3. User hovers over `<section>` (dragover).
4. Browser checks: Does this section prevent default? YES -> Shows 'Copy/Move' cursor.
5. User lets go (drop).
6. JS reads "task-1" from memory and physically moves the HTML node to the new section.
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Assuming `draggable="true"` automatically moves the HTML element for you. It does not. The HTML attribute only creates the visual UI (the ghost image attached to the cursor). You *must* write a tiny bit of JS to actually move the DOM node when dropped.
**Senior Pro Tip:** The HTML5 Native Drag and Drop API is notoriously finicky on mobile touch screens. For enterprise applications (like Jira), teams often use libraries like `dnd-kit` that map touch events to drag events. However, understanding the native `draggable` attribute is the foundation.

**Task:**
1. Create a `<form>`.

3. Authorize the box to receive drops.
4. Inside the box, put a paragraph "Drag your resume here, or" and then a file input.

<summary>Hint</summary>

</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<form>
  <div class="dropzone" ondragover="event.preventDefault()">

  </div>
</form>
```
With a little JS, this HTML pattern allows users to drag a PDF directly from their Mac Desktop right onto the web page!

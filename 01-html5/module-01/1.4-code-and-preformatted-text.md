# Code and Preformatted Text

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building a documentation page for your company's API. You paste a Python code snippet into a `<p>` tag. When you load the page, the browser strips all the indentation, line breaks, and spacing. The Python code, which relies on indentation to function, is now completely broken and unreadable.

### 2. Plain English Explanation & Physical Metaphor (The "What")
The `<pre>` (preformatted) tag tells the browser: "Hands off! Render this exact text with all the spaces and line breaks exactly as I typed them." The `<code>` tag tells the browser: "This is a piece of computer code." `<kbd>` represents keyboard input, and `<samp>` represents computer output.
Think of standard HTML like water—it flows and fills the container, ignoring gaps. `<pre>` is like a solid block of ice—it retains its exact physical shape no matter where you put it.

### 3. Complete Working Runnable Code
```html
<article class="docs-section">
  <h2>Installation Instructions</h2>
  <p>To install the package, open your terminal and press <kbd>Ctrl</kbd> + <kbd>C</kbd> to exit any running processes, then run:</p>

  <pre><code>
def hello_world():
    print("Initializing...")
    return True
  </code></pre>

  <p>If successful, you will see this output:</p>
  <p><samp>Build successful. 0 errors.</samp></p>
</article>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: Representing Keystrokes**
```html
press <kbd>Ctrl</kbd> + <kbd>C</kbd>
```
*Why this comes first:* In documentation, you often need to instruct users to press keys. The `<kbd>` tag semantically marks these as user inputs. Browsers typically style them in a monospace font by default.

**Step 2: The Preformatted Code Block**
```html
<pre><code>
def hello_world():
    print("Initializing...")
</code></pre>
```
*Why this is required next:* We wrap `<code>` inside `<pre>`. The `<code>` tag provides the semantic meaning ("this is computer code"), but without `<pre>`, the spaces would still collapse! The `<pre>` preserves the 4-space indentation required for Python.

**Step 3: Sample Output**
```html
<samp>Build successful. 0 errors.</samp>
```
*Why this follows:* After running code, there is output. `<samp>` tells the browser that this text is generated by a computer program, distinct from human-written text.

### 5. Behind-the-Scenes / Visual Data Flow
```text
Standard HTML Parsing: "def run():    pass" -> "def run(): pass" (Spaces stripped)
<pre> HTML Parsing:    "def run():    pass" -> "def run():    pass" (Spaces preserved)

DOM Tree:
[ pre ] -> [ code ] -> (Literal text node with exact spacing)
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using `<br>` and `&nbsp;` (non-breaking space) repeatedly to manually format a code snippet on screen. It is tedious and breaks easily on different screen sizes.
**Senior Pro Tip:** Always nest `<code>` inside `<pre>` for block-level code snippets. For inline code (like mentioning a variable name mid-sentence), just use `<code>` by itself.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A GitHub comment describing a command.
**Task:** Use inline code to show the command `npm install` inside a sentence.
**Starting Code:**
```html
<p>To start, run npm install in your project.</p>
```
**Expected Output:** The command wrapped in the correct tag.
<details>
<summary>Hint</summary>
Wrap "npm install" with `<code>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<p>To start, run <code>npm install</code> in your project.</p>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** A troubleshooting guide.
**Task:** Tell the user to press 'Enter' using the keyboard tag, and show a simulated server response "Error 404" using the sample output tag.
<details>
<summary>Hint</summary>
Use `<kbd>` for Enter, and `<samp>` for the error message.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<p>Press <kbd>Enter</kbd> to submit.</p>
<p>If it fails, you will see: <samp>Error 404</samp></p>
```
</details>

### Level 3: Boss Level
**Scenario:** Writing a complete technical doc section (combining 1.1, 1.3, 1.4).
**Task:** Create a heading for "Configuration", a paragraph telling the user it is *strongly important* to backup their files. Then provide a multi-line JSON configuration snippet where spacing is preserved.
<details>
<summary>Hint</summary>
Combine `<h2>`, `<strong>`, `<pre>`, and `<code>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<h2>Configuration</h2>
<p><strong>Back up your files before proceeding.</strong></p>
<pre><code>
{
  "project": "Instedia",
  "version": "1.0.0",
  "secure": true
}
</code></pre>
```
This is the gold standard for writing developer documentation in HTML.
</details>

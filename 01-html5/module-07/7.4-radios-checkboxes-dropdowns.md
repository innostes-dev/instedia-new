# Radios, Checkboxes, and Dropdowns

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building an order form for Domino's Pizza. The user needs to choose a pizza size (Small, Medium, or Large) and toppings (Pepperoni, Mushrooms, Onions). If you just use text inputs, a user might type "Gigantic" for size, crashing your database. If you try to use the same logic for size and toppings, a user might accidentally select "Small AND Large" at the same time. You need strict UI controls to enforce logic.

### 2. Plain English Explanation & Physical Metaphor (The "What")
- **Radio Buttons** (`type="radio"`): Allow a user to select *exactly one* option from a group (like pizza size).
- **Checkboxes** (`type="checkbox"`): Allow a user to select *zero, one, or multiple* options from a group (like toppings).
- **Select Dropdowns** (`<select>`): Allow a user to choose from a long list without taking up massive screen space (like picking a Country).
Think of Radios like an old car stereo: pushing one button pops the other one out. Think of Checkboxes like a grocery checklist: you can cross off as many items as you want. Think of a Select like a Rolodex hidden inside a small box.

### 3. Complete Working Runnable Code
```html
<form action="/order" method="POST">

  <!-- Radio Buttons (Pick ONE) -->
  <fieldset>
    <legend>Pizza Size (Choose 1)</legend>
    <!-- Note: The 'name' attribute must be exactly the same for radios to group! -->
    <input type="radio" id="size-sm" name="size" value="small">
    <label for="size-sm">Small</label><br>

    <input type="radio" id="size-md" name="size" value="medium" checked>
    <label for="size-md">Medium</label>
  </fieldset>

  <!-- Checkboxes (Pick ANY) -->
  <fieldset>
    <legend>Toppings (Choose multiple)</legend>
    <input type="checkbox" id="top-pep" name="toppings" value="pepperoni">
    <label for="top-pep">Pepperoni</label><br>

    <input type="checkbox" id="top-mush" name="toppings" value="mushrooms">
    <label for="top-mush">Mushrooms</label>
  </fieldset>

  <!-- Dropdown Select -->
  <label for="crust-type">Crust Type:</label>
  <select id="crust-type" name="crust">
    <option value="thin">Thin Crust</option>
    <option value="regular" selected>Regular Hand-Tossed</option>
    <option value="stuffed">Stuffed Crust</option>
  </select>

</form>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: Radio Button Grouping Strategy**
```html
<input type="radio" id="size-sm" name="size" value="small">
<input type="radio" id="size-md" name="size" value="medium">
```
*Why this works:* The secret to making radios work is giving them the *exact same `name` attribute*. The browser sees two inputs with `name="size"` and instantly links them logically. If you click one, the browser automatically deselects the other. The `value` attribute is what actually gets sent to the server (e.g., `size=small`).

**Step 2: Checkboxes**
```html
<input type="checkbox" id="top-pep" name="toppings" value="pepperoni">
```
*Why this is required next:* Checkboxes act independently. They do not pop each other out. If a user checks this, the server receives `toppings=pepperoni`. Notice that with both radios and checkboxes, the `<input>` comes *before* the `<label>`, which is the standard visual pattern (a box, then the text).

**Step 3: The Dropdown Select**
```html
<select id="crust-type" name="crust">
  <option value="thin">Thin Crust</option>
</select>
```
*Why this follows:* `<select>` is a completely different tag, not an `<input>`. It acts as the container (providing the `name`), and the nested `<option>` tags provide the choices (the `value`s). It is perfect for lists of 5 or more items where radios would take up too much vertical space.

### 5. Behind-the-Scenes / Visual Data Flow
```text
User selects: "Medium", "Pepperoni", "Mushrooms", "Thin Crust".

Browser packages data for POST:
{
  "size": "medium",
  "toppings": ["pepperoni", "mushrooms"],
  "crust": "thin"
}
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using a `<select>` dropdown for Yes/No questions. Dropdowns require three clicks to use on mobile (Tap to open, scroll to find, tap to select).
**Senior Pro Tip:** For 2 to 4 options (like Yes/No, or Small/Medium/Large), always use Radio Buttons. They expose all options instantly with one click. Only use `<select>` when you have 5+ options (like selecting a US State).

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A form asking for gender selection.
**Task:** Create two radio buttons (Male, Female). Ensure selecting one deselects the other.
**Expected Output:** Two `<input type="radio">` tags with linked labels.
<details>
<summary>Hint</summary>
Give both inputs the same `name="gender"`. Ensure their `id`s are unique.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<input type="radio" id="g-male" name="gender" value="male">
<label for="g-male">Male</label>

<input type="radio" id="g-female" name="gender" value="female">
<label for="g-female">Female</label>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** An opt-in for marketing emails.
**Task:** Create a checkbox that is checked by default. The label should say "Send me updates".
<details>
<summary>Hint</summary>
Use `type="checkbox"` and add the boolean attribute `checked`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<input type="checkbox" id="marketing" name="subscribe" value="yes" checked>
<label for="marketing">Send me updates</label>
```
</details>

### Level 3: Boss Level
**Scenario:** A vehicle configuration tool (combining Mod 7.2, 7.4).
**Task:**
1. Create a dropdown (`<select>`) named `make` with options for "Ford" and "Toyota".
2. Create radio buttons named `transmission` for "Manual" and "Automatic".
3. Create checkboxes named `extras` for "Sunroof" and "Navigation".
<details>
<summary>Hint</summary>
Combine `<select>/<option>`, `<input type="radio">`, and `<input type="checkbox">`. Ensure `name` and `value` attributes are set perfectly.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<label for="car-make">Make:</label>
<select id="car-make" name="make">
  <option value="ford">Ford</option>
  <option value="toyota">Toyota</option>
</select>

<p>Transmission:</p>
<input type="radio" id="t-man" name="transmission" value="manual">
<label for="t-man">Manual</label>
<input type="radio" id="t-auto" name="transmission" value="automatic">
<label for="t-auto">Automatic</label>

<p>Extras:</p>
<input type="checkbox" id="ex-sun" name="extras" value="sunroof">
<label for="ex-sun">Sunroof</label>
<input type="checkbox" id="ex-nav" name="extras" value="navigation">
<label for="ex-nav">Navigation</label>
```
This data structure is robust, strictly typed, and completely accessible.
</details>

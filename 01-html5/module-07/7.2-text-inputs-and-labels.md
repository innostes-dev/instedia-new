# Text Inputs and Labels

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are filling out a checkout form on a phone. The text above a box says "Billing Name". You try to tap the tiny white box to type your name, but your finger misses and taps the background. Nothing happens. You tap again, miss, and get frustrated. Furthermore, a blind user hears the screen reader say "Edit Text, blank," because the browser has no idea that the text "Billing Name" is supposed to be connected to the visual white box below it.

### 2. Plain English Explanation & Physical Metaphor (The "What")
The `<input type="text">` tag creates the physical box where users type. The `<label>` tag creates the text describing the box. We use the `for` attribute on the label, and point it to the `id` of the input to securely link them together.
Think of the `input` like a blank manila folder. Think of the `label` like a printed sticky note. By writing the exact same identification number (`id` and `for`) on both, you staple the sticky note permanently to the folder. If you tap the sticky note, the folder automatically opens.

### 3. Complete Working Runnable Code
```html
<form action="/checkout" method="POST">
  <!-- A perfectly linked label and input -->
  <div class="form-group">
    <label for="billing-name">Full Name on Card</label>
    <input type="text" id="billing-name" name="fullName">
  </div>

  <div class="form-group">
    <label for="billing-city">City</label>
    <input type="text" id="billing-city" name="city">
  </div>
</form>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Visual Input Box**
```html
<input type="text" id="billing-name" name="fullName">
```
*Why this works:* `type="text"` tells the browser to render a single-line text box. The `id` is a unique identifier required for the HTML document structure. The `name` attribute is strictly for the server (when submitted, it sends `fullName=Jane`).

**Step 2: The Label Container**
```html
<label>Full Name on Card</label>
```
*Why this is required next:* A `<p>` or a `<span>` is not semantically correct for forms. A `<label>` tells the browser, "This text describes a form field."

**Step 3: The Magical Link (for/id)**
```html
<label for="billing-name">Full Name</label>
<input id="billing-name">
```
*Why this follows:* The `for` attribute MUST exactly match the `id` attribute. When linked:
1. Screen readers will read "Full Name" when the user tabs into the input.
2. If a user clicks or taps the *words* "Full Name" on their screen, the browser will automatically focus the blinking cursor inside the input box, vastly increasing the clickable area on mobile!

### 5. Behind-the-Scenes / Visual Data Flow
```text
State 1: Visual Rendering
[Label Text] -> (Visual link) -> [Input Box]

State 2: Submit to Server (The Action)
Browser ignores the <label> completely.
Browser ignores the `id`.
Browser packages: name="fullName" + User Input ("Jane") -> Sends { fullName: "Jane" }
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using the `placeholder` attribute (e.g., `<input placeholder="First Name">`) *instead* of a `<label>`. As soon as the user types one letter, the placeholder disappears, and the user forgets what box they are in. Placeholders also have notoriously bad color contrast for accessibility.
**Senior Pro Tip:** Always use `<label>` tags. If a designer forces you to visually hide labels for aesthetic reasons, you must use CSS (often called a `.sr-only` class) to hide the label visually while keeping it in the HTML for screen readers.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A basic username field.
**Task:** Create a text input with an ID of `user`. Create a label for it that says "Username".
**Expected Output:** HTML with linked `<label>` and `<input>`.
<details>
<summary>Hint</summary>
The label's `for` must match the input's `id`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<label for="user">Username</label>
<input type="text" id="user" name="username">
```
</details>

### Level 2: Real-World Scenario
**Scenario:** Requesting a ZIP code for shipping.
**Task:** Ensure the input is connected to a label saying "Postal Code". Ensure that when the form is submitted, the server receives the data under the key `zip_code`.
<details>
<summary>Hint</summary>
Use `name="zip_code"` on the input. Use matching `for` and `id`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<label for="postal">Postal Code</label>
<input type="text" id="postal" name="zip_code">
```
</details>

### Level 3: Boss Level
**Scenario:** A complete, accessible search form (combining Mod 7.1, 7.2).
**Task:**
1. Create a `<form>` pointing to `/search` using GET.
2. Inside, add a text input with the ID `q_box` and name `query`.
3. Add a proper label for the input saying "Search site".
4. Add a submit button.
<details>
<summary>Hint</summary>
Combine `<form>`, `<label>`, `<input>`, and `<button>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<form action="/search" method="GET">
  <label for="q_box">Search site</label>
  <input type="text" id="q_box" name="query">
  <button type="submit">Go</button>
</form>
```
If you click the word "Search site" in a browser, your cursor will jump right into the box!
</details>

# Secure Credentials and Keyboards

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
A user is on a crowded train typing their password into an Uber login screen. If the form uses `<input type="text">`, everyone on the train can see their password in plain English. Later, they try to type their phone number into a different box, but the phone keyboard pops up showing full alphabet letters (QWERTY) instead of a numeric dial pad, forcing them to awkwardly switch keyboard modes manually.

### 2. Plain English Explanation & Physical Metaphor (The "What")
Changing the `type` attribute on an `<input>` drastically changes how the browser treats it. `type="password"` obscures the text visually (dots or asterisks). `type="email"` validates that an '@' symbol exists. The `inputmode` attribute tells mobile phones exactly which virtual keyboard to pop up on the screen (e.g., numeric vs text).
Think of changing the `type` like changing the physical shape of a coin slot. `type="password"` is a slot with a curtain over it so no one can see inside. `inputmode="numeric"` is telling the vending machine to only offer a calculator keypad to the user.

### 3. Complete Working Runnable Code
```html
<form action="/login" method="POST">

  <!-- Email Input (Mobile will show a keyboard with '@' and '.com') -->
  <div class="form-group">
    <label for="user-email">Email Address</label>
    <input type="email" id="user-email" name="email">
  </div>

  <!-- Password Input (Text is obscured automatically) -->
  <div class="form-group">
    <label for="user-pass">Password</label>
    <input type="password" id="user-pass" name="password">
  </div>

  <!-- Number Input (Mobile will show a numeric dial pad) -->
  <div class="form-group">
    <label for="2fa-code">6-Digit Auth Code</label>
    <input type="text" id="2fa-code" name="authCode" inputmode="numeric" pattern="[0-9]*">
  </div>

</form>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Password Type**
```html
<input type="password" id="user-pass">
```
*Why this comes first:* Security is paramount. By simply changing `text` to `password`, the browser visually obscures the characters and prevents standard "Copy" (Ctrl+C) functionality from extracting the text, protecting users from shoulder-surfing.

**Step 2: The Email Type**
```html
<input type="email" id="user-email">
```
*Why this is required next:* `type="email"` gives us two massive benefits for free. 1) If the user submits "hello" without an '@', the browser natively blocks the form and shows an error. 2) On iOS and Android, the virtual keyboard dynamically changes to include a dedicated `@` key right next to the spacebar.

**Step 3: Controlling the Mobile Keyboard (inputmode)**
```html
<input type="text" inputmode="numeric">
```
*Why this follows:* Why not use `type="number"` for an auth code? Because `type="number"` is mathematically meant for quantities (like choosing 3 apples), and browsers often add ugly up/down arrows (spinners) to it. An auth code (or zip code) isn't a math quantity, it's just a string of digits. `inputmode="numeric"` triggers the numeric keyboard perfectly without the side-effects of `type="number"`.

### 5. Behind-the-Scenes / Visual Data Flow
```text
User taps <input type="email">
-> Browser asks OS for virtual keyboard.
-> OS checks type="email" -> Returns keyboard layout (QWERTY + @ + .com).

User types "A" into <input type="password">
-> Browser intercepts keystroke.
-> Stores "A" in memory.
-> Renders "•" on screen.
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using `type="number"` for credit card numbers or phone numbers. Browsers will strip leading zeros (making a phone number `0555` turn into `555`) and will try to round large numbers (like 16-digit credit cards) into scientific notation.
**Senior Pro Tip:** For credit cards, zip codes, and phone numbers, always use `<input type="text" inputmode="numeric">`. This ensures it is treated as a safe text string, but still gives the user the beautiful numeric keypad on mobile.

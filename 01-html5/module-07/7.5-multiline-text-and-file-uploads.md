# Multiline Text and File Uploads

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building an HR portal for LinkedIn. A user needs to submit their resume. If you only provide `<input type="text">`, they have to copy and paste their entire 5-page work history into a single, infinite horizontal line. Then, you need them to attach a PDF of their degree, but you have no button that opens their computer's file explorer.

### 2. Plain English Explanation & Physical Metaphor (The "What")
The `<textarea>` tag creates a multi-line, resizable text box perfect for essays, comments, or cover letters.
The `<input type="file">` tag summons the operating system's native file picker window, allowing users to select documents or photos from their hard drive to upload.
Think of a standard `<input>` like a label maker that prints on one thin tape. Think of `<textarea>` like a full sheet of blank notebook paper. Think of `<input type="file">` as a physical mail slot where you can slide an entire folder through the wall to the server.

### 3. Complete Working Runnable Code
```html
<!-- Critical: enctype is MANDATORY when uploading files! -->
<form action="/apply" method="POST" enctype="multipart/form-data">

  <div class="form-group">
    <label for="cover-letter">Cover Letter (Max 500 words)</label>
    <!-- Note: textarea is NOT self-closing! -->
    <textarea id="cover-letter" name="coverLetter" rows="6" cols="40">Dear Hiring Manager, </textarea>
  </div>

  <div class="form-group">
    <label for="resume-upload">Upload Resume (PDF only)</label>
    <!-- The accept attribute restricts what files can be clicked -->
    <input type="file" id="resume-upload" name="resumeFile" accept=".pdf, application/pdf">
  </div>

  <button type="submit">Submit Application</button>
</form>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Form Enctype (The File Requirement)**
```html
<form enctype="multipart/form-data">
```
*Why this comes first:* If you have a file input in your form, you **MUST** include this exact attribute on the `<form>` tag. Without it, the browser only sends the *name* of the file (e.g., "resume.pdf") to the server, instead of sending the actual megabytes of file data!

**Step 2: The Textarea**
```html
<textarea id="msg" name="message" rows="6">Default text here</textarea>
```
*Why this works:* Unlike `<input>`, the `<textarea>` tag has a closing tag (`</textarea>`). Any text placed *between* the tags becomes the default value. The `rows` attribute tells the browser how many lines of text tall the box should be by default.

**Step 3: The File Input and Accept Filter**
```html
<input type="file" name="resumeFile" accept=".pdf">
```
*Why this follows:* `type="file"` renders a button that says "Choose File". When clicked, it opens the OS file explorer. The `accept=".pdf"` attribute is a UX safeguard: it grays out JPGs, DOCs, and ZIPs in the file explorer so the user can only physically click on PDF files.

### 5. Behind-the-Scenes / Visual Data Flow
```text
User clicks <input type="file" accept="image/png">
-> Browser pauses HTML thread.
-> Browser calls Windows/macOS API: "Open File Explorer, show only PNGs".
-> User selects "dog.png".
-> Browser grabs file path, prepares to stream binary data on POST.
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Putting `value="Hello"` inside a textarea (`<textarea value="Hello"></textarea>`). It doesn't work! Textareas do not use the `value` attribute for default text; the text must go between the tags.
**Senior Pro Tip:** The `accept` attribute is strictly for *client-side User Experience*, not security. A malicious user can easily bypass it and upload a `.exe` virus renamed to `.pdf`. You must *always* re-validate file types on your backend server.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A contact form message box.
**Task:** Create a label "Your Message" and a multiline text box that is 4 rows tall.
**Expected Output:** Linked `<label>` and `<textarea>`.
<details>
<summary>Hint</summary>
Use `<textarea rows="4">`. Remember it needs a closing tag.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<label for="contact-msg">Your Message</label>
<textarea id="contact-msg" name="message" rows="4"></textarea>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** An Instagram clone profile picture upload.
**Task:** Create a file input that only accepts image files (`.jpg`, `.png`).
<details>
<summary>Hint</summary>
Use `type="file"` and `accept="image/png, image/jpeg"`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<label for="avatar">Upload Profile Picture</label>
<input type="file" id="avatar" name="profile_pic" accept="image/png, image/jpeg">
```
</details>

### Level 3: Boss Level
**Scenario:** A complete bug report form (combining Mod 7.1, 7.5).
**Task:**
1. Create a `<form>` ready to POST file data (Don't forget the secret form attribute!).
2. Create a `<textarea>` for "Describe the bug".
3. Create a file input for "Attach Screenshot" that only accepts images.
4. Add a submit button.
<details>
<summary>Hint</summary>
You must use `enctype="multipart/form-data"` on the form.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<form action="/report-bug" method="POST" enctype="multipart/form-data">

  <label for="bug-desc">Describe the bug</label>
  <textarea id="bug-desc" name="description" rows="5"></textarea>

  <label for="bug-shot">Attach Screenshot</label>
  <input type="file" id="bug-shot" name="screenshot" accept="image/png, image/jpeg">

  <button type="submit">Report Bug</button>

</form>
```
If you forget `enctype`, your backend engineer will be very angry when the screenshot is completely missing from the database!
</details>

# Articles, Sections, and Asides

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building a Twitter thread UI. The page has a main tweet, 5 reply tweets, and a sidebar showing "Trending Topics". If everything is inside `<main>`, how does Apple News or a smart watch know which text is the primary tweet, which are the replies, and what is just side-content? If it tries to summarize the page, it might grab the "Trending Topics" text instead of the actual tweet!

### 2. Plain English Explanation & Physical Metaphor (The "What")
- `<article>`: A completely self-contained piece of content. If you ripped it out of the page and put it on a different website, it would still make 100% sense (e.g., a Tweet, a blog post, a product card).
- `<section>`: A thematic grouping of content. It usually needs a heading (`<h2>`). It breaks a long page into chapters.
- `<aside>`: Content that is tangentially related to the main content, but not strictly necessary (e.g., a sidebar, author bio, or related links).
Think of a magazine. The magazine itself is the `<main>`. An `<article>` is the 2-page spread on "Healthy Eating". Inside that article, you have a `<section>` for "Fruits" and a `<section>` for "Vegetables". In the margin of the page, there is an `<aside>` box with a coupon for bananas.

### 3. Complete Working Runnable Code
```html
<main>
  <!-- The main, self-contained piece of content -->
  <article>
    <header>
      <h1>The Future of Web Development</h1>
      <p>By Jane Doe</p>
    </header>

    <!-- A thematic breakdown of the article -->
    <section>
      <h2>HTML5 Semantics</h2>
      <p>Using the right tags is crucial for accessibility.</p>
    </section>

    <section>
      <h2>CSS Grid</h2>
      <p>Grid allows for two-dimensional layouts.</p>
    </section>
  </article>

  <!-- Tangentially related content (Sidebar) -->
  <aside>
    <h2>Trending Articles</h2>
    <ul>
      <li><a href="#">Understanding JavaScript Closures</a></li>
      <li><a href="#">The rise of TypeScript</a></li>
    </ul>
  </aside>
</main>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Article Wrapper**
```html
<article>
  <h1>The Future of Web...</h1>
</article>
```
*Why this comes first:* By wrapping the post in `<article>`, you tell search engines: "This is the syndicatable meat of the page."

**Step 2: Sectioning the Content**
```html
<section>
  <h2>HTML5 Semantics</h2>
</section>
```
*Why this is required next:* A `<section>` *must* have a thematic heading (usually `<h2>` or `<h3>`). If there is no logical heading for a block of content, it probably should just be a `<div>`. Sections create a rigid document outline (like chapters in a book).

**Step 3: The Aside**
```html
<aside>
  <h2>Trending Articles</h2>
</aside>
```
*Why this follows:* The `<aside>` is placed outside the `<article>` but inside the `<main>`. This tells the browser: "These links are related to the main page topic, but they are not part of the article itself." If the user prints the page, the browser knows it can safely hide the `<aside>` to save ink.

### 5. Behind-the-Scenes / Visual Data Flow
```text
Browser Document Outline Generator:
1. H1: The Future of Web Development (Article context)
   2. H2: HTML5 Semantics (Section context)
   2. H2: CSS Grid (Section context)
1. H2: Trending Articles (Aside context)
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using `<section>` as a wrapper for styling (e.g., `<section class="background-blue">`). If it doesn't have a heading, and it doesn't group a specific theme of content, use a `<div>`.
**Senior Pro Tip:** `<article>` tags can be nested! A blog post is an `<article>`. The comment section below it contains individual user comments. Each user comment should be its own `<article>` nested inside the main `<article>`, because a comment is a self-contained thought authored by a distinct user.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A product card on an e-commerce site.
**Task:** Since a product card is a self-contained entity that makes sense on its own, wrap the `<h2>Nike Shoes</h2>` in the correct semantic tag.
**Expected Output:** HTML with `<article>`.
<details>
<summary>Hint</summary>
Use `<article>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<article>
  <h2>Nike Shoes</h2>
  <p>$100</p>
</article>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** A "Features" area of a landing page.
**Task:** Create a thematic grouping for the features. It needs a heading "Our Features", and a paragraph describing them.
<details>
<summary>Hint</summary>
Use `<section>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<section>
  <h2>Our Features</h2>
  <p>Fast, secure, and reliable.</p>
</section>
```
</details>

### Level 3: Boss Level
**Scenario:** Building a complex blog layout (combining 8.1, 8.3).
**Task:**
1. Create a `<main>` tag.
2. Inside, create an `<article>`. Give it an `<h2>` for "My Vacation".
3. Inside the article, add a `<section>` with an `<h3>` for "Day 1".
4. Below the article (but still inside main), create an `<aside>` with an `<h2>` for "Author Bio".
<details>
<summary>Hint</summary>
Nesting is key. The section goes inside the article. The aside goes next to the article.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<main>
  <article>
    <h2>My Vacation</h2>
    <section>
      <h3>Day 1</h3>
      <p>We arrived in Hawaii.</p>
    </section>
  </article>

  <aside>
    <h2>Author Bio</h2>
    <p>Written by John.</p>
  </aside>
</main>
```
This is a perfect, machine-readable document outline!
</details>

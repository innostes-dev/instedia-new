# Page Landmarks

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
Imagine you are blind and visiting a news website (like Medium or Substack) using a screen reader. Every time you click a new article, the screen reader starts reading from the very top of the HTML: "Company Logo, Link Home, Link About, Link Search, Link Contact..." You have to listen to 20 links before you finally hear the actual news story. This makes the web completely unusable.

### 2. Plain English Explanation & Physical Metaphor (The "What")
HTML5 "Landmark" tags (`<header>`, `<nav>`, `<main>`, `<footer>`) define the macroscopic layout of a webpage. Screen readers can see these landmarks and provide users with a "shortcut menu" to jump instantly to the `<main>` content, bypassing the `<header>` entirely.
Think of landmarks like the signs hanging from the ceiling in a massive supermarket. Instead of walking down every single aisle (Div Soup) to find milk, you look up, see the "Dairy" sign (Landmark), and walk straight there.

### 3. Complete Working Runnable Code
```html
<body>
  <!-- Landmark: The Site Header -->
  <header>
    <h1>The Daily Tech</h1>

    <!-- Landmark: Primary Navigation -->
    <nav aria-label="Main Navigation">
      <ul>
        <li><a href="/">Home</a></li>
        <li><a href="/tech">Tech</a></li>
      </ul>
    </nav>
  </header>

  <!-- Landmark: The Core Content -->
  <main>
    <h2>Today's Top Story: AI Advances</h2>
    <p>Researchers have announced a breakthrough...</p>
  </main>

  <!-- Landmark: The Site Footer -->
  <footer>
    <nav aria-label="Footer Legal Links">
      <ul>
        <li><a href="/privacy">Privacy Policy</a></li>
      </ul>
    </nav>
    <p>&copy; 2024 The Daily Tech</p>
  </footer>
</body>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Header and Footer**
```html
<header>...</header>
<footer>...</footer>
```
*Why this comes first:* These tags map out the "bookends" of your site. `<header>` usually contains the logo and search bar. `<footer>` contains copyright and legal links. Note: You can technically use a `<header>` *inside* an `<article>`, but when placed directly inside the `<body>`, it becomes a global Page Landmark.

**Step 2: The Navigation Landmark**
```html
<nav>
  <ul>...</ul>
</nav>
```
*Why this is required next:* `<nav>` designates a major block of navigation links. You shouldn't wrap every single `<a>` tag on your site in a `<nav>`. It is reserved for the primary site menu, a table of contents, or pagination buttons.

**Step 3: ARIA Labels for Multiple Navs**
```html
<nav aria-label="Main Navigation">...</nav>
<nav aria-label="Footer Legal Links">...</nav>
```
*Why this follows:* If you have two `<nav>` tags on a page, a screen reader will just announce "Navigation. Navigation." The blind user won't know which is which. Adding the `aria-label` (Accessible Rich Internet Applications) gives the landmark a specific name, vastly improving accessibility.

### 5. Behind-the-Scenes / Visual Data Flow
```text
Screen Reader "Rotor" Menu Generation:
Browser scans DOM for Landmarks -> Compiles a list -> Presents to user.

[ Jump Menu ]
1. Banner (Header)
2. Navigation (Main Navigation)
3. Main (Core Content)
4. Navigation (Footer Legal Links)
5. Content Info (Footer)
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Wrapping the `<main>` tag inside a generic `<div id="app">`. While this is common in React/Vue apps, strict HTML standards prefer `<main>` to be a direct child of `<body>` whenever possible to ensure screen readers calculate the DOM tree hierarchy perfectly.
**Senior Pro Tip:** Never use more than one `<main>` tag on a single page. It represents the *unique* content of that specific URL. If a page has two main topics, they belong in separate `<article>` or `<section>` tags inside the single `<main>`.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A basic navigation menu.
**Task:** Wrap an unordered list of links (Home, About) inside a navigation landmark.
**Expected Output:** HTML with `<nav>`.
<details>
<summary>Hint</summary>
Wrap the `<ul>` with `<nav>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<nav>
  <ul>
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** A page with two menus.
**Task:** Create a `<nav>` for the main menu and a `<nav>` for the social media links. Distinguish them for screen readers.
<details>
<summary>Hint</summary>
Use `aria-label="Main Menu"` and `aria-label="Social Links"`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<nav aria-label="Main Menu">
  <!-- links -->
</nav>
<nav aria-label="Social Links">
  <!-- links -->
</nav>
```
</details>

### Level 3: Boss Level
**Scenario:** Structuring a complete landing page.
**Task:**
1. Create a `<header>`. Inside it, put an `<h1>` for the company name, and a `<nav>` for the main menu.
2. Below the header, create a `<main>` section containing a `<p>` about the company.
3. Below main, create a `<footer>`.
<details>
<summary>Hint</summary>
Ensure `header`, `main`, and `footer` are siblings (not nested inside each other).
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<header>
  <h1>Innostes</h1>
  <nav aria-label="Primary">
    <ul>
      <li><a href="/services">Services</a></li>
    </ul>
  </nav>
</header>

<main>
  <p>We build scalable web solutions.</p>
</main>

<footer>
  <p>Copyright 2024</p>
</footer>
```
You have just built the skeleton of 99% of all production websites!
</details>

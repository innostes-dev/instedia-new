# Accordions Without JavaScript

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building a Netflix FAQ page with 20 questions. If you show all the answers at once, the page is 10 miles long. You want to create "accordions" (click a question to reveal the answer). Historically, you had to write complex JavaScript: adding event listeners, measuring heights, toggling CSS `display: none`, and managing ARIA states for screen readers. It took 50 lines of code and broke if JS failed to load.

### 2. Plain English Explanation & Physical Metaphor (The "What")
HTML5 introduced the `<details>` and `<summary>` tags. They create a native, zero-JavaScript accordion. The `<summary>` is the visible button. The content inside the `<details>` (below the summary) is hidden by default and revealed when the summary is clicked.
Think of `<details>` like a physical folder with a flap. The `<summary>` is the label on the flap. When you tap the label, the browser automatically opens the flap to reveal the papers inside.

### 3. Complete Working Runnable Code
```html
<section class="faq-section">
  <h2>Frequently Asked Questions</h2>

  <!-- A Native HTML Accordion -->
  <details>
    <!-- The visible clickable trigger -->
    <summary>How do I cancel my subscription?</summary>

    <!-- The hidden content (revealed on click) -->
    <div class="faq-answer">
      <p>You can cancel your subscription at any time by visiting your account settings page and clicking "Cancel Plan".</p>
      <a href="/settings">Go to Settings</a>
    </div>
  </details>

  <!-- An Accordion open by default -->
  <details open>
    <summary>What forms of payment do you accept?</summary>
    <p>We accept Visa, Mastercard, and PayPal.</p>
  </details>
</section>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: The Details Wrapper**
```html
<details>
  <!-- content -->
</details>
```
*Why this comes first:* The `<details>` tag is the state machine. The browser manages an internal boolean state (open or closed) for this specific tag. By default, it hides everything inside it.

**Step 2: The Summary Trigger**
```html
<details>
  <summary>How do I cancel?</summary>
</details>
```
*Why this is required next:* The `<summary>` tag MUST be the very first child inside `<details>`. The browser turns this into a highly accessible, keyboard-focusable button (usually with a small triangle arrow next to it).

**Step 3: The Hidden Content and the `open` Attribute**
```html
<details open>
  <summary>...</summary>
  <p>The answer is hidden until clicked.</p>
</details>
```
*Why this follows:* Any HTML placed after the `<summary>` becomes the hidden payload. If you want the accordion to be open when the page first loads, simply add the boolean `open` attribute to the `<details>` tag.

### 5. Behind-the-Scenes / Visual Data Flow
```text
State 1 (Default):
Browser renders `<summary>`. Applies CSS `display: none` to all sibling elements.

State 2 (User Clicks Summary):
Browser intercepts click -> Toggles `open` attribute on `<details>`.
Browser removes `display: none` -> Content appears!
Screen reader announces: "Expanded."
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using `<div>` and JavaScript to build accordions instead of `<details>`. A custom JS accordion often fails "Find in Page" (Ctrl+F). If a user searches for a word hidden inside a `<details>` tag, Chrome is smart enough to automatically open the accordion and highlight the word! Custom JS accordions remain stubbornly closed.
**Senior Pro Tip:** You can style the little triangle arrow! In CSS, you target `summary::marker` to change its color, or use `list-style: none` to remove it entirely and replace it with your own custom SVG plus/minus icon.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A spoiler warning.
**Task:** Create a toggle that says "View Spoiler". When clicked, it should reveal "Darth Vader is his father".
**Expected Output:** HTML with `<details>` and `<summary>`.
<details>
<summary>Hint</summary>
Wrap everything in `<details>`. Use `<summary>` for the trigger text.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<details>
  <summary>View Spoiler</summary>
  <p>Darth Vader is his father.</p>
</details>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** A Terms of Service section that is open by default.
**Task:** Create an accordion titled "Read Terms". Ensure it is open when the page loads. Place a paragraph inside it.
<details>
<summary>Hint</summary>
Use the `open` attribute on the `<details>` tag.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<details open>
  <summary>Read Terms</summary>
  <p>You agree to give us your soul.</p>
</details>
```
</details>

### Level 3: Boss Level
**Scenario:** A nested UI component.
**Task:** Create a `<details>` accordion titled "Advanced Settings". Inside the hidden content, create a `<form>` containing a `<label>` and a checkbox (`<input type="checkbox">`) for "Enable Beta Features".
<details>
<summary>Hint</summary>
You can put any valid HTML inside a `<details>` tag, including fully functional forms!
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<details>
  <summary>Advanced Settings</summary>
  <form action="/save" method="POST">
    <input type="checkbox" id="beta" name="betaFeatures">
    <label for="beta">Enable Beta Features</label>
  </form>
</details>
```
This is a standard pattern for hiding complex configuration options until the user requests them.
</details>

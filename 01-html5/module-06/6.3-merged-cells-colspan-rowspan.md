# Merged Cells (Colspan & Rowspan)

## PHASE A: CONCEPT BREAKDOWN

### 1. The Real-World Pain Point / Trigger (The "Why")
You are building an Airline Flight Matrix. You have a "First Class" section that spans across two distinct columns: "Window Seat" and "Aisle Seat". If you just create a standard grid, the words "First Class" will sit strictly inside the "Window" column, leaving an empty, confusing cell above "Aisle". You need a way to tear down the wall between two cells to create one giant master cell.

### 2. Plain English Explanation & Physical Metaphor (The "What")
The `colspan` attribute tells a cell (`<td>` or `<th>`) to stretch horizontally and eat the columns to its right. The `rowspan` attribute tells a cell to stretch vertically and eat the rows directly beneath it.
Think of a physical brick wall. Every brick is a `<td>`. `colspan="2"` means you replace two standard 1-inch bricks side-by-side with a single 2-inch double-wide block.

### 3. Complete Working Runnable Code
```html
<table border="1">
  <caption>Flight Seating Chart</caption>

  <tr>
    <!-- Empty top-left corner -->
    <td></td>
    <!-- This header eats 2 columns -->
    <th colspan="2" scope="col">First Class</th>
  </tr>

  <tr>
    <!-- This row header eats 2 rows downwards -->
    <th rowspan="2" scope="row">Row 1</th>
    <td>Seat 1A (Window)</td>
    <td>Seat 1B (Aisle)</td>
  </tr>

  <tr>
    <!-- NOTE: The 'Row 2' header is missing here because Row 1's rowspan ate this space! -->
    <td>Seat 1C (Window)</td>
    <td>Seat 1D (Aisle)</td>
  </tr>
</table>
```

### 4. Progressive Step-by-Step Code Breakdown

**Step 1: Horizontal Merging (`colspan`)**
```html
<tr>
  <td></td>
  <th colspan="2">First Class</th>
</tr>
```
*Why this works:* In this row, there are technically 3 columns of space. We provided an empty cell for column 1. Then we provided a header. By giving it `colspan="2"`, it absorbs column 2 and column 3 into a single wide block. The total mathematical width of this row is 1 + 2 = 3.

**Step 2: Vertical Merging (`rowspan`)**
```html
<tr>
  <th rowspan="2">Row 1</th>
  <td>Seat 1A</td>
  <td>Seat 1B</td>
</tr>
```
*Why this is required next:* The `<th>` drops down vertically, claiming the first column space of the *current* row AND the first column space of the *next* row.

**Step 3: The Ghost Cell Consequence**
```html
<tr>
  <!-- First column is missing! -->
  <td>Seat 1C</td>
  <td>Seat 1D</td>
</tr>
```
*Why this follows:* Because the row above it claimed the vertical space using `rowspan`, this row mathematically only needs 2 cells defined instead of 3. If you tried to add a third cell here, it would blow out the side of the table and break the grid!

### 5. Behind-the-Scenes / Visual Data Flow
```text
Table Rendering Engine Math:

Row 1 [ 1 ] [   2   ]
Row 2 [ 1 ] [ 1 ] [ 1 ]
Row 3 [ | ] [ 1 ] [ 1 ]  <-- The [ | ] is physically occupied by the rowspan from Row 2.
```

### 6. Noob Trap vs. Senior Pro Tip
**Noob Trap:** Using `colspan` without deleting the corresponding `<td>` in the HTML. If your table has 3 columns, and you write `<tr> <td colspan="2"></td> <td></td> <td></td> </tr>`, you have mathematically asked for 4 columns of space (2+1+1). The browser will render a deformed table with cells sticking out the right side.
**Senior Pro Tip:** Merged cells are notorious for breaking screen reader flow if not scoped perfectly. Avoid complex nested rowspans unless absolutely necessary. Keep tables as simple grids whenever possible.

## PHASE B: PROGRESSIVE 3-LEVEL PRACTICE ARENA

### Level 1: Warm-Up
**Scenario:** A 3-column table summarizing an invoice. You want the bottom row to have one giant cell that says "Total" stretching across the first 2 columns.
**Task:** Create a `<tr>` with a cell that spans 2 columns, followed by a cell with the price.
**Expected Output:** HTML row with `colspan`.
<details>
<summary>Hint</summary>
Use `<td colspan="2">Total</td>` and `<td>$100</td>`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<tr>
  <td colspan="2">Total</td>
  <td>$100</td>
</tr>
```
</details>

### Level 2: Real-World Scenario
**Scenario:** A timesheet where someone worked the exact same task for Monday and Tuesday.
**Task:** Create a 2-column table (Day, Task). Merge Monday and Tuesday's task into a single vertical cell spanning 2 rows.
<details>
<summary>Hint</summary>
Row 1 has Day (Monday) and Task (with `rowspan="2"`). Row 2 only has Day (Tuesday).
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<table>
  <tr>
    <td>Monday</td>
    <td rowspan="2">Coding</td>
  </tr>
  <tr>
    <td>Tuesday</td>
    <!-- No task cell here, it was eaten by Monday! -->
  </tr>
</table>
```
</details>

### Level 3: Boss Level
**Scenario:** An advanced scheduling matrix (combining Mod 6.1, 6.2, 6.3).
**Task:** Create a `<table>`.
1. Top row (`<thead>`): A blank cell, then a `<th>` for "Morning" and a `<th>` for "Afternoon".
2. Data row 1 (`<tbody>`): `<th scope="row">` for "Monday". Then a `<td>` spanning exactly 2 columns horizontally, containing the text "All Day Workshop".
<details>
<summary>Hint</summary>
You must delete the third cell in Data Row 1 to make room for the `colspan="2"`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```html
<table>
  <thead>
    <tr>
      <td></td>
      <th scope="col">Morning</th>
      <th scope="col">Afternoon</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Monday</th>
      <td colspan="2">All Day Workshop</td>
    </tr>
  </tbody>
</table>
```
This requires perfect mathematical tracking of rows and columns to achieve!
</details>

# 4.4 Event Delegation & Bubbling (Senior Performance)

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
You have a table of 1,000 employees. Each row has a "Delete" button. If you use a `for` loop to attach an `addEventListener` to all 1,000 buttons, you consume massive amounts of memory, and your app lags. Worse, if you dynamically add a *new* employee row, its button won't have a listener because the loop already ran!

### 2. Plain English Metaphor (The What)
- **Event Bubbling:** When you drop a stone (a click) in a pond (a button), the ripples travel outward to the shore (up through the parent elements to the document). If you click a `button`, you also implicitly clicked the `div` holding it, and the `body` holding that.
- **Event Delegation:** Instead of hiring 1,000 security guards (listeners) for 1,000 apartment doors (buttons), you put **ONE guard at the front gate** (the parent `<ul>` or `<table>`). When the guard hears a window break, they look at the "police report" (`event.target`) to see exactly which apartment it came from.

### 3. Complete Runnable Code
```javascript
// Example: High-Performance Dynamic Task Board List
// HTML: <ul id="board">
//         <li>Task 1 <button class="del-btn">X</button></li>
//       </ul>

const board = document.querySelector("#board");

// ONE Listener on the Parent Element!
board.addEventListener("click", (event) => {
  // `event.target` is the EXACT pixel the user clicked on.
  // We check if they clicked a delete button, or just dead space.

  // Use .matches() to check if the target has a specific CSS class
  if (event.target.matches(".del-btn")) {

    // .closest() searches UP the tree to find the nearest <li> parent
    const rowToDelete = event.target.closest("li");

    // Remove the element from the DOM
    rowToDelete.remove();
    console.log("Deleted a task efficiently!");
  }
});

// Proving Dynamic Elements work automatically:
// Let's add a new task AFTER the listener was attached.
const newTask = document.createElement("li");
newTask.innerHTML = `Task 2 <button class="del-btn">X</button>`;
board.appendChild(newTask);

// If you click Task 2's delete button, it WORKS!
// Because the ripple bubbles up to the #board guard.
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Parent Listener**
We attach ONE `"click"` listener to the parent container (`#board`).
**Step 2: The Ripple (Bubbling)**
When a user clicks the `<button>`, the click event "bubbles" up to the `<li>`, and then to the `<ul id="board">`, triggering our listener.
**Step 3: Target Validation (`.matches`)**
Because clicking *anywhere* in the board triggers the listener, we must check what was clicked. `event.target.matches(".del-btn")` ensures we only run code if a delete button was clicked.
**Step 4: DOM Traversal (`.closest`)**
We have the button, but we want to delete the whole row (`<li>`). `event.target.closest("li")` travels up the tree from the button and grabs the first `<li>` it finds, which we then `.remove()`.

### 5. ASCII Data Flow
```text
Click <button>!
      |
      v (Ripples UP!)
      |
[ <li> ]
      |
      v (Ripples UP!)
      |
[ <ul id="board"> ] ---> HAS LISTENER!
      |
      v
Runs callback(event)
      |
event.target === <button>
event.target.closest("li") === <li>
<li>.remove()
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `querySelectorAll` + `forEach` to attach 500 click listeners. It breaks as soon as you dynamically render a new element via JS.
**Pro Tip:** Event Delegation is a mandatory interview topic for Senior Frontend Engineers. Always attach listeners to the nearest stable parent container and use `event.target.matches()` to filter the clicks.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** You have `<div id="menu"> <button class="nav">Home</button> <button class="nav">About</button> </div>`. Add ONE event listener to `#menu`. If the clicked target has the class `.nav`, log "Navigating!".
<details>
<summary>Hint</summary>
`menu.addEventListener('click', (e) => { if(e.target.matches('.nav')) ... })`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const menu = document.querySelector("#menu");

menu.addEventListener("click", (event) => {
  if (event.target.matches(".nav")) {
    console.log("Navigating to: " + event.target.textContent);
  }
});
```
One listener handles infinite buttons.
</details>

### Level 2: Real-World
**Task:** A shopping cart table `<table id="cart">...</table>`. Inside are rows with `<button class="qty-up">+</button>`.
Attach a delegated listener to the table. If they click `.qty-up`, find the nearest `<tr>` row (using `.closest()`). Add a class `"highlight"` to that row to show it was updated.
<details>
<summary>Hint</summary>
`const row = event.target.closest("tr"); row.classList.add("highlight");`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const cartTable = document.querySelector("#cart");

cartTable.addEventListener("click", (event) => {
  if (event.target.matches(".qty-up")) {
    const parentRow = event.target.closest("tr");
    parentRow.classList.add("highlight");
    console.log("Increased quantity!");
  }
});
```
This demonstrates traversing UP the DOM tree from the `target` to manipulate related elements.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) The dynamic filter UI.
HTML: `<div id="filters"> <span class="tag" data-id="1">JS</span> <span class="tag" data-id="2">React</span> </div>`
1. Use Event Delegation on `#filters`.
2. Check if the click was on a `.tag`.
3. If it was, safely read its text content (using optional chaining/nullish coalescing if needed).
4. Safely extract its custom data ID using `event.target.getAttribute("data-id")` and cast it to a Number.
5. Create a lookup map: `1: "Javascript Logic", 2: "React Framework"`.
6. Log: "Filtering by: [MappedName] (ID: [id])".
<details>
<summary>Hint</summary>
Combine `.matches()`, `.getAttribute()`, `Number()`, and an Object map!
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const filterBox = document.querySelector("#filters");

const categoryMap = {
  1: "Javascript Logic",
  2: "React Framework"
};

filterBox.addEventListener("click", (event) => {
  if (event.target.matches(".tag")) {
    // Extract and format data
    const rawId = event.target.getAttribute("data-id") ?? "0";
    const numId = Number(rawId);

    // Look it up
    const fullName = categoryMap[numId] ?? "Unknown Category";

    console.log(`Filtering by: ${fullName} (ID: ${numId})`);
  }
});
```
This is a senior-level data architecture pattern embedded in a high-performance UI delegated listener. Flawless execution.
</details>

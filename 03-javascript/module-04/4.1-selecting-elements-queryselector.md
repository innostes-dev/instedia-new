# 4.1 Selecting Elements: querySelector and the DOM Tree

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
You wrote a beautiful script to switch a page to Dark Mode. But how does JavaScript actually *talk* to the HTML? HTML is just text in a file. If JavaScript doesn't know where the `<body>` or the `<button>` is, it can't change their colors. We need a bridge between the JS engine and the visual page.

### 2. Plain English Metaphor (The What)
The **DOM (Document Object Model)** is like a **holographic map** of your HTML house.
When the browser loads your HTML, it builds this 3D map in memory.
- `document.querySelector` is your **GPS search bar**. You type in an address (a CSS selector), and it finds the exact room (HTML element) on the map so you can paint it black.

### 3. Complete Runnable Code
```javascript
// Example: Dark Mode Theme Switcher DOM Controller
// (Assume an HTML file with: <body class="light"> <button id="theme-btn">Toggle</button> </body>)

// 1. Selecting Elements using CSS Selectors
// Find the FIRST element with the ID 'theme-btn'
const themeButton = document.querySelector("#theme-btn");

// Find the FIRST 'body' tag
const bodyElement = document.querySelector("body");

// 2. Proving we have the elements
console.log("Button Found:", themeButton);
console.log("Body Class:", bodyElement.className);

// 3. Modifying the DOM (Preview for next lesson)
// When clicked, we change the class to trigger CSS changes
themeButton.addEventListener("click", () => {
  if (bodyElement.className === "light") {
    bodyElement.className = "dark";
    themeButton.textContent = "Switch to Light";
  } else {
    bodyElement.className = "light";
    themeButton.textContent = "Switch to Dark";
  }
});
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The `document` Object**
The `document` is the global object that holds the entire holographic map of your page. Every DOM query starts here.
**Step 2: `querySelector`**
We pass a string into `querySelector()`. This string must be a valid CSS selector (`#` for IDs, `.` for classes, or plain tags like `body`). It returns the *first* element that matches.
**Step 3: Storing References**
We store the result in a `const` variable. `themeButton` is now a direct remote control to the physical button on the screen. Changing properties on this variable updates the screen instantly.

### 5. ASCII Data Flow
```text
HTML: <button id="theme-btn">
          |
       (Browser parses HTML)
          |
DOM Tree: [ document ] -> [ body ] -> [ button#theme-btn ]
                                           ^
JS: document.querySelector("#theme-btn") --+
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using old methods like `document.getElementById('btn')` or `document.getElementsByClassName('card')`. While they work, they return different, harder-to-use data types (like HTMLCollections).
**Pro Tip:** Always use `document.querySelector()` (for a single element) and `document.querySelectorAll()` (for an array-like list of multiple elements). They use standard CSS syntax, making your code uniform and modern.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Imagine HTML `<h1 class="title">Hello</h1>`. Write the JavaScript to select this `h1` using its class name and store it in a variable called `heading`. Log it.
<details>
<summary>Hint</summary>
Use `.` for class names in `querySelector`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
// Select via class selector
const heading = document.querySelector(".title");
console.log(heading);
```
Just like writing CSS: `.title { color: red; }`.
</details>

### Level 2: Real-World
**Task:** You have multiple cards: `<div class="card">A</div> <div class="card">B</div>`.
If you use `querySelector(".card")`, what does it return?
Write the code using `document.querySelectorAll()` to get *all* cards. Then use a `for...of` loop to log the `textContent` of each card.
<details>
<summary>Hint</summary>
`querySelectorAll` returns a NodeList, which you can loop over perfectly with `for...of`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
// querySelector returns ONLY the first card "A".
// querySelectorAll returns a list of all cards!
const allCards = document.querySelectorAll(".card");

for (const card of allCards) {
  console.log(card.textContent); // Logs "A", then "B"
}
```
This is how you apply changes to hundreds of elements at once.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Combine DOM selection, safe navigation, and arrays.
You have a deeply nested element: `<div id="dashboard"><p class="user-score">100</p></div>`.
1. Select the `#dashboard` element.
2. What if `#dashboard` doesn't exist? Use optional chaining to safely try to select the `.user-score` *inside* the dashboard (e.g., `dashboardEl?.querySelector(...)`).
3. If it exists, cast its `.textContent` to a Number.
4. Fallback to `0` using `??` if the element wasn't found.
Log the numeric score.
<details>
<summary>Hint</summary>
`const scoreNode = dashboardEl?.querySelector(".user-score");`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const dashboard = document.querySelector("#dashboard");

// Safely query INSIDE the dashboard element (if it exists)
const scoreNode = dashboard?.querySelector(".user-score");

// Safely get textContent, convert to Number, fallback to 0
const rawText = scoreNode?.textContent ?? "0";
const numericScore = Number(rawText);

console.log(`User Score: ${numericScore}`);
```
This is a highly resilient pattern. Instead of querying the whole document, you query *inside* a specific element, and protect against null errors if the UI hasn't rendered yet!
</details>

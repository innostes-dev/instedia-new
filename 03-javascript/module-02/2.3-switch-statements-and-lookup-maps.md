# 2.3 Switch Statements and Object Lookup Maps

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
You are building a payment system. You have PayPal, Stripe, Apple Pay, Google Pay, Crypto, and Bank Transfer. If you write an `if / else if` chain for this, you end up with 20 lines of repetitive, ugly code: `if (type === 'paypal') ... else if (type === 'stripe') ...`. It's slow to read and hard to maintain.

### 2. Plain English Metaphor (The What)
- A **Switch Statement** is a **train switch track**. The train (data) comes in, looks at the signs (cases), and gets diverted down a single specific path.
- An **Object Lookup Map** is a **mailroom directory**. Instead of asking 10 different people where Bob sits, you look at a dictionary: `Directory['Bob']` and instantly get the room number. It's faster and cleaner.

### 3. Complete Runnable Code
```javascript
// Example: Multi-Option Payment Gateway Dispatcher
const paymentMethod = "apple_pay";

// Approach 1: The Switch Statement
let processingFee = 0;

switch (paymentMethod) {
  case "stripe":
  case "paypal":
    // Fall-through: Both use this logic
    processingFee = 0.03;
    break;
  case "apple_pay":
    processingFee = 0.02;
    break; // ALWAYS REMEMBER THE BREAK!
  case "crypto":
    processingFee = 0.01;
    break;
  default:
    processingFee = 0.05;
}
console.log(`Switch Fee: ${processingFee}`);

// Approach 2: The Object Lookup Map (Pro Pattern)
const feeDirectory = {
  stripe: 0.03,
  paypal: 0.03,
  apple_pay: 0.02,
  crypto: 0.01
};

// Look it up instantly. If it doesn't exist, fallback to 0.05
const mapFee = feeDirectory[paymentMethod] ?? 0.05;

console.log(`Map Fee: ${mapFee}`);
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Switch Setup**
`switch(paymentMethod)` evaluates the string `"apple_pay"`. It jumps directly to `case "apple_pay":`.
**Step 2: The Break Keyword**
It executes `processingFee = 0.02`. Then it hits `break;`. The `break` tells the train to leave the switch station. If you forget it, the train keeps driving down the track into the `crypto` case (this is called "fall-through").
**Step 3: The Object Map Alternative**
We create an object `feeDirectory` where the keys match the payment strings. We use bracket notation `feeDirectory["apple_pay"]` to instantly retrieve `0.02`.
**Step 4: The Default Fallback**
We combine the Object Map with the Nullish Coalescing operator `?? 0.05` to handle the `default` case if the payment method isn't in the directory.

### 5. ASCII Data Flow
```text
[ paymentMethod = "apple_pay" ]

Switch Data Flow:
evaluates -> skips 'stripe/paypal' -> matches 'apple_pay' -> sets 0.02 -> BREAK -> exits

Object Map Data Flow:
feeDirectory["apple_pay"] ---> instantly returns 0.02
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Forgetting the `break;` in a switch statement. The code will execute every single case below the matched one, completely ruining your variables.
**Pro Tip:** Senior engineers heavily prefer **Object Lookup Maps** over `switch` statements for 1-to-1 value mapping. They are shorter, don't require `break` statements, and look much cleaner. Save `switch` for when you need to execute complex blocks of logic per case.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Write a `switch` statement that takes a variable `day = 2`. If day is 1, log "Monday". If 2, log "Tuesday". Default should log "Unknown Day". Don't forget your breaks!
<details>
<summary>Hint</summary>
`switch(day) { case 1: ... }`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const day = 2;

switch(day) {
  case 1:
    console.log("Monday");
    break;
  case 2:
    console.log("Tuesday");
    break;
  default:
    console.log("Unknown Day");
}
```
Standard switch syntax. The `break` prevents "Tuesday" from falling into "Unknown Day".
</details>

### Level 2: Real-World
**Task:** Refactor a status checker into an Object Lookup Map.
Status options: `"pending"` -> "Waiting on user", `"shipped"` -> "Out for delivery", `"delivered"` -> "Arrived".
Variable: `currentStatus = "shipped"`.
Use an object to look up the message. If the status isn't found, default to "Status unknown" using `??`. Log it.
<details>
<summary>Hint</summary>
Create a `const statusMap = { ... }`. Access it via `statusMap[currentStatus]`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const currentStatus = "shipped";

const statusMap = {
  pending: "Waiting on user",
  shipped: "Out for delivery",
  delivered: "Arrived"
};

const message = statusMap[currentStatus] ?? "Status unknown";
console.log(message); // "Out for delivery"
```
This is much cleaner than a 15-line switch statement!
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Combine Object Maps, safe navigation (`?.`), and type coercion.
You have a response: `const apiData = { data: { roleId: "2" } }`. (Note: roleId is a string!).
1. Safely extract the `roleId`. If missing, default to string `"0"`.
2. Convert the extracted `roleId` to a Number.
3. Create a Lookup Map for Roles where keys are *numbers*: `1` is "User", `2` is "Editor", `3` is "Admin".
4. Use the numeric role ID to get the role name from the map. Default to "Guest" using `??`.
5. Log a template literal: "Welcome, [RoleName]!"
<details>
<summary>Hint</summary>
Get the id using `?.` and `?? "0"`. Wrap that in `Number()`. Then use `map[numId]`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const apiData = { data: { roleId: "2" } };

{
  // 1 & 2: Safely extract and explicitly convert to a Number
  const rawId = apiData.data?.roleId ?? "0";
  const numId = Number(rawId);

  // 3: The Lookup Map (keys are automatically converted to strings in JS, but we can write them as numbers)
  const roleMap = {
    1: "User",
    2: "Editor",
    3: "Admin"
  };

  // 4: Lookup the name, provide a default
  const roleName = roleMap[numId] ?? "Guest";

  // 5: Final output
  console.log(`Welcome, ${roleName}!`);
}
```
This is a perfect simulation of real-world API handling: protecting against missing data, fixing bad data types (string to number), and cleanly mapping IDs to readable UI text without massive `if/else` blocks.
</details>

# 2.1 Conditionals, Truthiness, and the Falsy Traps

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Imagine an Uber app that charges the same $10 price whether it's 2 PM on a Tuesday or 2 AM on New Year's Eve in a blizzard. The company would go bankrupt. We need our code to make *decisions* based on current conditions. If demand is high, increase the price. If it's raining, add a fee.

### 2. Plain English Metaphor (The What)
Conditionals (`if`, `else if`, `else`) are the **bouncers at a club**.
They check your ID (the condition). If you meet the criteria (it is `true`), they open the door and let you run the code inside. If you don't (it is `false`), they point you to the next line or kick you out to the `else` block.

### 3. Complete Runnable Code
```javascript
// Example: Uber Surge Pricing Tier Calculator
const baseFare = 10;
const isRaining = true;
const activeDrivers = 3;
let finalFare = baseFare;

// Strict Equality (===) vs Truthiness
if (activeDrivers === 0) {
  console.log("No drivers available. Try again later.");
} else if (activeDrivers < 5 && isRaining) {
  // High demand + Bad weather
  finalFare = baseFare * 2.5;
  console.log("MAX SURGE PRICING APPLIED!");
} else if (isRaining) {
  // Just bad weather
  finalFare = baseFare * 1.5;
  console.log("Weather surge applied.");
} else {
  // Normal conditions
  console.log("Standard pricing.");
}

console.log(`Final Fare: $${finalFare}`);
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: Setting up State**
We define our base conditions: `isRaining` is a boolean `true`, and `activeDrivers` is the number `3`.
**Step 2: The First Check (The Bouncer)**
`if (activeDrivers === 0)` checks for strict equality. We use `===` instead of `==` because `==` does dangerous type coercion (it thinks `0 == "0"` is true!). Since we have 3 drivers, this check fails, and we move to the next.
**Step 3: The Logical AND (&&)**
`else if (activeDrivers < 5 && isRaining)` requires *both* conditions to be true. Since 3 < 5 is true, AND it is raining, this block executes. The code inside runs, and we skip all remaining `else if` and `else` blocks.

### 5. ASCII Data Flow
```text
[ isRaining: true, drivers: 3 ]
       |
       v
( drivers === 0? ) ---- YES ---> [ Print "No drivers" ]
       | NO
       v
( drivers < 5 AND isRaining? ) -- YES -> [ finalFare = 10 * 2.5 ] ---> [ Skip Rest ]
       | NO                                                                |
       v                                                                   v
( isRaining? ) -- YES -> [ finalFare = 10 * 1.5 ]                          |
       | NO                                                                v
       v                                                            [ Print $25 ]
[ Standard Pricing ]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** The Falsy Trap. In JavaScript, `0`, `""` (empty string), `null`, `undefined`, `NaN`, and `false` are considered "falsy". If you do `let drivers = 0; if (drivers) { ... }`, the block will NOT run because `0` is falsy. Beginners often write `if (drivers === false)` which is wrong because `0 !== false` strictly.
**Pro Tip:** Always use `===` instead of `==`. It checks both value AND type, saving you from hours of debugging weird coercion bugs.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Create a variable `userAge = 16`. Write an `if / else` statement. If the user is 18 or older, log "Access Granted". Otherwise, log "Access Denied".
<details>
<summary>Hint</summary>
Use the `>=` (greater than or equal to) operator.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const userAge = 16;

if (userAge >= 18) {
  console.log("Access Granted");
} else {
  console.log("Access Denied");
}
```
Standard conditional branching based on numerical comparison.
</details>

### Level 2: Real-World
**Task:** You have an input `userName = ""`. Write an `if / else` block that relies purely on *truthiness/falsiness* (do not use `===` or `.length`). If they entered a name, log "Hello [name]". If it's empty, log "Please enter a name".
<details>
<summary>Hint</summary>
An empty string `""` is falsy. A string with text `"Bob"` is truthy. Just pass the variable directly into the `if()`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const userName = "";

// Evaluates truthiness directly!
if (userName) {
  console.log(`Hello ${userName}`);
} else {
  console.log("Please enter a name");
}
```
This is a senior pattern. Instead of `userName.length > 0`, we rely on JavaScript's built-in falsy evaluation of empty strings.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Combine data types, template literals, and complex conditionals.
Variables: `accountStatus = "suspended"`, `balance = "50"` (string!), `isAdmin = false`.
Logic:
1. Convert `balance` to a Number.
2. If `isAdmin` is true, log "Admin Access".
3. Else if `accountStatus` is strictly equal to "suspended", log "Account Locked".
4. Else if `accountStatus` is "active" AND the numeric `balance` is greater than 0, log a template literal: "Ready to shop! Balance: $[balance]".
5. Else, log "Please add funds."
<details>
<summary>Hint</summary>
Handle the explicit casting first. Then chain your `if / else if / else`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const accountStatus = "suspended";
const balanceString = "50";
const isAdmin = false;

const numBalance = Number(balanceString);

if (isAdmin) {
  console.log("Admin Access");
} else if (accountStatus === "suspended") {
  console.log("Account Locked");
} else if (accountStatus === "active" && numBalance > 0) {
  console.log(`Ready to shop! Balance: $${numBalance}`);
} else {
  console.log("Please add funds.");
}
```
This requires type casting (to do accurate math comparisons), strict equality checking, logical ANDs, and fallback logic!
</details>

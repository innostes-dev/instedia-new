# 5.2 The Promise Specification

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Before Promises, if you wanted to fetch user data, then fetch their friends, then fetch their friends' photos, you had to nest callbacks inside callbacks inside callbacks. This created the infamous "Callback Hell" or "Pyramid of Doom"—a triangular mess of unreadable code where error handling was nearly impossible.

### 2. Plain English Metaphor (The What)
A **Promise** is a **restaurant buzzer**.
When you order food, you don't stand at the counter waiting (blocking). The cashier gives you a buzzer. The buzzer is in a `Pending` state. You go sit down.
- If the food finishes, the buzzer vibrates (it is `Resolved`), and you get your food (`.then()`).
- If they run out of ingredients, the buzzer flashes red (it is `Rejected`), and you get an apology (`.catch()`).

### 3. Complete Runnable Code
```javascript
// Example: Chained API Data Fetcher Simulation
console.log("1. Ordering food...");

// Creating a manual Promise (Simulating a database fetch)
const foodOrder = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true; // Change this to false to see the catch block!

    if (success) {
      resolve({ meal: "Burger", price: 15 }); // Buzzer Vibrates!
    } else {
      reject("Grill is broken."); // Buzzer flashes Red!
    }
  }, 1000);
});

console.log("2. Sitting at table...");

// Consuming the Promise
foodOrder
  .then((data) => {
    // This runs ONLY if resolve() was called
    console.log(`3. Success! I received my ${data.meal}.`);

    // We can chain Promises! Return a new value for the next .then()
    return data.price + 5; // Add tip
  })
  .then((finalPrice) => {
    console.log(`4. I paid $${finalPrice} total.`);
  })
  .catch((error) => {
    // This runs ONLY if reject() was called
    console.log(`Error: The chef said '${error}'`);
  });

console.log("3. Scrolling on phone...");
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: Construction**
`new Promise(...)` takes a function with two arguments provided by the engine: `resolve` (success) and `reject` (failure).
**Step 2: The Async Work**
Inside the Promise, we do async work (simulated by `setTimeout`). When finished, we call `resolve(data)` to fulfill the promise.
**Step 3: Consumption & Chaining**
We attach `.then(callback)` to the Promise object. The callback receives the data passed into `resolve()`. By returning a new value from a `.then()`, we can chain another `.then()` endlessly without nesting!
**Step 4: Error Handling**
If anything goes wrong, or if `reject()` is called, the chain breaks instantly and skips straight to `.catch()`.

### 5. ASCII Data Flow
```text
[ Promise Created (Pending) ]
             |
       (1 sec delay...)
             |
[ resolve({meal: "Burger"}) ] ----> [ .then(data) runs! ]
                                            |
[ reject("Grill broken") ] -------> [ .catch(error) runs! ]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Putting async work inside a Promise but forgetting to call `resolve()` or `reject()`. The Promise will stay strictly in the "Pending" state forever, and your `.then()` will literally never fire, silently hanging your app.
**Pro Tip:** You don't usually *create* Promises using `new Promise` in daily work. APIs like `fetch()` automatically create and return Promises for you! Your main job is to consume them via `.then()` and `.catch()`.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Create a resolved Promise that returns the string "Hello". Chain a `.then()` to it that logs the string.
<details>
<summary>Hint</summary>
You can use the shortcut `Promise.resolve("Hello")`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
const myPromise = Promise.resolve("Hello");

myPromise.then((text) => {
  console.log(text);
});
```
This is the simplest way to wrap a value in a Promise to kick off an async chain.
</details>

### Level 2: Real-World
**Task:** Chain multiple transformations. Create `Promise.resolve(10)`. Chain a `.then()` that multiplies the number by 2 (return it). Chain a second `.then()` that adds 5 (return it). Chain a third `.then()` that logs the final result.
<details>
<summary>Hint</summary>
`.then(num => num * 2).then(num => num + 5).then(res => console.log(res))`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
Promise.resolve(10)
  .then(num => {
    return num * 2; // 20
  })
  .then(num => {
    return num + 5; // 25
  })
  .then(final => {
    console.log(`Final value: ${final}`);
  });
```
This flat chain is infinitely better than nested callbacks!
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Combine Object mapping, conditionals, and Promises.
Create a function `processPayment(methodString)` that returns a `new Promise`.
1. Inside the promise, check a map: `const validMethods = { card: true, paypal: true }`.
2. If `validMethods[methodString]` is truthy, use `setTimeout` (500ms) to call `resolve("Payment Successful")`.
3. If it's falsy, immediately call `reject("Invalid Payment Method")`.
4. Call `processPayment("crypto")`. Attach a `.then()` to log success, and a `.catch()` to log the error.
<details>
<summary>Hint</summary>
`new Promise((resolve, reject) => { if(validMethods[m]) { setTimeout(()=>resolve("ok"), 500) } else { reject("fail") } })`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
function processPayment(method) {
  return new Promise((resolve, reject) => {
    const validMethods = { card: true, paypal: true };

    if (validMethods[method]) {
      setTimeout(() => {
        resolve("Payment Successful!");
      }, 500);
    } else {
      reject("Invalid Payment Method!");
    }
  });
}

// Execute and consume
processPayment("crypto")
  .then(msg => console.log("Success:", msg))
  .catch(err => console.error("Error:", err));
```
You have built a fully functional, async payment simulation pipeline that correctly branches logic and routes data to the proper Promise consumers!
</details>

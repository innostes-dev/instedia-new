# 5.4 Fetching JSON from APIs

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Your app is useless if it can't talk to the outside world. You need a way to send a request across the internet to a server (like GitHub or a weather API) and download the raw data (usually in JSON format) so you can render it in your UI.

### 2. Plain English Metaphor (The What)
`fetch()` is the **browser's built-in mail carrier**.
You give the mail carrier an address (URL). They drive off (Async Promise). They come back with a package (the HTTP Response). But the package is sealed in a box! You have to run `.json()` to unpack the box into actual JavaScript objects and arrays you can use.

### 3. Complete Runnable Code
```javascript
// Example: GitHub User Repository Search Engine

async function getGitHubUser(username) {
  try {
    // 1. Send the mail carrier (Returns a Promise!)
    console.log(`Fetching data for ${username}...`);
    const response = await fetch(`https://api.github.com/users/${username}`);

    // 2. HTTP Status Checking (CRITICAL!)
    // fetch() does NOT reject on 404 errors! It only rejects on network failures.
    if (!response.ok) {
      throw new Error(`API Error: ${response.status} ${response.statusText}`);
    }

    // 3. Unpack the package (This is ALSO async and returns a Promise!)
    const userData = await response.json();

    // 4. Use the data
    console.log(`Success! ${userData.name} has ${userData.public_repos} repos.`);

  } catch (error) {
    // Catches network errors OR the manual 404 error we threw
    console.error(`Failed to load user: ${error.message}`);
  }
}

// Valid user
getGitHubUser("octocat");

// Invalid user (will hit the manual throw)
getGitHubUser("thisuserdoesnotexist123456789");
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Initial Fetch**
`await fetch(url)` fires the HTTP GET request. It pauses until the server replies with headers (not the full data body yet).
**Step 2: Checking `response.ok`**
This is the biggest gotcha in JavaScript. If a server returns a `404 Not Found`, `fetch()` considers it a "successful" connection! The promise *resolves*. You must manually check `if (!response.ok)` (which checks if the status is outside the 200-299 range) and `throw` an error yourself.
**Step 3: Parsing JSON**
The body of the response arrives as a raw data stream. Calling `response.json()` reads that stream to completion and parses it into a JS Object. Because reading streams takes time, `.json()` *also* returns a Promise, requiring a second `await`.

### 5. ASCII Data Flow
```text
await fetch('url')
       |
[ HTTP Request goes to server ]
       |
[ Server replies with Headers (Status: 200 OK) ]
       |
response.ok is TRUE
       |
await response.json()
       |
[ Reads Data Stream ] -> Converts JSON string -> [ JS Object: {name: "Bob"} ]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Doing `const data = await fetch(url)` and then trying to do `console.log(data.name)`. `data` is a Response object, not the JSON data! You MUST do `await data.json()` first. Also, forgetting to check `!response.ok` and accidentally parsing a 404 HTML error page as JSON, causing a crash.
**Pro Tip:** Abstract your fetch calls into a helper function that automatically checks `response.ok` and parses the JSON, so you don't repeat that boilerplate 50 times in your app.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Write a simple `async function getJoke()` that `await`s a fetch to `https://official-joke-api.appspot.com/random_joke`. Don't worry about error handling. Just `await` the fetch, `await` the `.json()`, and log the `.setup` and `.punchline` properties of the result.

</details>

```javascript
async function getJoke() {
  const response = await fetch("https://official-joke-api.appspot.com/random_joke");
  const joke = await response.json();

  console.log(joke.setup);
  console.log(joke.punchline);
}

```
The bare minimum to extract data from a public API.

### Level 2: Real-World
**Task:** Create a robust fetcher. Write `async function fetchCat()` hitting `https://http.cat/404` (this is a URL that returns an image, not JSON, but we will use it to force a 404 status).
1. Use `try/catch`.
2. `await fetch()`.
3. Check `if (!response.ok)`. If not OK, throw a new Error with the `response.status` code (e.g., "Error: 404").
4. Catch the error and log it.
<details>
<summary>Hint</summary>
`if (!response.ok) throw new Error("Status: " + response.status);`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
async function fetchCat() {
  try {
    const response = await fetch("https://http.cat/404");

    if (!response.ok) {
      throw new Error(`HTTP Error Status: ${response.status}`);
    }

    // We won't reach here
    const data = await response.json();
  } catch (error) {
    console.error(error.message); // HTTP Error Status: 404
  }
}
// fetchCat();
```
This is the only safe way to use `fetch` in production.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Fetch, Map, and DOM render!
(Imagine you are writing a script for an HTML page with `<ul id="user-list"></ul>`).
1. Write an async function that fetches `https://jsonplaceholder.typicode.com/users`.
2. Validate `response.ok`. Parse the JSON.
3. The data is an Array of Objects. Use `.map()` to transform it into an array of DOM `<li>` elements, where the text is the user's `.name`.
4. Use a `for...of` loop to append them to the `#user-list` element.
<details>
<summary>Hint</summary>
`const users = await res.json(); const nodes = users.map(...)`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
async function renderUsers() {
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/users");
    if (!res.ok) throw new Error("Network issue");

    const usersArray = await res.json();

    // Select the DOM container
    // const list = document.querySelector("#user-list");

    // Transform Array of Objects -> Array of DOM Nodes
    const liElements = usersArray.map(user => {
      const li = document.createElement("li");
      li.textContent = user.name;
      return li;
    });

    // Append to DOM
    /*
    for (const li of liElements) {
      list.appendChild(li);
    }
    */
    console.log(`Created ${liElements.length} DOM nodes ready for append!`);

  } catch (err) {
    console.error("UI Error:", err);
  }
}

// renderUsers();
```
This is a complete, real-world Frontend application flow: Fetch data over the network, validate it, parse it, transform it immutably, and safely render it to the DOM.

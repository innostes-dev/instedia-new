# 6.1 ES6 Modules: The End of Spaghetti Code

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Imagine an E-Commerce site with 10,000 lines of JavaScript in a single `app.js` file. Variables conflict (`let cart = []` is declared twice), scrolling to find a bug takes hours, and multiple developers trying to edit the same file causes massive Git merge conflicts.

### 2. Plain English Metaphor (The What)
- A **Module** is a **Legos bag**. Instead of dumping 5,000 mixed Lego pieces on the floor, you organize them: Bag 1 (Wheels), Bag 2 (Windows).
- `export` is putting a piece on the **store shelf**. You make it available for others to take.
- `import` is **buying a piece** from the shelf to use in your current file.

### 3. Complete Runnable Code
```javascript
// Example: Modular E-Commerce App Architecture

// ---------------------------------------------------------
// FILE 1: utils/math.js (The Library)
// ---------------------------------------------------------

// Named Export: You can export as many things as you want
export const calculateTax = (amount) => amount * 0.08;
export const addDiscount = (amount, discount) => amount - discount;

// Default Export: The "main" thing this file provides (Only ONE per file)
export default function formatCurrency(amount) {
  return `$${amount.toFixed(2)}`;
}


// ---------------------------------------------------------
// FILE 2: cart.js (The Consumer)
// ---------------------------------------------------------

// Import the Default export (can name it whatever we want)
import formatter from './utils/math.js';

// Import Named exports (MUST use exact names in {})
import { calculateTax, addDiscount } from './utils/math.js';

const itemPrice = 100;
const afterDiscount = addDiscount(itemPrice, 20);
const finalTax = calculateTax(afterDiscount);

const total = afterDiscount + finalTax;
console.log(`Final Cart Total: ${formatter(total)}`);
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Named Export**
By placing `export` in front of `const calculateTax`, we make it public. Anything without `export` is strictly private to `math.js`.
**Step 2: The Default Export**
`export default` is used for the primary feature of a file. In React, this is usually a Component.
**Step 3: The Consumer Imports**
In `cart.js`, we use `import {}` to pull specific named functions. We use `import name` (no braces) to pull the default export.
**Step 4: Module Isolation**
If `math.js` had a `const secretRate = 0.5;` without an `export`, `cart.js` could NEVER see it. Modules create perfect, private scopes automatically.

### 5. ASCII Data Flow
```text
[ math.js ]
  |-- (Named) --> calculateTax --+
  |-- (Named) --> addDiscount ---|
  |-- (Default)-> formatCurrency |
                                 v
                            [ cart.js ]
                                 |
                        Runs calculation!
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using HTML `<script src="app.js">` without `type="module"`. Browsers will throw a "SyntaxError: Cannot use import statement outside a module".
**Pro Tip:** Avoid Default Exports when building utilities or helper libraries. Stick exclusively to Named Exports. It forces you to use the exact correct name when importing, making refactoring across hundreds of files much safer.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Imagine a file `auth.js`. Write the code to export a `const API_KEY = "123"` as a named export, and a `function login()` as the default export.
<details>
<summary>Hint</summary>
`export const ...` and `export default function...`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
// auth.js
export const API_KEY = "123";

export default function login() {
  console.log("Logging in...");
}
```
This sets up the module for consumption.
</details>

### Level 2: Real-World
**Task:** Imagine a file `main.js`. Write the `import` statements to get the `login` function and the `API_KEY` from `./auth.js`.
<details>
<summary>Hint</summary>
Import the default outside the braces, and the named inside the braces.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
// main.js
import login, { API_KEY } from './auth.js';

console.log(API_KEY);
login();
```
You can import default and named exports on the same line!
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Module pattern with Data Transformation.
File 1 (`users.js`): Export an array `const rawUsers = ["alice", "bob"]` (named). Export a default function `capitalize(str)`.
File 2 (`app.js`): Import both. Use `.map()` on `rawUsers`, passing the default `capitalize` function to transform the array. Log the new array.
<details>
<summary>Hint</summary>
`import capitalize, { rawUsers } from './users.js'`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
// --- users.js ---
export const rawUsers = ["alice", "bob"];
export default function capitalize(str) {
  return str[0].toUpperCase() + str.slice(1);
}

// --- app.js ---
import capitalize, { rawUsers } from './users.js';

const formattedUsers = rawUsers.map(user => capitalize(user));
console.log(formattedUsers); // ["Alice", "Bob"]
```
This is the essence of React/Vue components. A module provides data and logic, and the main app consumes and renders it.
</details>

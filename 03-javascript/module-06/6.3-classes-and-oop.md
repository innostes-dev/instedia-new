# 6.3 Classes and Object-Oriented Programming (OOP)

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
In 6.2, we used a function to create an object with private state. But what if we need to create 10,000 `Enemy` objects in a game? If every object carries its own unique copy of the `attack()` function, it destroys the browser's memory. We need a blueprint that shares the functions, but keeps the data separate.

### 2. Plain English Metaphor (The What)
A **Class** is a **Cookie Cutter**.
The `class` itself isn't a cookie; it's the blueprint.
- `new` is pressing the cookie cutter into dough to create a specific `Instance` (a cookie).
- `constructor()` is the **sprinkles** you add the moment the cookie is created.
- Modern JS `#` fields are the **secret filling** (private state).

### 3. Complete Runnable Code
```javascript
// Example: Role-Based User Permission System

// 1. The Blueprint
class User {
  // Private fields must be declared at the top with a '#'
  #password;

  // 2. The Setup Phase
  // Runs automatically when 'new User()' is called
  constructor(username, role, password) {
    this.username = username; // Public property
    this.role = role;         // Public property
    this.#password = password; // Private property
  }

  // 3. Shared Methods
  // Every User shares this function in memory!
  authenticate(attempt) {
    return attempt === this.#password;
  }

  getProfile() {
    return `[${this.role.toUpperCase()}] ${this.username}`;
  }
}

// 4. Inheritance (Extending the Blueprint)
class Admin extends User {
  constructor(username, password) {
    // 'super' calls the parent (User) constructor!
    super(username, "admin", password);
  }

  deleteServer() {
    console.log(`${this.username} deleted the database!`);
  }
}

// Usage
const standardUser = new User("Alice", "guest", "123");
console.log(standardUser.getProfile()); // [GUEST] Alice
console.log("Login OK?", standardUser.authenticate("123")); // true

const boss = new Admin("Bob", "godmode");
console.log(boss.getProfile()); // [ADMIN] Bob
boss.deleteServer(); // Inherits User methods AND has its own!

// console.log(standardUser.#password); // ERROR: Private field!
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Blueprint and `this`**
`class` creates the template. Inside the `constructor`, `this` refers to the *specific instance* being created. `this.username = "Alice"` attaches data directly to the new object.
**Step 2: Private Fields (`#`)**
ES2022 introduced `#`. By prefixing a variable with `#`, it behaves exactly like the Closure privacy in 6.2, but with much cleaner syntax.
**Step 3: Methods**
Functions like `getProfile()` are placed outside the constructor. This attaches them to the Class *Prototype*, meaning 10,000 Users share the exact same function in memory, drastically improving performance.
**Step 4: Inheritance (`extends`)**
`class Admin extends User` copies everything from User. `super()` is mandatory—it passes data up to the parent `User` constructor before the `Admin` does its own setup.

### 5. ASCII Data Flow
```text
class User (Blueprint)
       |
new User("Alice", "123")
       |
(Constructor Runs) ---> this.username = "Alice", this.#password = "123"
       |
[ Instance: { username: "Alice", authenticate() } ]
       |
instance.authenticate("123") -> reads this.#password -> returns TRUE
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Forgetting `this.`. If you write `username = "Bob"` instead of `this.username = "Bob"` inside a method, JS looks for a global variable named `username`, crashes, and burns.
**Pro Tip:** Prefer Composition (using functions/modules) over deep Inheritance trees. If you have `class Warrior extends Human extends Mammal extends Animal`, it becomes a nightmare to maintain. Use `extends` sparingly.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Create a `class Product`. The constructor should take `name` and `price` and assign them to `this`. Add a method `display()` that returns the string `"${name} costs $${price}"`. Create an instance and log the display.
<details>
<summary>Hint</summary>
`class Product { constructor(name, price) { this.name = name... } ... }`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
class Product {
  constructor(name, price) {
    this.name = name;
    this.price = price;
  }

  display() {
    return `${this.name} costs $${this.price}`;
  }
}

const apple = new Product("Apple", 2);
console.log(apple.display()); // Apple costs $2
```
Basic object initialization and method calling.
</details>

### Level 2: Real-World
**Task:** Create a `class BankAccount` with a private `#balance`.
Constructor takes `initialBalance`.
Add a `deposit(amt)` method.
Add a `getter` method (e.g. `get balance() { ... }`) that returns the private balance.
Test depositing and retrieving the balance.
<details>
<summary>Hint</summary>
Declare `#balance;` at the top of the class. Use `this.#balance` everywhere inside.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
class BankAccount {
  #balance; // Must be declared up here!

  constructor(initial) {
    this.#balance = initial;
  }

  deposit(amt) {
    this.#balance += amt;
  }

  // A 'getter' allows you to read it like a property: account.balance
  get balance() {
    return this.#balance;
  }
}

const acct = new BankAccount(100);
acct.deposit(50);
console.log(acct.balance); // 150
```
This is the modern ES6+ equivalent of the Closure pattern from 6.2.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Classes, Arrays, and DOM Simulation.
Imagine a UI with `<div id="cart-total"></div>`.
1. Create a `class Cart`. It has a private `#items` array (initialized empty).
2. Method: `addItem(priceNumber)`. Pushes the price into `#items`.
3. Method: `getTotal()`. Uses `.reduce()` on `#items` to calculate the sum!
4. Method: `renderTotal(domElement)`. Safely sets the `textContent` of the provided DOM element to `Total: $[total]`.
Create a `new Cart()`, add 10 and 20, and render it.
<details>
<summary>Hint</summary>
Inside `getTotal`, `this.#items.reduce(...)`.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
class Cart {
  #items = []; // Can initialize right on the declaration!

  addItem(price) {
    this.#items.push(price);
  }

  getTotal() {
    return this.#items.reduce((acc, curr) => acc + curr, 0);
  }

  renderTotal(element) {
    const total = this.getTotal();
    if (element) {
      element.textContent = `Total: $${total}`;
    }
    console.log(`Rendered: Total: $${total}`);
  }
}

const myCart = new Cart();
myCart.addItem(10);
myCart.addItem(20);

// Mocking the DOM element
const fakeDiv = document.createElement("div");
myCart.renderTotal(fakeDiv);
// fakeDiv.textContent is now "Total: $30"
```
This encapsulates Data (Array), Logic (Reduce), and UI Control (DOM) perfectly inside a single highly-testable Class blueprint!
</details>

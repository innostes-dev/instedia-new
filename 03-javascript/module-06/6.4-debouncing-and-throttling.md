# 6.4 Debouncing and Throttling (The Performance Protectors)

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
A user is typing into an Auto-Complete search bar. They type "J-A-V-A" quickly. Your script has an `input` event listener that runs a `fetch()` search for every keystroke. You just hit your database 4 times in 0.5 seconds. If 1,000 users do this, your server crashes instantly. We need to delay the function until the user *stops* typing.

### 2. Plain English Metaphor (The What)
- **Debouncing** is an **elevator door**. Every time someone runs up and presses the button, the elevator door's 5-second timer resets. The elevator ONLY leaves when 5 seconds pass with NO ONE pressing the button. (Wait until the user finishes typing).
- **Throttling** is a **water fountain valve**. You can hold the button down all day, but it will only release exactly 1 cup of water every 3 seconds. (Used for scrolling/resizing events so the browser doesn't freeze).

### 3. Complete Runnable Code
```javascript
// Example: Google Auto-Complete Search Bar Debouncer

// The Debounce Higher-Order Function (Returns a closure!)
function debounce(callbackFunc, delayMs) {
  // Private state to hold the elevator timer
  let timerId;

  return function (...args) {
    // If the button is pressed again, clear the old timer!
    clearTimeout(timerId);

    // Set a new timer
    timerId = setTimeout(() => {
      // Run the actual search function
      callbackFunc(...args);
    }, delayMs);
  };
}

// 1. The Expensive Function
function performSearch(query) {
  console.log(`Fetching database for: "${query}"...`);
}

// 2. The Protected Function
// We wrap our search in the debounce function, setting a 500ms delay.
const debouncedSearch = debounce(performSearch, 500);

// 3. Simulating rapid user typing
console.log("User typing: j");
debouncedSearch("j");

console.log("User typing: ja");
debouncedSearch("ja");

console.log("User typing: jav");
debouncedSearch("jav");

// Result:
// The first two fetches are cancelled.
// ONLY "Fetching database for: jav" will log, half a second later!
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Higher-Order Function**
`debounce` takes a function and a time. It returns a *new* function. This relies entirely on the **Closures** concept from 6.2 to remember the `timerId`.
**Step 2: Clearing the Timeout**
Every time the returned function is called (every keystroke), `clearTimeout(timerId)` destroys the previous countdown.
**Step 3: Setting the Timeout**
It then immediately sets a new `setTimeout`. If the user stops typing for 500ms, the timeout survives, executes, and calls the original `callbackFunc`.
**Step 4: The Rest Operator (`...args`)**
We use `...args` so the debouncer can safely pass any event objects or strings (like `"jav"`) directly down to the original function.

### 5. ASCII Data Flow
```text
[ User Types 'j' ] -> debouncedSearch('j') -> Sets 500ms Timer (A)
       |
( 100ms later )
       |
[ User Types 'a' ] -> debouncedSearch('a') -> CLEARS Timer (A)!
                                           -> Sets 500ms Timer (B)
       |
( 500ms passes with no typing... )
       |
Timer (B) Completes! ---> performSearch('a') runs!
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Putting the `let timerId` *inside* the returned function. If you do that, every keystroke creates a brand new, separate timer variable, and nothing gets cleared. Your app will execute all 4 fetches simultaneously after the delay.
**Pro Tip:** While it's crucial to understand how to write these from scratch for interviews, in production environments (like React), engineers almost universally use the battle-tested versions from libraries like `lodash` (`_.debounce(fn, 500)`).

function debounce(func, delay) {
  let timerId;

### Level 2: Real-World
**Task:** Build a Throttle function from scratch.
Unlike Debounce (elevator), Throttle (water valve) runs immediately, but then *locks* the function for a set time.
1. `function throttle(func, limitMs)`.
2. Private state: `let inThrottle = false;`
3. Return a function. If `inThrottle` is true, do nothing (return).
4. If false, run `func(...)`, set `inThrottle = true`, and start a `setTimeout` that sets `inThrottle = false` after `limitMs`.
<details>
<summary>Hint</summary>
`if (!inThrottle) { func(); inThrottle = true; setTimeout(() => inThrottle = false, limitMs); }`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
function throttle(func, limitMs) {
  let inThrottle = false;

  return function (...args) {
    if (!inThrottle) {
      func(...args); // Run immediately
      inThrottle = true; // Lock the valve

      // Unlock the valve after limitMs
      setTimeout(() => {
        inThrottle = false;
      }, limitMs);
    }
  };
}

const throttledScroll = throttle(() => console.log("Scroll event processed!"), 2000);

throttledScroll(); // Runs instantly
throttledScroll(); // Blocked!
// ... wait 2.1 seconds ...
// throttledScroll(); // Will run again!
```
Used for `window.addEventListener('scroll', throttledScroll)`.
</details>

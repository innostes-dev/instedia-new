# 6.2 Closures and Encapsulation

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
You need to track a user's bank balance. If you do `let balance = 100` globally, any other script, browser extension, or malicious code can just write `balance = 10000000`. You need a way to store data that is *completely inaccessible* to the outside world, but can still be modified securely through specific rules.

### 2. Plain English Metaphor (The What)
A **Closure** is a **backpack**.
When a function is created, it gets a backpack. Any variables that were near it when it was created get stuffed into that backpack. When you take that function and pass it somewhere else, it *takes the backpack with it*. The variables inside the backpack are invisible to everyone else, creating true **Encapsulation** (privacy).

### 3. Complete Runnable Code
```javascript
// Example: Secure Bank Account State Manager

function createBankAccount(initialDeposit) {
  // 1. Private State
  // This variable is trapped inside this function.
  // The outside world CANNOT read or write to it directly.
  let _balance = initialDeposit;

  // 2. The Closure (The Backpack)
  // We return an object containing functions.
  // These functions remember '_balance' because it's in their backpack.
  return {
    deposit: function(amount) {
      if (amount > 0) {
        _balance += amount;
        console.log(`Deposited ${amount}.`);
      }
    },
    withdraw: function(amount) {
      if (amount <= _balance) {
        _balance -= amount;
        console.log(`Withdrew ${amount}.`);
      } else {
        console.log("Insufficient funds!");
      }
    },
    // The ONLY way to see the balance is to ask this specific function.
    getBalance: function() {
      return _balance;
    }
  };
}

// 3. Usage
const myAccount = createBankAccount(500);

myAccount.deposit(200);
myAccount.withdraw(100);
console.log(`Final Balance: $${myAccount.getBalance()}`); // 600

// Proving the privacy (Encapsulation):
console.log(myAccount._balance); // undefined! Hacking failed.
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: The Lexical Scope**
`_balance` is created inside `createBankAccount`. By default, it should be deleted from memory when the function finishes running.
**Step 2: Returning the Functions**
Instead of returning a number, we return an object full of functions. Because these functions *reference* `_balance`, JavaScript realizes it cannot delete `_balance`. It locks `_balance` into a Closure (backpack).
**Step 3: State Mutation via API**
We can no longer do `myAccount._balance = 0`. We are forced to use `.withdraw()`. The closure acts as a bouncer, enforcing our business logic and protecting the state.

### 5. ASCII Data Flow
```text
createBankAccount(500)
       |
Creates `_balance = 500`
       |
Returns { deposit(), withdraw(), getBalance() }
       |
( _balance is locked in the Closure Backpack )
       |
myAccount.deposit(200) ---> Reaches into Backpack -> _balance = 700
       |
myAccount._balance -------> Undefined (Outer scope cannot pierce the backpack)
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Thinking that `let` and `const` inside blocks give you full privacy. They do, but once the block ends, the data dies. Closures are how you keep private data *alive* and usable over time.
**Pro Tip:** This exact pattern (a function returning state and mutator functions) is how React `useState()` works under the hood! `const [count, setCount] = useState(0)` is just a closure.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Create a function `createCounter()`. Inside, define `let count = 0`. Return a function that adds 1 to `count` and returns the new `count`. Call `createCounter()` and store it in `const myCounter`. Call `myCounter()` twice and log the results.
<details>
<summary>Hint</summary>
`return function() { count++; return count; }`
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
function createCounter() {
  let count = 0;

  return function() {
    count = count + 1;
    return count;
  }
}

const myCounter = createCounter();
console.log(myCounter()); // 1
console.log(myCounter()); // 2
```
The inner function remembers `count` across multiple executions!
</details>

### Level 2: Real-World
**Task:** Create a `createPasswordManager(initialPassword)` function.
It should return an object with two methods:
1. `checkPassword(guess)`: returns true if it matches the hidden password, false otherwise.
2. `resetPassword(oldPw, newPw)`: changes the password only if `oldPw` is correct.
<details>
<summary>Hint</summary>
Store `let _password = initialPassword` privately. Reference it inside the returned object methods.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
function createPasswordManager(initial) {
  let _password = initial;

  return {
    checkPassword: function(guess) {
      return guess === _password;
    },
    resetPassword: function(oldPw, newPw) {
      if (oldPw === _password) {
        _password = newPw;
        return true;
      }
      return false;
    }
  }
}

const vault = createPasswordManager("secret123");
console.log(vault.checkPassword("wrong")); // false
vault.resetPassword("secret123", "newPass");
console.log(vault.checkPassword("newPass")); // true
```
Perfect encapsulation. The password string is completely hidden from the global scope.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Combine Closures with Array Methods and DOM Events.
Imagine HTML: `<button id="like-btn">Like</button> <span id="like-count">0</span>`.
Write a function `setupLikeButton(btnId, countId)`.
1. Inside, define a private `let likes = 0`.
2. Select the button and the span using `querySelector`.
3. Add a click event listener to the button.
4. When clicked, increment `likes`, and update the `.textContent` of the span.
Because `likes` is trapped in the event listener closure, it is perfectly safe from mutation!
<details>
<summary>Hint</summary>
The event listener callback acts as the inner function that remembers the `likes` variable.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
// MOCK DOM (for testing in console)
// document.body.innerHTML = `<button id="like-btn">Like</button> <span id="like-count">0</span>`;

function setupLikeButton(btnId, countId) {
  // 1. Private State
  let likes = 0;

  // 2. Selectors
  const btn = document.querySelector(btnId);
  const display = document.querySelector(countId);

  // 3. Closure Event Listener
  btn?.addEventListener("click", () => {
    // This callback forms a closure around 'likes'
    likes++;
    display.textContent = likes;
    console.log(`Liked! Total: ${likes}`);
  });
}

// setupLikeButton("#like-btn", "#like-count");
```
You have built an encapsulated, reusable UI component without needing a framework! You could call this function 10 times for 10 different buttons, and they would all maintain their own private `likes` state perfectly.
</details>

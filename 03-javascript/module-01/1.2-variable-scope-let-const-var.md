# 1.2 Variable Scope: let, const, and the Ghost of var

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Imagine writing a massive 500-line script for a shopping cart. Somewhere at the top, you define `price = 10`. Later, inside a discount calculation, you accidentally write `price = 5`. Suddenly, every item in the store is $5, and you bankrupt the company. We need strict rules about *where* a variable lives and *if* it can be changed.

### 2. Plain English Metaphor (The What)
- `const` is a **locked safe**. Once you put something in, you can't replace it with something else.
- `let` is a **whiteboard**. You can write a value, erase it, and write a new one.
- `var` is a **leaky bucket**. It bleeds out into places it shouldn't be, causing unexpected messes. (Modern engineers never use it).
Scope is the "room" the variable lives in. You can't see the whiteboard if it's in another closed room.

### 3. Complete Runnable Code
```javascript
// Example: Shopping Cart Item Price Calculator
const taxRate = 0.08; // Locked. Cannot change.
let cartTotal = 0;    // Whiteboard. We will update this.

{
  // Block Scope: Imagine this is a separate checkout module
  const itemPrice = 50;
  let discount = 10;

  cartTotal = itemPrice - discount;
  console.log("Item total before tax: " + cartTotal);
}

// console.log(itemPrice); // ERROR: itemPrice is not defined here!

cartTotal = cartTotal + (cartTotal * taxRate);
console.log("Grand Total: " + cartTotal);
```

### 4. Progressive Step-by-Step Breakdown
**Step 1: Global Setup**
We use `const` for `taxRate` because tax rates shouldn't be accidentally altered during a calculation. We use `let` for `cartTotal` because the total grows as items are added.
**Step 2: Block Scope Boundaries**
The curly braces `{ }` create a "Block". `itemPrice` and `discount` are born inside this block and die when the block ends. This prevents them from conflicting with other items.
**Step 3: Calculating Final State**
Because `cartTotal` was defined outside the block, we can access and update it globally. We apply the tax rate to get the final grand total.

### 5. ASCII Data Flow
```text
[Global Scope]
 ├── const taxRate = 0.08
 ├── let cartTotal = 0
 │
 ├── [Block Scope { }]
 │    ├── const itemPrice = 50
 │    ├── let discount = 10
 │    └── UPDATE Global cartTotal -> 40
 │
 └── UPDATE Global cartTotal -> 40 + (40 * 0.08) = 43.2
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `var` because an old tutorial said so. `var` ignores block scope (`{}`) and hoists variables, leading to catastrophic bugs where variables bleed into other logic. Also, falling into the Temporal Dead Zone (TDZ) by trying to access a `let` variable before line execution.
**Pro Tip:** Default to `const`. Only change it to `let` if you explicitly know the value needs to be reassigned. This reduces bugs drastically by locking state down.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Create a block `{}`. Inside the block, define `const secretPassword = "123"`. Try to `console.log(secretPassword)` *outside* the block to intentionally trigger a ReferenceError.
<details>
<summary>Hint</summary>
Variables defined with `let` or `const` cannot be accessed outside the curly braces they were created in.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
{
  const secretPassword = "123";
}
// This will throw a ReferenceError: secretPassword is not defined
console.log(secretPassword);
```
This proves block scoping works, keeping data isolated!
</details>

### Level 2: Real-World
**Task:** Write a script to calculate an employee's weekly pay. Base pay is $1000. If they worked overtime (simulate with a block `{}`), define a local `bonus` of $200 and update a global `totalPay`. Log the final pay.
<details>
<summary>Hint</summary>
Define `totalPay` globally with `let` before the block.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
let totalPay = 1000;

{
  // Overtime calculation block
  const bonus = 200;
  totalPay = totalPay + bonus;
}

console.log("Total Pay: $" + totalPay); // $1200
```
`totalPay` can be modified inside the block because it's in a higher (outer) scope. `bonus` remains safely contained.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Setup a banking scenario. Global `balance` is 500. Use three separate blocks to simulate three days.
Day 1: Deposit $100.
Day 2: Withdraw $50. Try to declare a `const dailyLimit = 200`.
Day 3: Try to declare another `const dailyLimit = 300` in this *new* block. Update balance by adding $50.
Log the final balance.
<details>
<summary>Hint</summary>
You can reuse variable names like `dailyLimit` as long as they are in completely separate blocks.
</details>
<details>
<summary>Solution Walkthrough</summary>

```javascript
let balance = 500;
console.log("Start: " + balance);

{ // Day 1
  const deposit = 100;
  balance = balance + deposit;
}

{ // Day 2
  const dailyLimit = 200;
  const withdrawal = 50;
  balance = balance - withdrawal;
}

{ // Day 3
  // This is allowed because it's a completely different scope block!
  const dailyLimit = 300;
  const deposit = 50;
  balance = balance + deposit;
}

console.log("End Balance: " + balance); // 600
```
This shows the true power of block scoping: you don't have to invent unique variable names for every single calculation across a massive file.
</details>

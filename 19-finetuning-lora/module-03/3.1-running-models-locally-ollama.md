# Module 03: High-Throughput Production Serving (Ollama & vLLM)
## 3.1 Running Models Locally with Ollama

### Phase A: The Core Concept

#### 1. Real-World Pain Point (The Why)
You successfully trained a QLoRA adapter for Llama-3 and merged it with the base weights. Now you want your development team to test it on their MacBooks. If you hand them a folder with PyTorch `.bin` or `.safetensors` files, they will have to install Python, PyTorch, Transformers, handle CUDA or Metal (MPS) dependencies, and write a custom inference script just to chat with the model. It will take them a whole day just to set up the environment, and it will probably crash.

#### 2. Plain English Metaphor (The What)
Imagine you built a highly-tuned race car engine (your fine-tuned `.safetensors` model).
**Standard PyTorch Inference:** This is like handing someone the engine block and telling them to build the car chassis, connect the fuel lines, and wire the steering column themselves before they can drive it.
**Ollama (and GGUF):** This is like dropping your engine into a pre-built, consumer-friendly sports car with an automatic transmission. They just turn the key (type `ollama run model_name`) and drive. Ollama handles all the complex memory management, GPU/CPU offloading, and quantization under the hood.

#### 3. Complete Runnable Code
Here is how you define a custom model using an Ollama `Modelfile` and simulate the CLI commands to run it.

```bash
# 1. The Modelfile
# Think of this like a Dockerfile for LLMs.
# It takes a base model, injects custom prompts, and sets parameters.

cat << 'EOF' > Modelfile
# Pull a pre-quantized base model from the Ollama registry
FROM llama3:8b

# Set the temperature to 0 for highly deterministic, factual output (good for coding/data)
PARAMETER temperature 0.0

# Set a custom system prompt that is baked into the model
SYSTEM """
You are a senior database engineer.
You only respond with valid PostgreSQL queries.
Do not include any pleasantries or markdown wrapping.
If a query is impossible, output: ERROR: INVALID_SCHEMA
"""
EOF

print("Modelfile created!")

# 2. Simulate Ollama CLI Commands
print("\n--- To build and run this locally, you would type: ---")
print("1. Build the model:   ollama create db_engineer -f ./Modelfile")
print("2. Run the model:     ollama run db_engineer")
print("3. Query the API:     curl http://localhost:11434/api/generate -d '{\"model\": \"db_engineer\", \"prompt\": \"Get all users who signed up today.\"}'")
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: The Base Model (`FROM`)**
Ollama pulls models in a highly optimized format called GGUF (GPT-Generated Unified Format). GGUF files contain the model weights AND the tokenizer AND the model architecture in a single file, written in C++ (via `llama.cpp`). This makes them blazing fast and independent of Python.

**Step 2: Parameters (`PARAMETER`)**
You can bake default parameters into your model. Setting `temperature 0` ensures the model doesn't try to be "creative" when you want strict technical outputs.

**Step 3: The System Prompt (`SYSTEM`)**
By baking the system prompt into the `Modelfile`, users don't have to prepend instructions to every message. The model fundamentally boots up believing it is a database engineer.

#### 5. ASCII Data Flow

```text
[ Developer's MacBook (No Python Required) ]
       |
       v
`ollama run db_engineer`
       |
       v (Ollama Engine C++ / llama.cpp)
+---------------------------------------+
| Loads GGUF File into RAM              |
| Offloads layers to Apple Metal GPU    |
| Applies baked-in System Prompt        |
+---------------------------------------+
       |
       v
"SELECT * FROM users WHERE created_at = CURRENT_DATE;"
```

#### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Trying to use Ollama for training or fine-tuning. Ollama is strictly an **inference** (running) engine. You train in Python (PyTorch/Transformers) -> Export to GGUF -> Run in Ollama.
*   **Pro Tip:** If you have an older machine, Ollama will automatically split the model between your GPU VRAM and your standard system RAM (CPU offloading). It will be slower than pure GPU, but it will not crash with an Out of Memory error like PyTorch does!

#### Level 2: Real-World
**Challenge:** Ollama exposes a REST API by default. Write a Python script using the `requests` library to send a prompt to a local Ollama server running a model named `customer_support`.
<details>
<summary>Hint</summary>
Send a POST request to `http://localhost:11434/api/generate`. The JSON body needs `"model"` and `"prompt"`. Set `"stream": False` to get the full response at once.
</details>
<details>
<summary>Solution Walkthrough</summary>
```python
import requests
import json

def query_ollama(prompt, model_name="customer_support"):
    url = "http://localhost:11434/api/generate"
    payload = {
        "model": model_name,
        "prompt": prompt,
        "stream": False # Don't stream tokens back, wait for the full string
    }

    try:
        response = requests.post(url, json=payload)
        response.raise_for_status()
        result = response.json()
        return result.get("response", "No response found")
    except requests.exceptions.ConnectionError:
        return "Error: Ensure Ollama is running (ollama serve)"

# Example usage (will fail if Ollama isn't running):
# print(query_ollama("How do I return an item?"))
```
</details>

PARAMETER num_ctx 8192

# 3. (Optional) Set the format to enforce JSON output if your fine-tune was for data extraction

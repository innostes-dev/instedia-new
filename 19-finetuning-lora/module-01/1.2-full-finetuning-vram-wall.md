# Module 01: The Prompting Limit (Why We Need Fine-Tuning)
## 1.2 The Full Fine-Tuning VRAM Wall

### Phase A: The Core Concept

#### 1. Real-World Pain Point (The Why)
You've decided to fine-tune Llama-3 8B. You rent a beefy server with a 24GB RTX 4090 or RTX 3090, load up PyTorch, and hit run. Immediately, your terminal throws: `CUDA Out of Memory (OOM)`. Llama-3 8B is 8 billion parameters. Why can't a 24GB card train an 8GB model?
Because in full fine-tuning, the model weights are just the tip of the iceberg. You need VRAM for gradients, optimizer states (Adam stores running averages for *every* parameter), and activations. You've hit the VRAM wall.

#### 2. Plain English Metaphor (The What)
Imagine you are renovating a small house (the 8B model).
**Inference (Just running the model):** This is like walking into the house to look around. You just need space for yourself (the VRAM for weights).
**Full Fine-Tuning:** This is like tearing down walls and replacing plumbing. You need space for the house, plus scaffolding, a dumpster, toolboxes, blueprints, and a crew of 10 workers (gradients, optimizer states, activations). A plot of land that barely fits the house will not fit the construction crew.

#### 3. Complete Runnable Code
Here is a VRAM calculator that shows exactly why full fine-tuning crashes on consumer hardware.

```python
def calculate_training_vram(model_params_billions, precision_bytes=2):
    """Calculates VRAM requirements for full fine-tuning using AdamW."""

    # 1. Model Weights
    weights_vram = model_params_billions * precision_bytes

    # 2. Gradients (Same size as weights in full FT)
    gradients_vram = model_params_billions * precision_bytes

    # 3. Optimizer States (Adam needs 2 states per parameter: momentum & variance)
    # Even if training in FP16/BF16, optimizer states are usually kept in FP32 (4 bytes)
    optimizer_vram = (model_params_billions * 4) * 2

    # 4. Activations (Highly dependent on batch size and sequence length, approx 20%)
    base_vram = weights_vram + gradients_vram + optimizer_vram
    activations_vram = base_vram * 0.20

    total_vram_gb = base_vram + activations_vram

    return {
        "Weights (GB)": weights_vram,
        "Gradients (GB)": gradients_vram,
        "Optimizer (GB)": optimizer_vram,
        "Activations (GB)": activations_vram,
        "Total VRAM Required (GB)": total_vram_gb
    }

# Calculate for Llama-3 8B (8 billion params) trained in 16-bit (2 bytes)
llama_8b_vram = calculate_training_vram(8.0, precision_bytes=2)

print("--- VRAM Required for Full Fine-Tuning Llama-3 8B (AdamW) ---")
for key, val in llama_8b_vram.items():
    print(f"{key}: {val:.2f} GB")

print("\nResult: Will it fit on a 24GB RTX 4090/3090?")
print("NO. You need ~134GB of VRAM (Multiple A100s 80GB required).")
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: The Model Weights**
An 8 Billion parameter model in 16-bit precision (FP16 or BF16) takes 2 bytes per parameter. 8B * 2 bytes = 16 GB just to load the model.

**Step 2: The Gradients**
During backpropagation, we calculate a gradient for *every single weight*. That's another 16 GB.

**Step 3: The Optimizer (The Real Killer)**
The Adam optimizer tracks two values (momentum and variance) for *every* parameter, usually in full 32-bit float (4 bytes) to prevent numerical instability. 8B * 4 bytes * 2 = 64 GB. This is the massive hidden cost of training.

#### 5. ASCII Data Flow

```text

+---------------------------------------------------+
| Weights (16 GB)  [================]               |
| Gradients (16 GB)[================]               |
| Optimizer (64 GB)[================================|================] |
| Activations (~38GB)[===================]          |
+---------------------------------------------------+
```

#### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Trying to solve CUDA OOM by just reducing the batch size to 1. In full fine-tuning, the optimizer states (64GB for an 8B model) are independent of batch size. It will still crash.
*   **Pro Tip:** If you absolutely *must* full fine-tune on limited hardware, look into Fully Sharded Data Parallel (FSDP) or DeepSpeed Zero-3 to shard the optimizer states across multiple smaller GPUs. However, the modern solution is to *not* full fine-tune at all, and use PEFT/LoRA (covered in the next module).

#### Level 2: Real-World
**Challenge:** If we switch the optimizer from standard AdamW (stores states in FP32 / 4-bytes) to an 8-bit Optimizer (like `bitsandbytes.optim.AdamW8bit`), the optimizer states drop to 1 byte per state instead of 4 bytes. Modify the VRAM calculator to include an `optimizer_bytes` parameter and calculate the new total VRAM for Llama-3 8B.
<details>
<summary>Hint</summary>
Change the optimizer formula to: `optimizer_vram = (model_params_billions * optimizer_bytes) * 2`. Pass `optimizer_bytes=1` when calling it.
</details>
<details>
<summary>Solution Walkthrough</summary>
```python
def calculate_vram_with_8bit_optim(model_params_billions, precision_bytes=2, optimizer_bytes=4):
    weights_vram = model_params_billions * precision_bytes
    gradients_vram = model_params_billions * precision_bytes
    # 8-bit Adam uses 1 byte per state instead of 4
    optimizer_vram = (model_params_billions * optimizer_bytes) * 2
    base_vram = weights_vram + gradients_vram + optimizer_vram
    activations_vram = base_vram * 0.20
    return base_vram + activations_vram

total = calculate_vram_with_8bit_optim(8.0, precision_bytes=2, optimizer_bytes=1)
print(f"Total VRAM with 8-bit Adam: {total:.2f} GB")
# Output: ~57.6 GB. A massive reduction, but still doesn't fit on a single 24GB card.
```
</details>

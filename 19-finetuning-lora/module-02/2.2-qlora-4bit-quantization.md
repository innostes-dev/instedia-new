# Module 02: Parameter-Efficient Tuning (LoRA & QLoRA)
## 2.2 QLoRA: 4-bit Quantization

### Phase A: The Core Concept

#### 1. Real-World Pain Point (The Why)
In Module 2.1, we used LoRA to reduce the gradients and optimizer states, allowing us to train an 8B model on a 24GB GPU. But what if you want to train a 70B model? Even with LoRA, loading a 70B model in 16-bit takes 140GB of VRAM just for the base weights! Or what if you only have a 12GB gaming laptop and want to train an 8B model? LoRA alone isn't enough because the *base model weights* are too heavy.

#### 2. Plain English Metaphor (The What)
Imagine you have a high-resolution, 4K digital photograph (16-bit precision weights) that is 100MB. It won't fit on your tiny USB drive.
**Quantization** is like compressing that photo into a high-quality JPEG. It might drop down to 25MB (4-bit precision). If you zoom all the way in, you might lose a tiny bit of detail, but for general viewing, it looks identical.
**QLoRA (Quantized LoRA)** is compressing the massive textbook (Base Model) into a cheap paperback (4-bit), and then putting the high-quality transparent sheet (16-bit LoRA adapter) on top.

#### 3. Complete Runnable Code
Here is how you load a model in 4-bit using `bitsandbytes` to prepare it for QLoRA training.

```python
import torch
from transformers import BitsAndBytesConfig

# 1. Configure the 4-bit Quantization (The Q in QLoRA)
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,                   # Compress to 4-bit
    bnb_4bit_use_double_quant=True,      # Quantize the quantization constants (saves more VRAM)
    bnb_4bit_quant_type="nf4",           # NormalFloat4: Specially designed for LLM weight distributions
    bnb_4bit_compute_dtype=torch.bfloat16 # Keep calculations in 16-bit for accuracy
)

print("Quantization Configuration created!")
print(f"Load in 4-bit: {bnb_config.load_in_4bit}")
print(f"Quant Type: {bnb_config.bnb_4bit_quant_type}")
print(f"Compute Dtype: {bnb_config.bnb_4bit_compute_dtype}")

# In a real environment, you pass this config when loading the model:
# model = AutoModelForCausalLM.from_pretrained(
#     "meta-llama/Meta-Llama-3-8B",
#     quantization_config=bnb_config,
#     device_map="auto"
# )
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: NormalFloat4 (NF4)**
Weights in LLMs usually follow a normal distribution (bell curve). `nf4` is a special 4-bit data type mathematically optimized to hold bell-curve data without losing much information. It is significantly better than standard 4-bit integers.

**Step 2: Compute Dtype (`torch.bfloat16`)**
While the weights are *stored* in 4-bit to save VRAM, when the model actually does math during the forward pass, it temporarily unpacks those 4-bit numbers into 16-bit (`bfloat16`). This prevents math errors from accumulating during training.

**Step 3: Double Quantization**
To compress weights to 4-bit, you need "scaling constants". On a 70B model, just storing these constants can take a few gigabytes! Double quantization means we quantize the scaling constants themselves, squeezing out another 0.5 - 1GB of VRAM savings.

#### 5. ASCII Data Flow

```text
[ VRAM Storage vs Computation ]

Storage:
Base Model Weights (4-bit NF4) ----> Massive VRAM Savings

Computation Time (Forward Pass):
(4-bit NF4) -> Unpack -> (16-bit BF16) + (16-bit LoRA Adapter) = Output
```

#### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Using `load_in_8bit=True` (int8) instead of 4-bit NF4. 4-bit NF4 has been empirically proven to provide nearly identical performance to 8-bit, while using half the VRAM.
*   **Pro Tip:** Always set `bnb_4bit_compute_dtype=torch.bfloat16` if your GPU supports it (Ampere architecture or newer, e.g., RTX 30-series, 40-series, A100). If you have an older card (T4, V100), you must use `torch.float16`, but watch out for gradient spikes.

**Challenge:** Write a python function `estimate_4bit_model_vram(params_billions)` that calculates the VRAM needed just to load a model in 4-bit.
<details>
<summary>Hint</summary>
If 8-bit is 1 byte per parameter, 4-bit is 0.5 bytes per parameter. Multiply params by 0.5.

<details>
<summary>Solution Walkthrough</summary>
```python
def estimate_4bit_model_vram(params_billions):
    # 4 bits = 0.5 bytes
    vram_gb = params_billions * 0.5
    return vram_gb

llama_8b = estimate_4bit_model_vram(8.0)
llama_70b = estimate_4bit_model_vram(70.0)

print(f"Llama 8B 4-bit: {llama_8b} GB")   # 4.0 GB
print(f"Llama 70B 4-bit: {llama_70b} GB") # 35.0 GB
```

```python
def get_quant_config(gpu_architecture):
    gpu_architecture = gpu_architecture.lower()

    if gpu_architecture in ["ampere", "ada", "hopper"]:
        compute_dtype = torch.bfloat16
    else:
        compute_dtype = torch.float16

    config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_use_double_quant=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_dtype=compute_dtype
    )
    return config

config = get_quant_config("ampere")
print(f"Compute dtype for Ampere: {config.bnb_4bit_compute_dtype}")
```

#### Level 3: Boss Level (Cumulative)
**Challenge:** Combine Module 2.1 and 2.2. Write `calculate_qlora_vram(base_params_b, lora_trainable_percent)`.
1. The base model weights are now in 4-bit (0.5 bytes).
2. The LoRA params, gradients, and optimizer states are still the same as in 2.1 (16-bit, 16-bit, and 32-bit respectively).
Calculate the VRAM needed for QLoRA on Llama-3 70B with a 1% LoRA adapter. Will it fit on a single 48GB RTX A6000 or two 24GB RTX 4090s?
<details>
<summary>Hint</summary>
Base weights = 70B * 0.5.
LoRA params = 70B * 0.01 = 0.7B.
Calculate gradients (0.7 * 2) and optimizer (0.7 * 4 * 2) for LoRA. Add activations (10%).
</details>
<details>
<summary>Solution Walkthrough</summary>
```python
def calculate_qlora_vram(base_params_b, lora_trainable_percent):
    # 1. Base Model Weights (4-bit)
    base_vram = base_params_b * 0.5

    lora_params_b = base_params_b * lora_trainable_percent

    # 2. Gradients (Only for LoRA, 16-bit)
    gradients_vram = lora_params_b * 2

    # 3. Optimizer (Only for LoRA, 32-bit Adam)
    optimizer_vram = (lora_params_b * 4) * 2

    # 4. Activations (10% rule of thumb)
    activations = base_vram * 0.10

    total = base_vram + gradients_vram + optimizer_vram + activations
    return total

vram_70b = calculate_qlora_vram(70.0, 0.01)
print(f"Total VRAM for QLoRA on 70B model: {vram_70b:.2f} GB")
# Output: ~45.50 GB.
# YES! A 70B model can be fine-tuned on a single 48GB card,
# or across two 24GB cards using device mapping. This is the magic of QLoRA.
```
</details>

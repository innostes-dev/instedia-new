# Module 02: Parameter-Efficient Tuning (LoRA & QLoRA)
## 2.1 LoRA: Low-Rank Adaptation

### Phase A: The Core Concept

#### 1. Real-World Pain Point (The Why)
In Module 1.2, we saw that full fine-tuning an 8B model requires ~134GB of VRAM, mostly consumed by gradients and optimizer states for all 8 billion parameters. You cannot do this on your local RTX 3090, and renting massive AWS clusters is expensive and complex. You need a way to train the model to act exactly how you want, but without touching all 8 billion parameters. You need a parameter-efficient approach.

#### 2. Plain English Metaphor (The What)
Imagine the base LLM is a massively complex, beautifully published textbook (the frozen weights).
**Full Fine-Tuning** is like re-writing and re-printing the entire textbook just to add a few new chapters. It's expensive and takes forever.
**LoRA (Low-Rank Adaptation)** is like slipping a thin, transparent plastic sheet over the textbook pages. You write your new notes (the "Adapter") on the transparent sheet with a dry-erase marker. When you read the book, you look *through* your notes at the original text. You only had to buy a plastic sheet and a marker (less than 1% of the VRAM), but you completely changed the output of the book!

#### 3. Complete Runnable Code
Here is how you configure a LoRA adapter using the HuggingFace `peft` (Parameter-Efficient Fine-Tuning) library.

```python
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM
import torch

# 1. Load the BASE model (The Textbook)
# We load it in bfloat16 to save memory
model_id = "meta-llama/Meta-Llama-3-8B"
# Note: In a real environment, you'd use a quantized model or have enough VRAM
print("Loading base model architecture...")
# We use a dummy model here to simulate the structure for the script to run without downloading 16GB
class DummyModel(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.q_proj = torch.nn.Linear(4096, 4096)
        self.v_proj = torch.nn.Linear(4096, 4096)
base_model = DummyModel()

# 2. Configure LoRA (The Transparent Sheet)
lora_config = LoraConfig(
    r=16,               # Rank: The "thickness" of the adapter. Higher = smarter but slower.
    lora_alpha=32,      # Scaling factor. Usually 2x the rank.
    target_modules=["q_proj", "v_proj"], # Where to put the sheets (usually attention modules)
    lora_dropout=0.05,  # Helps prevent overfitting
    bias="none",
    task_type="CAUSAL_LM"
)

# 3. Apply LoRA to the Base Model
peft_model = get_peft_model(base_model, lora_config)

# 4. Prove it's Parameter Efficient!
def print_trainable_parameters(model):
    trainable_params = 0
    all_param = 0
    for _, param in model.named_parameters():
        all_param += param.numel()
        if param.requires_grad:
            trainable_params += param.numel()
    print(f"Trainable params: {trainable_params:,} || All params: {all_param:,} || Trainable %: {100 * trainable_params / all_param:.4f}")

print_trainable_parameters(peft_model)
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: Rank (`r`) and Alpha (`lora_alpha`)**
The "Rank" (`r`) determines how expressive the LoRA adapter is. An `r=8` is standard, `r=16` or `r=32` is good for complex tasks like coding. `lora_alpha` scales the learned weights. A standard rule of thumb is `alpha = 2 * r`.

**Step 2: Target Modules**
You don't put the transparent sheet on every page. Usually, we target the attention matrices (`q_proj`, `k_proj`, `v_proj`, `o_proj`). The more modules you target, the smarter the adapter, but the more VRAM it takes.

**Step 3: The Result**
When you run the script, you'll see the trainable percentage is usually less than 1%. This means the optimizer only has to track states for 1% of the model. 134GB VRAM requirement drops to ~18GB!

#### 5. ASCII Data Flow


#### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Setting `r=256` thinking "bigger is better". High rank LoRA adapters suffer from catastrophic forgetting, train much slower, and often perform *worse* than `r=16` because they overfit to the training data.
*   **Pro Tip:** Start with `r=16` and target all linear layers (`target_modules="all-linear"`). This is currently the most robust baseline for Llama-3 and Mistral architectures.

#### Level 2: Real-World
**Challenge:** In production, you often want to target *every* linear layer in a model, not just attention, for maximum quality. Write a function `get_all_linear_layers(model)` that inspects a PyTorch model and returns a list of strings representing all `torch.nn.Linear` layers, ignoring the final `lm_head`.
<details>
<summary>Hint</summary>
Iterate through `model.named_modules()`. If `isinstance(module, torch.nn.Linear)`, extract the name. Exclude "lm_head".
</details>
<details>
<summary>Solution Walkthrough</summary>
```python
def get_all_linear_layers(model):
    linear_layer_names = set()
    for name, module in model.named_modules():
        if isinstance(module, torch.nn.Linear):
            # Split to get just the base name (e.g., 'model.layers.0.self_attn.q_proj' -> 'q_proj')
            layer_name = name.split('.')[-1]
            if layer_name != 'lm_head':
                linear_layer_names.add(layer_name)
    return list(linear_layer_names)

# In the DummyModel, this would return ['q_proj', 'v_proj']
# In Llama-3 it returns: ['q_proj', 'k_proj', 'v_proj', 'o_proj', 'gate_proj', 'up_proj', 'down_proj']
```
</details>

#### Level 3: Boss Level (Cumulative)
**Challenge:** Combine Module 1.2 (VRAM math) with LoRA.
Write a function `calculate_lora_vram(base_params_b, lora_trainable_percent)`.
1. The base model weights still take up VRAM (in 16-bit).
2. ONLY the LoRA adapter requires gradients.
3. ONLY the LoRA adapter requires Adam optimizer states (4 bytes per param).
Calculate the total VRAM needed to train an 8B model with a 1% LoRA adapter. Does it fit on a 24GB GPU now?
<details>
<summary>Hint</summary>
Base weights = 8B * 2 bytes.
LoRA params = 8B * 0.01 = 0.08B.
Gradients = 0.08B * 2 bytes.
Optimizer = 0.08B * 4 bytes * 2.
Add them up!
</details>
<details>
<summary>Solution Walkthrough</summary>
```python
def calculate_lora_vram(base_params_b, lora_trainable_percent):
    # 1. Base Model Weights (Still loaded in 16-bit)
    base_vram = base_params_b * 2

    # Calculate LoRA parameters
    lora_params_b = base_params_b * lora_trainable_percent

    # 2. Gradients (Only for LoRA!)
    gradients_vram = lora_params_b * 2

    # 3. Optimizer (Only for LoRA!)
    optimizer_vram = (lora_params_b * 4) * 2

    # 4. Activations (Lower for LoRA, assume 10% of base)
    activations = base_vram * 0.10

    total = base_vram + gradients_vram + optimizer_vram + activations
    return total

vram = calculate_lora_vram(8.0, 0.01)
print(f"Total VRAM for 1% LoRA on 8B model: {vram:.2f} GB")
# Output: ~18.56 GB!
# YES! It fits perfectly on a single 24GB RTX 3090/4090. We beat the VRAM wall.
```
</details>

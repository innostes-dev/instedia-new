# 1.1 Why Flask Blocks Under AI Loads (ASGI vs WSGI)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
Imagine you have an AI microservice deployed with Flask. When a user requests an LLM generation, it takes 5 seconds. If 10 users hit the endpoint simultaneously and you have 4 workers, 6 users are completely blocked. The server hangs. Traditional WSGI (like Flask) uses one thread per request, waiting synchronously for I/O operations like database queries or external API calls (e.g., OpenAI).

### 2. Plain English Metaphor (The What)
WSGI (Flask) is like a chef who puts a pizza in the oven and then stands there staring at the oven for 15 minutes, ignoring all other customers until that pizza is done.
ASGI (FastAPI) is like a smart chef who puts the pizza in the oven, sets a timer, and immediately starts taking orders and preparing salads for other customers. When the timer rings, they take the pizza out.

### 3. Complete Runnable Code
```python
from fastapi import FastAPI
import asyncio

app = FastAPI(title="Ultra-Fast AI Health-Check Endpoint")

# Notice the 'async' keyword!
@app.get("/health")
async def health_check():
    # Simulate a slow background check (e.g., pinging a database)
    await asyncio.sleep(1)
    return {"status": "ok", "service": "ai-gateway"}
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The App Instance**
```python
from fastapi import FastAPI
app = FastAPI(title="Ultra-Fast AI Health-Check Endpoint")
```
We initialize the ASGI application. This object automatically generates OpenAPI documentation at `/docs`.

**Step 2: The Async Endpoint**
```python
@app.get("/health")
async def health_check():
```
The `async def` tells FastAPI that this function can yield control back to the event loop while waiting for something.

**Step 3: Awaiting I/O**
```python
    await asyncio.sleep(1)
    return {"status": "ok", "service": "ai-gateway"}
```
`await` is the magic word. It pauses this function's execution without blocking the main server thread, allowing FastAPI to handle thousands of other requests in the meantime.

### 5. ASCII Data Flow
```text
[Client 1] -- GET /health --> [Uvicorn Server] -> [FastAPI Event Loop]
                                                     |
                                                  (await DB) -> [Yields Control]
                                                     |
[Client 2] -- GET /health --> [Uvicorn Server] -> [Takes Next Request Immediately]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `time.sleep(1)` inside an `async def` endpoint. This blocks the entire event loop and ruins FastAPI's performance!
**Pro Tip:** If you absolutely must run a synchronous, blocking library (like an old database driver), declare the endpoint as standard `def` instead of `async def`. FastAPI will smartly run it in an isolated threadpool.

**Challenge:** Create an endpoint `GET /ping` that simulates an async network call for 0.5 seconds and returns `{"ping": "pong"}`.
<details>

```python
from fastapi import FastAPI

app = FastAPI()

```

### Level 2: Real-World
**Challenge:** Create an AI status aggregator. Create a `GET /ai-status` endpoint that asynchronously waits for 3 mock services (e.g., 1s, 2s, and 1.5s) concurrently using `asyncio.gather`, and returns their combined statuses.
<details>
<summary><b>Hint</b></summary>
Define three separate async functions that sleep and return a string. Use <code>results = await asyncio.gather(func1(), func2(), func3())</code> in the route.
</details>
<details>
<summary><b>Solution</b></summary>

```python
import asyncio
from fastapi import FastAPI

app = FastAPI()

async def check_llm():
    await asyncio.sleep(2)
    return "LLM: Online"

async def check_db():
    await asyncio.sleep(1)
    return "DB: Online"

async def check_cache():
    await asyncio.sleep(1.5)
    return "Cache: Online"

@app.get("/ai-status")
async def ai_status():
    results = await asyncio.gather(check_llm(), check_db(), check_cache())
    return {"services": results}
```
</details>

### Level 3: Boss Level
**Challenge:** Build an endpoint that measures the performance difference. You can't actually start another server, but write a route `GET /benchmark` that simulates an LLM call. It must accept a query parameter `count`. If `count` is 10, it spins up 10 concurrent tasks of a 1-second sleep, and returns the total execution time (which should be ~1 second, not 10).
<details>
<summary><b>Hint</b></summary>
Use <code>time.time()</code> to measure start and end. Create a list of tasks and <code>await asyncio.gather(*tasks)</code>.
</details>
<details>
<summary><b>Solution Walkthrough</b></summary>

```python
import asyncio
import time
from fastapi import FastAPI

app = FastAPI()

async def mock_llm_call():
    await asyncio.sleep(1)
    return "Done"

@app.get("/benchmark")
async def benchmark(count: int = 1):
    start_time = time.time()

    # Create 'count' number of concurrent tasks
    tasks = [mock_llm_call() for _ in range(count)]
    await asyncio.gather(*tasks)

    end_time = time.time()
    return {
        "requested_calls": count,
        "elapsed_time_seconds": round(end_time - start_time, 2)
    }
```
*Walkthrough:* Because we are using the async event loop, asking for 10 mock LLM calls doesn't block sequentially. All 10 sleeps happen at the same time, returning the result in ~1 second flat.
</details>

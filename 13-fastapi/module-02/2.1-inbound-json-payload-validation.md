# 2.1 Inbound JSON Payload Validation (Pydantic v2)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
Accepting POST requests in Python usually involves parsing `request.json()`, navigating a dictionary with `.get()`, and manually checking if fields exist, if they are the right type, and if nested objects are formatted correctly. This is error-prone, impossible to type-check natively, and results in massive "spaghetti" functions.

### 2. Plain English Metaphor (The What)
Handling raw dictionaries is like catching items thrown at you in the dark; you have to feel each object to figure out what it is before organizing it.
Pydantic is like a rigid mold. If the user pours data that doesn't fit the shape perfectly, it overflows and rejects the pour automatically. You only ever receive a perfectly molded object.

### 3. Complete Runnable Code
```python
from fastapi import FastAPI
from pydantic import BaseModel, Field, field_validator

app = FastAPI()

class AIPrompt(BaseModel):
    system_prompt: str = Field(default="You are a helpful assistant.", max_length=500)
    user_message: str = Field(..., min_length=1, max_length=2000)
    max_tokens: int = Field(default=100, ge=10, le=4096)

    @field_validator("user_message")
    @classmethod
    def prevent_jailbreak(cls, v: str) -> str:
        if "ignore all previous instructions" in v.lower():
            raise ValueError("Jailbreak attempt detected.")
        return v

@app.post("/generate")
async def generate_response(prompt: AIPrompt):
    return {"status": "accepted", "tokens": prompt.max_tokens}
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Pydantic Model**
```python
class AIPrompt(BaseModel):
    system_prompt: str = Field(default="You are a helpful assistant.", max_length=500)
    user_message: str = Field(..., min_length=1, max_length=2000)
    max_tokens: int = Field(default=100, ge=10, le=4096)
```
We define our data contract by subclassing `BaseModel`. The `Field` function provides metadata and constraints (min/max length, bounds). FastAPI uses this to generate the OpenAPI schema.

**Step 2: Complex Validation**
```python
    @field_validator("user_message")
    @classmethod
    def prevent_jailbreak(cls, v: str) -> str:
        if "ignore all previous instructions" in v.lower():
            raise ValueError("Jailbreak attempt detected.")
        return v
```
Sometimes constraints like `min_length` aren't enough. `@field_validator` allows us to write custom Python logic to inspect incoming data. If we raise a `ValueError`, FastAPI turns it into a 422 error for the user.

**Step 3: Endpoint Injection**
```python
@app.post("/generate")
async def generate_response(prompt: AIPrompt):
```
By simply type-hinting the argument as `AIPrompt`, FastAPI automatically reads the request body, parses the JSON, validates it against our model, and passes a fully instanced Pydantic object into the function.

### 5. ASCII Data Flow
```text
Client JSON -> {"user_message": "Hello"}
      |
[Pydantic BaseModel]
      |-- Types Match? (Yes)
      |-- Field Limits OK? (Yes)
      |-- Custom Validators Pass? (Yes)
      |
[Endpoint receives 'AIPrompt' Object]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using raw dictionaries `def endpoint(payload: dict)` and throwing away all of FastAPI/Pydantic's power.
**Pro Tip:** In Pydantic v2, use `@model_validator(mode='after')` if you need to validate multiple fields against each other (e.g., ensuring `end_date` is strictly after `start_date`).

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Challenge:** Create a Pydantic model `UserSignup` with a string `username` (min 3 chars), a string `email` (use `EmailStr` from pydantic, requires `pip install pydantic[email]`), and an integer `age` (must be >= 18). Create a POST endpoint `/signup`.
<details>
<summary><b>Hint</b></summary>
Import <code>EmailStr</code> from <code>pydantic</code>. Use <code>Field(ge=18)</code> for age.
</details>
<details>
<summary><b>Solution</b></summary>

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field, EmailStr

app = FastAPI()

class UserSignup(BaseModel):
    username: str = Field(..., min_length=3)
    email: EmailStr
    age: int = Field(..., ge=18)

@app.post("/signup")
async def signup(user: UserSignup):
    return {"msg": f"Welcome {user.username}"}
```
</details>

### Level 2: Real-World
**Challenge:** AI Image Generation Request. Create a model `ImageRequest` with `width` and `height` (must be exactly 512, 768, or 1024), and a `prompt` string. Use a custom `@model_validator(mode='after')` to ensure that width and height are the same (only square images allowed for now).
<details>
<summary><b>Hint</b></summary>
Use <code>Literal[512, 768, 1024]</code> for width and height. Use <code>@model_validator(mode='after')</code> and check <code>self.width == self.height</code>. Raise ValueError if not.
</details>
<details>
<summary><b>Solution</b></summary>

```python
from typing import Literal
from fastapi import FastAPI
from pydantic import BaseModel, model_validator

app = FastAPI()

class ImageRequest(BaseModel):
    prompt: str
    width: Literal[512, 768, 1024]
    height: Literal[512, 768, 1024]

    @model_validator(mode='after')
    def check_square(self):
        if self.width != self.height:
            raise ValueError("Images must be square (width == height)")
        return self

@app.post("/generate-image")
async def generate(req: ImageRequest):
    return {"specs": f"{req.width}x{req.height}"}
```
</details>

### Level 3: Boss Level
**Challenge:** Combine Module 1 and 2. Endpoint: `POST /process-data/{task_id}`.
- `task_id` is a Path parameter (UUID string).
- Query parameter `priority` (boolean, default False).
- Body: `DataPayload` model with `data_list` (List of strings, max 10 items) and `retries` (int, 0-3).
- Simulate an async processing delay of 0.5s. Return all inputs combined.
<details>
<summary><b>Hint</b></summary>
Put Path, Query, and Body parameters all in the same endpoint signature. FastAPI will figure out where to parse them from.
</details>
<details>
<summary><b>Solution Walkthrough</b></summary>

```python
import asyncio
from typing import List
from fastapi import FastAPI, Path, Query
from pydantic import BaseModel, Field

app = FastAPI()

class DataPayload(BaseModel):
    data_list: List[str] = Field(..., max_length=10)
    retries: int = Field(default=0, ge=0, le=3)

@app.post("/process-data/{task_id}")
async def process_task(
    task_id: str = Path(..., min_length=36, max_length=36),
    payload: DataPayload = None, # Pydantic parses body
    priority: bool = Query(False)
):
    await asyncio.sleep(0.5)
    return {
        "task": task_id,
        "priority": priority,
        "items_count": len(payload.data_list),
        "retries": payload.retries
    }
```
*Walkthrough:* FastAPI natively understands that `task_id` belongs in the URL, `priority` belongs in the query string, and `payload` (because it's a Pydantic model) must be extracted from the JSON request body. Everything is validated, typed, and cleanly separated.
</details>

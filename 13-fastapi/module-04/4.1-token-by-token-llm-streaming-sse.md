# 4.1 Token-by-Token LLM Streaming (SSE)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
Large Language Models (LLMs) take time to generate responses. If a user asks for a 500-word essay, the model might take 10 seconds to finish. If your API waits for the whole thing to finish before sending an HTTP response, the user stares at a loading spinner for 10 seconds, thinks the app is broken, and leaves.

### 2. Plain English Metaphor (The What)
Standard HTTP is like ordering a custom cake. You pay, wait 3 days, and get the whole cake at once.
Server-Sent Events (SSE) streaming is like sitting at a hibachi grill. The chef cooks the food and tosses pieces of shrimp directly onto your plate one by one as they are ready. You start eating immediately while they finish the rest.

### 3. Complete Runnable Code
```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import asyncio

app = FastAPI()

async def fake_llm_generator(prompt: str):
    words = ["Here ", "is ", "your ", "streamed ", "AI ", "response!"]
    for word in words:
        # Simulate generation delay
        await asyncio.sleep(0.5)
        # Yielding data chunk by chunk
        yield word

@app.get("/chat/stream")
async def stream_chat(prompt: str = "Hello"):
    # Pass the async generator directly to StreamingResponse
    return StreamingResponse(
        fake_llm_generator(prompt),
        media_type="text/event-stream"
    )
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Async Generator**
```python
async def fake_llm_generator(prompt: str):
    words = ["Here ", "is ", "your ", "streamed ", "AI ", "response!"]
    for word in words:
        await asyncio.sleep(0.5)
        yield word
```
Instead of `return`, we use `yield` inside an async function. This creates an asynchronous generator. It produces a value, yields it, and then pauses until the next iteration.

**Step 2: The StreamingResponse**
```python
@app.get("/chat/stream")
async def stream_chat(prompt: str = "Hello"):
    return StreamingResponse(
        fake_llm_generator(prompt),
        media_type="text/event-stream"
    )
```
FastAPI provides `StreamingResponse`. We hand it our generator. FastAPI keeps the HTTP connection open and flushes every `yield` directly to the client over the network immediately.

**Step 3: The Media Type**
`media_type="text/event-stream"` tells the browser/client that this isn't a standard JSON payload, but a continuous stream of events. Standard AI clients (like the OpenAI SDK) expect this format.

### 5. ASCII Data Flow
```text
[Client] ---> GET /chat/stream ---> [FastAPI]
                                        |
<-- HTTP 200 OK (Headers sent) ---------|
                                        | (loop begins)
<-- "Here " ----------------------------| (yield, sleep)
<-- "is " ------------------------------| (yield, sleep)
<-- "your " ----------------------------| (yield, sleep)
                                        |
[Connection Closed gracefully] <--------|
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Storing the entire generated string in memory and yielding it all at once at the end. That defeats the whole purpose of streaming!
**Pro Tip:** In a real SSE implementation, chunks usually need to be formatted specificially, like `yield f"data: {word}\n\n"`. This matches the strict Server-Sent Events specification.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Challenge:** Create a simple countdown streamer. Endpoint `GET /countdown`. It should stream numbers 5, 4, 3, 2, 1 with a 1-second delay between each, and then yield "Blastoff!".
<details>
<summary><b>Hint</b></summary>
Use a <code>for</code> loop with <code>range(5, 0, -1)</code>, yield the string version of the number, <code>await asyncio.sleep(1)</code>, and yield the final string. Wrap it in a <code>StreamingResponse</code>.
</details>
<details>
<summary><b>Solution</b></summary>

```python
import asyncio
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

async def countdown_gen():
    for i in range(5, 0, -1):
        yield f"{i}... "
        await asyncio.sleep(1)
    yield "Blastoff!"

@app.get("/countdown")
async def countdown():
    return StreamingResponse(countdown_gen(), media_type="text/plain")
```
</details>

### Level 2: Real-World
**Challenge:** SSE Formatted AI Stream. Create `GET /sse`. Stream 3 chunks of data: `"AI"`, `" is"`, `" cool"`. Format each chunk according to the SSE standard: `data: <chunk>\n\n`.
<details>
<summary><b>Hint</b></summary>
<code>yield f"data: {chunk}\n\n"</code>
</details>
<details>
<summary><b>Solution</b></summary>

```python
import asyncio
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

async def sse_generator():
    chunks = ["AI", " is", " cool"]
    for chunk in chunks:
        await asyncio.sleep(0.5)
        yield f"data: {chunk}\n\n"
    # standard way to tell client we are done
    yield "data: [DONE]\n\n"

@app.get("/sse")
async def sse_stream():
    return StreamingResponse(sse_generator(), media_type="text/event-stream")
```
</details>

### Level 3: Boss Level
**Challenge:** Client Disconnect Handling.
When a client closes their browser mid-stream, FastAPI will eventually raise a `CancelledError` when it tries to yield to a closed connection.
Write a stream generator that catches `asyncio.CancelledError`. When caught, print "Client disconnected!" to the server console, do some mock cleanup, and then re-raise the exception.
<details>
<summary><b>Hint</b></summary>
Wrap your <code>yield</code> loop in a <code>try...except asyncio.CancelledError:</code> block.
</details>
<details>
<summary><b>Solution Walkthrough</b></summary>

```python
import asyncio
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

async def robust_stream():
    try:
        for i in range(100):
            yield f"data: Chunk {i}\n\n"
            await asyncio.sleep(1)
    except asyncio.CancelledError:
        print("\n[ALERT] Client disconnected mid-stream!")
        print("Cleaning up GPU resources...")
        # Always re-raise CancelledError so FastAPI can close the socket properly
        raise

@app.get("/robust-stream")
async def get_robust_stream():
    return StreamingResponse(robust_stream(), media_type="text/event-stream")
```
*Walkthrough:* This is critical for AI infrastructure. If an LLM inference takes 30 seconds and the user cancels the request after 2 seconds, you want to immediately stop the GPU from generating the remaining 28 seconds of tokens. By catching `CancelledError`, you can send a signal to your inference engine to abort, saving massive compute costs.
</details>

# 4.2 Offloading Heavy Tasks (BackgroundTasks)

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
A user uploads a 50-page PDF and clicks "Process". Your backend needs to extract text, run it through an LLM for summarization, and save it to a database. This takes 45 seconds. If you do this in the route handler, the user's browser hangs, they can't use the app, and the HTTP connection might time out completely.

### 2. Plain English Metaphor (The What)
Synchronous processing is like dropping off your car at the mechanic and being forced to sit in the waiting room chair for 5 hours until it's done before you are allowed to leave.
Background Tasks are like dropping off your keys, getting a receipt (HTTP 202 Accepted), and immediately going home. The mechanic does the heavy work in the background and texts you when it's ready.

### 3. Complete Runnable Code
```python
from fastapi import FastAPI, BackgroundTasks
import time

app = FastAPI()

def process_heavy_document(doc_name: str):
    """This is a slow, blocking function."""
    print(f"Starting to process {doc_name}...")
    time.sleep(5) # Simulate heavy CPU/IO work
    print(f"Finished processing {doc_name}!")
    # In reality, you would update a DB status here to 'COMPLETED'

@app.post("/upload")
async def upload_document(doc_name: str, background_tasks: BackgroundTasks):
    # 1. Add the task to the background queue
    background_tasks.add_task(process_heavy_document, doc_name)

    # 2. Return an immediate response to the client
    return {
        "status": "Accepted",
        "message": "Document processing started in the background."
    }
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Heavy Worker Function**
```python
def process_heavy_document(doc_name: str):
    time.sleep(5)
```
This is standard Python code. It can be `async def` or regular `def`. FastAPI is smart enough to run regular `def` functions in an isolated threadpool so it doesn't block the async event loop.

**Step 2: Injecting BackgroundTasks**
```python
async def upload_document(doc_name: str, background_tasks: BackgroundTasks):
```
By adding `BackgroundTasks` to the route signature, FastAPI provides an object we can use to schedule tasks.

**Step 3: Scheduling and Returning**
```python
    background_tasks.add_task(process_heavy_document, doc_name)
    return {"status": "Accepted"}
```
We pass the function reference (without calling it!) and its arguments to `add_task`. The endpoint immediately returns JSON to the user. *After* the HTTP response is sent over the network, FastAPI begins executing the background task.

### 5. ASCII Data Flow
```text
POST /upload -> [FastAPI Route] -> background_tasks.add()
                       |
<-- HTTP 200 (Instantly)
                       |
               [Response Sent]
                       |
            [Background Task Begins] -> time.sleep(5)
                                           |
                                      [Task Finishes]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using FastAPI `BackgroundTasks` for mission-critical, long-running jobs (like processing payments). If the Uvicorn server restarts or crashes, all pending background tasks are lost forever.
**Pro Tip:** FastAPI background tasks are for lightweight, "best-effort" operations (like sending a welcome email). For robust, distributed AI workloads, use Celery, ARQ, or temporal.io with an external message broker (like Redis/RabbitMQ).

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Challenge:** Create a POST endpoint `/send-email` that accepts an email address. Create a function `send_notification(email: str)` that prints "Sending email to {email}" and sleeps for 2 seconds. Add it as a background task and immediately return `{"msg": "Email queued"}`.
<details>
<summary><b>Hint</b></summary>
Inject <code>bg_tasks: BackgroundTasks</code>. Use <code>bg_tasks.add_task(send_notification, email)</code>.
</details>
<details>
<summary><b>Solution</b></summary>

```python
import time
from fastapi import FastAPI, BackgroundTasks

app = FastAPI()

def send_notification(email: str):
    time.sleep(2)
    print(f"Sending email to {email}")

@app.post("/send-email")
async def send_email(email: str, bg_tasks: BackgroundTasks):
    bg_tasks.add_task(send_notification, email)
    return {"msg": "Email queued"}
```
</details>

### Level 2: Real-World
**Challenge:** Model Fine-Tuning Simulator.
Create an endpoint `/train` that accepts a `dataset_id`. It should start a background task that iterates 5 times, sleeping 1 second each time, printing "Epoch {i} finished". The endpoint should immediately return HTTP 202 Accepted (hint: use `status_code=202` on the decorator).
<details>
<summary><b>Hint</b></summary>
<code>@app.post("/train", status_code=202)</code>. The background task can be standard <code>def</code> with a <code>for</code> loop.
</details>
<details>
<summary><b>Solution</b></summary>

```python
import time
from fastapi import FastAPI, BackgroundTasks

app = FastAPI()

def train_model(dataset_id: str):
    print(f"Starting training for {dataset_id}")
    for i in range(1, 6):
        time.sleep(1)
        print(f"Epoch {i} finished")
    print("Training complete!")

@app.post("/train", status_code=202)
async def start_training(dataset_id: str, tasks: BackgroundTasks):
    tasks.add_task(train_model, dataset_id)
    return {"status": "training_started"}
```
</details>

### Level 3: Boss Level
**Challenge:** Background Dependency Cleanup.
Combine Background Tasks with Dependencies (Module 3.1).
Write a dependency `get_audit_logger` that yields an opened dummy log file (use a list `log = []`).
Write a background task that takes that log and "writes" it (prints it) after the request is done.
Pass both into the route.
<details>
<summary><b>Hint</b></summary>
A background task can accept objects injected by a dependency!
</details>
<details>
<summary><b>Solution Walkthrough</b></summary>

```python
from fastapi import FastAPI, Depends, BackgroundTasks

app = FastAPI()

def get_audit_logger():
    # In reality, this might be a DB connection or file handle
    log = []
    yield log

def write_audit_log(log_data: list):
    print(f"BACKGROUND AUDIT WRITE: {log_data}")

@app.get("/action")
async def perform_action(
    bg_tasks: BackgroundTasks,
    logger: list = Depends(get_audit_logger)
):
    # Do some business logic
    logger.append("User requested action")
    logger.append("Action successful")

    # Hand the injected logger to the background task
    bg_tasks.add_task(write_audit_log, logger)
    return {"status": "ok"}
```
*Walkthrough:* This is highly advanced. We use a dependency to create request-scoped state (the audit logger). We manipulate that state during the request. Finally, instead of blocking the user to write the audit logs to the database, we pass that state to a background task which handles the heavy I/O asynchronously after the user has already received their fast HTTP 200 response.
</details>

# 2.2 Process Management (ps, kill, htop)

## Phase A: Core Concepts

### 1. Real-World Pain Point (The Why)
Your server CPU is spiked at 100% and the server is unresponsive. A buggy script got caught in an infinite loop and is consuming all resources. You need to identify which program is doing this and forcibly terminate it before the entire server crashes, without rebooting the machine.

### 2. Plain English Metaphor (The What)
- **Processes:** Every program running on your computer is a "process" with a unique ID number (PID).
- `ps` (Process Status) is like taking a snapshot photo of everyone currently working in the office.
- `htop` / `top` is like a live security camera feed showing who is working the hardest right now.
- `kill` is a communication system. You can send a "Please stop working and go home" message (`SIGTERM`), or a "Sniper shot, drop dead immediately" message (`SIGKILL`).

### 3. Complete Runnable Code
Here is an Automated Zombie Process Detective & Killer script.

```bash
#!/usr/bin/env bash

# Start a background process that just sleeps (simulating a stuck program)
sleep 9999 &
# Grab the Process ID (PID) of the command we just ran in the background
STUCK_PID=$!
echo "Started a stuck process with PID: $STUCK_PID"

echo "Locating the process using 'ps':"
ps aux | grep "[s]leep 9999"

echo "Attempting a graceful shutdown (SIGTERM)..."
kill -15 $STUCK_PID
sleep 1

# Check if it's still alive using pgrep
if pgrep -x "sleep" > /dev/null; then
    echo "Process ignored the polite request. Forcing termination (SIGKILL)..."
    kill -9 $STUCK_PID
else
    echo "Process terminated gracefully."
fi
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Viewing Running Processes**
```bash
ps aux | grep "[s]leep 9999"
```
`ps aux` lists every process running on the system by every user. We pipe this into `grep` to find our specific program.
*(Pro-tip: putting brackets around the first letter like `[s]leep` prevents grep from finding its own process in the list!).*

**Step 2: Sending a Polite Termination Signal**
```bash
kill -15 $STUCK_PID
```
The `kill` command sends signals. Signal 15 is `SIGTERM` (Terminate). This is polite: it asks the program to save its data, close its files, and exit cleanly.

**Step 3: The Nuclear Option**
```bash
kill -9 $STUCK_PID
```
Signal 9 is `SIGKILL`. The program does not get a chance to save data or close files. The Linux kernel simply obliterates the process immediately. Use this only when `SIGTERM` fails.

### 5. ASCII Data Flow

```text
[Bash Shell] --- Sends Signal 15 (SIGTERM) ---> [Application Process]
                                                     |
                                            (App decides to ignore it)
                                                     |
[Bash Shell] --- Sends Signal 9 (SIGKILL)  ---> [Linux Kernel] ---> Obliterates App
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `kill -9` by default for everything. If you `kill -9` a database process, it might leave database files corrupted because it couldn't finish writing them.
**Pro Tip:** Use `pgrep` (Process Grep) to find a PID by name instead of parsing `ps aux`, and use `pkill` to kill processes by name instead of PID.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Find the Process ID (PID) of your current `ssh` session and see what user is running it.
<details>
<summary>Hint</summary>
Use <code>ps aux | grep ssh</code>.
</details>
<details>
<summary>Solution Walkthrough</summary>
Run <code>ps aux | grep ssh</code>. The output will show columns. The first column is the USER, and the second column is the PID.
</details>

### Level 2: Real-World
**Task:** A Node.js application is stuck on port 3000. You don't know the PID, but you need to kill all `node` processes gracefully.
<details>
<summary>Hint</summary>
Use <code>pkill</code>.
</details>
<details>
<summary>Solution Walkthrough</summary>
<code>pkill -15 node</code>
`pkill` finds all processes matching the name "node" and sends them the signal specified (15 = SIGTERM).
</details>

### Level 3: Boss Level
**Task:** Write a single command pipeline that finds the top 3 processes consuming the most CPU percentage, and then writes their PIDs and CPU usage to a file called `/tmp/cpu_hogs.txt`.
<details>
<summary>Hint</summary>
Use <code>ps aux --sort=-%cpu</code>, then <code>head</code>, then <code>awk</code> to format the output, and finally redirect <code>></code> to a file.
</details>
<details>
<summary>Solution Walkthrough</summary>

```bash
ps aux --sort=-%cpu | head -n 4 | awk 'NR>1 {print "PID:", $2, "- CPU:", $3"%"}' > /tmp/cpu_hogs.txt
```
1. `ps aux --sort=-%cpu` sorts all processes descending by CPU usage.
2. `head -n 4` grabs the header row plus the top 3 processes.
3. `awk 'NR>1 { ... }'` skips the header row (Number of Records > 1) and prints the specific columns for PID ($2) and CPU ($3).
4. `>` writes it to the file.
</details>

# 3.1 Bash Scripting & Exit Codes

## Phase A: Core Concepts

### 1. Real-World Pain Point (The Why)
You have a deployment process that requires pulling code from git, stopping a server, installing dependencies, and restarting the server. Doing this manually means typing 5-10 commands. If you make a typo on step 3, but blindly copy-paste and run steps 4 and 5 anyway, you will break production. You need a way to automate these steps, but more importantly, a way to make the automation stop immediately if any single step fails.

### 2. Plain English Metaphor (The What)
- **Shebang (`#!/usr/bin/env bash`):** The instruction manual telling the computer which translator to use to understand the script.
- **Variables (`APP_DIR="/opt/app"`):** Nicknames for things so you don't have to repeat long words.
- **Exit Codes (`$?`):** The report card a program hands you when it finishes. `0` means A+ (Success). Anything other than `0` (like `1` or `2`) means it failed.
- **Conditionals (`if / then`):** Crossroads where the script makes a decision based on the report card.

### 3. Complete Runnable Code
Here is an Automated Zero-Downtime Deployment Shell Script.

```bash
#!/usr/bin/env bash

# Enable strict mode: script exits immediately if any command returns a non-zero exit code
set -e

# Variables
APP_DIR="/tmp/production-app"
BACKUP_DIR="/tmp/app-backups"
TIMESTAMP=$(date +%s)

echo "Starting Deployment..."

# 1. Setup directories
mkdir -p "$APP_DIR"
mkdir -p "$BACKUP_DIR"

# 2. Simulate taking a backup
echo "Taking pre-deployment backup..."
# The cp command will return 0 if successful, or >0 if it fails.
# Because of 'set -e', if this fails, the script aborts here.
cp -r "$APP_DIR" "$BACKUP_DIR/backup-$TIMESTAMP"

# 3. Check if a specific file exists before proceeding
if [ -f "$APP_DIR/config.json" ]; then
    echo "Configuration found. Proceeding with update..."
else
    echo "WARNING: config.json missing. Creating default..."
    echo '{"status": "online"}' > "$APP_DIR/config.json"
fi

# 4. Simulate application restart
echo "Restarting application..."
sleep 1

echo "Deployment Successful!"
# Explicitly return a success exit code
exit 0
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Shebang and Strict Mode**
```bash
#!/usr/bin/env bash
set -e
```
The shebang tells the system this is a Bash script. `set -e` is the most important line in any bash script. It forces the script to immediately exit if any command within it fails. Without it, bash will blindly continue to the next line even if the previous line crashed.

**Step 2: Variables and Command Substitution**
```bash
TIMESTAMP=$(date +%s)
```
We create a variable `TIMESTAMP`. We use `$(...)` to run the `date +%s` command (which gets the current time in seconds) and capture its output to store inside the variable. Note: there are NO spaces around the `=` sign in bash variable assignment.

**Step 3: Conditionals and File Checking**
```bash
if [ -f "$APP_DIR/config.json" ]; then
```
This is an `if` statement. The `[ -f ... ]` specifically checks if a file exists and is a regular file. We always wrap variables in double quotes `"$APP_DIR"` to prevent errors if the variable contains spaces.

### 5. ASCII Data Flow

```text
[ Command: cp -r ]
       |
       v
Did it work?
 /        \
YES (0)    NO (1)
 |          |
 |          v
 |    [ set -e catches the '1' ] --> ABORTS ENTIRE SCRIPT
 v
[ Next Command ]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `#!/bin/bash` instead of `#!/usr/bin/env bash`. On some operating systems (like FreeBSD or macOS via Homebrew), bash might be installed somewhere else. `/usr/bin/env bash` tells the system to search for bash in the user's environment path, making your script portable across different OS types.
**Pro Tip:** Use `set -euxo pipefail` at the top of your scripts. `-e` exits on error, `-u` exits if you use an unassigned variable, `-x` prints commands as they run (great for debugging), and `-o pipefail` ensures that if a command inside a pipe fails (e.g., `grep` fails in `cat file | grep | awk`), the whole pipe fails.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Write a 3-line script that defines a variable `USER_NAME="Alice"`, and prints "Hello, Alice!".
<details>

</details>
<details>

```bash
#!/usr/bin/env bash
USER_NAME="Alice"
echo "Hello, $USER_NAME!"
```
Remember not to put spaces around the `=`.
</details>

### Level 2: Real-World
**Task:** Write a script that tries to create a directory `/root/forbidden`. If it fails (which it will, unless you run it as sudo), catch the exit code and print a custom error message.
<details>
<summary>Hint</summary>
Do not use `set -e` here. Run the command, then check the special variable <code>$?</code> using an <code>if</code> statement.
</details>
<details>
<summary>Solution Walkthrough</summary>

```bash
#!/usr/bin/env bash

mkdir /root/forbidden 2> /dev/null

if [ $? -ne 0 ]; then
    echo "Custom Error: You do not have permission to create this directory."
    exit 1
fi
echo "Success!"
```
`$?` holds the exit code of the last run command. `-ne 0` means "not equal to 0" (which implies an error occurred).
</details>

### Level 3: Boss Level
**Task:** Write a script that takes a URL as a command-line argument. Use `curl` to check if the website is up. If it's up, print "Website is up". If it's down, write the URL and the timestamp to a file `downtime.log`.
<details>
<summary>Hint</summary>
Command line arguments are accessed via `$1`. You can use `curl -s -o /dev/null -w "%{http_code}" $1` to get just the HTTP status code.
</details>
<details>
<summary>Solution Walkthrough</summary>

```bash
#!/usr/bin/env bash

TARGET_URL=$1

if [ -z "$TARGET_URL" ]; then
    echo "Usage: ./check_site.sh <URL>"
    exit 1
fi

HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" "$TARGET_URL")

if [ "$HTTP_CODE" -eq 200 ]; then
    echo "Website $TARGET_URL is up (200 OK)."
else
    TIMESTAMP=$(date)
    echo "[$TIMESTAMP] $TARGET_URL is down! (HTTP: $HTTP_CODE)" >> downtime.log
    echo "Website is down. Logged to downtime.log"
fi
```
1. `$1` grabs the first argument passed to the script.
2. `[ -z ... ]` checks if the string is empty.
3. The `curl` command silently fetches the site and extracts only the HTTP code.
4. We use `-eq 200` to check for a successful response.
5. `>>` appends the downtime message to the log file without overwriting previous entries.
</details>

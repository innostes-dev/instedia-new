# 1.2 Taming Giant Logs (head, tail, less, df, du)

## Phase A: Core Concepts

### 1. Real-World Pain Point (The Why)
Your production application just went down, and a 20GB `application.log` file is sitting on your server. If you try to open a 20GB file in a traditional text editor, it will consume all your server's RAM and crash the system entirely. Furthermore, you might be out of disk space, but you don't know which files are eating it up.

### 2. Plain English Metaphor (The What)
- `df` (Disk Free) is like looking at your car's fuel gauge to see how much gas is left.
- `du` (Disk Usage) is like opening the trunk to see exactly which luggage is taking up the most space.
- `head` / `tail` is like reading just the first or last chapter of a massive encyclopedia without taking the book off the shelf.
- `less` is like using a magnifying glass to read the encyclopedia page by page, holding only one page in memory at a time.

### 3. Complete Runnable Code
Here is a Live Nginx Access Log Monitor script.

```bash
#!/usr/bin/env bash

echo "Checking overall disk space..."
df -h

echo "Finding the largest directories in /var/log..."
du -sh /var/log/* | sort -hr | head -n 5

echo "Streaming live Nginx logs (press Ctrl+C to stop)..."
# In a real environment, this might be /var/log/nginx/access.log
# We use a dummy file here to prevent errors if the file doesn't exist
touch /tmp/dummy-access.log
tail -f /tmp/dummy-access.log
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Checking Overall Disk Space**
```bash
df -h
```
`df` shows the disk space available on all mounted filesystems. The `-h` flag makes it "human-readable" (printing sizes in Megabytes and Gigabytes instead of bytes).

**Step 2: Finding Disk Space Hogs**
```bash
du -sh /var/log/*
```
`du` estimates file space usage. The `-s` flag gives a summary (total size) for each argument, and `-h` makes it human-readable. It answers "how big is this specific directory?".

**Step 3: Streaming Live Logs**
```bash
tail -f /var/log/nginx/access.log
```
The `tail` command outputs the last 10 lines of a file. The `-f` (follow) flag makes it wait and stream new lines as they are appended to the file. It is the ultimate tool for watching live application activity.

### 5. ASCII Data Flow

```text
[Live Application] --> Writes error --> [giant-app.log]
                                              |
[tail -f command] <--- Reads last lines <-----+
      |
      v
[Terminal Output] (Continuous stream)
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `cat giant.log` or `vim giant.log`. `cat` will dump millions of lines to your terminal, making it freeze. `vim` will try to load the entire file into RAM, crashing the server.
**Pro Tip:** Always use `less giant.log` for reading large files. It only loads the portion of the file you are currently viewing, making it instantly open a file of any size.

### Level 2: Real-World
**Task:** You are investigating a disk space alert. Find the top 3 largest files or directories inside `/var/log/`.
<details>
<summary>Hint</summary>
Combine <code>du</code>, <code>sort</code>, and <code>head</code>.
</details>
<details>
<summary>Solution Walkthrough</summary>
<code>du -sh /var/log/* | sort -hr | head -n 3</code>
The <code>du -sh</code> calculates sizes. We pipe it to <code>sort -hr</code> (human-readable, reverse order) so the biggest items are at the top, and then <code>head -n 3</code> grabs just the top 3.
</details>

### Level 3: Boss Level
**Task:** Write a script that checks if disk usage on the root partition `/` is above 90%. For now, just simulate grabbing the percentage value. Then, view a live log file but only see the lines added to it.
<details>
<summary>Hint</summary>
You can extract the percentage from <code>df -h /</code>.
</details>
<details>
<summary>Solution Walkthrough</summary>

```bash
#!/usr/bin/env bash

# Extract usage percentage for root partition
USAGE=$(df -h / | awk 'NR==2 {print $5}' | sed 's/%//')
echo "Current Root Disk Usage: $USAGE%"

if [ "$USAGE" -gt 90 ]; then
  echo "WARNING: Disk space critical!"
fi

# To view live logs:
# tail -f /var/log/syslog
```
We use `df -h /` to get the root partition info, `awk` to get the second row and 5th column, and `sed` to strip the `%` sign so we have a raw integer for our conditional.
</details>

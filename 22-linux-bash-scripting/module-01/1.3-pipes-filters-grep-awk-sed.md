# 1.3 Pipes & Filters (grep, awk, sed)

## Phase A: Core Concepts

### 1. Real-World Pain Point (The Why)
You have a high-traffic web server producing thousands of log lines per minute. You need to extract just the IP addresses of users who are getting "404 Not Found" errors, and figure out which IP is hitting you the most. Doing this manually by scrolling would take days.

### 2. Plain English Metaphor (The What)
- **Standard Streams (stdin, stdout, stderr):** Every command has an input door (stdin), a normal output door (stdout), and an emergency exit for errors (stderr).
- **Pipes `|`:** An assembly line conveyor belt. The output of one machine (command) goes directly into the input of the next machine.
- `grep` is a powerful magnet that pulls out only the specific items you are searching for.
- `awk` is a column-extractor, taking a table of data and slicing out specific columns.
- `sed` is a find-and-replace robot.

### 3. Complete Runnable Code
Here is a High-Speed Traffic & Error IP Analyzer Pipeline.

```bash
#!/usr/bin/env bash

# Create a sample log file to parse
cat << 'EOF' > /tmp/sample-access.log
192.168.1.10 - - [10/Oct/2024:13:55:36] "GET /index.html" 200
10.0.0.15 - - [10/Oct/2024:13:55:37] "GET /admin.php" 404
192.168.1.10 - - [10/Oct/2024:13:55:38] "GET /styles.css" 200
10.0.0.15 - - [10/Oct/2024:13:55:39] "GET /config.json" 404
10.0.0.15 - - [10/Oct/2024:13:55:40] "GET /wp-login.php" 404
EOF

echo "Top IP addresses causing 404 errors:"

cat /tmp/sample-access.log | grep " 404" | awk '{print $1}' | sort | uniq -c | sort -nr
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Filtering Rows with Grep**
```bash
cat /tmp/sample-access.log | grep " 404"
```
We push the contents of the log into `grep`. `grep` scans every line and only outputs lines that contain the exact string `" 404"`.

**Step 2: Extracting Columns with Awk**
```bash
... | awk '{print $1}'
```
We pipe the 404 lines into `awk`. By default, `awk` splits lines by spaces. Since the IP address is the very first thing on the line, we tell it to `{print $1}` (print the first column).

**Step 3: Counting Frequencies with Sort and Uniq**
```bash
... | sort | uniq -c | sort -nr
```
`uniq -c` counts consecutive duplicate lines. But they *must* be consecutive, so we `sort` them first. Finally, we `sort -nr` (numeric, reverse) to put the IP with the most 404 errors at the very top.

### 5. ASCII Data Flow

```text
[Log File]
   |
(stdout)
   v
[ grep "404" ]  --> Filters out 200 OK requests
   |
(stdout)
   v
[ awk '{print $1}' ] --> Strips away timestamps and URLs, keeps IP
   |
(stdout)
   v
[ uniq -c ] --> Counts duplicates and outputs final list
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `uniq` without `sort` first. `uniq` only compares adjacent lines. If you have "IP1, IP2, IP1", `uniq` will not group the two IP1s together unless they are sorted first.
**Pro Tip:** You can redirect `stderr` to the void so you don't see error messages cluttering your output by appending `2> /dev/null` to your command. (0=stdin, 1=stdout, 2=stderr).

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Given a file `/etc/os-release`, find the line that contains the word `PRETTY_NAME`.
<details>
<summary>Hint</summary>
Use the <code>cat</code> and <code>grep</code> commands.
</details>
<details>
<summary>Solution Walkthrough</summary>
<code>cat /etc/os-release | grep "PRETTY_NAME"</code>
Alternatively, you can just do <code>grep "PRETTY_NAME" /etc/os-release</code> without using <code>cat</code>.
</details>

### Level 2: Real-World
**Task:** Replace all instances of the word "warning" with "CRITICAL" in a log stream, and only display lines containing "CRITICAL".
<details>
<summary>Hint</summary>
Use <code>sed 's/old/new/g'</code> to replace, then pipe to <code>grep</code>.
</details>
<details>
<summary>Solution Walkthrough</summary>
<code>echo "system warning: high CPU" | sed 's/warning/CRITICAL/g' | grep "CRITICAL"</code>
<code>sed</code> acts as a stream editor, performing search-and-replace, and <code>grep</code> filters for the modified string.
</details>

### Level 3: Boss Level
**Task:** You have a file `auth.log`. Find all the IP addresses that failed to log in via SSH (look for "Failed password"), count how many times each IP failed, and list the top 5 offenders.
<details>
<summary>Hint</summary>
Combine <code>grep</code>, <code>awk</code>, <code>sort</code>, <code>uniq -c</code>, <code>sort -nr</code>, and <code>head</code>. You'll need to figure out which column number in <code>auth.log</code> represents the IP.
</details>
<details>
<summary>Solution Walkthrough</summary>

```bash
# Assuming the IP is the 11th column in the log format:
grep "Failed password" /var/log/auth.log | awk '{print $11}' | sort | uniq -c | sort -nr | head -n 5
```
1. `grep "Failed password"` isolates the bad login attempts.
2. `awk '{print $11}'` extracts the IP address column.
3. `sort` alphabetizes the IPs.
4. `uniq -c` counts them up.
5. `sort -nr` puts the highest counts at the top.
6. `head -n 5` gives you the top 5.
</details>

# 1.3 Port Mapping and Environment Variables

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
**The Scenario:** You successfully built a Docker image for your web application. You run `docker run my-app`, the terminal says "Server listening on port 3000", but when you go to `http://localhost:3000` in your browser, the site can't be reached! Worse, the app connects to a database using a hardcoded password in the source code, which is a massive security violation.

**The Pain:** By default, containers are locked down. Their internal network is completely isolated from your host machine's network. Furthermore, burying configuration details (like API keys or database URLs) inside a compiled image makes it impossible to promote that exact same image from "Development" to "Production" without rebuilding it.

### 2. Plain English Metaphor (The What)
Imagine a highly secure bank vault (the Container). Inside the vault, a teller (your application) is waiting at window #3000 to process transactions.
If you stand outside the bank building (your Host Machine) and yell through the walls, the teller won't hear you. You need to build a secure pneumatic tube (Port Mapping) that connects a slot on the outside of the bank directly to window #3000 on the inside.

Additionally, the teller needs to know today's secret vault code. You shouldn't tattoo the code on the teller's arm (hardcoding in the Image). Instead, you slide a piece of paper under the door right as they walk in for their shift (Environment Variables).

### 3. Complete Runnable Code
Here is how you securely run a web application container, mapping ports and injecting secrets at runtime.

```bash
# 1. Create a file to hold your secrets (NEVER commit this to git!)
echo "DB_PASSWORD=super_secret_db_pass" > .env
echo "API_KEY=xyz123_dev_key" >> .env

# 2. Run the container with port mapping and the env file
docker run -d \
  --name my-secure-app \
  -p 8080:3000 \
  --env-file .env \
  my-web-image:latest
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The `.env` file**
We create a standard text file containing key-value pairs. This keeps sensitive data completely out of our Dockerfile and source code repository.

**Step 2: Port Mapping (`-p 8080:3000`)**
The syntax is **always** `-p HOST_PORT:CONTAINER_PORT`.
- `3000` is the port the app is listening on *inside* the isolated container.
- `8080` is the port we are opening on our *host machine* (your laptop).
When you visit `http://localhost:8080`, Docker intercepts the traffic and routes it through the "pneumatic tube" into port 3000 of the container.

**Step 3: Injecting Configuration (`--env-file`)**
The `--env-file .env` flag reads the text file and injects those variables into the running container's environment. Inside a Node.js app, you can now access `process.env.API_KEY`. Inside Python, `os.environ.get('API_KEY')`.

### 5. ASCII Data Flow

```text
  Host Machine (Your Laptop)                      Docker Container
+------------------------------+              +------------------------------+
|                              |              |                              |
|   Browser:                   |              |   Application (Node/Python)  |
|   http://localhost:8080      |              |   Listening on Port 3000     |
|             |                |              |             ^                |
|             v                |              |             |                |
|       [ Port 8080 ] ============================> [ Port 3000 ]            |
|       (Host Port)    Docker Networking Tube       (Container Port)         |
|                              |              |                              |
|                              |              |                              |
|   .env File                  |              |   Memory / Environment       |
|   DB_PASSWORD=secret --------|--(--env-file)--> DB_PASSWORD=secret         |
|                              |              |                              |
+------------------------------+              +------------------------------+
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `ENV` instructions in your Dockerfile for secrets. e.g., `ENV API_KEY="secret123"`. Anyone who gains access to your Docker image can run `docker inspect` and see the API key in plain text! `ENV` in a Dockerfile is for non-sensitive default configurations (like `ENV NODE_ENV=production`). Use runtime flags (`-e` or `--env-file`) for actual secrets.

**Pro Tip:** If you want a quick, single variable injection without a file, use the `-e` flag. Example: `docker run -e NODE_ENV=development -p 80:80 my-image`.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Objective:** Run the official `nginx` image in the background. Map port 8080 on your host machine to port 80 inside the container.

<details>
<summary><b>Click for Hint</b></summary>
Use `-d` for background, `-p HOST:CONTAINER` for ports. Nginx always listens on 80 internally.
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

```bash
docker run -d -p 8080:80 nginx:alpine
```
You can now open a browser and go to `http://localhost:8080` to see the Nginx welcome page!
</details>

### Level 2: Real-World
**Objective:** You are deploying a pre-built Postgres database container (`postgres:15-alpine`). The Postgres image *requires* an environment variable called `POSTGRES_PASSWORD` to start up. Map the database port (5432) to your host so your local PGAdmin tool can connect to it.

<details>
<summary><b>Click for Hint</b></summary>
Use `-e` to pass the single required environment variable. Use `-p` to map 5432 on the host to 5432 in the container.
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

```bash
docker run -d \
  --name my-postgres \
  -e POSTGRES_PASSWORD=my_strong_password \
  -p 5432:5432 \
  postgres:15-alpine
```
*Note: Because we mapped 5432 to 5432, your local database tools can connect to `localhost:5432` just as if Postgres was installed directly on your machine!*
</details>

### Level 3: Boss Level
**Objective:** Combining everything.
1. Build the Nginx image from the Level 3 challenge in module 1.2 (the one with the custom `index.html`).
2. Run it in the background.
3. Map host port 8000 to container port 80.
4. Pass an environment variable `SITE_ENV=staging`.
5. Verify it's working by using `curl` on your host machine, then stop the container.

<details>
<summary><b>Click for Hint</b></summary>
Remember `docker build -t ...`, then `docker run -d -p ... -e ...`, then `curl http://localhost:8000`.
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

**1. Create the files and build (if you haven't already):**
```bash
echo "<h1>Hello Staging!</h1>" > index.html
echo "FROM nginx:alpine" > Dockerfile
echo "COPY index.html /usr/share/nginx/html/index.html" >> Dockerfile
docker build -t my-custom-nginx .
```

**2, 3, 4. Run with ports and env vars:**
```bash
docker run -d --name test-site -p 8000:80 -e SITE_ENV=staging my-custom-nginx
```

**5. Verify and cleanup:**
```bash
# Test the port mapping
curl http://localhost:8000
# Output should be: <h1>Hello Staging!</h1>

# Check if the env var was injected correctly by running a command INSIDE the running container
docker exec test-site printenv SITE_ENV
# Output should be: staging

# Stop and remove
docker stop test-site
docker rm test-site
```
</details>

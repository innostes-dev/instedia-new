# 3.1 Multi-Stage Builds: Shrinking Images

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
**The Scenario:** You build a Dockerfile for a React/Next.js application. You push it to a cloud registry, and the image is **1.5 GB**. When your auto-scaling group tries to launch 10 new instances during a traffic spike, it takes 3 minutes just to download the images. Furthermore, a security scan reveals 45 vulnerabilities, mostly originating from development tools (like compilers and testing frameworks) left inside the final production image.

**The Pain:** Modern web apps require heavy build tools (TypeScript compilers, Webpack, Babel, node-gyp) to generate the final code. However, the *production server* only needs the final built Javascript and a minimal runtime to serve it. Including build tools in your final image balloons the size and drastically increases the attack surface.

### 2. Plain English Metaphor (The What)
Imagine you are a sculptor creating a marble statue to display in a museum.
A **Single-Stage Build** is like putting the statue, your chisels, your hammers, the leftover chunks of marble, and your lunchbox into a massive glass display case and shipping all of it to the museum.

A **Multi-Stage Build** is hiring two rooms. Room 1 (The Builder Stage) is your messy workshop. You do all your carving here. Room 2 (The Runner Stage) is a pristine, empty display case. When the statue is finished, you carry *only the finished statue* from Room 1 into Room 2. Room 1 is then completely destroyed. You ship a tiny, beautiful display case.

### 3. Complete Runnable Code
Here is a Multi-Stage Dockerfile for a compiled Node.js application (like Next.js or NestJS).

```dockerfile
# ==========================================
# STAGE 1: The Builder (The Messy Workshop)
# ==========================================
FROM node:18-alpine AS builder
WORKDIR /app

# Install ALL dependencies (including devDependencies)
COPY package*.json ./
RUN npm ci

# Copy source code and run the build step (e.g., tsc, next build)
COPY . .
RUN npm run build

# ==========================================
# STAGE 2: The Runner (The Clean Display Case)
# ==========================================
# Start over from a brand new, empty alpine image
FROM node:18-alpine AS runner
WORKDIR /app

# Copy ONLY the production dependencies
COPY package*.json ./
RUN npm ci --only=production

# Copy ONLY the compiled output from the 'builder' stage
COPY --from=builder /app/dist ./dist

# Run the app
EXPOSE 3000
CMD ["node", "dist/main.js"]
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The `AS` Keyword**
We start our first `FROM` instruction and append `AS builder`. This names this specific phase of the build process. We install everything and run our heavy compiler (`npm run build`). This generates a folder of static, compiled files (e.g., `/dist` or `/.next`).

**Step 2: The Second `FROM` Keyword**
The moment Docker hits the second `FROM node:18-alpine AS runner`, it starts with a completely blank slate. All the dev dependencies, source files, and temporary caches from the `builder` stage are left behind.

**Step 3: `COPY --from=`**
This is the magic wand. `COPY --from=builder /app/dist ./dist` reaches back into the temporary "builder" container, grabs *only* the compiled `/dist` folder, and pulls it into our pristine "runner" container. The final image size drops from 1.5GB to ~100MB.

### 5. ASCII Data Flow

```text
STAGE 1: "builder" Container (1.5 GB)          STAGE 2: "runner" Container (100 MB)
+--------------------------------------+       +------------------------------------+
|                                      |       |                                    |
| 1. Install heavy devDependencies     |       | 1. Install lightweight prod deps   |
| 2. Copy TypeScript Source            |       |                                    |
| 3. Run Webpack / TSC Compiler        |       | 2. COPY --from=builder /app/dist   |
|    |                                 |======>|    (Pull only the final build)     |
|    v                                 |       |                                    |
|  [ /app/dist ] (Compiled output)     |       | 3. Run production server           |
+--------------------------------------+       +------------------------------------+
       (Destroyed after build)                       (Pushed to Docker Hub)
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using standard Linux base images (like `node:18` or `python:3.9`) for production. These images contain full Debian OS installations (800MB+). Always use `-alpine` variants for production to shrink your base image to ~5MB.

**Pro Tip (Distroless Images):** For the absolute highest security in Stage 2, don't even use Alpine. Use Google's "Distroless" images (e.g., `gcr.io/distroless/nodejs18-debian11`). Distroless images contain *only* the Node runtime. They don't even have a package manager (`apt`), a shell (`bash`), or basic utilities (`ls`, `cd`). If a hacker exploits your Node app, they are trapped in an empty void with no shell to execute commands!

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Objective:** You have a Go backend. Go compiles down to a single binary executable. Write a 2-stage Dockerfile. Stage 1 (builder) uses `golang:1.20`, copies `main.go`, and runs `go build -o myapp main.go`. Stage 2 (runner) uses `alpine:latest`, copies the `myapp` binary from the builder, and runs it.

<details>
<summary><b>Click for Hint</b></summary>
Use `FROM ... AS builder`. In the second stage, use `COPY --from=builder /go/myapp /myapp`.
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

```dockerfile
# Stage 1: Build the Go binary
FROM golang:1.20 AS builder
WORKDIR /app
COPY main.go .
RUN go build -o myapp main.go

# Stage 2: Run the binary
FROM alpine:latest
WORKDIR /app
# Pull the compiled binary from the builder stage
COPY --from=builder /app/myapp .
CMD ["./myapp"]
```
</details>

### Level 2: Real-World
**Objective:** Optimize a React Single Page Application (SPA). Stage 1 should use Node to build the static React files (`npm run build`, which outputs to `/app/build`). Stage 2 should use an Nginx web server (`nginx:alpine`) and copy the static build folder into Nginx's default serving directory (`/usr/share/nginx/html`).

<details>
<summary><b>Click for Hint</b></summary>
The final image will completely discard Node.js! Nginx doesn't need Node to serve static HTML/JS/CSS.
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

```dockerfile
# Stage 1: Node Builder
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build # Outputs static files to /app/build

# Stage 2: Nginx Web Server
FROM nginx:alpine
# Copy the static assets to Nginx
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
# Nginx runs automatically
```
</details>

### Level 3: Boss Level
**Objective:** Implement a 3-Stage build for a Next.js application that needs to share a `package.json` for installing dependencies, but must run in a minimal production environment.
- Stage 1 (`deps`): Install all dependencies (`npm ci`).
- Stage 2 (`builder`): Copy `node_modules` from `deps`, copy source code, and run `npm run build`.
- Stage 3 (`runner`): Copy only the `.next` build folder, the `public` folder, and production `node_modules` into a fresh alpine image.

<details>
<summary><b>Click for Hint</b></summary>
You can use `COPY --from=stage_name` multiple times in your final runner stage!
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

```dockerfile
# Stage 1: Install dependencies only
FROM node:18-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

# Stage 2: Build the app
FROM node:18-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

# Stage 3: Production Server
FROM node:18-alpine AS runner
WORKDIR /app

ENV NODE_ENV production

# Only copy the required compiled output and public assets
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./package.json

EXPOSE 3000
CMD ["npm", "start"]
```
*Note: This is an incredibly common pattern for enterprise Next.js and Nuxt.js apps.*
</details>

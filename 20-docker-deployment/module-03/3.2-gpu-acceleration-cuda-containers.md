# 3.2 GPU Acceleration: NVIDIA CUDA Containers

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
**The Scenario:** You spent three weeks fine-tuning an open-source Large Language Model using PyTorch. The model works perfectly on your desktop computer, which has a powerful NVIDIA RTX 4090 graphics card. You package the Python code into a Docker container and deploy it to a cloud server equipped with massive A100 GPUs. However, when the container starts, PyTorch throws an error: `RuntimeError: Found no NVIDIA driver on your system.` Your AI model falls back to using the CPU, running 1,000x slower.

**The Pain:** Standard Docker containers are isolated from the host operating system's hardware. By default, a container cannot "see" or access the host's GPU, meaning high-performance AI, Machine Learning, and 3D rendering workloads are physically impossible to execute efficiently inside standard containers.

### 2. Plain English Metaphor (The What)
Imagine you buy an incredibly expensive, state-of-the-art sports car (the Host Machine with a GPU). You build a standard wooden crate (a standard Docker Container) and place a driver (your AI application) inside the crate. You bolt the crate into the passenger seat of the sports car.

The driver has no steering wheel, no gas pedal, and cannot see out of the crate. They are stuck inside the box.

The **NVIDIA Container Toolkit** acts as a special set of cables and windows that you install onto the host machine. When you start the container with the `--gpus all` flag, Docker plugs those cables from the sports car's engine (the GPU) directly into your wooden crate, giving the driver full control over the massive horsepower underneath them.

### 3. Complete Runnable Code
Here is how to run a GPU-accelerated PyTorch container.

*(Note: Running this code requires a host machine with an NVIDIA GPU and the `nvidia-container-toolkit` installed).*

```bash
# 1. Run a PyTorch container, requesting access to all host GPUs
docker run -it --rm \
  --gpus all \
  nvcr.io/nvidia/pytorch:23.08-py3

# 2. Inside the container shell, verify Python can see the GPU
python -c "import torch; print(f'GPU Available: {torch.cuda.is_available()}')"
# Output should be: GPU Available: True

# 3. View the physical GPU hardware details from inside the container
nvidia-smi
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Host Requirement (NVIDIA Container Toolkit)**
You cannot just run GPU containers out of the box. The Host OS (the physical server running Docker) *must* have the NVIDIA Drivers installed, and it *must* have the `nvidia-container-toolkit` software installed. This toolkit intercepts the Docker daemon and bridges the gap to the hardware.

**Step 2: The Base Image (`nvcr.io/nvidia/pytorch...`)**
Standard Python images (`python:3.10`) do not contain the massive C++ CUDA libraries required to talk to NVIDIA hardware. Instead of building these yourself (which takes hours), you pull pre-built CUDA base images. NVIDIA maintains an official registry (`nvcr.io`) with highly optimized base images for PyTorch, TensorFlow, and more.

**Step 3: The `--gpus all` Flag**
This flag tells the Docker daemon to attach the GPU bridge to this specific container. You can also allocate specific GPUs in a multi-GPU server (e.g., `--gpus '"device=0,1"'` will only give the container access to the first two GPUs, leaving the rest free for other containers).

### 5. ASCII Data Flow

```text
    Host Server (Physical Machine)
+-------------------------------------------------------------+
|                                                             |
|  [ NVIDIA RTX 4090 Hardware ]                               |
|              ^                                              |
|              | (PCIe Bus)                                   |
|              v                                              |
|  [ Host OS NVIDIA Drivers ]                                 |
|              ^                                              |
|              |                                              |
|  [ NVIDIA Container Toolkit ] <---- (Docker Daemon Bridge)  |
|              ^                                              |
|              | (--gpus all)                                 |
+--------------|----------------------------------------------+
               v
+-------------------------------------------------------------+
| Docker Container                                            |
|                                                             |
|  [ CUDA Toolkit Libraries ]  (From Base Image)              |
|              ^                                              |
|              |                                              |
|  [ PyTorch / vLLM Python Code ] (AI Workload)               |
+-------------------------------------------------------------+
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Installing NVIDIA drivers *inside* your Dockerfile using `apt-get install nvidia-driver`. Never do this! Drivers are deeply tied to the specific Linux kernel running on the host machine. The driver must live on the Host. The container only needs the CUDA *Toolkit* (which is provided by the base image).

**Pro Tip:** For modern LLM (Large Language Model) serving in production, raw PyTorch is too slow. Use an engine like **vLLM** or **TensorRT-LLM**. These engines have official Docker images (`vllm/vllm-openai:latest`) that are already optimized with the correct CUDA dependencies. You just run them with `--gpus all` and map your model weights folder using a volume mount (`-v`)!

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Objective:** You want to run the official CUDA base image provided by NVIDIA (not PyTorch, just raw CUDA). The image is `nvidia/cuda:11.8.0-base-ubuntu22.04`. Run this container interactively, giving it access to all GPUs, and run the `nvidia-smi` command to prove it worked.

```bash
docker run -it --rm --gpus all nvidia/cuda:11.8.0-base-ubuntu22.04 nvidia-smi
```
*If your host is configured correctly, this will print the classic NVIDIA hardware table showing your GPU name, VRAM usage, and CUDA version.*
</details>

### Level 2: Real-World
**Objective:** You are using `docker-compose` to orchestrate a backend API and an AI inference worker. Add the required configuration to the `worker` service in this `docker-compose.yml` to give it access to all GPUs.

```yaml
version: '3.8'
services:
  worker:
    image: my-pytorch-worker:latest
    # Add GPU configuration here!
```

<details>
<summary><b>Click for Hint</b></summary>
In docker-compose, GPU configuration is added under the `deploy` key, then `resources`, then `reservations`, then `devices`.
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

```yaml
version: '3.8'
services:
  worker:
    image: my-pytorch-worker:latest
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
```
*This yaml block is the compose equivalent of the `--gpus all` CLI flag.*
</details>

### Level 3: Boss Level
**Objective:** Write a complete `docker-compose.yml` to deploy an OpenAI-compatible API using the `vLLM` engine.
1. Use the image `vllm/vllm-openai:latest`.
2. Give the container access to all GPUs.
3. Map host port 8000 to container port 8000.
4. Mount a named volume `model_weights` to `/root/.cache/huggingface` in the container (so downloaded multi-gigabyte models aren't lost if the container restarts).
5. Override the `command` to run: `--model facebook/opt-125m` (a tiny model suitable for testing).

<details>
<summary><b>Click for Hint</b></summary>
Combine the `deploy` block from Level 2 with the `ports`, `volumes`, and `command` directives you learned in Module 2!
</details>

<details>
<summary><b>Click for Solution Walkthrough</b></summary>

```yaml
version: '3.8'

services:
  vllm-server:
    image: vllm/vllm-openai:latest
    command: --model facebook/opt-125m
    ports:
      - "8000:8000"
    volumes:
      - model_weights:/root/.cache/huggingface
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]

volumes:
  model_weights:
```
*You can now bring this up with `docker-compose up -d`. The container will use the GPU to incredibly rapidly serve requests at `http://localhost:8000/v1/completions`!*
</details>

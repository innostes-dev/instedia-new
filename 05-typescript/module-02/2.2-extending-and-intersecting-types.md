# 2.2 Extending and Intersecting Types: Building the Hierarchy

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You have a `User` object. Now you need an `Admin` object that has all the same properties as `User`, but adds an `accessLevel`. Copying and pasting the `id`, `email`, and `name` properties from `User` to `Admin` violates DRY (Don't Repeat Yourself). When you inevitably need to add a `phoneNumber` to all users, you have to manually update every duplicate interface, risking mistakes.

### 2. Plain English Metaphor (The What)
Think of extending types like a base model of a car versus a luxury model. The `BaseCar` interface has wheels and an engine. To create a `LuxuryCar`, you don't rebuild the wheels and engine; you just say `LuxuryCar extends BaseCar` and then add the heated seats. Intersections (`&`) are like mashing two completely different machines together—like taking a `Camera` and a `Phone` and smashing them together to guarantee the resulting object has the properties of both (a Smartphone).

### 3. Complete Runnable Code: Role-Based Access Control (RBAC) Hierarchies

**Extending Interfaces (`extends`)**
```typescript
interface BaseEntity {
  id: string;
  createdAt: Date;
}

// User INHERITS id and createdAt, and adds email.
interface User extends BaseEntity {
  email: string;
}

// Admin INHERITS id, createdAt, and email, and adds permissions.
interface Admin extends User {
  permissions: string[];
}

const sysAdmin: Admin = {
  id: "a1",
  createdAt: new Date(),
  email: "admin@system.com",
  permissions: ["DELETE_USER", "BAN_IP"]
};
```

**Intersecting Types (`&`)**
```typescript
type HasBilling = { creditCard: string; tier: string };
type HasShipping = { address: string; zip: string };

// Customer MUST have properties of BOTH HasBilling AND HasShipping
type Customer = HasBilling & HasShipping & { name: string };

const validCustomer: Customer = {
  name: "Alice",
  creditCard: "1234-5678-9012-3456",
  tier: "Gold",
  address: "123 Main St",
  zip: "12345"
};
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: The Base Contract (`BaseEntity`)**
    We extract common fields (`id`, `createdAt`) into a root interface. This is highly common for database models.
*   **Step 2: Extending (`extends`)**
    When `interface User extends BaseEntity`, it effectively copies the fields from `BaseEntity` into `User` behind the scenes.
*   **Step 3: Intersecting (`&`)**
    Type intersections are a way of combining multiple types. `A & B` means the resulting object must satisfy *both* A and B simultaneously.
*   **Step 4: Choosing between the two**
    Use `extends` for hierarchical, "Is-A" relationships (An Admin *is a* User). Use `&` (intersections) for compositional, "Has-A" relationships (A Customer *has* Billing logic and *has* Shipping logic).

### 5. ASCII Data Flow

```text
[BaseEntity] (id, date)
      ^
      | (extends)
   [User] (email)
      ^
      | (extends)
  [Admin] (permissions)  ---> Final Object requires: id, date, email, permissions
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Duplicating fields across interfaces because you don't know how to extract a base interface.
*   **Pro Tip:** If you find yourself extending an interface, but you actually want to *remove* a property from the base interface, you are doing it wrong. Extensions can only add requirements, not subtract them (we will learn how to subtract later using `Omit`).

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Create an interface `Animal` with a `name` (string). Create a `Dog` interface that extends `Animal` and adds a `bark` method (returns void).

<details>
<summary>Hint</summary>
`interface Dog extends Animal`
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
interface Animal {
  name: string;
}

interface Dog extends Animal {
  bark(): void;
}

const myDog: Dog = {
  name: "Rex",
  bark() {
    console.log("Woof!");
  }
};
```
*Walkthrough:* Simple inheritance. `Dog` gets `name` from `Animal` and adds its own method.
</details>

### Level 2: Real-World
**Task:** You have `type APIResponse = { status: number, data: unknown }`. You also have `type Pagination = { page: number, totalPages: number }`. Create a new type `PaginatedResponse` that intersects both of these, and then write a function that takes a `PaginatedResponse` and logs the current page and status.

<details>
<summary>Hint</summary>
Use `type PaginatedResponse = APIResponse & Pagination;`
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
type APIResponse = { status: number, data: unknown };
type Pagination = { page: number, totalPages: number };

type PaginatedResponse = APIResponse & Pagination;

function logResponse(res: PaginatedResponse) {
  console.log(`Status: ${res.status}, Page ${res.page} of ${res.totalPages}`);
}
```
*Walkthrough:* Intersection (`&`) beautifully combines unrelated concerns (the HTTP response shape and the pagination metadata) into a single, cohesive type requirement.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Create a base `Document` interface (id, createdAt).
Create a type `Shareable` with an array of `sharedWith` strings (emails).
Create an `Invoice` interface that extends `Document` and adds `amount` (number).
Finally, create a type `SharedInvoice` that intersects `Invoice` and `Shareable`.
Write a function `processSharedInvoice` that takes a `SharedInvoice` and verifies that the `amount` is > 0 and the `sharedWith` array has at least one email.

<details>
<summary>Hint</summary>
Build them up step by step: `interface`, `type`, `interface extends`, `type = ... & ...`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
interface Document {
  readonly id: string;
  createdAt: Date;
}

type Shareable = {
  sharedWith: string[];
};

interface Invoice extends Document {
  amount: number;
}

type SharedInvoice = Invoice & Shareable;

function processSharedInvoice(invoice: SharedInvoice): boolean {
  if (invoice.amount <= 0) {
    console.error("Invalid amount");
    return false;
  }

  if (invoice.sharedWith.length === 0) {
    console.error("Invoice must be shared with someone");
    return false;
  }

  console.log(`Invoice ${invoice.id} processed safely.`);
  return true;
}
```
*Walkthrough:* This perfectly demonstrates combining OOP-style inheritance (`extends`) with functional-style composition (`&`). We built a complex data requirement entirely out of small, reusable, easily understandable blocks.
</details>

# 5.2 Generic Constraints and `keyof`: Restricting the Blueprint

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You write a generic function `function logId<T>(item: T) { console.log(item.id); }`. TypeScript throws an error: `Property 'id' does not exist on type 'T'`. Why? Because `T` could be *anything*. It could be a `number`, a `string`, or an object without an `id`. You need a way to tell TypeScript: "This function is generic, BUT the type you pass in *must* have at least these specific properties."

### 2. Plain English Metaphor (The What)
A standard Generic `<T>` is an open casting call—anyone can audition. A Generic Constraint (`<T extends ...>`) is a casting call with requirements: "Anyone can audition, *as long as* they can sing and dance."
The `keyof` operator is like looking at a dictionary and generating a strict list of all the words defined in it. Combined, they let you write functions that safely pluck dynamic properties off dynamic objects.

### 3. Complete Runnable Code: Safe Key-Value Object Plucker

```typescript
// 1. Generic Constraints (`extends`)
interface HasId {
  id: string | number;
}

// T can be anything, AS LONG AS it has an `id` property
function logIdentity<T extends HasId>(item: T): T {
  console.log(`Processing item with ID: ${item.id}`);
  return item;
}

logIdentity({ id: 99, name: "Alice" }); // OK
// logIdentity({ name: "Bob" }); // ERROR: Property 'id' is missing

// 2. The `keyof` Operator
interface User {
  id: number;
  email: string;
  role: string;
}

// `keyof User` creates a union of the keys: "id" | "email" | "role"
type UserKeys = keyof User;

// 3. Combining them: The Safe Plucker
// "K MUST be one of the keys of T"
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const myUser: User = { id: 1, email: "a@b.com", role: "admin" };

const emailValue = getProperty(myUser, "email"); // TS infers return type as `string`
const idValue = getProperty(myUser, "id");       // TS infers return type as `number`

// const badValue = getProperty(myUser, "password"); // ERROR: "password" is not a key of User
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: The `extends` Keyword in Generics**
    `T extends HasId` means that whatever type `T` ultimately is, it must fulfill the contract of `HasId`. It restricts the infinite possibilities of `T`.
*   **Step 2: The `keyof` Operator**
    `keyof Type` inspects a type and returns a string literal union of its keys.
*   **Step 3: The Magic Relationship (`K extends keyof T`)**
    This creates a dynamic relationship between two generics. `K` is constrained to whatever keys exist on the object `T` that was passed in.
*   **Step 4: Indexed Access Types (`T[K]`)**
    The return type `T[K]` tells TypeScript: "Look up the type of property `K` on object `T`, and return that exact type."

### 5. ASCII Data Flow

```text
getProperty({ name: "Alice", age: 30 }, "age")
       |                                   |
       v                                   v
 T is inferred as               K is constrained to
 { name: string, age: number }  "name" | "age"
                                           |
                                      "age" is valid!
                                           |
                              Return type T[K] -> T["age"] -> number
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Using `any` when writing object utility functions because mapping keys seems too hard.
*   **Pro Tip:** Memorize `<T, K extends keyof T>`. It is the secret password to writing advanced, deeply type-safe utility functions in TypeScript (especially useful in React for writing generic Table or Form components).

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Write a generic function `printLength<T>` that accepts an argument of type `T`. The function should log `arg.length`. Use a generic constraint to ensure that `T` has a `length` property of type `number`. Test it with a string and an array.

<details>
<summary>Hint</summary>
Create an interface `HasLength { length: number; }` and use `T extends HasLength`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
interface HasLength {
  length: number;
}

function printLength<T extends HasLength>(arg: T): void {
  console.log(arg.length);
}

printLength("hello"); // OK: String has .length
printLength([1, 2, 3]); // OK: Array has .length
// printLength(42); // ERROR: Number has no .length
```
*Walkthrough:* We constrained `T` so that the compiler guarantees `arg` will have a `length` property, making `arg.length` completely safe.
</details>

### Level 2: Real-World
**Task:** Create an interface `Product` (name: string, price: number, inStock: boolean).
Use `keyof Product` to create a type `ProductKeys`.
Write a function `updateProductKey` that takes a `Product`, a key, and a new value.
Can you figure out how to make sure the `newValue` matches the type expected by that specific key? (e.g., you can't pass `"true"` as a string if the key is `inStock`).

<details>
<summary>Hint</summary>
Use the exact pattern from the lesson: `<T, K extends keyof T>`. The `newValue` parameter should be typed as `T[K]`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
interface Product {
  name: string;
  price: number;
  inStock: boolean;
}

function updateProductKey<T, K extends keyof T>(obj: T, key: K, newValue: T[K]): void {
  obj[key] = newValue;
}

const p: Product = { name: "Laptop", price: 999, inStock: true };

updateProductKey(p, "price", 899); // OK
// updateProductKey(p, "price", "899"); // ERROR: Expected number, got string
// updateProductKey(p, "invalidKey", 123); // ERROR: invalidKey not in Product
```
*Walkthrough:* By tying the third parameter to `T[K]`, TypeScript ensures that if `K` is `"price"`, `newValue` *must* be a `number`. It maps the relationship perfectly.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Create a generic function `extractValues<T, K extends keyof T>(arr: T[], key: K): T[K][]`.
It takes an array of objects, and a specific key.
It returns an array containing just the values of that key from all the objects.
Test it by extracting all `email` strings from an array of `User` objects.

<details>
<summary>Hint</summary>
Use the `.map()` function inside your implementation: `return arr.map(item => item[key]);`
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
interface User {
  id: number;
  email: string;
}

function extractValues<T, K extends keyof T>(arr: T[], key: K): T[K][] {
  return arr.map(item => item[key]);
}

const users: User[] = [
  { id: 1, email: "alice@example.com" },
  { id: 2, email: "bob@example.com" }
];

// emails is strongly typed as string[]
const emails = extractValues(users, "email");

// ids is strongly typed as number[]
const ids = extractValues(users, "id");
```
*Walkthrough:* This is a production-grade utility function. By using generics and constraints, one single function can safely extract strings, numbers, or even complex nested objects from an array of data, while maintaining 100% type safety.
</details>

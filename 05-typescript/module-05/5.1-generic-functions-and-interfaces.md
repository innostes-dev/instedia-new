# 5.1 Generic Functions and Interfaces: Reusable Type-Safe Logic

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You write a function that wraps an API call and parses JSON. `function apiGet(url) { return fetch(url).then(r => r.json()); }`. The return type of `r.json()` is `any`. So, your beautiful, type-safe app is immediately polluted with `any` as soon as it talks to the network. You could write a specific `getUser` and `getProduct` function, but writing 50 identical functions just to change the return type is miserable.

### 2. Plain English Metaphor (The What)
Generics are like a 3D printer. The 3D printer (the generic function) doesn't know what it's going to print until you feed it a specific blueprint (the type argument). If you feed it a blueprint for a mug (`<Mug>`), it prints a mug. If you feed it a blueprint for a toy (`<Toy>`), it prints a toy. The internal mechanics of the printer remain exactly the same, but the output strictly matches the blueprint you provided.

### 3. Complete Runnable Code: Universal Generic API Client

```typescript
// The Type Variable 'T' is the "Blueprint"
// We declare it in the angle brackets <T> before the parameter list.
// We use it as the return type: Promise<T>
async function apiGet<T>(url: string): Promise<T> {
  const response = await fetch(url);

  if (!response.ok) {
    throw new Error("Network request failed");
  }

  // We have to assert the type here because JSON.parse returns `any`
  // (In Module 7, we'll learn to validate this safely with Zod)
  const data: T = await response.json();
  return data;
}

// Defining our Blueprints
interface UserProfile {
  id: number;
  name: string;
}

interface ProductDetails {
  sku: string;
  price: number;
}

async function run() {
  // We pass the Blueprint <UserProfile> to the 3D Printer
  const user = await apiGet<UserProfile>("/api/users/1");
  console.log(user.name); // TS knows `name` exists and is a string

  // We pass a different Blueprint <ProductDetails>
  const product = await apiGet<ProductDetails>("/api/products/a1");
  console.log(product.price); // TS knows `price` exists and is a number
}
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: The Type Parameter `<T>`**
    When declaring `function name<T>()`, you are creating a placeholder type named `T`. You can name it anything (`<Type>`, `<ItemType>`), but `T` is the convention.
*   **Step 2: Using the Placeholder**
    You can use `T` anywhere inside the function signature or body: as a parameter type (`(arg: T)`), a return type (`: T`), or a variable type (`let x: T`).
*   **Step 3: Supplying the Argument**
    When calling the function, you provide the actual type inside angle brackets: `apiGet<User>(...)`. TypeScript replaces every instance of `T` with `User` for that specific function call.

### 5. ASCII Data Flow

```text
apiGet<UserProfile>("/users/1")
      |
      v
(TS secretly rewrites the signature just for this call)
async function apiGet(url: string): Promise<UserProfile>
      |
      v
Returns: { id: 1, name: "Alice" } (Strongly Typed!)
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Naming generics meaningless letters like `<T, U, V>` when you have multiple generics, making the code unreadable.
*   **Pro Tip:** If you have more than one generic, give them descriptive names! `function mapData<InputType, OutputType>(...)` is much better than `<T, U>`.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Write a generic function `wrapInArray<T>` that takes a single value of type `T` and returns an array containing that value `[value]`. The return type should be `T[]`. Test it with a number and a string.

<details>
<summary>Hint</summary>
`function wrapInArray<T>(value: T): T[] { ... }`
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
function wrapInArray<T>(value: T): T[] {
  return [value];
}

const numArr = wrapInArray<number>(5);      // Inferred as number[]
const strArr = wrapInArray("hello");        // TS can infer <string> from the argument!
```
*Walkthrough:* Notice in the second call, we didn't explicitly write `<string>`. TypeScript's inference engine is smart enough to see `"hello"` is a string, and automatically deduces that `T` must be `string`.
</details>

### Level 2: Real-World
**Task:** Create a generic Interface `APIResponse<DataT>`. It should have `status: number`, and `data: DataT`. Create two functions that return this interface: one returning an array of strings, and another returning a single boolean.

<details>
<summary>Hint</summary>
`interface APIResponse<DataT> { ... }`. When using it as a return type, write `APIResponse<string[]>` and `APIResponse<boolean>`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
interface APIResponse<DataT> {
  status: number;
  data: DataT;
}

function getNames(): APIResponse<string[]> {
  return { status: 200, data: ["Alice", "Bob"] };
}

function checkAccess(): APIResponse<boolean> {
  return { status: 200, data: true };
}
```
*Walkthrough:* Generics aren't just for functions. You can make interfaces generic too! This is the standard way to model wrapped API responses across entire codebases.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Create a generic function `getFirstSafe<T>` that takes an array of `T`.
If the array is empty, it returns `undefined`.
Otherwise, it returns the first element.
The return type should precisely represent this.
Then, test it on an array of Discriminated Union objects (e.g., `Shape[]` from 4.1).

<details>
<summary>Hint</summary>
The parameter is `arr: T[]`. The return type will be a union of `T | undefined`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
interface Square { kind: "square"; size: number; }
interface Circle { kind: "circle"; radius: number; }
type Shape = Square | Circle;

// T represents the item type in the array
function getFirstSafe<T>(arr: T[]): T | undefined {
  if (arr.length === 0) {
    return undefined;
  }
  return arr[0];
}

const shapes: Shape[] = [{ kind: "square", size: 10 }];
const first = getFirstSafe(shapes); // Type is: Shape | undefined

if (first) { // Type Narrowing!
  if (first.kind === "square") { // Discriminated Union Switch!
    console.log(first.size);
  }
}
```
*Walkthrough:* This brings everything together. The generic function handles the array logic cleanly. The return type forces the developer to handle `undefined` (using a truthy check to narrow). Once narrowed to `Shape`, they use the discriminator `kind` to access properties safely.
</details>

# 6.3 ReturnType, Parameters, Awaited: Unlocking Black Boxes

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
You are using a third-party library (like Redux or a complex SDK). They give you a function `createComplexStore()`, but they *didn't export* the Interface for what that function returns. Now you want to write a helper function that takes the store as an argument, but you don't know what type to annotate it with! `function helper(store: ???)`.

### 2. Plain English Metaphor (The What)
These utility types act as X-Ray machines.
- `ReturnType` looks at a function and says, "I don't care how it works, just tell me the exact shape of what comes out."
- `Parameters` looks at a function and says, "Tell me the exact blueprint of what I need to feed into it."
- `Awaited` looks at a `Promise` (a wrapped box) and says, "Unwrap the box and tell me what the actual prize inside is."

### 3. Complete Runnable Code: Extracting Types from Unexported SDKs

```typescript
// Imagine this is from a 3rd-party library that didn't export its interfaces
function initPaymentSDK(clientId: string, options: { debug: boolean }) {
  return {
    tokenize: () => "tok_123",
    charge: (amount: number) => true
  };
}

// 1. ReturnType<typeof FunctionName>
// We use `typeof` to get the function's type signature,
// and `ReturnType` extracts the object shape it returns!
type SDKInstance = ReturnType<typeof initPaymentSDK>;

// Now we can strictly type our own code using the extracted type!
function useSDK(sdk: SDKInstance) {
  sdk.charge(100);
}

// 2. Parameters<typeof FunctionName>
// Extracts the arguments as a Tuple (an array with strict types/lengths).
// SDKParams is now: [clientId: string, options: { debug: boolean }]
type SDKParams = Parameters<typeof initPaymentSDK>;

const myArgs: SDKParams = ["client_999", { debug: true }];
initPaymentSDK(...myArgs);

// 3. Awaited<Type>
// Imagine an async function returning a Promise.
async function fetchConfig() {
  return { timeout: 5000 };
}

// ReturnType gives us: Promise<{ timeout: number }>
type RawReturn = ReturnType<typeof fetchConfig>;

// Awaited unwraps the Promise to give us: { timeout: number }
type ConfigData = Awaited<RawReturn>;
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: The `typeof` keyword (Type Context)**
    In JavaScript, `typeof` runs at runtime. In TypeScript (when used inside a type definition), `typeof myFunction` extracts the *entire type signature* of the function statically.
*   **Step 2: `ReturnType`**
    It takes a function signature and returns whatever is on the right side of the `:` arrow.
*   **Step 3: `Awaited`**
    If a function is `async`, its ReturnType is *always* a `Promise<T>`. You usually don't want to pass a Promise around; you want the data inside. `Awaited<T>` recursively unwraps Promises until it hits the raw data type.

### 5. ASCII Data Flow

```text
function calc(x: number): string { ... }
             |              |
Parameters<typeof calc>   ReturnType<typeof calc>
             |              |
         [number]        string
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Manually re-typing complex objects returned by third-party libraries because they forgot to export the interface. `interface MyHack { ... }`. If the library updates, your hack breaks silently.
*   **Pro Tip:** Use `ReturnType<typeof ...>` extensively when building React Redux apps (e.g., extracting the `RootState` type from the `configureStore` function). It creates perfectly synchronized types that update automatically when you add new reducers.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Write a simple function `getUser()` that returns `{ id: 1, name: "Alice" }`.
Use `ReturnType` and `typeof` to create a type `ExtractedUser`.
Create a variable of type `ExtractedUser` and assign a valid object to it.

<details>
<summary>Hint</summary>
`type ExtractedUser = ReturnType<typeof getUser>;`
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
function getUser() {
  return { id: 1, name: "Alice" };
}

// ExtractedUser is now strictly { id: number; name: string; }
type ExtractedUser = ReturnType<typeof getUser>;

const user: ExtractedUser = {
  id: 2,
  name: "Bob"
};
```
*Walkthrough:* We didn't have to define an interface! TS inferred the return shape of `getUser` and we grabbed it using the X-Ray tool.
</details>

### Level 2: Real-World
**Task:** You are wrapping a legacy library function `function drawChart(elementId: string, data: number[], animate: boolean)`.
You want to write an `executeLater` function that takes exactly the same arguments as `drawChart` and stores them.
Use `Parameters<typeof drawChart>` to type your arguments.

<details>
<summary>Hint</summary>
`Parameters` returns a tuple (array). You can type a rest parameter `...args: Parameters<typeof drawChart>`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
function drawChart(elementId: string, data: number[], animate: boolean) {
  // complex legacy logic
}

type DrawArgs = Parameters<typeof drawChart>;

function executeLater(...args: DrawArgs) {
  console.log("Will execute later with:", args);
}

// Strict typing based on the original function!
executeLater("canvas", [1, 2, 3], true);
// executeLater("canvas", "invalid", true); // ERROR
```
*Walkthrough:* This pattern is incredibly useful for creating debouncers, throttle wrappers, or event queues for functions without having to manually duplicate their parameter types.
</details>

### Level 3: Boss Level
**Task:** (Cumulative)
1. Create an async function `async function fetchDbUser()` that returns `{ uuid: "abc", role: "admin" }`.
2. Create a type `DbUser` that extracts the *unwrapped* return type of that function (using `ReturnType` and `Awaited`).
3. Now, create a type `PublicDbUser` that uses `Omit` to remove the `role` property from the extracted `DbUser`.

<details>
<summary>Hint</summary>
`type DbUser = Awaited<ReturnType<typeof fetchDbUser>>;` Then wrap that in `Omit`.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
async function fetchDbUser() {
  return { uuid: "abc", role: "admin" };
}

// 1. typeof fetchDbUser -> () => Promise<{ uuid: string, role: string }>
// 2. ReturnType -> Promise<{ uuid: string, role: string }>
// 3. Awaited -> { uuid: string, role: string }
type DbUser = Awaited<ReturnType<typeof fetchDbUser>>;

// 4. Omit -> { uuid: string }
type PublicDbUser = Omit<DbUser, "role">;

const safeClientPayload: PublicDbUser = {
  uuid: "xyz-123"
  // role is banned here!
};
```
*Walkthrough:* We just combined four different advanced TypeScript concepts into a single fluid pipeline. We inspected a black-box async function, unwrapped its data, sculpted it to hide sensitive information, and created a perfectly safe DTO—all without writing a single manual interface.
</details>

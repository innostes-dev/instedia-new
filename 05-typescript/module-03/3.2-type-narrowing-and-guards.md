# 3.2 Type Narrowing and Guards: Interrogating Your Data

## Phase A: The Core Concept

### 1. Real-World Pain Point (The Why)
In the previous lesson, we learned that if a variable is `string | number`, you can't call `.toUpperCase()` on it because numbers don't have that method. You are stuck holding a mystery box. If you just forcefully cast it (`as string`), you might cause a runtime crash if it was actually a number. You need a safe way to figure out what's inside the box.

### 2. Plain English Metaphor (The What)
Type Narrowing is like playing a game of "Guess Who?". You ask the compiler yes/no questions ("Is it a string?", "Does it have this property?"). With every "Yes" or "No", TypeScript eliminates possibilities (flips down the faces on the board) until it is 100% certain what type it's dealing with.

### 3. Complete Runnable Code: Universal Value Formatter

```typescript
// Type Guards: typeof, instanceof, in

class DateManager {
  dateObj = new Date();
}

function formatUniversalValue(value: string | number | DateManager | { customFormat: boolean }) {
  // 1. Narrowing primitives with `typeof`
  if (typeof value === "string") {
    // TS knows it's a string here
    return value.trim().toUpperCase();
  }

  if (typeof value === "number") {
    // TS knows it's a number here
    return `$${value.toFixed(2)}`;
  }

  // 2. Narrowing classes with `instanceof`
  if (value instanceof DateManager) {
    // TS knows it's a DateManager object here
    return value.dateObj.toISOString();
  }

  // 3. Narrowing plain objects with the `in` operator
  if ("customFormat" in value) {
    // TS knows it's the { customFormat: boolean } object here
    return `Custom formatted: ${value.customFormat}`;
  }

  // 4. The Exhaustive fallback
  // If we reach here, we forgot to handle a type!
  throw new Error("Unknown value type");
}
```

### 4. Progressive Step-by-Step Breakdown

*   **Step 1: The `typeof` Guard**
    Used exclusively for basic JavaScript primitives (`string`, `number`, `boolean`, `symbol`, `bigint`, `undefined`). `typeof null` is notoriously `"object"`, so be careful!
*   **Step 2: The `instanceof` Guard**
    Used to check if an object was created by a specific `class`. It does *not* work for TypeScript `interfaces` (because interfaces don't exist at runtime).
*   **Step 3: The `in` Operator Guard**
    Used for plain JavaScript objects. `if ("key" in obj)` checks if a property exists. If it does, TypeScript assumes the object is the specific type from the union that has that property.
*   **Step 4: Control Flow Analysis**
    TypeScript watches your `if/else` branches. When you `return` inside an `if` block, TypeScript removes that type from the union for the rest of the function.

### 5. ASCII Data Flow

```text
value: (string | number)
        |
    if (typeof === 'string')
       /                     (TRUE)               (FALSE)
   return             value is now narrowed
   upper()            to ONLY (number)!
```

### 6. Noob Trap vs Pro Tip
*   **Noob Trap:** Using Type Assertions (`value as string`) instead of Narrowing. Assertions tell the compiler to shut up and trust you, which defeats the purpose of TS and causes crashes.
*   **Pro Tip:** Let TypeScript's Control Flow Analysis do the heavy lifting. Use early `return` statements inside your type guards to keep your code flat and narrow types automatically for the rest of the function scope.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Write a function `doubleOrRepeat` that takes a `value: string | number`. If it's a number, multiply it by 2. If it's a string, return the string concatenated with itself (e.g., "ha" -> "haha").

<details>
<summary>Hint</summary>
Use the `typeof` operator.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
function doubleOrRepeat(value: string | number): string | number {
  if (typeof value === "number") {
    return value * 2;
  }
  return value + value; // TS knows it MUST be a string here!
}
```
*Walkthrough:* Because we return early in the `number` branch, TypeScript deduces that if execution reaches the last line, `value` can only be a `string`.
</details>

### Level 2: Real-World
**Task:** You are handling API responses.
`type Success = { status: "ok", data: string[] };`
`type Failure = { status: "error", code: number };`
Write a function `handleResponse(res: Success | Failure)` that uses the `in` operator to check if `data` exists. If it does, print the first item. If not, print the error code.

<details>
<summary>Hint</summary>
`if ("data" in res)`
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
type Success = { status: "ok", data: string[] };
type Failure = { status: "error", code: number };

function handleResponse(res: Success | Failure) {
  if ("data" in res) {
    console.log(res.data[0]); // TS knows this is Success
  } else {
    console.log(res.code);    // TS knows this is Failure
  }
}
```
*Walkthrough:* The `in` operator checks for the unique property. Once inside the `if` block, TS statically types `res` as `Success`. In the `else` block, by process of elimination, it must be `Failure`.
</details>

### Level 3: Boss Level
**Task:** (Cumulative) Create a system to handle events.
1. `class ClickEvent { x: number; y: number }`
2. `interface ScrollEvent { deltaY: number }`
3. `type TextEvent = string;`
Write a function `processEvent(event: ClickEvent | ScrollEvent | TextEvent)`.
- If it's a TextEvent, log the string.
- If it's a ClickEvent, log x and y.
- If it's a ScrollEvent, log deltaY.
Use the correct guards for each!

<details>
<summary>Hint</summary>
Use `typeof` for strings, `instanceof` for classes, and `in` for interfaces/plain objects.
</details>

<details>
<summary>Solution Walkthrough</summary>

```typescript
class ClickEvent {
  constructor(public x: number, public y: number) {}
}

interface ScrollEvent {
  deltaY: number;
}

type TextEvent = string;

function processEvent(event: ClickEvent | ScrollEvent | TextEvent) {
  if (typeof event === "string") {
    console.log(`Text: ${event}`);
    return;
  }

  if (event instanceof ClickEvent) {
    console.log(`Clicked at ${event.x}, ${event.y}`);
    return;
  }

  if ("deltaY" in event) {
    console.log(`Scrolled ${event.deltaY}`);
    return;
  }
}
```
*Walkthrough:* This challenge forces you to choose the right tool for the job. `typeof` handles the primitive. `instanceof` handles the instantiated class. `in` handles the plain object matching an interface.
</details>

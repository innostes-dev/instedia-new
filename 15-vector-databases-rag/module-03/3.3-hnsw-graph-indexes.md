# 3.3 HNSW Graph Indexes

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
IVF (Inverted File) is fast, but it has a problem: it requires a "training" phase to find the centroids. If your database is constantly adding new vectors (streaming data), the old centroids become obsolete, and you have to pause everything to expensively retrain the index. We need a data structure that is blazing fast, highly accurate, and allows for *dynamic inserts* without ever needing to be "trained".

### 2. Plain English Metaphor (The What)
**HNSW (Hierarchical Navigable Small World)** is like navigating the highway system.
- **Top Layer (Interstates):** You want to go from New York to a tiny street in Los Angeles. You don't use local roads. You jump on a massive Interstate highway that takes huge leaps across the country (navigating only a few major nodes).
- **Middle Layers (State Highways):** Once you are near LA, you drop down to regional highways to get to the right neighborhood.
- **Bottom Layer (Local Roads):** Finally, you drop down to the street level and check house-by-house.
HNSW builds a multi-layered graph where the top layers have very few, long-distance connections, and the bottom layer contains every vector with short-distance connections.

### 3. Complete Runnable Code
Let's see HNSW in action using `hnswlib`, the industry-standard C++ library used under the hood by ChromaDB and others.

```python
# pip install hnswlib numpy
import hnswlib
import numpy as np
import time

# 1. Setup
dim = 128
num_elements = 100_000

# Generating sample data
data = np.float32(np.random.random((num_elements, dim)))
ids = np.arange(num_elements)

# 2. Initializing HNSW Index
print("--- Building HNSW Index ---")
# space='l2' means Euclidean distance.
p = hnswlib.Index(space='l2', dim=dim)

# M: Max number of connections per node (The "streets" connecting houses)
# ef_construction: Size of the dynamic list during index building (Higher = better quality, slower build)
p.init_index(max_elements=num_elements, ef_construction=200, M=16)

# 3. Adding data (Notice: NO TRAINING REQUIRED!)
start = time.time()
p.add_items(data, ids)
print(f"Index built in {time.time() - start:.4f} seconds")

# 4. Querying
print("\n--- Querying HNSW ---")
query_data = np.float32(np.random.random((1, dim)))

# ef: Size of the dynamic list during search (Higher = better recall, slower search)
# ef MUST be >= k (number of neighbors requested)
p.set_ef(50)

start = time.time()
labels, distances = p.knn_query(query_data, k=5)
print(f"Search Time: {time.time() - start:.6f} seconds")
print(f"Top 5 IDs: {labels[0]}")
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Parameters**
HNSW is tuned by three variables:
- `M`: The maximum number of edges a node can have in the graph. Higher `M` means a denser web, better for high-dimensionality data, but uses more RAM.
- `ef_construction`: How hard the algorithm works to find the perfect connections when *inserting* data.
- `ef` (Search): How far the algorithm expands its search radius when *querying* data.

**Step 2: Dynamic Insertion**
Unlike Faiss IVF which requires `index.train(data)`, HNSW immediately accepts `.add_items()`. It dynamically weaves the new vector into the graph, promoting it to higher layers based on random probability.

**Step 3: Graph Traversal Search**
When querying, the algorithm starts at a single "entry point" at the very top layer. It greedily hops to the neighbor closest to the query. When it can't find a closer neighbor, it drops down a layer. It repeats this until it reaches the bottom layer (Layer 0), yielding the nearest neighbors.

### 5. ASCII Data Flow

```text
Query arrives.

Layer 2 (Few nodes):  [Entry] -----> [Node A] (Drops down)
                                        |
Layer 1 (More nodes):                   v
                                     [Node A] -> [Node B] -> [Node C] (Drops down)
                                                                |
Layer 0 (All nodes):                                            v
                                                             [Node C] -> [Node D] (Winner!)
```

### 6. Noob Trap vs Pro Tip
- **Noob Trap:** Using HNSW in environments with extremely limited RAM. HNSW stores both the vectors *and* the massive graph of connections in memory. It uses significantly more memory than IVF.
- **Pro Tip:** Tune `ef_construction` to 200-400 for production indexes. It slows down insertion, but you only insert once. High `ef_construction` guarantees high recall at extremely fast search speeds. During search, you can tweak `ef` on the fly to balance QPS (Queries Per Second) and accuracy.

### Level 2: Real-World
**Challenge:** Tuning the Search `ef`. The `ef` parameter controls the speed/accuracy tradeoff during querying. Write a loop that tests `ef` values of `[10, 50, 100, 500]`. Run a query batch of 100 vectors for each `ef` value and print the total time taken.
<details>
<summary>Hint</summary>
Use `p.set_ef(ef_val)`. Time `p.knn_query(batch, k=5)`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
query_batch = np.float32(np.random.random((100, dim)))

for ef_val in [10, 50, 100, 500]:
    p.set_ef(ef_val)
    start = time.time()
    p.knn_query(query_batch, k=5)
    duration = time.time() - start
    print(f"ef={ef_val:3d} | Search Time: {duration:.4f}s")
```
You will see that as `ef` increases, search time increases. In production, you find the lowest `ef` that still yields 99% recall.
</details>

### Level 3: Boss Level
**Challenge:** Serialization. Production indexes must survive server reboots. Save the HNSW index to disk as `"my_index.bin"`. Then, initialize a completely new `hnswlib.Index` object, and load the index from the binary file. Run a query on the loaded index to prove it works.
<details>
<summary>Hint</summary>
Use `p.save_index("my_index.bin")`. Then `p2 = hnswlib.Index(space='l2', dim=dim)`. Then `p2.load_index("my_index.bin", max_elements=num_elements)`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
# Save to disk
p.save_index("my_index.bin")
print("Index saved to disk.")

# Simulate server reboot
del p

# Load from disk
print("Loading index from disk...")
p2 = hnswlib.Index(space='l2', dim=dim)
p2.load_index("my_index.bin", max_elements=num_elements)

# Verify it works
p2.set_ef(50)
labels, distances = p2.knn_query(query_data, k=5)
print(f"Loaded Index Top 5 IDs: {labels[0]}")
```
This is how stateful vector databases (like Milvus or Qdrant) persist data to disk while keeping the graph available.
</details>

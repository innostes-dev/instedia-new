# 3.2 Inverted File Index (IVF)

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
We know that grouping vectors into "buckets" (clusters) makes search faster. But how do we decide which vectors go into which buckets? If we group them randomly, we haven't solved anything—we'd still have to search every bucket. We need a mathematical way to partition the data so that similar vectors live in the same bucket, and we need a fast way to figure out which bucket a user's query belongs to.

### 2. Plain English Metaphor (The What)
Imagine a massive city (Vector Space) with 1 million residents (Vectors).
- **Training Centroids:** You build 100 post offices evenly spread throughout the city. The exact location of a post office is a "Centroid".
- **Voronoi Cells (Buckets):** Every resident is assigned to their absolute closest post office. The territory belonging to a post office is a Voronoi cell.
- **IVF Search:** A tourist (Query Vector) arrives in the city. To find the nearest residents, they don't check every house in the city. They just find the 1 closest post office (Centroid), and then only knock on the doors of the residents assigned to that specific post office.

### 3. Complete Runnable Code
Let's build a simple 2D representation of IVF using KMeans clustering to visualize how centroids are chosen.

```python
# pip install scikit-learn numpy
import numpy as np
from sklearn.cluster import KMeans

# 1. Create a tiny 2D dataset so we can understand it
# 10 vectors, 2 dimensions (X, Y coordinates)
data = np.array([
    [1.0, 1.1], [1.2, 1.0], [0.8, 1.2], # Group A (bottom left)
    [8.0, 8.1], [8.2, 8.0], [7.8, 8.2], # Group B (top right)
    [5.0, 1.1], [5.2, 1.0], [4.8, 1.2], # Group C (bottom middle)
    [9.0, 1.0]                          # Outlier
])

print("--- Step 1: Training Centroids (Post Offices) ---")
# We want 3 buckets (nlist=3)
nlist = 3
kmeans = KMeans(n_clusters=nlist, random_state=42, n_init=10)
kmeans.fit(data)

centroids = kmeans.cluster_centers_
for i, c in enumerate(centroids):
    print(f"Centroid {i}: {c}")

print("\n--- Step 2: Assigning Vectors to Buckets (Inverted Index) ---")
# Create our "Inverted File" - a dictionary mapping Centroid ID to a list of Vector IDs
ivf = {i: [] for i in range(nlist)}
assignments = kmeans.predict(data)

for vector_id, centroid_id in enumerate(assignments):
    ivf[centroid_id].append(vector_id)

for centroid_id, members in ivf.items():
    print(f"Bucket {centroid_id} contains Vectors: {members}")

print("\n--- Step 3: Querying the IVF ---")
query = np.array([[8.1, 7.9]]) # A query clearly near Group B

# Find the closest centroid to the query
closest_centroid_id = kmeans.predict(query)[0]
print(f"Query {query[0]} is closest to Centroid {closest_centroid_id}.")

# Only search within that bucket!
vectors_to_search = ivf[closest_centroid_id]
print(f"Instead of searching all 10 vectors, we only search: {vectors_to_search}")
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Training (K-Means)**
We use the K-Means algorithm to analyze the distribution of our data and place `nlist` (3) centroids right in the center of the densest areas. This step is computationally expensive but only happens occasionally (during index building).

**Step 2: The Inverted File (IVF)**
The "Inverted File" is literally just a Hash Map (Dictionary). The keys are the Centroid IDs, and the values are lists of Vector IDs that belong to that centroid's territory (Voronoi cell).

**Step 3: The Search**
When a query comes in, we calculate its distance to the 3 Centroids. It's closest to Centroid 1. We look up Key 1 in our dictionary and retrieve `[3, 4, 5]`. We now only perform mathematical distance calculations against those 3 vectors, completely ignoring the other 7.

### 5. ASCII Data Flow

```text
[ Training ] -> K-Means places Centroids (C0, C1, C2)

[ Indexing ]
Vector 4 -> Closest to C1 -> Add to IVF[1]
Vector 8 -> Closest to C2 -> Add to IVF[2]

[ IVF Hash Map in Memory ]
C0: [0, 1, 2]
C1: [3, 4, 5]
C2: [6, 7, 8, 9]

[ Querying ]
Query -> Compare to (C0, C1, C2) -> Closest is C1.
Fetch IVF[1] -> Search only [3, 4, 5].
```

### 6. Noob Trap vs Pro Tip
- **Noob Trap:** Setting `nlist` (number of buckets) too high or too low. If `nlist` is 1, you just have Exact Search. If `nlist` equals your total vector count, you are comparing the query to millions of centroids, which is also Exact Search.
- **Pro Tip:** A standard heuristic for `nlist` is `4 * sqrt(N)` where N is your total number of vectors. If you have 1,000,000 vectors, `nlist` should be around 4,000.

### Level 2: Real-World
**Challenge:** Implement the `nprobe` logic. Sometimes a query lands right on the border between two Voronoi cells. If you only search 1 bucket (`nprobe=1`), you might miss the true nearest neighbor that is sitting just across the border in the next bucket. Write logic to find the *Top 2* closest centroids to the query, and combine their lists.
<details>
<summary>Hint</summary>
Use `kmeans.transform(query)` to get the distances to *all* centroids. Use `np.argsort()` on that array to find the indices of the 2 smallest distances. Combine `ivf[closest1] + ivf[closest2]`.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
# distances to all 3 centroids
distances = kmeans.transform(query)[0]

# get indices of the top 2 closest centroids (nprobe=2)
top_2_centroids = np.argsort(distances)[:2]

print(f"Top 2 Centroids: {top_2_centroids}")
vectors_to_search = []
for c_id in top_2_centroids:
    vectors_to_search.extend(ivf[c_id])

print(f"Searching across borders (nprobe=2): {vectors_to_search}")
```
This is the core mechanic of `nprobe` in Faiss!
</details>

### Level 3: Boss Level
**Challenge:** Implement the final Exact Search step. You have the `vectors_to_search` list. Write a loop that calculates the exact Euclidean distance (L2) between the `query` and every vector in `data` that is listed in `vectors_to_search`. Print the ID of the single closest vector.
<details>
<summary>Hint</summary>
Loop over `vectors_to_search`. For each `vid`, get the vector `data[vid]`. Calculate L2 distance: `np.linalg.norm(query[0] - data[vid])`. Keep track of the minimum distance.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
best_id = -1
min_dist = float('inf')

for vid in vectors_to_search:
    target_vector = data[vid]
    # L2 Distance calculation
    dist = np.linalg.norm(query[0] - target_vector)

    if dist < min_dist:
        min_dist = dist
        best_id = vid

print(f"Ultimate Winner: Vector {best_id} at {data[best_id]} with distance {min_dist:.4f}")
```
You have just built a fully functional Approximate Nearest Neighbor IVF index from scratch.
</details>

# 2.4 Semantic Chunking by Structure

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Recursive character chunking is great for plain text, but it completely destroys structured documents like Markdown (GitHub READMEs) or HTML (Web pages). If a chunk boundary happens to fall immediately after a Markdown header (`### API Setup`), the header gets placed in Chunk 1, and the actual code instructions get placed in Chunk 2. The LLM retrieves Chunk 2 ("Run npm install..."), but has no idea *what* is being installed because the header was lost in the previous chunk.

### 2. Plain English Metaphor (The What)
Imagine reading a cookbook.
- **Recursive Chunking:** Ripping out pages exactly every 500 words. You might get the title "Chocolate Cake" on page 1, and the ingredients on page 2.
- **Semantic Structure Chunking:** Using the Table of Contents. You staple the Title, the Ingredients, and the Instructions together into one single packet per recipe, ensuring the context is never separated.

### 3. Complete Runnable Code
Let's build a Markdown Header Splitter. It identifies headers and groups all the content beneath that header into a single, highly-contextual chunk.

```python
import re

markdown_doc = """
# Getting Started with the Project

Welcome to the repo.

## Installation

To install, you must have Node.js.
Run `npm install`.

## Configuration

Set your `.env` file with API keys.

# API Reference

Use the `/v1/users` endpoint to get data.
"""

def markdown_header_chunker(md_text):
    # Regex to find markdown headers (e.g., #, ##, ###) and capture the title
    # Pattern: ^(#+)\s+(.*)
    lines = md_text.split('\n')

    chunks = []
    current_header = "Document Start"
    current_content = []

    for line in lines:
        header_match = re.match(r'^(#+)\s+(.*)', line)

        if header_match:
            # We found a new header! Save the previous chunk.
            if current_content:
                chunks.append({
                    "header": current_header,
                    "content": "\n".join(current_content).strip()
                })
                current_content = []

            # Update to the new header
            current_header = header_match.group(2) # The text of the header
        else:
            if line.strip(): # ignore purely empty lines
                current_content.append(line)

    # Save the final chunk
    if current_content:
        chunks.append({
            "header": current_header,
            "content": "\n".join(current_content).strip()
        })

    return chunks

print("--- Semantic Markdown Chunking ---")
structured_chunks = markdown_header_chunker(markdown_doc)

for i, chunk in enumerate(structured_chunks):
    print(f"\nChunk {i+1}:")
    print(f"Header Context: [{chunk['header']}]")
    print(f"Body:\n{chunk['content']}")
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Parsing by Lines and Regex**
Instead of looking at raw character counts, we parse the document line-by-line. We use a Regular Expression `^(#+)\s+(.*)` to detect if a line is a Markdown header (starting with `#`).

**Step 2: Grouping Content**
When we hit a normal line of text, we append it to a `current_content` list. All this text belongs to whatever the most recently seen header was.

**Step 3: Chunk Splitting at Structural Boundaries**
When we encounter a *new* header, we know the previous section is complete. We package the previous header and its accumulated content into a chunk, save it, and reset our buffers for the new section. The output chunks now perfectly map to the logical sections written by the human author.

### 5. ASCII Data Flow

```text
[ Markdown Input ]
# Installation
Run npm install.
## Config
Set .env keys.

[ Parsing Loop ]
  |-- Line 1: "# Installation" -> NEW SECTION! Header = "Installation"
  |-- Line 2: "Run npm install." -> Add to content.
  |-- Line 3: "## Config" -> NEW SECTION! Save previous chunk. Header = "Config"
  |-- Line 4: "Set .env keys." -> Add to content.

[ Final Output Chunks ]
Chunk 1: { Header: "Installation", Body: "Run npm install." }
Chunk 2: { Header: "Config", Body: "Set .env keys." }
```

### 6. Noob Trap vs Pro Tip
- **Noob Trap:** Putting raw HTML pages into a Vector DB. The LLM gets confused by `<div>` and `class="tailwind-utilities"` tags, wasting thousands of tokens on layout code rather than semantic meaning.
- **Pro Tip:** If scraping documentation sites, always use an HTML-to-Markdown converter (like `Turndown` or `BeautifulSoup`) *first*, and then use a Markdown Header Splitter to ingest the data into your RAG pipeline.

### Level 2: Real-World
**Challenge:** Track Header Hierarchy. If you see an `H1` (#), and then an `H2` (##), the H2 belongs to the H1. Modify the script to track the hierarchy so the chunk header for "Configuration" becomes `Getting Started with the Project > Configuration`.
<details>
<summary>Hint</summary>
You need a list `header_stack = []`. When you hit a header, count the `#` symbols using `len(header_match.group(1))`. If it's an H2 (level 2), truncate the stack to level 1, then append the new header. `>`.join(stack)` creates the breadcrumbs.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
# Simplified hierarchy tracker
current_hierarchy = {}

for line in lines:
    header_match = re.match(r'^(#+)\s+(.*)', line)
    if header_match:
        level = len(header_match.group(1))
        title = header_match.group(2)

        # Clear out any deeper levels
        current_hierarchy = {k: v for k, v in current_hierarchy.items() if k < level}
        current_hierarchy[level] = title

        # Build breadcrumbs
        breadcrumbs = " > ".join(current_hierarchy[k] for k in sorted(current_hierarchy.keys()))
        current_header = breadcrumbs
```
This is essential for massive document trees so deep subsections retain top-level context.
</details>

### Level 3: Boss Level
**Challenge:** What happens if the content under a single header is massive (e.g., 5000 tokens) and exceeds the embedding model limit? You must combine Structural Chunking with Recursive Character Chunking. Write pseudocode or implement a wrapper function that takes the output of `markdown_header_chunker` and runs any oversized bodies through the `recursive_chunker` (from module 2.3), re-attaching the header to every sub-chunk.
<details>
<summary>Hint</summary>
Loop over the `structured_chunks`. Check `if len(chunk['content']) > MAX_SIZE`. If yes, call `recursive_chunker(chunk['content'])`. Iterate over those sub-chunks, prepending `chunk['header']` to each one.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
def robust_markdown_ingestion(md_text, max_size):
    # 1. Structure split
    structured_chunks = markdown_header_chunker(md_text)

    final_ingestion_chunks = []

    for chunk in structured_chunks:
        header = chunk["header"]
        content = chunk["content"]

        # 2. Size check
        if len(content) > max_size:
            # 3. Recursive fallback for massive sections
            sub_chunks = recursive_chunker(content, max_size) # (from 2.3)
            for sub in sub_chunks:
                final_ingestion_chunks.append(f"[Context: {header}]\n{sub}")
        else:
            final_ingestion_chunks.append(f"[Context: {header}]\n{content}")

    return final_ingestion_chunks
```
This is the ultimate, production-grade text ingestion strategy. Structure first, size fallback second.
</details>

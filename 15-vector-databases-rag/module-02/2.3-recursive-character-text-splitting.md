# 2.3 Recursive Character Text Splitting

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
We established that chunking by pure characters is bad (cuts words in half) and chunking by sentences is better. But what if a paragraph has 20 short sentences that all relate to one idea? Splitting them up destroys the context. If the sentence "He pressed the red button" is separated from "The reactor initiated meltdown," the LLM won't understand what the button did. You need a hierarchy that tries to keep paragraphs together first, then falls back to sentences, then words.

### 2. Plain English Metaphor (The What)
Imagine you have to pack a beautifully constructed Lego castle into small shipping boxes.
- First, you try to put the whole castle in a box. (Too big!)
- Next, you detach the towers from the courtyard and pack whole towers. (If a tower fits, great!)
- If a tower is still too big, you break it down into floors.
- If a floor is too big, you break it down into individual bricks.
**Recursive Chunking** works down a hierarchy of separators (`\n\n` for paragraphs -> `\n` for lines -> `.` for sentences -> ` ` for words) until the piece is small enough to fit.

### 3. Complete Runnable Code
Let's build a simplified Recursive Character Text Splitter from scratch to understand how LangChain does it under the hood.

```python
text = """
The Apollo 11 mission was the first manned mission to land on the Moon. It was a massive success.

Neil Armstrong and Buzz Aldrin were the first humans to walk on the lunar surface. They collected lunar rocks.
Meanwhile, Michael Collins orbited above in the Command Module.

This event changed the course of history forever.
"""

def recursive_chunker(text, chunk_size, separators=["\n\n", "\n", ". ", " "]):
    """Recursively splits text using a hierarchy of separators."""

    # Base case: if it fits, return it
    if len(text) <= chunk_size:
        return [text]

    # Find the highest level separator that actually exists in the text
    good_separator = ""
    for sep in separators:
        if sep in text:
            good_separator = sep
            break

    # If no separators found, we have to force split by character (worst case)
    if good_separator == "":
        return [text[i:i+chunk_size] for i in range(0, len(text), chunk_size)]

    # Split the text by the chosen separator
    splits = text.split(good_separator)

    final_chunks = []
    current_chunk = ""

    for split in splits:
        # Re-add the separator if it's not a paragraph break, for readability
        item = split + good_separator if good_separator != "\n\n" else split

        # If adding this item exceeds the chunk size, we must flush the buffer
        if len(current_chunk) + len(item) > chunk_size:
            if current_chunk:
                final_chunks.append(current_chunk.strip())
            current_chunk = item
        else:
            current_chunk += item

    if current_chunk:
        final_chunks.append(current_chunk.strip())

    # Recursion step: check if any generated chunks STILL exceed chunk_size
    # (e.g., a massive paragraph with no \n\n but is over the limit)
    verified_chunks = []
    for chunk in final_chunks:
        if len(chunk) > chunk_size:
            # Drop the separator we just used, go to the next level down
            next_seps = separators[separators.index(good_separator)+1:]
            verified_chunks.extend(recursive_chunker(chunk, chunk_size, next_seps))
        else:
            verified_chunks.append(chunk)

    return verified_chunks

print("--- Recursive Chunking (Max 100 chars) ---")
chunks = recursive_chunker(text.strip(), chunk_size=100)
for i, c in enumerate(chunks):
    print(f"\nChunk {i+1} (Len: {len(c)}):\n{c}")
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Hierarchy of Separators**
We define `["\n\n", "\n", ". ", " "]`. The algorithm will always try to split by Double Newline (Paragraphs) first. It wants to keep paragraphs fully intact if possible.

**Step 2: Buffer Packing**
Once split into paragraphs, it tries to pack them into a chunk up to `chunk_size`. If Paragraph 1 and Paragraph 2 together are under the limit, they stay together!

**Step 3: The Recursive Fallback**
If a single paragraph is *larger* than `chunk_size`, the algorithm recursively calls itself on *just that paragraph*, but this time it moves down the hierarchy and tries to split it by `\n` (lines) or `. ` (sentences). This guarantees semantic cohesion at the highest possible level.

### 5. ASCII Data Flow

```text
Text (500 chars). Max Limit: 200 chars.

[ Try Sep: \n\n ] -> Yields: Para A (180c), Para B (300c)

[ Packing ]
  |-- Para A fits limit. (Chunk 1 = Para A)
  |-- Para B (300c) > Limit (200c). Must recurse!

      [ Recursive Call on Para B ]
      [ Try Sep: . ] -> Yields Sentence 1 (150c), Sentence 2 (150c)

      [ Packing ]
        |-- S1 fits limit. (Chunk 2 = S1)
        |-- S2 fits limit. (Chunk 3 = S2)

Final Output: Chunk 1, Chunk 2, Chunk 3.
```

### 6. Noob Trap vs Pro Tip
- **Noob Trap:** Using a flat separator like only `. ` (sentences) for everything. This rips apart short paragraphs that should remain contextually linked.
- **Pro Tip:** LangChain's `RecursiveCharacterTextSplitter` is the industry standard for general unstructured text ingestion. You rarely need to write it from scratch, but understanding the recursive `\n\n` fallback prevents you from misconfiguring it.

```python
# Inside the for loop:
for split in splits:

    if len(current_chunk) + len(item) > chunk_size:
        if current_chunk:
            final_chunks.append(current_chunk.strip())
        # OVERLAP: start the new chunk with the last item from the previous chunk
        current_chunk = (last_item if last_item else "") + item
    else:
        current_chunk += item

    last_item = item # track for next iteration
```

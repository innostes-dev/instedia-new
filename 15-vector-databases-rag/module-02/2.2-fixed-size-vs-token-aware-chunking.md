# 2.2 Fixed-Size vs Token-Aware Chunking

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Embedding models (like OpenAI's `text-embedding-3-small`) have strict limits on how much text they can process at once (e.g., 8191 tokens). If you try to feed a whole legal contract into the model, it crashes. Therefore, you must "chunk" the document. If you split the document blindly by character count (e.g., every 1000 characters), you will likely slice a word, a sentence, or a critical legal clause right in half, destroying the semantic meaning of that chunk.

### 2. Plain English Metaphor (The What)
Imagine you are packing books into moving boxes, and the boxes have a strict weight limit (token limit).
- **Fixed-Size (Character) Chunking:** Taking a chainsaw and cutting a stack of books right down the middle so exactly 50 lbs goes in each box. You just ruined a bunch of books.
- **Token-Aware / Semantic Chunking:** Carefully packing whole books until the box is nearly full. If the next book pushes it over the limit, you put it in the next box. The books (sentences/words) remain intact and readable.

### 3. Complete Runnable Code
Let's see the destruction caused by naive character chunking versus token-aware sentence chunking.

```python
# pip install tiktoken
import tiktoken
import textwrap

text = "The quick brown fox jumps over the lazy dog. A corporate merger between Company A and Company B is strictly prohibited under section 4b. However, exceptions apply."

# 1. Naive Fixed-Size Character Chunking
print("--- Naive Character Chunking (Cut every 40 chars) ---")
naive_chunks = textwrap.wrap(text, width=40, break_long_words=True)
for i, chunk in enumerate(naive_chunks[:3]):
    print(f"Chunk {i+1}: '{chunk}'")
# Notice how words and sentences are awkwardly broken.

# 2. Token-Aware Chunking (using OpenAI's tokenizer)
print("\n--- Token-Aware Chunking ---")
enc = tiktoken.get_encoding("cl100k_base") # standard tokenizer for GPT-4 / embeddings

def token_aware_chunker(text, max_tokens):
    sentences = text.replace("!", ".").split(". ")
    chunks = []
    current_chunk = ""
    current_tokens = 0

    for sentence in sentences:
        sentence = sentence.strip() + ". "
        sentence_tokens = len(enc.encode(sentence))

        # If adding this sentence exceeds our limit, start a new chunk
        if current_tokens + sentence_tokens > max_tokens and current_chunk:
            chunks.append(current_chunk.strip())
            current_chunk = ""
            current_tokens = 0

        current_chunk += sentence
        current_tokens += sentence_tokens

    if current_chunk:
        chunks.append(current_chunk.strip())
    return chunks

# Limit chunks to ~15 tokens to force splits
token_chunks = token_aware_chunker(text, max_tokens=15)
for i, chunk in enumerate(token_chunks):
    print(f"Chunk {i+1} ({len(enc.encode(chunk))} tokens): '{chunk}'")
# Sentences remain whole!
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Naive Character Splitting**
Using basic string manipulation to split by length. It is fast, but it ignores linguistic boundaries. It might cut "prohibited" into "prohib" and "ited", making it impossible for the embedder to understand the rule.

**Step 2: Understanding Tokens**
A token is approximately 3/4ths of a word. We initialize `tiktoken`, the exact library OpenAI uses to count tokens. This ensures we never send a payload to the API that exceeds the maximum token limit.

**Step 3: Accumulating by Sentence Boundary**
We split the text into logical sentences. We evaluate the token count of each sentence. We pack sentences into a `current_chunk` buffer until adding one more would exceed our `max_tokens` threshold. When full, we save the chunk and start a new one.

### 5. ASCII Data Flow

```text
Input Text: [Sentence 1 (10 tokens)] [Sentence 2 (8 tokens)] [Sentence 3 (12 tokens)]
Max Tokens: 20

[ Token-Aware Loop ]
  |-- Add S1? 10 < 20. Yes. (Chunk 1 = S1)
  |-- Add S2? 10+8 < 20. Yes. (Chunk 1 = S1 + S2)
  |-- Add S3? 18+12 = 30. STOP. Exceeds 20!
  |-- Save Chunk 1. Start new chunk with S3.

Result:
Chunk 1: S1 + S2 (18 tokens)
Chunk 2: S3 (12 tokens)
```

### 6. Noob Trap vs Pro Tip
- **Noob Trap:** Using `len(string.split(" "))` to count tokens. A word is not a token. "Hello" is 1 token. "Supercalifragilisticexpialidocious" is roughly 10 tokens. If you estimate using words, you will hit API token limit errors.
- **Pro Tip:** Add **Chunk Overlap**. Even with sentence boundaries, context can bleed across chunks. Always carry over the last 10-20% of the tokens from Chunk A to the beginning of Chunk B so the LLM doesn't lose the thread of the conversation.

### Level 2: Real-World
**Challenge:** Add a basic form of **Chunk Overlap**. When finishing a chunk and starting a new one, make the *new* chunk start with the *last sentence* of the previous chunk.
<details>
<summary>Hint</summary>
Keep track of the `last_sentence` in the loop. When saving `current_chunk` and resetting, initialize `current_chunk` to `last_sentence` and update `current_tokens` accordingly.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
def overlapped_chunker(text, max_tokens):
    sentences = text.replace("!", ".").split(". ")
    chunks = []
    current_chunk = ""
    current_tokens = 0
    last_sentence = ""

    for sentence in sentences:
        sentence = sentence.strip() + ". "
        sentence_tokens = len(enc.encode(sentence))

        if current_tokens + sentence_tokens > max_tokens and current_chunk:
            chunks.append(current_chunk.strip())
            # Overlap: start next chunk with the last sentence
            current_chunk = last_sentence + sentence
            current_tokens = len(enc.encode(last_sentence)) + sentence_tokens
        else:
            current_chunk += sentence
            current_tokens += sentence_tokens

        last_sentence = sentence

    if current_chunk:
        chunks.append(current_chunk.strip())
    return chunks
```
</details>

# Simplified failsafe logic for boss level
for sentence in sentences:
    sentence = sentence.strip() + ". "
    sentence_tokens = len(enc.encode(sentence))

    if sentence_tokens > max_tokens:
        print(f"[WARNING] Sentence exceeds max tokens. Force splitting: {sentence[:30]}...")
        # Force split: cut the string in half blindly
        half = len(sentence) // 2
        part1, part2 = sentence[:half], sentence[half:]

        # In a robust production system, you would recursively chunk part1 and part2.
        # For this challenge, just appending part1 and part2 to chunks directly demonstrates the failsafe concept.
        if current_chunk:
             chunks.append(current_chunk.strip())
        chunks.append(part1)
        chunks.append(part2)
        current_chunk = ""
        current_tokens = 0
        continue

    # ... normal sentence processing continues ...

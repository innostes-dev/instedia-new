# 2.3 Native Hardware & Platform Channels

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
Flutter is amazing for UI, but it runs inside a Dart Virtual Machine. What happens when your client demands a feature like reading the device's battery temperature, accessing a legacy bluetooth SDK provided by a hardware manufacturer, or using a brand-new iOS 18 ARKit feature that doesn't have a Flutter package yet? Dart cannot directly talk to the C/Objective-C/Java hardware layers of the OS. You are blocked.

### 2. Plain English Metaphor (The What)
Imagine Flutter as an English-speaking CEO sitting in a glass office (the Dart VM).
The Android OS is a factory floor that only speaks Kotlin.
The iOS OS is a factory floor that only speaks Swift.

When the CEO wants to know the battery level, they can't just shout out the window. They have to use a **Platform Channel** (a two-way radio).
1. The CEO speaks English into the radio: `"getBatteryLevel"`.
2. The radio translates this into binary, sends it down to the factory floor.
3. The floor manager (Native Code) hears the request, checks the battery, and speaks the result back into the radio.
4. The radio translates it back to English for the CEO.

### 3. Complete Runnable Code
Here is a complete setup for requesting the Battery Level. *Note: Running this fully requires modifying `MainActivity.kt` and `AppDelegate.swift`, which is shown in the breakdown.*

```dart
import 'package:flutter/material.dart';
import 'package:flutter/services.dart';

void main() => runApp(const HardwareApp());

class HardwareApp extends StatelessWidget {
  const HardwareApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      home: BatteryOptimizerScreen(),
    );
  }
}

class BatteryOptimizerScreen extends StatefulWidget {
  const BatteryOptimizerScreen({super.key});

  @override
  State<BatteryOptimizerScreen> createState() => _BatteryOptimizerScreenState();
}

class _BatteryOptimizerScreenState extends State<BatteryOptimizerScreen> {
  // 1. Define the MethodChannel with a unique string identifier
  static const platform = MethodChannel('com.instedia.app/battery');

  String _batteryLevel = 'Unknown battery level.';

  // 2. Async function to communicate with native code
  Future<void> _getBatteryLevel() async {
    String batteryLevel;
    try {
      // 3. Invoke the specific method
      final int result = await platform.invokeMethod('getBatteryLevel');
      batteryLevel = 'Battery level at $result % .';
    } on PlatformException catch (e) {
      batteryLevel = "Failed to get battery level: '${e.message}'.";
    } on MissingPluginException {
      batteryLevel = "Native method not implemented on this platform.";
    }

    setState(() {
      _batteryLevel = batteryLevel;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Native Hardware Bridge')),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Text(_batteryLevel, style: const TextStyle(fontSize: 24, fontWeight: FontWeight.bold)),
            const SizedBox(height: 30),
            ElevatedButton(
              onPressed: _getBatteryLevel,
              child: const Text('Get Battery Level from OS'),
            ),
          ],
        ),
      ),
    );
  }
}
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Flutter Side (`MethodChannel`)**
*Rationale: We define a channel string. This string must exactly match the string used in the Android/iOS code, acting as the radio frequency they tune into.*
```dart
static const platform = MethodChannel('com.instedia.app/battery');
```
We then call `invokeMethod('getBatteryLevel')`. This serializes the string and sends it asynchronously to the native side.

**Step 2: The Android Side (Kotlin)**
*Rationale: In `android/app/src/main/kotlin/.../MainActivity.kt`, we listen for the call and use standard Android SDKs to get the battery.*
```kotlin
import io.flutter.embedding.android.FlutterActivity
import io.flutter.embedding.engine.FlutterEngine
import io.flutter.plugin.common.MethodChannel
// ... android battery imports ...

class MainActivity: FlutterActivity() {
    private val CHANNEL = "com.instedia.app/battery"

    override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
        super.configureFlutterEngine(flutterEngine)
        MethodChannel(flutterEngine.dartExecutor.binaryMessenger, CHANNEL).setMethodCallHandler {
            call, result ->
            if (call.method == "getBatteryLevel") {
                val batteryLevel = getBatteryLevel() // Calls Android API
                if (batteryLevel != -1) {
                    result.success(batteryLevel) // Sends back to Dart
                } else {
                    result.error("UNAVAILABLE", "Battery level not available.", null)
                }
            } else {
                result.notImplemented() // Throws MissingPluginException in Dart
            }
        }
    }
}
```

**Step 3: The iOS Side (Swift)**
*Rationale: Similarly, in `ios/Runner/AppDelegate.swift`, we hook into the iOS `UIDevice` API.*
```swift
import UIKit
import Flutter

@UIApplicationMain
@objc class AppDelegate: FlutterAppDelegate {
  override func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
  ) -> Bool {
    let controller : FlutterViewController = window?.rootViewController as! FlutterViewController
    let batteryChannel = FlutterMethodChannel(name: "com.instedia.app/battery",
                                              binaryMessenger: controller.binaryMessenger)

    batteryChannel.setMethodCallHandler({
      (call: FlutterMethodCall, result: @escaping FlutterResult) -> Void in
      if call.method == "getBatteryLevel" {
         let device = UIDevice.current
         device.isBatteryMonitoringEnabled = true
         result(Int(device.batteryLevel * 100))
      } else {
        result(FlutterMethodNotImplemented)
      }
    })

    return super.application(application, didFinishLaunchingWithOptions: launchOptions)
  }
}
```

### 5. ASCII / Architecture Data Flow
```text
[ Dart (Flutter) ]
  | platform.invokeMethod('getBatteryLevel')
  v
[ StandardMessageCodec (Serialization) ] -> Translates to Binary
  |
  |--- (Asynchronous C++ Engine Bridge) ---|
  v
[ Native Platform Host ]
  |-- Android MainActivity checks call.method == "getBatteryLevel"
  |-- Calls Kotlin getBatteryLevel()
  |-- result.success(85)
  v
[ StandardMessageCodec (Deserialization) ] -> Translates to Dart Int
  |
  v
[ Dart (Flutter) ]
  | await returns 85
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using `MethodChannel` for real-time continuous data (like reading an accelerometer 60 times a second). `MethodChannel` is for single request/response pairs (like HTTP). Constantly invoking it creates massive serialization overhead and will cause UI stutter.

**Pro Tip:** For continuous streams of data (GPS, Gyroscope, WebSockets from Native), use an `EventChannel`. It sets up a permanent pipe. The native side pushes data into a sink, and the Dart side listens to a standard Dart `Stream`.

### Level 1: Warm-Up
**Task:** Write the Dart code to invoke a method called `showNativeToast` with arguments. You want to pass a Map `{"message": "Hello", "duration": "short"}` to the native side.

<details>
<summary>Hint</summary>
<code>invokeMethod</code> takes a second optional parameter for arguments.
</details>

<details>
<summary>Full Solution</summary>

```dart
static const platform = MethodChannel('com.instedia.app/ui');

Future<void> triggerToast() async {
  try {
    await platform.invokeMethod('showNativeToast', {
      "message": "Hello from Flutter!",
      "duration": "short"
    });
  } catch (e) {
    print("Failed to show toast: $e");
  }
}
```

### Level 2: Real-World
**Task:** Write a stubbed `EventChannel` listener for a hardware pedometer (step counter). Set up the Dart `Stream` to listen to an `EventChannel` named `'com.instedia.app/steps'`. Print the steps to the console as they arrive.

<details>
<summary>Hint</summary>
Use <code>EventChannel('...').receiveBroadcastStream()</code> which returns a <code>Stream<dynamic></code>. Listen to it.
</details>

<details>
<summary>Full Solution</summary>

```dart
import 'package:flutter/services.dart';
import 'dart:async';

class StepCounter {
  static const EventChannel _stepChannel = EventChannel('com.instedia.app/steps');
  StreamSubscription? _subscription;

  void startListening() {
    _subscription = _stepChannel.receiveBroadcastStream().listen(
      (dynamic event) {
        print("Steps taken: $event");
      },
      onError: (dynamic error) {
        print("Sensor error: ${error.message}");
      }
    );
  }

  void stopListening() {
    _subscription?.cancel();
  }
}
```
</details>

### Level 3: Boss Level
**Task:** Build a safe Native Interop Wrapper class.
Create a class `NativeBridge`. It should have a method `Future<T?> safeInvoke<T>(String method, [dynamic arguments])`.
This method should wrap the `MethodChannel.invokeMethod` call. It should:
1. Try the call.
2. If a `PlatformException` occurs, log it using `debugPrint` and return `null`.
3. If a `MissingPluginException` occurs, log "Method not implemented on this OS" and return `null`.
4. Cast the result to `<T>` safely.

<details>
<summary>Hint</summary>
Use generics and specific <code>on ... catch</code> blocks.
</details>

<details>
<summary>Full Solution</summary>

```dart
import 'package:flutter/services.dart';
import 'package:flutter/foundation.dart';

class NativeBridge {
  final MethodChannel _channel;

  NativeBridge(String channelName) : _channel = MethodChannel(channelName);

  Future<T?> safeInvoke<T>(String method, [dynamic arguments]) async {
    try {
      final result = await _channel.invokeMethod(method, arguments);
      // Ensure the return type matches T, otherwise return null (or handle cast error)
      if (result is T) {
        return result;
      } else {
        debugPrint('Type mismatch: Expected $T but got ${result.runtimeType}');
        return null;
      }
    } on PlatformException catch (e) {
      debugPrint('Native Bridge Error [$method]: ${e.message}');
      return null;
    } on MissingPluginException {
      debugPrint('Native Bridge Error: Method "$method" is not implemented on this OS.');
      return null;
    } catch (e) {
      debugPrint('Unknown Error: $e');
      return null;
    }
  }
}

```
</details>

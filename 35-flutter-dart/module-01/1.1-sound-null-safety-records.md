# 1.1 Sound Null Safety & Records

## Phase A: Core Concept

### 1. Real-World Pain Point (The Why)
In mobile development, one of the most common causes of production app crashes is the dreaded "Null Pointer Exception" or "Null Reference Error." When parsing JSON from an unstable API or handling user inputs, a missing `address` or `userRole` field can instantly crash your app. Before Sound Null Safety, variables could implicitly hold `null` at runtime, meaning the compiler couldn't protect you from calling methods on non-existent data.

### 2. Plain English Metaphor (The What)
Imagine you are running a high-end restaurant. Without Sound Null Safety, the waiter might bring an empty box to the table instead of a meal. When the customer opens it and tries to eat (calling a method on it), they throw a fit (the app crashes).

Sound Null Safety is like a strict kitchen inspector. The inspector forces the chef to label every box: "This box ALWAYS has food" (`String`) or "This box MIGHT be empty" (`String?`). If a box is labeled "MIGHT be empty", the waiter is explicitly forced to check inside before serving it to the customer. Records in Dart 3 act like a bento box: letting you package multiple different distinct items together safely without creating a whole new class.

### 3. Complete Runnable Code
Here is a crash-proof User Profile & Settings Data Transfer Object (DTO) using Dart 3 Sound Null Safety, Records, and Pattern Matching.

```dart
void main() {
  // Simulating an API payload with missing data
  final Map<String, dynamic> apiResponse = {
    'id': 101,
    'username': 'FlutterDev99',
    // 'email' is missing!
    'settings': {
      'theme': 'dark',
      'notifications': true,
    }
  };

  // 1. Parsing with Records & Pattern Matching
  final (id, username, email, settings) = parseUserProfile(apiResponse);

  print('User ID: $id');
  print('Username: $username');
  print('Email: ${email ?? "No email provided"}'); // Safe null handling

  // 2. Safe deeply nested extraction
  if (settings case {'theme': String theme, 'notifications': bool notify}) {
    print('Theme: $theme, Notifications On: $notify');
  } else {
    print('Default settings applied.');
  }
}

/// Returns a Record containing typed user data
(int, String, String?, Map<String, dynamic>?) parseUserProfile(Map<String, dynamic> json) {
  // Using explicit types and null checks
  final id = json['id'] as int? ?? 0;
  final username = json['username'] as String? ?? 'Guest';

  // Email is explicitly allowed to be null (?)
  final email = json['email'] as String?;

  final settings = json['settings'] as Map<String, dynamic>?;

  return (id, username, email, settings);
}
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: Defining the Typed Record Return Type**
*Rationale: Before Dart 3, returning multiple values meant creating a custom class or using a messy List/Map. Records allow us to define an ad-hoc struct securely.*
```dart
(int, String, String?, Map<String, dynamic>?) parseUserProfile(...)
```
Here, we declare that our function returns exactly four items. Notice `String?`. The `?` tells the Dart compiler: "This value is permitted to be null." The compiler will then enforce that whoever uses this email variable *must* check if it's null before using it.

**Step 2: Safe JSON Extraction with `as` and `??` (Null-Coalescing)**
*Rationale: JSON data is inherently untyped (`dynamic`). We must safely cast it and provide fallbacks to prevent runtime crashes.*
```dart
final username = json['username'] as String? ?? 'Guest';
```
We cast `json['username']` to a nullable String (`String?`). If the API omitted the username, it evaluates to `null`. The `??` operator then catches the `null` and assigns the default fallback `'Guest'`.

**Step 3: Destructuring and Pattern Matching**
*Rationale: Accessing deeply nested JSON traditionally requires endless `if (json['settings'] != null && json['settings']['theme'] != null)` boilerplate. Pattern matching simplifies this.*
```dart
if (settings case {'theme': String theme, 'notifications': bool notify}) {
  // Variables `theme` and `notify` are now securely bound and typed!
}
```
This single line checks if `settings` is a Map, checks if it has the keys `'theme'` and `'notifications'`, validates their types, and extracts them into local variables. If any check fails, it safely falls through to the `else` block without crashing.

### 5. ASCII / Architecture Data Flow
```text
[ Raw JSON API Response (Dynamic & Unsafe) ]
       |
       v
[ parseUserProfile() ]
  |-- Type Casting (as String?)
  |-- Null Coalescing (?? 'Fallback')
  |
  v
[ Dart 3 Record (int, String, String?, Map?) ]
       |
       v
[ Destructuring & Pattern Matching (case { ... }) ]
       |
       v
[ Safe, Crash-Proof UI Render ]
```

### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using the `!` (bang operator) aggressively. E.g., `String name = json['name']!;`. This overrides the compiler's safety warnings. If `json['name']` is null, your app will hard crash with a CastError at runtime.

**Pro Tip:** Use exhaustive pattern matching and switch statements to handle state. With Dart 3, a `switch` on a sealed class or enum must cover all cases, meaning you will never accidentally forget to handle a loading, success, or error state.

## Phase B: Engineering Challenges

### Level 1: Warm-Up
**Task:** Create a function that parses a product JSON `{ "id": 1, "price": 29.99, "tags": ["sale", "new"] }`. Return a Record `(int id, double price, List<String> tags)`. If a field is missing, provide safe defaults (id: 0, price: 0.0, tags: []).

<details>
<summary>Hint</summary>
Use the <code>??</code> operator for defaults. Cast lists cautiously: <code>(json['tags'] as List<dynamic>?)?.cast<String>() ?? []</code>.
</details>

<details>
<summary>Full Solution</summary>

```dart
(int, double, List<String>) parseProduct(Map<String, dynamic> json) {
  final id = json['id'] as int? ?? 0;
  final price = json['price'] as double? ?? 0.0;
  final tags = (json['tags'] as List<dynamic>?)?.cast<String>() ?? [];

  return (id, price, tags);
}

void main() {
  var data = parseProduct({"id": 1, "price": 29.99}); // missing tags
  print(data.$1); // 1
  print(data.$2); // 29.99
  print(data.$3); // []
}
```
</details>

### Level 2: Real-World
**Task:** Build a `Result` type parser. Often, APIs return either data or an error. Write a function that takes a Map and returns a Record with named parameters: `({String? error, UserData? data})`. If the map contains a key `'error'`, return the error. If it contains `'user'`, parse it securely into a `UserData` record.

<details>
<summary>Hint</summary>
Use Dart 3 Records with named fields. e.g., <code>return (error: "Timeout", data: null);</code>
</details>

<details>
<summary>Full Solution</summary>

```dart
typedef UserData = (String name, int age);
typedef ApiResponse = ({String? error, UserData? data});

ApiResponse handleApi(Map<String, dynamic> json) {
  if (json.containsKey('error')) {
    return (error: json['error'] as String?, data: null);
  }

  if (json case {'user': {'name': String name, 'age': int age}}) {
    return (error: null, data: (name, age));
  }

  return (error: "Malformed Data", data: null);
}

void main() {
  var res = handleApi({'user': {'name': 'Alice', 'age': 30}});
  if (res.data != null) {
    print("Welcome ${res.data!.$1}");
  }
}
```
</details>

### Level 3: Boss Level
**Task:** Combining Records, Null Safety, and Pattern Matching, create an Exhaustive Router Guard.
You are given a `Map<String, dynamic>` representing a deep link payload.
Extract a Record `(String route, {String? auth_token, int? item_id})`.
Then, write a `String navigate(...)` function that uses a Dart 3 `switch` expression to return destination paths:
- If route is `'/profile'` and token is null -> return `'/login'`
- If route is `'/profile'` and token is valid -> return `'/dashboard'`
- If route is `'/item'` and `item_id` is a positive integer -> return `'/item/$item_id'`
- Otherwise -> return `'/404'`

<details>
<summary>Hint</summary>
Use switch expressions with guard clauses (<code>when</code>). e.g., <code>case ('/item', _, int id) when id > 0:</code>
</details>

<details>
<summary>Full Solution</summary>

```dart
(String, {String? authToken, int? itemId}) parseDeepLink(Map<String, dynamic> payload) {
  final route = payload['route'] as String? ?? '/';
  final authToken = payload['auth_token'] as String?;
  final itemId = payload['item_id'] as int?;

  return (route, authToken: authToken, itemId: itemId);
}

String navigate((String, {String? authToken, int? itemId}) linkData) {
  return switch (linkData) {
    ('/profile', authToken: null, itemId: _) => '/login',
    ('/profile', authToken: String _, itemId: _) => '/dashboard',
    ('/item', authToken: _, itemId: int id) when id > 0 => '/item/$id',
    _ => '/404',
  };
}

void main() {
  final payload1 = {'route': '/profile'};
  final payload2 = {'route': '/item', 'item_id': 42};

  final link1 = parseDeepLink(payload1);
  final link2 = parseDeepLink(payload2);

  print(navigate(link1)); // /login
  print(navigate(link2)); // /item/42
}
```
</details>

# 2.2 Chain-of-Thought Reasoning

## Phase A: Core Intuition

### Real-World Pain Point (The Why)
You ask an LLM: "If I have 5 apples, eat 2, buy 10 more, and distribute them evenly among 3 friends, how many does each get?" The LLM instantly replies "5". Wait, (5-2+10)/3 = 4.33. Why did it fail basic math?
LLMs predict the *next* token immediately. If you force them to give the final answer right away, they don't have "time" or computational space to work through the logic. They guess.

### Plain English Metaphor (The What)
Imagine asking a human to multiply 345 by 812 in their head and demanding the answer *instantly*. They will guess wrong. But if you give them a piece of scratchpad paper and say, "Show your work step-by-step," they will get it right.
**Chain-of-Thought (CoT)** prompting is simply telling the AI to "think out loud" and generate intermediate reasoning tokens (the scratchpad) before outputting the final answer.

### Complete Runnable Code

```python
# Multi-Step Financial Invoice Discrepancy Analyzer
import json

# Mock API for demonstration
def mock_llm_call(prompt):
    if "step-by-step" not in prompt:
        return '{"discrepancy": false, "reason": "Totals seem to match."}'
    else:
        return '''
Step 1: Calculate Line 1: 5 laptops * $1000 = $5000.
Step 2: Calculate Line 2: 10 mice * $50 = $500.
Step 3: Calculate Subtotal: $5000 + $500 = $5500.
Step 4: Apply 10% tax to subtotal: $5500 * 0.10 = $550.
Step 5: Calculate Expected Final Total: $5500 + $550 = $6050.
Step 6: Compare Expected ($6050) to Invoice Final ($5500). They do not match. The invoice forgot to add the tax.

FINAL_JSON:
{"discrepancy": true, "reason": "Calculated total with tax is $6050, but invoice states $5500."}
'''

def analyze_invoice(invoice_text, use_cot=True):
    # 1. The Standard Prompt (Fails on complex logic)
    standard_prompt = (
        "Analyze this invoice. Does the math add up? "
        "Output ONLY JSON with keys 'discrepancy' (bool) and 'reason' (string). \n"
        f"Invoice: {invoice_text}"
    )

    # 2. The Chain-of-Thought Prompt (Succeeds)
    cot_prompt = (
        "Analyze this invoice. You must calculate the math step-by-step. "
        "1. Calculate line items.\n"
        "2. Calculate subtotal.\n"
        "3. Apply tax.\n"
        "4. Compare to final total.\n"
        "Write out your reasoning. Then, at the very end, write 'FINAL_JSON:' followed by "
        "ONLY JSON with keys 'discrepancy' (bool) and 'reason' (string).\n"
        f"Invoice: {invoice_text}"
    )

    prompt = cot_prompt if use_cot else standard_prompt

    # 3. Call the API
    raw_response = mock_llm_call(prompt)

    # 4. Extract the JSON from the CoT output
    if use_cot:
        json_str = raw_response.split("FINAL_JSON:")[1].strip()
    else:
        json_str = raw_response.strip()

    return json.loads(json_str)

# Test Data
invoice = "Items: 5 Laptops ($1000 ea), 10 Mice ($50 ea). Tax: 10%. Final Total: $5500."

print("Standard Prompt Result (Often misses the tax error):")
print(analyze_invoice(invoice, use_cot=False))

print("\nChain-of-Thought Result (Catches the error):")
print(analyze_invoice(invoice, use_cot=True))
```

### Progressive Step-by-Step Breakdown

**Step 1: The Zero-Shot Failure**
When `use_cot=False`, we ask for the final JSON immediately. The LLM has to jump straight from reading the invoice to outputting `true/false`. It lacks the tokens to process the multiplication and addition.

**Step 2: Forcing the Scratchpad**
When `use_cot=True`, we explicitly instruct the model to "calculate the math step-by-step." This forces the model to generate words like "5 * 1000 = 5000". Because LLMs have attention mechanisms, when it generates the *next* token, it looks back at the "5000" it just wrote, allowing it to correctly add the next number to it. Generating text *is* how an LLM processes logic.

**Step 3: Parsing the Output**
Because we told the model to write out its thoughts, the output is no longer pure JSON. It's a block of text followed by JSON. We use a delimiter (`FINAL_JSON:`) in the prompt. In our Python code, we use `.split("FINAL_JSON:")[1]` to grab just the structured data we need for our application, discarding the "scratchpad" text.

### ASCII Data Flow

```text
[Standard] Input --> LLM --> Guesses Result: {"discrepancy": false} (INCORRECT)

[CoT] Input --> LLM --> Generates Step 1 -> Reads Step 1 -> Generates Step 2 -> Reads Step 2 -> Computes Final -> "FINAL_JSON: {...}" (CORRECT)
```

### Noob Trap vs Pro Tip
**Noob Trap:** Using Chain-of-Thought for simple extraction tasks (e.g., "Extract the name from this text. Think step-by-step."). This wastes tokens (money) and increases latency unnecessarily for tasks that don't require reasoning.
**Pro Tip:** For highly complex logic, use **Few-Shot CoT**. Don't just say "think step-by-step." Provide an actual example in the prompt of *how* you want it to think. (e.g., `Example: User: 2 apples, 3 bananas. Assistant: Step 1: 2+3=5. Total is 5.`).

If the resulting `json.loads()` fails (because the model messed up the JSON formatting during its CoT rambling), catch the exception, and make a *second* API call to the LLM. Pass the broken output back to the LLM and say: "You produced invalid JSON. Here is the error. Fix it."

<details>

<details>
<summary>Solution Walkthrough</summary>
```python
def robust_analyze(invoice_text, max_retries=2):
    prompt = f"Analyze invoice, reason step-by-step, end with FINAL_JSON: {{...}}\n{invoice_text}"

    for attempt in range(max_retries):
        raw_response = mock_llm_call(prompt) # Pretend this sometimes returns bad JSON

        try:
            json_str = raw_response.split("FINAL_JSON:")[1].strip()
            return json.loads(json_str) # If success, return immediately

        except (IndexError, json.JSONDecodeError) as e:
            print(f"Attempt {attempt+1} failed. Asking AI to correct itself...")
            # Modify prompt for the next loop iteration
            prompt = (
                f"Your previous output was invalid. I got this error: {str(e)}.\n"
                f"Here was your output:\n{raw_response}\n"
                "Please fix it and output ONLY valid JSON this time."
            )

    raise Exception("Model failed to produce valid JSON after retries.")
```
LLMs are surprisingly good at fixing their own syntax errors if you just show them the Python error message!
</details>

# 2.3 Temperature and Sampling Controls

## Phase A: Core Intuition

### Real-World Pain Point (The Why)
You build a tool that extracts a person's Date of Birth from a medical record. Yesterday, it extracted "1985-10-12". Today, for the exact same record, it output "Oct 12, 1985". Tomorrow, it might output "The patient was born on 10/12/85." Your database ingestion script crashes every day because the formatting changes unpredictably. Why can't the AI just give the same answer every time?

### Plain English Metaphor (The What)
Think of an LLM as a chef trying to complete a recipe.
If **Temperature = 0.0**, the chef strictly follows the recipe card. Every single time you ask for a cake, they use the exact same ingredients in the exact same order. It is highly predictable, but boring.
If **Temperature = 1.0** (or higher), the chef gets creative. They might swap sugar for honey, or add cinnamon. It's great for brainstorming new recipes, but terrible if you just wanted a standard vanilla cake.
Temperature controls the "randomness" of the next-token prediction.

### Complete Runnable Code

```python
# Legal Policy Assistant with Zero-Temperature Tuning
import random

# Mocking LLM sampling behavior based on temperature
def mock_predict_next_word(temperature):
    # The LLM has calculated probabilities for the next word:
    # 80% chance of "Violates"
    # 15% chance of "Breaches"
    # 5% chance of "Contravenes"

    if temperature == 0.0:
        # T=0 means ALWAYS pick the highest probability (greedy sampling)
        return "Violates"

    else:
        # T>0 means we randomly sample based on probabilities
        # Higher temperature flattens the curve, making rare words more likely
        roll = random.random()
        if roll < 0.80: return "Violates"
        elif roll < 0.95: return "Breaches"
        else: return "Contravenes"

def analyze_contract_clause(clause, temperature):
```

### Progressive Step-by-Step Breakdown

**Step 1: The Probability Distribution**
At every step, the LLM generates a list of possible next words and assigns a probability to each. "Violates" (80%), "Breaches" (15%), etc.

**Step 2: Temperature = 0 (Greedy Sampling)**
When `temperature=0`, we tell the model: "Ignore the distribution. Just take the #1 most likely word every single time." This is called *greedy sampling*. It makes the model almost entirely deterministic. If you ask the exact same prompt, you will get the exact same answer 99% of the time. This is mandatory for data extraction, coding, and classification.

**Step 3: Temperature > 0 (Probabilistic Sampling)**
When `temperature > 0`, we roll a weighted dice. Most of the time it picks "Violates", but sometimes it picks "Breaches". As you increase the temperature (e.g., to 1.5 or 2.0), the probabilities flatten out, meaning the model might pick a wildly irrelevant word, leading to "hallucinations" or gibberish. This is useful for writing poetry or brainstorming marketing copy.

### ASCII Data Flow

```text
Logits (Raw Scores) -> Softmax (Converts to %) -> [Violates: 80%, Breaches: 15%, Contravenes: 5%]
                               |
                               |--> IF T=0.0 -> Pick #1 -> "Violates" (Always)
                               |
                               |--> IF T=0.8 -> Roll Dice -> "Breaches" (Sometimes)
```

### Noob Trap vs Pro Tip
**Noob Trap:** Using the default temperature (usually 0.7 or 1.0) for tasks that require strict JSON outputs or data extraction. The model will eventually get "creative" with your JSON syntax and break your app.
**Pro Tip:** `temperature` is not the only control. `top_p` (Nucleus Sampling) is another parameter. `top_p=0.1` means "only sample from the pool of words that make up the top 10% of probability." **Rule of thumb:** Alter `temperature` OR `top_p`, but never both at the same time, as they interact unpredictably.

### Level 1: Warm-Up
**Task:** You are building a "Creative Story Generator". Should you use `temperature=0.0`, `0.7`, or `2.0`? Why?
**Goal:** Understand the practical application of high vs low temperature.

<details>
<summary>Hint</summary>
Think about what happens at the extremes. 0 is boring. 2.0 is often gibberish.
</details>

<details>
<summary>Solution Walkthrough</summary>
You should use **0.7**.
At `0.0`, the story will be incredibly predictable and cliché (always picking the most obvious next word).
At `2.0`, the math breaks down, and it will pick completely random tokens, resulting in unreadable nonsense.
`0.7` to `0.9` is the sweet spot for creativity while maintaining coherence.
</details>


### Level 2: Real-World
**Task:** Look at the documentation for the OpenAI API and find the `seed` parameter. Explain how `seed` combined with `temperature=0` can guarantee perfectly reproducible outputs for unit testing your AI application.
**Goal:** Learn how to make stochastic models testable in CI/CD pipelines.

<details>
<summary>Hint</summary>
A `seed` initializes the random number generator at the hardware level.
</details>

<details>
<summary>Solution Walkthrough</summary>
Even at `temperature=0`, minor floating-point math differences on GPU clusters can occasionally cause a different token to win by 0.00001%.
By passing `temperature=0` AND `seed=42` (or any integer), you lock the backend RNG. This ensures that the exact same prompt will yield the exact same response string every time, allowing you to write standard Python `assert response == "Expected String"` in your unit tests without flaky failures.
</details>

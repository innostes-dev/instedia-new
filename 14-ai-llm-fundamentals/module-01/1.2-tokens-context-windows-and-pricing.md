# 1.2 Tokens, Context Windows, and Pricing

## Phase A: Core Intuition

### Real-World Pain Point (The Why)
You build a summarization tool using an LLM. It works perfectly on short articles. Then, a user uploads a 500-page legal contract, and the API throws an error: `context_length_exceeded`. Or worse, the API succeeds, but you check your billing dashboard and realize that single request cost you $2.50. You suddenly realize that AI doesn't read words or bytes—it reads "tokens," and tokens equal money and technical constraints.

### Plain English Metaphor (The What)
Think of a token as a syllable or a chunk of a word. If language is a pizza, a token is a slice. Some small words (like "cat") are a single slice. Large words (like "unbelievable") are chopped into multiple slices ("un", "believ", "able").
The Context Window is the size of the pizza box. You can only fit so many slices into the box at once. If you try to shove a 500-page book into a small box, it won't fit. And importantly, you are charged by the AI provider *per slice* that goes into the box and comes out of the box.

### Complete Runnable Code

```python
# Real-Time Token Cost Estimator using tiktoken
import tiktoken

def estimate_llm_cost(text, model="gpt-4", input_cost_per_1m=30.00):
    # 1. Initialize the specific tokenizer (BPE) for the model
    # Different models chunk text differently!
    encoding = tiktoken.encoding_for_model(model)

    # 2. Encode the text into integer tokens
    tokens = encoding.encode(text)
    token_count = len(tokens)

    # 3. Calculate cost
    cost = (token_count / 1_000_000) * input_cost_per_1m

    return tokens, token_count, cost

sample_text = "Hello world! This is a tokenization example. Supercalifragilisticexpialidocious!"

tokens, count, cost = estimate_llm_cost(sample_text)

print(f"Original Text: '{sample_text}'")
print(f"Token Count: {count}")
print(f"Estimated Input Cost: ${cost:.6f}")
print(f"Token Integer IDs: {tokens}")

# Let's decode one specific token to see how it chunked the long word
print(f"Decoding token {tokens[-2]}: '{encoding.decode([tokens[-2]])}'")
```

### Progressive Step-by-Step Breakdown

**Step 1: Byte-Pair Encoding (BPE)**
LLMs don't read raw text. The library `tiktoken` uses an algorithm called BPE to compress text into a vocabulary of known chunks. In the code, `encoding.encode(text)` converts our string into an array of integers (e.g., `[9906, 1917, 0, 2028...]`). Each integer represents a token.

**Step 2: Token Counting**
A rough rule of thumb in English is that 1 token ≈ 0.75 words. However, complex words (like "Supercalifragilisticexpialidocious") get shattered into many tokens. Spaces and punctuation also consume tokens. We count the length of the integer array to know our exact token usage.

**Step 3: Calculating Costs and Limits**
API providers charge based on $X per 1,000,000 tokens. We divide our `token_count` by 1M and multiply by the rate. Furthermore, every model has a fixed Context Window (e.g., 8k, 128k, 1M tokens). This window is shared between your input (prompt) and the model's output (completion). If `len(tokens)` exceeds this window, the API rejects the request.

### ASCII Data Flow

```text
Raw Text ("AI is cool!")
    |
    v
Tokenizer (BPE Algorithm)
    |
    v
Token IDs [15592, 374, 3608, 0]  --> Checks Context Window Limit (e.g., < 128,000)
    |
    v
LLM Processing --> Output Tokens [778, 120, 0] --> Billing: (Input Tokens + Output Tokens) = $$$
```

### Noob Trap vs Pro Tip
**Noob Trap:** Using `len(text.split(" "))` (counting spaces) to estimate if a document will fit in the context window. This will vastly underestimate the size, especially for code, foreign languages, or tabular data (where white spaces and special characters explode token counts).
**Pro Tip:** Always use the official tokenizer library (like `tiktoken` for OpenAI) to count tokens *before* sending a large payload to the API. If it's too big, you must proactively chunk the text or use a model with a larger context window.

### Level 2: Real-World
**Task:** Write a function `safe_truncate(text, max_tokens)` that takes a string, tokenizes it, truncates the token array if it exceeds `max_tokens`, and decodes it back to a string.
**Goal:** Prevent `context_length_exceeded` errors gracefully by dropping excess text.

<details>
<summary>Hint</summary>
Encode the text, slice the resulting list `tokens[:max_tokens]`, and then use `encoding.decode()` to turn it back into a string.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
def safe_truncate(text, max_tokens, model="gpt-4"):
    enc = tiktoken.encoding_for_model(model)
    tokens = enc.encode(text)

    if len(tokens) <= max_tokens:
        return text

    truncated_tokens = tokens[:max_tokens]
    return enc.decode(truncated_tokens)

long_text = "This is a very long story that we need to cut short."
print(safe_truncate(long_text, max_tokens=5))
# Output: "This is a very long"
```
This is a standard preprocessing step before feeding user-generated content into an LLM.
</details>


### Level 3: Boss Level
**Task:** Create a `CostAnalyzer` class. It should track total input tokens and total output tokens across multiple simulated LLM calls. Provide a method `get_total_cost()` that applies a rate of $10.00/1M Input tokens and $30.00/1M Output tokens.
**Goal:** Build a billing telemetry system similar to what production applications use to monitor AI costs per user.

<details>
<summary>Hint</summary>
Initialize `self.input_tokens = 0` and `self.output_tokens = 0`. Create an `add_usage(input_text, output_text)` method that tokenizes and adds to the counters.
</details>

<details>
<summary>Solution Walkthrough</summary>
```python
import tiktoken

class CostAnalyzer:
    def __init__(self, model="gpt-4"):
        self.enc = tiktoken.encoding_for_model(model)
        self.input_tokens = 0
        self.output_tokens = 0
        self.in_rate = 10.00 / 1_000_000
        self.out_rate = 30.00 / 1_000_000

    def add_usage(self, input_text, output_text):
        self.input_tokens += len(self.enc.encode(input_text))
        self.output_tokens += len(self.enc.encode(output_text))

    def get_total_cost(self):
        in_cost = self.input_tokens * self.in_rate
        out_cost = self.output_tokens * self.out_rate
        return in_cost + out_cost

# Usage
telemetry = CostAnalyzer()
telemetry.add_usage("Summarize this doc.", "Here is the summary...")
telemetry.add_usage("Translate to French.", "Bonjour le monde...")

print(f"Total spent: ${telemetry.get_total_cost():.6f}")
```
Tracking input vs output separately is vital because Output tokens are computationally harder to generate and usually cost 3x to 4x more than Input tokens!
</details>

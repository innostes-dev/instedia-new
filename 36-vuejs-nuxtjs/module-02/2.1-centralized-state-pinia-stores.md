# Module 02: Enterprise State Management & Navigation
## 2.1 Centralized State: Pinia Stores

### Phase A: Core Concept Exploration

#### 1. Real-World Pain Point (The Why)
In complex enterprise applications, multiple components need access to the same data (e.g., user session, multi-tenant billing state, theme preferences). Passing data down via props (prop-drilling) or emitting events up becomes a tangled, unmaintainable nightmare.
Previously, Vuex was the solution. However, Vuex required massive boilerplate: you had to define `mutations` to change state, `actions` to call mutations, and strings like `dispatch('UPDATE_USER')` which broke TypeScript inference and IDE auto-complete.

#### 2. Plain English Metaphor (The What)
Think of Vuex like an old-school bank. To change your balance, you couldn't just do it. You had to fill out a form (action), hand it to a specific teller (mutation), who would then update the vault (state). It was safe, but incredibly slow and tedious.
Pinia is like a high-tech smart wallet app. You are fully authenticated. When you want to update your balance, you just open the app and type the new number. The app automatically records the transaction, updates your UI, and syncs to the cloud. It's direct, typed, and frictionless.

#### 3. Complete Runnable Code: Multi-Tier SaaS Organization Store
```javascript
// stores/organization.js (Pinia Setup Syntax)
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useOrgStore = defineStore('organization', () => {
  // 1. State (equivalent to data/ref)
  const currentOrgId = ref('org_123');
  const planTier = ref('pro');
  const userCount = ref(15);

  // 2. Getters (equivalent to computed)
  const maxUsersAllowed = computed(() => {
    switch (planTier.value) {
      case 'free': return 5;
      case 'pro': return 50;
      case 'enterprise': return 9999;
      default: return 5;
    }
  });

  const isCloseToLimit = computed(() => {
    return userCount.value >= (maxUsersAllowed.value * 0.8);
  });

  // 3. Actions (equivalent to methods, can be async)
  async function upgradePlan(newTier) {
    // Simulate API call
    console.log(`Upgrading org ${currentOrgId.value} to ${newTier}...`);
    await new Promise(resolve => setTimeout(resolve, 1000));

    // Direct state mutation! No Vuex mutations needed.
    planTier.value = newTier;
  }

  function addUser() {
    if (userCount.value < maxUsersAllowed.value) {
      userCount.value++;
    } else {
      throw new Error("User limit reached for current tier.");
    }
  }

  return {
    currentOrgId, planTier, userCount,
    maxUsersAllowed, isCloseToLimit,
    upgradePlan, addUser
  };
});
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: Defining the Store (Setup Syntax)**
*Rationale: We use Pinia's Setup Syntax (passing a function instead of an object) because it allows us to use standard Vue Composition API (`ref`, `computed`, `watch`) directly inside the store. It feels identical to writing a `<script setup>` block.*
```javascript
export const useOrgStore = defineStore('organization', () => {
  const planTier = ref('free'); // State
  return { planTier };
});
```

**Step 2: Defining Actions & Direct Mutations**
*Rationale: Unlike Vuex, Pinia actions handle both business logic and direct state mutation. We don't need a separate mutation layer. We also see that we can mutate state directly from the component (`orgStore.currentOrgId = 'xxx'`), which is perfectly safe and tracked by Pinia's DevTools.*
```javascript
async function upgradePlan(newTier) {
  // await apiCall()
  planTier.value = newTier; // Direct mutation
}
```

**Step 3: Consuming the Store**
*Rationale: We call `useOrgStore()` inside the component. Pinia ensures that no matter how many components call this, they all get the exact same reactive instance. We map it to `orgStore` to easily access properties in the template.*
```javascript
const orgStore = useOrgStore();
// Access via orgStore.planTier in template
```

#### 5. ASCII Architecture Data Flow
```text
[ Component A (Dashboard) ]           [ Component B (Navbar) ]
      │             ▲                       │             ▲
   (Calls Action)   │                       │             │
      │             │                       │             │
      ▼             │                       ▼             │
    [ Pinia Store (`useOrgStore`) Singleton Instance ]    │
    │  - Actions (Business Logic / API Calls)            │
    │  - State (Reactive Refs) ──────────────────────────┘
    │  - Getters (Cached Computeds)
    └─────────────────────────────────────────────────────
```

#### 6. Noob Trap vs Pro Tip
**Noob Trap:** Destructuring a store directly like `const { planTier } = useOrgStore();`. Pinia stores are reactive objects. If you destructure them standardly, you strip reactivity (just like destructuring `reactive()`). If `planTier` changes, your UI won't update.
**Pro Tip:** If you must destructure a store to save typing in the template, use Pinia's `storeToRefs`.
```javascript
import { storeToRefs } from 'pinia';
const orgStore = useOrgStore();
const { planTier } = storeToRefs(orgStore); // Maintains reactivity!
const { upgradePlan } = orgStore; // Actions can be destructured normally.
```

// stores/counter.js
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useCounterStore = defineStore('counter', () => {
  const count = ref(0);
  const doubleCount = computed(() => count.value * 2);
  function increment() { count.value++; }

  return { count, doubleCount, increment };
});

#### Level 2: Real-World
**Task:** Build an Authentication Store. It should track `user` (object or null) and `isAuthenticated` (computed). Add an async `login(email, password)` action that simulates an API call (1s delay), sets the user, and sets an auth token in `localStorage`.
<details>
<summary>Hint</summary>
`isAuthenticated` should check if `user.value !== null`. Inside the `login` action, use `setTimeout` wrapped in a Promise to simulate network latency.
</details>
<details>
<summary>Solution Walkthrough</summary>
```javascript
// stores/auth.js
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useAuthStore = defineStore('auth', () => {
  const user = ref(null);

  const isAuthenticated = computed(() => user.value !== null);

  async function login(email, password) {
    // Simulate API
    await new Promise(resolve => setTimeout(resolve, 1000));

    if (email === 'admin@test.com' && password === 'password') {
      user.value = { id: 1, email, name: 'Admin User' };
      localStorage.setItem('auth_token', 'mock_jwt_token_123');
    } else {
      throw new Error('Invalid credentials');
    }
  }

  function logout() {
    user.value = null;
    localStorage.removeItem('auth_token');
  }

  return { user, isAuthenticated, login, logout };
});
```
</details>

#### Level 3: Boss Level
**Task:** Build a "Shopping Cart" store that depends on a "Products" store.
1. `useProductsStore` has a static list of products.
2. `useCartStore` has an array of cart items `{ id, quantity }`.
3. In `useCartStore`, create a getter `cartTotal` that loops through the cart items, looks up the price in the `useProductsStore`, and calculates the total monetary value.
<details>
<summary>Hint</summary>
You can call `useProductsStore()` directly *inside* the `useCartStore` (within getters or actions) to access its state.
</details>
<details>
<summary>Solution Walkthrough</summary>
```javascript
// stores/products.js
import { defineStore } from 'pinia';
import { ref } from 'vue';

export const useProductsStore = defineStore('products', () => {
  const inventory = ref([
    { id: 1, name: 'Laptop', price: 1000 },
    { id: 2, name: 'Mouse', price: 50 }
  ]);

  function getProductById(id) {
    return inventory.value.find(p => p.id === id);
  }

  return { inventory, getProductById };
});
```

```javascript
// stores/cart.js
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';
import { useProductsStore } from './products'; // Import the other store

export const useCartStore = defineStore('cart', () => {
  const items = ref([]); // { id, quantity }

  const cartTotal = computed(() => {
    // Instantiate the other store inside the computed property
    const productsStore = useProductsStore();

    return items.value.reduce((total, item) => {
      const productInfo = productsStore.getProductById(item.id);
      if (productInfo) {
        return total + (productInfo.price * item.quantity);
      }
      return total;
    }, 0);
  });

  function addToCart(id) {
    const existing = items.value.find(i => i.id === id);
    if (existing) {
      existing.quantity++;
    } else {
      items.value.push({ id, quantity: 1 });
    }
  }

  return { items, cartTotal, addToCart };
});
```
</details>

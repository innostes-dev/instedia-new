# Module 02: Enterprise State Management & Navigation
## 2.2 Vue Router & Navigation Guards

### Phase A: Core Concept Exploration

#### 1. Real-World Pain Point (The Why)
In a single-page application (SPA), the browser doesn't actually load new HTML pages when you click a link. Instead, JavaScript swaps out components dynamically. Without a router, you'd have to manage all this conditional rendering manually (`v-if="currentPage === 'home'"`), and the browser's back/forward buttons wouldn't work.
Furthermore, in an enterprise app, you have different user roles (Admin, Editor, Viewer). If you only hide the "Admin Dashboard" button using `v-if`, a smart user can simply type `/admin` into the URL bar and access unauthorized data. We need a robust way to intercept routing *before* the component loads to verify authentication.

#### 2. Plain English Metaphor (The What)
Vue Router is like the **Front Desk Receptionist** of a secure office building.
The URL is the visitor's request: "I want to go to room 402."
1. **Dynamic Routing:** If they ask for `/employee/john`, the receptionist knows they want the generic Employee Room template, populated with John's data.
2. **Navigation Guards (`beforeEach`):** Before handing over the key, the receptionist checks the security protocol (meta fields). "Ah, room 402 requires Admin clearance. Let me check your badge (Auth Store). No badge? I'm redirecting you to the Lobby (Login Page)."

#### 3. Complete Runnable Code: Enterprise Multi-Role Protected Portal
```javascript
// router/index.js
import { createRouter, createWebHistory } from 'vue-router';
import { useAuthStore } from '../stores/auth'; // Assume this exists

// Define components inline for demo purposes
const Home = { template: '<div><h1>Public Home</h1></div>' };
const Login = { template: '<div><h1>Login Page</h1></div>' };
const Dashboard = { template: '<div><h1>User Dashboard</h1></div>' };
const AdminPanel = { template: '<div><h1>Admin Control Panel</h1></div>' };
const Unauthorized = { template: '<div><h1 style="color:red">Access Denied</h1></div>' };

const routes = [
  { path: '/', component: Home },
  { path: '/login', component: Login, name: 'Login' },
  { path: '/unauthorized', component: Unauthorized, name: 'Unauthorized' },

  // Protected User Route
  {
    path: '/dashboard',
    component: Dashboard,
    meta: { requiresAuth: true }
  },

  // Protected Admin Route
  {
    path: '/admin',
    component: AdminPanel,
    meta: { requiresAuth: true, requiredRole: 'admin' }
  }
];

const router = createRouter({
  history: createWebHistory(),
  routes,
});

// GLOBAL NAVIGATION GUARD
router.beforeEach((to, from, next) => {
  const authStore = useAuthStore();

  console.log(`[Router Guard] Navigating from ${from.path} to ${to.path}`);

  // 1. Check if route requires authentication
  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    console.warn('Unauthorized access attempt. Redirecting to Login.');
    // Redirect to login, save original destination to redirect back later
    return next({ name: 'Login', query: { redirect: to.fullPath } });
  }

  // 2. Check Role-Based Access Control (RBAC)
  if (to.meta.requiredRole && authStore.user?.role !== to.meta.requiredRole) {
    console.error(`Requires ${to.meta.requiredRole} role. User has ${authStore.user?.role}.`);
    return next({ name: 'Unauthorized' });
  }

  // 3. Allow navigation
  next();
});

export default router;
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: Defining Routes and Meta Fields**
*Rationale: We map URL paths to Vue components. We attach custom `meta` objects to specific routes. This acts as configuration data for our security guards, tagging which routes need login or specific roles.*
```javascript
const routes = [
  { path: '/admin', component: AdminPanel, meta: { requiresAuth: true, requiredRole: 'admin' } }
];
```

**Step 2: The Global `beforeEach` Guard**
*Rationale: This function runs *before* every single route change. It intercepts the navigation. `to` is where the user wants to go. We check the `to.meta` properties against our Pinia auth store state.*
```javascript
router.beforeEach((to, from, next) => {
  if (to.meta.requiresAuth && !isLoggedIn) {
    next('/login'); // Intercept and redirect
  } else {
    next(); // Proceed normally
  }
});
```

**Step 3: `<router-view>` and `<router-link>`**
*Rationale: In the template, `<router-view>` is the dynamic placeholder where the router injects the matched component. `<router-link>` replaces standard `<a>` tags; it intercepts clicks to prevent the browser from doing a full page refresh, handling the navigation via JS instead.*

#### 5. ASCII Architecture Data Flow
```text
[ User Clicks <router-link to="/admin"> ]
                  │
                  ▼
[ URL Changes to /admin in Browser History ]
                  │
                  ▼
[ router.beforeEach() Global Guard Triggered ]
                  │
         Check `to.meta.requiresAuth`
                  │
        (Queries Pinia Auth Store) ───► Is User Admin?
                  │                           │
         [ No ] ──┴── [ Yes ] ◄───────────────┘
           │            │
           ▼            ▼
   next('/login')     next() (Proceed)
           │            │
           ▼            ▼
[ Render Login.vue ]  [ Render AdminPanel.vue inside <router-view> ]
```

#### 6. Noob Trap vs Pro Tip
**Noob Trap:** Forgetting to call `next()` in a navigation guard. If your guard has multiple `if/else` paths, and one path fails to execute `next()` or `return next(...)`, the routing process hangs indefinitely. The screen will freeze and the URL won't change.
**Pro Tip:** In newer Vue Router 4 syntax, you don't actually *have* to use the `next` callback. You can simply `return '/login'` or `return true`. This is less error-prone.
```javascript
// Modern Vue Router 4 Guard Syntax
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !isAuthenticated) return { name: 'Login' };
  // returning undefined (implicit) allows navigation to proceed
});
```

#### Level 2: Real-World
**Task:** Create a "Leave Site Warning" guard. In a `Settings.vue` component, you have a boolean ref `hasUnsavedChanges`. If the user tries to navigate away from this specific component while `hasUnsavedChanges` is true, prompt them with a `window.confirm`. If they click cancel, abort the navigation.
<details>
<summary>Hint</summary>
Use `onBeforeRouteLeave` inside the `Settings.vue` component rather than a global guard.
</details>
<details>
<summary>Solution Walkthrough</summary>
```vue
<!-- Settings.vue -->
<template>
  <div>
    <h2>Settings</h2>
    <input v-model="settingsData" @input="hasUnsavedChanges = true" />
    <button @click="save">Save Settings</button>
  </div>
</template>

<script setup>
import { ref } from 'vue';
import { onBeforeRouteLeave } from 'vue-router';

const settingsData = ref('');
const hasUnsavedChanges = ref(false);

const save = () => {
  hasUnsavedChanges.value = false;
  alert('Saved!');
};

// Component-specific navigation guard
onBeforeRouteLeave((to, from) => {
  if (hasUnsavedChanges.value) {
    const answer = window.confirm('You have unsaved changes. Do you really want to leave?');
    // Returning false cancels the navigation
    if (!answer) return false;
  }
});
</script>
```
</details>

#### Level 3: Boss Level
**Task:** Implement robust "Redirect after Login". When a user tries to access `/secure-dashboard` but isn't logged in, intercept them, redirect to `/login`, but pass the original destination in a query parameter (`?redirect=/secure-dashboard`). On the Login page, after successful login, read that query parameter and push them back to their original intended destination (fallback to `/` if no query param exists).
<details>
<summary>Hint</summary>
In the router guard: `return { path: '/login', query: { redirect: to.fullPath } }`. In the Login component: `router.push(route.query.redirect || '/')`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```javascript
// router.js guard
router.beforeEach((to) => {
  const isAuth = false; // Simulated auth check

  if (to.meta.requiresAuth && !isAuth) {
    // Send to login, but remember where they wanted to go
    return {
      path: '/login',
      query: { redirect: to.fullPath }
    };
  }
});
```

const handleLogin = () => {

# Module 03: Nuxt 3 Full-Stack Architecture
## 3.2 Nitro Server Engine & API Routes

### Phase A: Core Concept Exploration

#### 1. Real-World Pain Point (The Why)
In a traditional SPA setup, you build your frontend (Vue) and your backend (Express/NestJS) as two separate repositories. This means managing two servers, configuring CORS, handling two deployment pipelines, and duplicating types/interfaces between the front and back end. When building things like secure Stripe payments or interacting with third-party databases, you *cannot* do this in Vue directly because you'd expose your secret API keys in the browser bundle.

#### 2. Plain English Metaphor (The What)
Imagine running a restaurant.
**Old Way (Separate Front/Back end):** You have a dining room (Vue) across the street from the kitchen (Express API). Waiters have to run across traffic (Network latency/CORS) to place orders.
**Nitro Engine (Nuxt 3):** You knock down the wall. The dining room and the kitchen are in the exact same building. Waiters (frontend components) can instantly hand tickets to the kitchen (server API routes) with zero friction. You deploy the whole restaurant as one unit, and the kitchen is highly optimized to run anywhere (Node, Cloudflare Workers, Vercel).

#### 3. Complete Runnable Code: Serverless Stripe Payment Endpoint
```typescript
// server/api/checkout.post.ts
// The file name `.post` automatically restricts this to POST requests.
import { defineEventHandler, readBody, createError } from 'h3';

// Simulated database
const PRODUCT_DB = {
  'prod_1': { price: 2500 }, // $25.00
  'prod_2': { price: 5000 }  // $50.00
};

export default defineEventHandler(async (event) => {
  // 1. Read request body (H3 utility)
  const body = await readBody(event);
  const productId = body.productId;

  if (!productId || !PRODUCT_DB[productId]) {
    throw createError({
      statusCode: 400,
      statusMessage: 'Invalid Product ID provided'
    });
  }

  // 2. Access server-side secret keys safely (cannot be seen by browser)
  // In Nuxt, we use useRuntimeConfig() configured in nuxt.config.ts
  const config = useRuntimeConfig();
  const stripeSecretKey = config.stripeSecretKey; // e.g., sk_test_xxx

  try {
    // 3. Perform server-only logic (simulated Stripe call)
    console.log(`[Nitro Server] Initiating Stripe checkout with key ${stripeSecretKey.substring(0, 8)}...`);
    await new Promise(resolve => setTimeout(resolve, 800)); // Network delay

    const clientSecret = `pi_mock_${Date.now()}_secret_${Math.random()}`;

    // 4. Return JSON response to the Nuxt frontend
    return {
      success: true,
      amount: PRODUCT_DB[productId].price,
      clientSecret: clientSecret
    };
  } catch (error) {
    throw createError({
      statusCode: 500,
      statusMessage: 'Payment Gateway Error'
    });
  }
});
```

```vue
<!-- pages/checkout.vue (Frontend Consumer) -->
<template>
  <div class="checkout-panel">
    <h2>Secure Checkout</h2>

    <div class="products">
      <button @click="processPayment('prod_1')" :disabled="isProcessing">
        Buy Starter Kit ($25)
      </button>
      <button @click="processPayment('prod_2')" :disabled="isProcessing">
        Buy Pro Kit ($50)
      </button>
    </div>

    <div v-if="errorMsg" class="error">{{ errorMsg }}</div>

    <div v-if="successData" class="success">
      Payment Initialized! Client Secret: <code>{{ successData.clientSecret }}</code>
    </div>
  </div>
</template>

<script setup>
import { ref } from 'vue';
// Note: In Nuxt, $fetch automatically connects to local /api routes!

const isProcessing = ref(false);
const errorMsg = ref('');
const successData = ref(null);

const processPayment = async (productId) => {
  isProcessing.value = true;
  errorMsg.value = '';
  successData.value = null;

  try {
    // Call our Nitro API directly
    const response = await $fetch('/api/checkout', {
      method: 'POST',
      body: { productId }
    });

    successData.value = response;
  } catch (err) {
    errorMsg.value = err.data?.statusMessage || 'An unexpected error occurred.';
  } finally {
    isProcessing.value = false;
  }
};
</script>

</style>
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: File-Based API Routing**
*Rationale: Any file placed in the `server/api/` directory automatically becomes an API endpoint. `server/api/hello.ts` becomes the `http://localhost:3000/api/hello` route. By appending `.post`, `.get`, or `.put` to the filename, Nitro automatically restricts the HTTP method.*
```typescript
// server/api/checkout.post.ts
export default defineEventHandler((event) => { /* logic */ });
```

**Step 2: H3 Event Handlers and Utilities**
*Rationale: Nitro runs on an engine called **H3**. It is extremely lightweight compared to Express. Instead of `req` and `res` objects, everything is contained in an `event` object. H3 provides utilities like `readBody(event)` to parse JSON automatically, and `createError()` to send proper HTTP status codes.*

**Step 3: Secure Server Environment**
*Rationale: Code in the `server/` directory is **never** bundled or sent to the browser. This means you can safely use database credentials, private API keys, and file system modules (`fs`). The frontend uses `$fetch('/api/endpoint')` to communicate over standard HTTP.*

#### 5. ASCII Architecture Data Flow
```text
[ Browser (Vue Component) ]
            │
      ($fetch POST /api/checkout)
            │
            ▼
[ Nuxt Nitro Server (H3 Engine) ] ◄── Uses useRuntimeConfig() to get STRIPE_SECRET_KEY
            │
            ▼
[ server/api/checkout.post.ts ]
            │
            ├─► readBody(event) parses JSON `{ productId: 'prod_1' }`
            ├─► Validates against Database
            ├─► Makes secure HTTP call to Stripe API (Browser never sees this)
            │
            ▼
[ Returns JSON Object to Browser ]
            │
            ▼
[ Vue Component Updates DOM ]
```

#### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using Nuxt API routes for every single piece of data fetching when you already have an existing external backend (like a Django or Spring Boot API). Nitro is great, but if your company already has a dedicated backend team, use Nuxt mostly for SSR and proxying, don't rebuild the entire backend in `server/api/`.
**Pro Tip:** You can use Nitro's `server/routes/` folder to serve non-API files dynamically. For example, `server/routes/sitemap.xml.ts` can generate an XML sitemap on the fly based on your database contents, and serve it exactly at `yourdomain.com/sitemap.xml`.

#### Level 2: Real-World
**Task:** Build a "Newsletter Signup" POST route (`server/api/subscribe.post.ts`). It must read the `email` from the body. If the email doesn't include an `@` symbol, throw a 400 Bad Request error. Otherwise, return `{ success: true }`. Consume it from a form in a component.
<details>
<summary>Hint</summary>
Use `readBody(event)` in the server. Use `throw createError({ statusCode: 400, statusMessage: "..." })` for validation. Catch the error in the component.
</details>
<details>
<summary>Solution Walkthrough</summary>
```typescript
// server/api/subscribe.post.ts
import { defineEventHandler, readBody, createError } from 'h3';

export default defineEventHandler(async (event) => {
  const body = await readBody(event);

  if (!body.email || !body.email.includes('@')) {
    throw createError({
      statusCode: 400,
      statusMessage: 'Invalid email address provided.'
    });
  }

  // Simulate DB save...
  return { success: true, subscribed: body.email };
});
```

```vue
<!-- pages/subscribe.vue -->
<template>
  <form @submit.prevent="submitForm">
    <input v-model="email" type="text" placeholder="Email" />
    <button type="submit">Subscribe</button>
    <p v-if="error" style="color:red">{{ error }}</p>
    <p v-if="successMsg" style="color:green">{{ successMsg }}</p>
  </form>
</template>

<script setup>
import { ref } from 'vue';

const email = ref('');
const error = ref('');
const successMsg = ref('');

const submitForm = async () => {
  error.value = '';
  successMsg.value = '';

  try {
    const res = await $fetch('/api/subscribe', {
      method: 'POST',
      body: { email: email.value }
    });
    successMsg.value = `Successfully subscribed ${res.subscribed}`;
  } catch (err) {
    error.value = err.data?.statusMessage || 'Failed';
  }
};
</script>
```

#### Level 3: Boss Level
**Task:** Build an API route with a dynamic parameter: `server/api/users/[id].ts`. Extract the `id` from the route. Check if the ID exists in a mock user database. If not, throw a 404. If it does, return the user data. Fetch this dynamically from a Vue page (`pages/users/[id].vue`).
<details>
<summary>Hint</summary>
In H3, use `getRouterParam(event, 'id')` to extract the ID from the URL file path.
</details>
<details>
<summary>Solution Walkthrough</summary>
```typescript
// server/api/users/[id].ts
import { defineEventHandler, getRouterParam, createError } from 'h3';

const USERS_DB = {
  '1': { name: 'Alice', role: 'Admin' },
  '2': { name: 'Bob', role: 'Editor' }
};

export default defineEventHandler((event) => {
  // Extract dynamic ID from URL parameters
  const userId = getRouterParam(event, 'id');

  if (!userId || !USERS_DB[userId]) {
    throw createError({
      statusCode: 404,
      statusMessage: `User with ID ${userId} not found.`
    });
  }

  return USERS_DB[userId];
});
```

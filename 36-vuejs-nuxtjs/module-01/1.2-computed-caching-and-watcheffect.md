# Module 01: The Reactivity Proxy Revolution
## 1.2 Computed Caching, watch, and watchEffect

### Phase A: Core Concept Exploration

#### 1. Real-World Pain Point (The Why)
Imagine an e-commerce platform where a user searches through 10,000 products, filters by category, applies a discount code, and calculates regional tax. If you use a standard method/function in your template (e.g., `{{ calculateTax() }}`), Vue will re-run that heavy calculation *every single time* anything on the page changes—even if the user just types a single letter into a totally unrelated "contact us" input field. This destroys performance. Additionally, you often need to trigger side-effects (like fetching new data from an API) *automatically* when specific state changes.

#### 2. Plain English Metaphor (The What)
**Computed Properties:** Think of a `computed` property like a smart accountant with a notebook. You ask them, "What is 15% tax on this $10,000 order?" They do the math once, write the answer ($1,500) in their notebook, and hand it to you. If you ask again 5 minutes later, they don't do the math again; they just read the cached answer from the notebook. They only recalculate if the order total or tax rate changes.
**Watchers:** A `watch` or `watchEffect` is like setting an alarm on your phone. `watch` is specific: "Ring ONLY when the oven timer hits zero." `watchEffect` is observant: "I'll watch everything you do, and if you touch the oven or the fridge, I'll sound the alarm."

#### 3. Complete Runnable Code: High-Performance Search & Tax Engine
```vue
<template>
  <div class="engine-container">
    <h2>E-Commerce Data Engine</h2>

    <div class="controls">
      <input v-model="searchQuery" placeholder="Search products..." />
      <select v-model="selectedRegion">
        <option value="US">United States (8%)</option>
        <option value="UK">United Kingdom (20%)</option>
        <option value="JP">Japan (10%)</option>
      </select>
    </div>

    <div class="results">
      <h3>Filtered Catalog ({{ filteredProducts.length }} items)</h3>
      <ul>
        <li v-for="product in filteredProducts" :key="product.id">
          {{ product.name }} - Base: ${{ product.price }} | With Tax: ${{ calculateItemTax(product.price) }}
        </li>
      </ul>
      <p class="total">Total Catalog Value (with Tax): ${{ totalCatalogValue }}</p>
    </div>

    <!-- Unrelated state to prove computed caching -->
    <button @click="unrelatedCounter++">Unrelated Click: {{ unrelatedCounter }}</button>
  </div>
</template>

<script setup>
import { ref, computed, watch, watchEffect } from 'vue';

const searchQuery = ref('');
const selectedRegion = ref('US');
const unrelatedCounter = ref(0);

// Mock massive catalog
const catalog = ref([
  { id: 1, name: 'Quantum Processor', price: 500 },
  { id: 2, name: 'Mechanic Keyboard', price: 150 },
  { id: 3, name: 'Optical Mouse', price: 80 },
]);

const taxRates = { US: 1.08, UK: 1.20, JP: 1.10 };

// 1. Computed: Caches the filtered list.
// Won't re-run when 'unrelatedCounter' changes!
const filteredProducts = computed(() => {
  console.log('--- RUNNING HEAVY FILTER LOGIC ---');
  if (!searchQuery.value) return catalog.value;
  return catalog.value.filter(p =>
    p.name.toLowerCase().includes(searchQuery.value.toLowerCase())
  );
});

// 2. Computed: Depends on ANOTHER computed property.
const totalCatalogValue = computed(() => {
  return filteredProducts.value.reduce((total, p) => {
    return total + (p.price * taxRates[selectedRegion.value]);
  }, 0).toFixed(2);
});

// Helper for template (Not cached per-item in this context, just for display)
const calculateItemTax = (price) => {
  return (price * taxRates[selectedRegion.value]).toFixed(2);
};

// 3. watch(): Explicitly watches a specific source.
// Great for async operations when a specific ID changes.
watch(selectedRegion, async (newRegion, oldRegion) => {
  console.log(`[Watch] Region changed from ${oldRegion} to ${newRegion}. Fetching new shipping rates...`);
  // await fetchShippingRates(newRegion);
});

// 4. watchEffect(): Automatically tracks ANY reactive dependency used inside it.
// Great for broad sync tasks.
watchEffect(() => {
  console.log(`[WatchEffect] Analytics tracking: User is searching for "${searchQuery.value}" in region "${selectedRegion.value}"`);
  // If either changes, this runs automatically.
}, { flush: 'post' }); // Runs AFTER the DOM updates
</script>

<style scoped>
.engine-container { font-family: monospace; border: 1px solid #333; padding: 20px; }
.controls { margin-bottom: 20px; }
.total { font-weight: bold; color: green; }
</style>
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: Implementing `computed` for Cached Derived State**
*Rationale: We use `computed` for `filteredProducts` so that the heavy `.filter()` operation is only executed when `searchQuery` changes. If the user clicks the "Unrelated Click" button, the UI updates, but the filter logic skips execution and uses the cache.*
```javascript
const filteredProducts = computed(() => {
  // Logic here only re-runs if 'searchQuery' or 'catalog' mutates.
});
```

**Step 2: Explicit Side-Effects with `watch`**
*Rationale: When the user changes their region, we don't just want to update UI math; we want to trigger a side-effect (like an API call). `watch` allows us to compare the `oldRegion` and `newRegion` before firing.*
```javascript
watch(selectedRegion, (newValue, oldValue) => {
  // Fire API call based specifically on region change.
});
```

**Step 3: Automatic Dependency Tracking with `watchEffect`**
*Rationale: Sometimes you have an analytics function that needs to run if *any* relevant state changes. Instead of passing an array of 5 variables to `watch`, you use `watchEffect`. It automatically determines its dependencies based on what you read inside the function body.*
```javascript
watchEffect(() => {
  // Automatically tracks searchQuery and selectedRegion just by reading them.
});
```

#### 5. ASCII Architecture Data Flow
```text
[ searchQuery Ref mutates ] ---> (Invalidates 'filteredProducts' Cache)
                                      │
                                      ▼
                               [ computed() re-runs ]
                                      │
                                      ▼
             (Triggers downstream computed dependent: 'totalCatalogValue')
                                      │
                                      ▼
                             [ DOM Render Queue ]
                                      │
                                      ▼
             [ watchEffect( { flush: 'post' } ) Executes ] <-- Runs AFTER DOM is patched
```

#### 6. Noob Trap vs Pro Tip
**Noob Trap:** Using a `<template>` method like `{{ calculateTotal() }}` for heavy lists. Vue will execute `calculateTotal()` on every single re-render cycle, tanking frame rates. Also, putting asynchronous API calls inside a `computed` property—computed properties must be synchronous and pure (no side effects).
**Pro Tip:** Use the `{ flush: 'post' }` option on `watchEffect` or `watch` when you need to interact with the DOM *after* Vue has finished updating it (e.g., scrolling to the bottom of a chat window after a new message arrives). By default, watchers run *before* DOM updates.

#### Level 1: Warm-Up
**Task:** Create a `firstName` and `lastName` ref. Create a `fullName` computed property. Finally, create a `watch` that logs a message to the console every time `fullName` changes.
<details>
<summary>Hint</summary>
Computed properties return a ref, so you can pass the computed property directly into the first argument of `watch`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```vue
<template>
  <div>
    <input v-model="first" placeholder="First Name" />
    <input v-model="last" placeholder="Last Name" />
    <p>Full Name: {{ fullName }}</p>
  </div>
</template>

<script setup>
import { ref, computed, watch } from 'vue';

const first = ref('');
const last = ref('');

const fullName = computed(() => `${first.value} ${last.value}`.trim());

watch(fullName, (newVal) => {
  console.log(`Full name updated to: ${newVal}`);
});
</script>
```
</details>

#### Level 2: Real-World
**Task:** Build a password strength indicator. You have a `password` ref. Create a `computed` property called `strengthScore` (0-3) based on length and characters. Create a `watchEffect` that automatically saves the `password` to `localStorage` whenever it changes.
<details>
<summary>Hint</summary>
`watchEffect` doesn't need to be told to watch `password`. Just write `localStorage.setItem('pw', password.value)` inside it, and Vue will wire up the dependency automatically.
</details>
<details>
<summary>Solution Walkthrough</summary>
```vue
<template>
  <div>
    <input type="password" v-model="password" />
    <p>Strength Score: {{ strengthScore }} / 3</p>
  </div>
</template>

<script setup>
import { ref, computed, watchEffect } from 'vue';

const password = ref('');

const strengthScore = computed(() => {
  let score = 0;
  if (password.value.length > 5) score++;
  if (/[A-Z]/.test(password.value)) score++;
  if (/[0-9]/.test(password.value)) score++;
  return score;
});

watchEffect(() => {
  // Automatically tracks 'password'
  localStorage.setItem('draft_password', password.value);
});
</script>
```
</details>

#### Level 3: Boss Level
**Task:** Build an "Infinite Scroll Tracker". You have an array of `items` and a `containerHeight` ref. Use `computed` to determine if `items.length > 50` (returns boolean `isMaxed`). Use a `watch` with `flush: 'post'` to automatically scroll the container to the bottom *after* new items are pushed to the array and the DOM has rendered the new `<li>` elements.
<details>
<summary>Hint</summary>
You need a template ref (`<div ref="scrollContainer">`) to access the DOM element. The watch will look like `watch(items, () => { /* scroll logic */ }, { deep: true, flush: 'post' })`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```vue
<template>
  <div>
    <div ref="scrollBox" class="scroll-box">
      <div v-for="item in items" :key="item.id" class="item">
        {{ item.text }}
      </div>
    </div>
    <button :disabled="isMaxed" @click="addItem">Add Item</button>
    <p v-if="isMaxed">Maximum items reached!</p>
  </div>
</template>

<script setup>
import { ref, computed, watch } from 'vue';

const items = ref([{ id: 1, text: 'Initial Item' }]);
const scrollBox = ref(null); // Template ref

const isMaxed = computed(() => items.value.length >= 10);

const addItem = () => {
  items.value.push({ id: Date.now(), text: `New Item ${items.value.length + 1}` });
};

// Watch array for changes. flush: 'post' ensures the DOM has updated
// so scrollHeight includes the newly added element!
watch(items, () => {
  if (scrollBox.value) {
    scrollBox.value.scrollTop = scrollBox.value.scrollHeight;
  }
}, { deep: true, flush: 'post' });
</script>

<style scoped>
.scroll-box { height: 150px; overflow-y: auto; border: 1px solid black; }
.item { padding: 10px; border-bottom: 1px solid #ccc; }
</style>
```
</details>

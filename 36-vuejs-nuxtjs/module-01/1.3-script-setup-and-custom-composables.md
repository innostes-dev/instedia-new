# Module 01: The Reactivity Proxy Revolution
## 1.3 `<script setup>` and Custom Composables

### Phase A: Core Concept Exploration

#### 1. Real-World Pain Point (The Why)
In Vue 2 (Options API), code was organized by *type* (data, methods, computed, watch). For a single feature (like "User Authentication"), the code was scattered across the entire file. Reusing logic across components required Mixins, which caused namespace collisions (two mixins having a `fetchData` method) and obscure data sources (where did `this.userData` come from?).
In Vue 3, using standard `setup()` required a massive `return { ... }` block at the end of the script to expose variables to the template, leading to boilerplate fatigue.

#### 2. Plain English Metaphor (The What)
**`<script setup>`:** Imagine packing for a trip. In the old way (`setup()` with `return`), you put everything in your suitcase, and then right before leaving, you had to write a detailed manifest list of exactly what was in the suitcase to hand to TSA. With `<script setup>`, the suitcase is transparent. TSA (the template) can automatically see and use anything you put inside it.
**Composables:** A Composable is like a Lego block of behavior. Instead of copying and pasting the complex wiring for a "Motion Sensor" into every single Lego house you build, you build the sensor once as a distinct, pluggable block. You just snap `useMotionSensor()` into your house, and it works independently without interfering with other blocks.

#### 3. Complete Runnable Code: Reusable Breakpoint & Theme Composable
```vue
<!-- App.vue (Consumer) -->
<template>
  <div :class="['app-container', themeClass]">
    <h2>Composable Dashboard</h2>

    <div class="status-panel">
      <p>Current Theme: <strong>{{ currentTheme }}</strong></p>
      <button @click="toggleTheme">Toggle Theme</button>
    </div>

    <div class="status-panel">
      <p>Window Width: <strong>{{ windowWidth }}px</strong></p>
      <p>Device Mode: <strong>{{ isMobile ? '📱 Mobile' : '💻 Desktop' }}</strong></p>
    </div>
  </div>
</template>

<script setup>
// Notice no export default, no setup(), no return {}!
import { computed } from 'vue';
import { useTheme } from './composables/useTheme';
import { useWindowBreakpoints } from './composables/useWindowBreakpoints';

// 1. Consume Theme Composable
const { theme: currentTheme, toggleTheme } = useTheme();

// 2. Consume Breakpoint Composable
const { width: windowWidth, isMobile } = useWindowBreakpoints();

// Local logic combining composable state
const themeClass = computed(() => `theme-${currentTheme.value}`);
</script>

<style scoped>
.app-container { transition: all 0.3s; padding: 20px; min-height: 100vh; }
.theme-light { background: #ffffff; color: #333333; }
.theme-dark { background: #1a1a1a; color: #ffffff; }
.status-panel { margin-top: 20px; padding: 15px; border: 1px solid #888; border-radius: 8px;}
</style>
```

```javascript
// composables/useTheme.js
import { ref, watchEffect } from 'vue';

export function useTheme() {
  // Global state across instances (defined OUTSIDE the function)
  // vs Local state (defined INSIDE). Here we use local.
  const theme = ref('light');

  const toggleTheme = () => {
    theme.value = theme.value === 'light' ? 'dark' : 'light';
  };

  // Automatically sync to local storage
  watchEffect(() => {
    if (typeof window !== 'undefined') {
      localStorage.setItem('app-theme', theme.value);
    }
  });

  return { theme, toggleTheme };
}
```

```javascript
// composables/useWindowBreakpoints.js
import { ref, computed, onMounted, onUnmounted } from 'vue';

export function useWindowBreakpoints() {
  const width = ref(0);

  const updateWidth = () => {
    width.value = window.innerWidth;
  };

  onMounted(() => {
    updateWidth();
    window.addEventListener('resize', updateWidth);
  });

  onUnmounted(() => {
    window.removeEventListener('resize', updateWidth);
  });

  // Derived state exported directly
  const isMobile = computed(() => width.value < 768);
  const isTablet = computed(() => width.value >= 768 && width.value < 1024);
  const isDesktop = computed(() => width.value >= 1024);

  return { width, isMobile, isTablet, isDesktop };
}
```

#### 4. Progressive Step-by-Step Breakdown

**Step 1: The Magic of `<script setup>`**
*Rationale: We eliminate boilerplate. Any variable or function declared at the top level of `<script setup>` is immediately available to the template.*
```vue
<script setup>
const myVar = 'Hello'; // Usable directly in <template>
function doThing() {}  // Usable directly in <template>
</script>
```

**Step 2: Extracting Logic into a Composable**
*Rationale: `useWindowBreakpoints` handles its own state (`width`), lifecycle hooks (`onMounted`, `onUnmounted`), and computed logic. It encapsulates the entire "Window Size" feature into one file.*
```javascript
export function useWindowBreakpoints() {
  const width = ref(0);
  // ... event listeners ...
  return { width, isMobile }; // Expose only what's needed
}
```

**Step 3: Consuming and Renaming Composables**
*Rationale: Because composables return standard JS objects containing refs, we can destructure them. We can also rename them to prevent naming collisions (solving the Mixin problem).*
```javascript
const { theme: currentTheme } = useTheme();
// Inside this component, 'theme' is now referenced as 'currentTheme'
```

#### 5. ASCII Architecture Data Flow
```text
[ useTheme.js ]             [ useWindowBreakpoints.js ]
      │                                  │
      ▼                                  ▼
{ theme, toggleTheme }       { width, isMobile, ... }
      │                                  │
      └────────────► [ App.vue ] ◄───────┘
                     <script setup>
                           │
                           ▼
                    [ Vue Template ]
```

#### 6. Noob Trap vs Pro Tip
**Noob Trap:** Defining reactive state *outside* the exported function in a composable when you want it to be local to the component. If `const count = ref(0)` is outside `export function useCounter()`, the `count` becomes a global singleton shared by *every* component that uses it. This can cause severe state-bleeding bugs in SSR (Nuxt).
**Pro Tip:** Use the convention `useSomething` for composables. Always return an object `{ ref1, function2 }` from a composable rather than an array `[ref1, function2]` (like React hooks). Returning an object allows the consumer to destructure only what they need, regardless of order.

#### Level 2: Real-World
**Task:** Create a `useMouse` composable that tracks `x` and `y` coordinates using `onMounted` and `onUnmounted` lifecycle hooks. Consume it in a `<script setup>` component.
<details>
<summary>Hint</summary>
Create the composable file, return `{ x, y }` as refs. Import it into your component and destructure the return object.
</details>
<details>
<summary>Solution Walkthrough</summary>
```javascript
// composables/useMouse.js
import { ref, onMounted, onUnmounted } from 'vue';

export function useMouse() {
  const x = ref(0);
  const y = ref(0);

  const update = (e) => {
    x.value = e.pageX;
    y.value = e.pageY;
  };

  onMounted(() => window.addEventListener('mousemove', update));
  onUnmounted(() => window.removeEventListener('mousemove', update));

  return { x, y };
}
```

```vue
<!-- Consumer.vue -->
<template>
  <div>Mouse is at: {{ x }}, {{ y }}</div>
</template>

<script setup>
import { useMouse } from './composables/useMouse';

const { x, y } = useMouse();
</script>
```
</details>

#### Level 3: Boss Level
**Task:** Build a `useFetch` composable. It must take a URL, and return `data` (ref), `error` (ref), `isPending` (ref), and an `execute` function. Consume it in a component to fetch `https://jsonplaceholder.typicode.com/users/1`. Handle the loading state and display the user's name.
<details>
<summary>Hint</summary>
Initialize `data` as `null`, `error` as `null`, and `isPending` as `false`. In `execute`, set `isPending = true`, wrap the `fetch` in a `try/catch`, update `data` or `error`, and finally `isPending = false`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```javascript
// composables/useFetch.js
import { ref } from 'vue';

export function useFetch(url) {
  const data = ref(null);
  const error = ref(null);
  const isPending = ref(false);

  const execute = async () => {
    isPending.value = true;
    error.value = null;
    try {
      const response = await fetch(url);
      if (!response.ok) throw new Error('Failed to fetch');
      data.value = await response.json();
    } catch (err) {
      error.value = err.message;
    } finally {
      isPending.value = false;
    }
  };

  return { data, error, isPending, execute };
}
```

```vue
<!-- UserProfile.vue -->
<template>
  <div>
    <button @click="execute" :disabled="isPending">
      {{ isPending ? 'Loading...' : 'Fetch User' }}
    </button>

    <div v-if="error" style="color: red;">Error: {{ error }}</div>
    <div v-else-if="data">
      <h3>User: {{ data.name }}</h3>
      <p>Email: {{ data.email }}</p>
    </div>
  </div>
</template>

<script setup>
import { useFetch } from './composables/useFetch';

const { data, error, isPending, execute } = useFetch('https://jsonplaceholder.typicode.com/users/1');
</script>
```
</details>

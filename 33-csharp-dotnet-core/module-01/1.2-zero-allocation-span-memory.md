# 1.2 Zero-Allocation with Span<T> & Memory<T>

## Phase A: The Core Pedagogy

### 1. Real-World Pain Point (The Why)
You're writing a high-performance HTTP server or a parser for large CSV files. Every time you read a line, you use `string.Substring()` or `string.Split()`. Since strings are immutable in C#, every `Substring` call allocates a brand new string on the heap. Parsing a 1GB CSV file with 10 million rows might create 100 million temporary string allocations, triggering massive Gen 0 garbage collections, tanking your CPU and stalling your server.

### 2. Plain English Metaphor (The What)
Imagine you have a giant continuous map of the world (an array).
- **string.Substring:** You take a pair of scissors, cut out a country, glue it onto a brand new piece of paper, and hand it to someone. That wastes paper (memory) and time (allocation).
- **Span<T> / ReadOnlySpan<T>:** You take a red picture frame (a window) and place it over the country on the original map. You hand the frame to someone. They can see the country, but you didn't create a new map. It's a zero-allocation view into existing memory.

### 3. Complete Runnable Code
Here is a Blazing-Fast CSV/Log Line Protocol Parser.

```csharp
using System;

namespace SpanMemoryDemo
{
    class Program
    {
        static void Main()
        {
            string logLine = "2024-03-15,ERROR,Database connection timeout,1054";

            // BAD: Allocates 4 new strings on the heap
            string[] badParts = logLine.Split(',');
            Console.WriteLine($"[Bad] Level: {badParts[1]}");

            // GOOD: Zero allocations, purely structural view
            ReadOnlySpan<char> spanLine = logLine.AsSpan();

            // Find first comma
            int firstComma = spanLine.IndexOf(',');
            ReadOnlySpan<char> dateSpan = spanLine.Slice(0, firstComma);

            // Move past first comma
            ReadOnlySpan<char> remainder = spanLine.Slice(firstComma + 1);

            // Find second comma
            int secondComma = remainder.IndexOf(',');
            ReadOnlySpan<char> levelSpan = remainder.Slice(0, secondComma);

            Console.WriteLine($"[Good] Level: {levelSpan.ToString()}"); // .ToString() allocates, but in real life we might parse directly
        }
    }
}
```

### 4. Progressive Step-by-Step Breakdown

**Step 1: The Problem with Strings and Arrays**
*Why this precedes Step 2:* We must understand why `Substring` is bad. Strings in .NET are immutable arrays of characters. Any operation that extracts a part of a string requires allocating a new block of memory, copying the characters over, and returning a reference to the new string.

**Step 2: Enter Span<T> and ReadOnlySpan<T>**
*Why this precedes Step 3:* `Span<T>` is a `ref struct`. It lives entirely on the stack and contains just a pointer to the start of the memory and a length. `ReadOnlySpan<T>` is used for immutable strings. Slicing a span (`span.Slice()`) just creates a new stack struct with an updated pointer and length. Zero heap allocations.

**Step 3: The Limitation of Span and the rise of Memory<T>**
*Why this concludes the breakdown:* `Span<T>` is a `ref struct`, meaning it can *only* live on the stack. You cannot use it in async methods (which compile to state machines on the heap), or as fields in a class. If you need a zero-allocation view that *can* be stored on the heap or used across `await` boundaries, you use `Memory<T>` and `ReadOnlyMemory<T>`, which can be converted to a `Span<T>` when you need to read the data.

### 5. ASCII Architecture Data Flow
```text
Original String Array (Heap):  [ 2 | 0 | 2 | 4 | - | 0 | 3 | - | 1 | 5 | , | E | R | R | O | R | , ... ]

string.Substring(11, 5)   --> Allocates NEW String [ E | R | R | O | R ] (Heap) -> GC Pressure

ReadOnlySpan.Slice(11, 5) --> Pointer(Address of 'E') + Length(5) (Stack) -> ZERO GC Pressure
```

### 6. Noob Trap vs Pro Tip
- **Noob Trap:** Using `string.Split()` inside a high-frequency parsing loop, causing massive Gen 0 allocations.
- **Pro Tip:** Use `ReadOnlySpan<char>` for parsing logic. Use `int.Parse(ReadOnlySpan<char>)` which natively supports spans without needing to convert back to a string first!

## Phase B: Real-World Engineering Challenges

### Level 1: Warm-Up
**Challenge:** You have a string `string data = "ID-9938-XYZ";`. Extract the middle number (`9938`) as an integer without using `Substring`.
<details>
<summary>Hint</summary>
Use `.AsSpan()`, `.Slice()`, and `int.Parse()`.
</details>
<details>
<summary>Solution Walkthrough</summary>
```csharp
string data = "ID-9938-XYZ";
ReadOnlySpan<char> span = data.AsSpan();
ReadOnlySpan<char> numberSpan = span.Slice(3, 4); // Start at index 3, length 4
int id = int.Parse(numberSpan); // Native span parsing!
```
</details>

### Level 2: Real-World
**Challenge:** Write a zero-allocation method that counts how many times the character `';'` appears in a `ReadOnlySpan<char>`.
<details>
<summary>Hint</summary>
Use a `while` loop and `span.IndexOf(';')`. After finding one, slice the span past the index.
</details>
<details>
<summary>Solution Walkthrough</summary>
```csharp
public int CountSemicolons(ReadOnlySpan<char> input)
{
    int count = 0;
    int index;
    while ((index = input.IndexOf(';')) != -1)
    {
        count++;
        // Move the slice past the found semicolon
        input = input.Slice(index + 1);
    }
    return count;
}
```
</details>

### Level 3: Boss Level (Cumulative)
**Challenge:** Combine `Memory<T>` and `readonly struct`. You have an async method that processes a TCP stream. You read data into a rented `byte[]` buffer. Extract a slice of the buffer and pass it to an `async` logging method. Why can't you use `Span<T>` here?
<details>
<summary>Hint</summary>
`Span<T>` cannot cross `await` boundaries because it's a `ref struct`. Use `Memory<T>` to wrap the rented buffer.
</details>
<details>
<summary>Solution Walkthrough</summary>
```csharp
using System;
using System.Buffers;
using System.Threading.Tasks;

public class AsyncParser
{
    public async Task ProcessStreamAsync(int dataLength)
    {
        byte[] buffer = ArrayPool<byte>.Shared.Rent(dataLength);
        try
        {
            // Wrap array in Memory<T>
            Memory<byte> memoryBuffer = new Memory<byte>(buffer, 0, dataLength);

            // Slice the memory for the payload
            Memory<byte> payload = memoryBuffer.Slice(10, 50);

            // We CAN await with Memory<T>, we CANNOT with Span<T>
            await LogPayloadAsync(payload);
        }
        finally
        {
            ArrayPool<byte>.Shared.Return(buffer);
        }
    }

    private async Task LogPayloadAsync(Memory<byte> payload)
    {
        // When we need to read it, we get the Span synchronously
        ReadOnlySpan<byte> span = payload.Span;
        Console.WriteLine($"First byte: {span[0]}");
        await Task.Delay(10); // Simulate I/O
    }
}
```
This achieves zero-allocation slicing while maintaining async compatibility.
</details>
